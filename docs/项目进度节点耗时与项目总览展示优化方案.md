# 项目进度节点耗时与项目总览展示优化方案

> 文档日期：2026-09-16  
> 当前阶段：方案沉淀，尚未修改代码。  
> 目标：在项目进度节点中记录每个节点从开始到完成用了多少天，并在项目总览/项目列表中展示当前项目进行到哪一步以及当前节点已进行天数。

## 1. 背景

当前项目流程进度已经支持：

```text
项目进度节点
节点状态
计划完成日期
关联单据
实际完成时间
节点关联表单
当前进度节点
```

但目前缺少一个关键视角：

```text
这个节点从开始到完成用了多少天？
当前正在进行的节点已经进行了多少天？
```

因此项目负责人在项目详情或项目列表中，只能知道：

```text
做到哪一步
是否完成
什么时候完成
```

但不能直接看到：

```text
这一步耗时多久
当前这一步已经卡了几天
```

## 2. 本次优化目标

本次优化新增两个层面的展示：

### 2.1 项目详情页：进度节点表

每个项目进度节点显示：

```text
实际开始时间
实际完成时间
耗时天数
```

预期效果：

```text
节点名称 | 权重 | 计划完成 | 关联单据 | 状态   | 实际开始时间        | 实际完成时间        | 耗时天数 | 备注
11      | 50%  | ...      | MFG...   | 已完成 | 2026-09-15 10:00   | 2026-09-16 09:41   | 2天      |
22      | 50%  | ...      |          | 进行中 | 2026-09-16 09:41   | -                  | 已进行1天 |
```

### 2.2 项目总览/项目列表

项目列表显示：

```text
当前进度节点
当前节点耗时
```

预期效果：

```text
项目名称 | 状态   | 当前进度节点 | 当前节点耗时 | 立项日期   | 预计结项日期
222      | 进行中 | 22           | 已进行1天    | 2026-09-15 | -
```

## 4. 业务口径

### 4.1 节点什么时候开始

当节点状态从：

```text
待开始 -> 进行中
```

或者系统判断该节点成为当前未完成节点时，写入：

```text
actual_started_on = 当前时间
```

如果节点已经有开始时间，则不覆盖。

原因：

```text
一个节点可能被重复重算进度，不能每次重算都刷新开始时间。
开始时间应代表这个节点第一次进入执行状态的时间。
```

### 4.2 节点什么时候完成

沿用现有逻辑：

```text
绑定业务表单提交
  -> Project Progress Reference.status = Completed
  -> Project Progress Item.status = 已完成
  -> Project Progress Item.actual_completed_on = 完成时间
```

完成时计算：

```text
duration_days = actual_completed_on 日期 - actual_started_on 日期 + 1
duration_display = "{duration_days}天"
```

### 4.3 正在进行中的节点耗时

对于状态为：

```text
进行中
延期
```

并且已有 `actual_started_on` 的节点，显示：

```text
duration_days = 今天 - actual_started_on 日期 + 1
duration_display = "已进行{duration_days}天"
```

### 4.4 待开始节点

```text
actual_started_on = 空
duration_days = 空
duration_display = "-"
```

### 4.5 已完成节点但没有开始时间

兼容历史数据：

```text
如果 actual_started_on 为空，但 actual_completed_on 有值：
  actual_started_on 可回填为 actual_completed_on
  duration_days = 1
  duration_display = "1天"
```

这样可以避免历史节点出现无法计算的空值。

## 5. 计算规则

### 5.1 自然天口径

本次按自然天计算，包含开始当天：

```text
耗时天数 = 完成日期 - 开始日期 + 1
```

示例：

```text
2026-09-15 开始，2026-09-15 完成 = 1天
2026-09-15 开始，2026-09-16 完成 = 2天
2026-09-15 开始，2026-09-18 完成 = 4天
```

### 5.2 不按小时精算

首版不做：

```text
按小时换算
不足 24 小时算 0.x 天
工作日/节假日剔除
```

原因：

```text
项目管理场景里，自然天更容易理解。
后续如果要做工时或工作日，可新增独立字段，不影响本次设计。
```

## 6. 调用链路

### 6.1 项目开始

现有链路：

```text
点击 项目开始
  -> start_project(project)
  -> 项目阶段 = 进行中
  -> 第一个未完成节点状态 = 进行中
```

新增：

```text
第一个未完成节点 actual_started_on = 当前时间
第一个未完成节点 duration_display = 已进行1天
Project.custom_current_progress_step = 当前节点名称
Project.custom_current_progress_duration = 已进行1天
```

### 6.2 业务表单提交完成节点

现有链路：

```text
业务表单提交
  -> sync_progress_from_reference
  -> Project Progress Reference = Completed
  -> recalculate_progress_item
  -> Project Progress Item.status = 已完成
  -> Project Progress Item.actual_completed_on = 当前时间
```

新增：

```text
如果节点没有 actual_started_on：
  actual_started_on = actual_completed_on

计算 duration_days
写入 duration_display = X天

如果还有下一个未完成节点：
  下一个节点进入 进行中
  写入下一个节点 actual_started_on
  写入 Project 当前节点与当前节点耗时
```

### 6.3 每日重算

现有链路：

```text
scheduled_recalculate_project_progress
  -> _persist_project_totals(project)
```

新增：

```text
对于进行中/延期节点：
  根据今天刷新 duration_days 和 duration_display

同步 Project.custom_current_progress_duration
```

这样页面上的“已进行 X 天”每天会自动更新。

## 10. 数据兼容

对于历史数据：

```text
已有实际完成时间，但没有实际开始时间的节点
  -> actual_started_on = actual_completed_on
  -> duration_days = 1
  -> duration_display = 1天

进行中但没有开始时间的节点
  -> actual_started_on = 最近同步时间 或 当前时间
  -> duration_display = 已进行1天
```

建议在实现后执行一次重算：

```text
遍历所有项目
  -> 回填节点实际开始时间
  -> 回填耗时
  -> 更新项目当前节点耗时
```

## 12. 风险与回滚

### 12.1 风险

```text
历史数据没有实际开始时间，首轮回填只能按兼容规则估算。
```

处理：

```text
历史已完成节点按 1 天回填。
后续新节点会按真实进入“进行中”的时间记录。
```

### 12.2 回滚

如需回滚：

```text
保留字段不展示即可。
移除 Project 列表字段。
停止在计算逻辑中更新 duration 字段。
```

已有业务表单绑定和项目进度百分比不受影响。

## 13. 推荐实施顺序

```text
1. 新增字段
2. 修改项目进度计算逻辑
3. 回填历史数据
4. 项目详情页显示耗时列
5. 项目列表显示当前节点耗时
6. Playwright 验证
```

本次建议保持小增量：

```text
先实现节点耗时和当前节点耗时。
暂不实现项目总耗时、工作日耗时、小时级耗时。
```
