# 销售订单到销售出库简化流程沉淀

## 1. 背景

测试销售订单履约流程时，发现以下问题：

1. 有些销售订单可以直接生成销售送货单，并不会自动跳转到拣货单。
2. 已经完成交付的订单再次生成送货单时，会提示物料数量超出订单允许量。
3. “销售订单 -> 拣货单 -> 销售送货单 -> 提交”的步骤较多，容易重复操作。

结论：ERPNext 中拣货单不是销售出库的必经单据。销售订单可以直接生成销售送货单；拣货单主要用于需要仓库拣货、分仓库分配、批次/序列号拣选或集中波次拣货的场景。

## 2. 当前标准流程

### 2.1 简单出库流程

```text
销售订单（已提交）
    -> 创建销售送货单
    -> 核对仓库、数量、批次/序列号
    -> 提交销售送货单
    -> 库存扣减，销售订单交付数量更新
```

此流程不经过拣货单，适合以下情况：

- 一个订单对应一次出库；
- 出库仓库已经明确；
- 不需要仓库人员单独记录“已拣货数量”；
- 不存在复杂的多仓库、批次或序列号拣选要求。

### 2.2 仓库拣货流程

```text
销售订单（已提交）
    -> 创建拣货单
    -> 自动或人工分配仓库、批次、序列号
    -> 提交拣货单
    -> 从拣货单创建销售送货单
    -> 提交销售送货单
    -> 库存扣减，销售订单交付数量更新
```

拣货单提交只记录拣货结果，不直接完成销售出库；实际库存扣减发生在销售送货单提交时。

## 3. 为什么测试时没有跳转到拣货单

这属于标准行为，不一定是系统异常：

1. 从销售订单点击“创建销售送货单”时，系统直接进入销售送货单。
2. 只有点击“创建拣货单”，或者从仓库拣货相关入口发起时，才会进入拣货单。
3. 当销售订单明细已全部交付后，系统不会再生成可拣数量，也不能再次创建有效拣货单。
4. 如果拣货单已经生成过销售送货单，再次从同一拣货单创建整单送货单，可能导致同一销售订单明细重复出库。

因此，截图中的“数量超出订单允许量 50.0”表示该销售订单明细的 50 已经交付，当前操作又试图对同一明细生成第二次送货单。

## 4. 推荐的傻瓜式流程

### 4.1 推荐方案：销售订单直接出库

日常业务统一使用以下步骤：

1. 打开已提交的销售订单。
2. 点击“创建 -> 销售送货单”。
3. 核对客户、仓库、物料和本次出库数量。
4. 点击“提交”。
5. 完成后不再回到拣货单，也不重复创建送货单。

这是当前最少步骤、最不容易重复建单的标准流程。

### 4.2 拣货单作为例外流程

只有在下列情形才使用拣货单：

- 仓库需要先拣货、复核，再办理正式出库；
- 同一订单需要从多个仓库拣货；
- 需要按批次或序列号提前确定实物；
- 需要多个销售订单合并为一批拣货；
- 需要查看已拣数量与未拣数量。

使用拣货单时，必须遵守“一张拣货单只对应一次后续出库”的原则：

```text
销售订单 -> 拣货单 -> 销售送货单 -> 提交
```

送货单已提交后，不再从该拣货单重复创建送货单。

## 5. 测试操作规范

### 5.1 首次出库

优先选择“销售订单 -> 销售送货单”。确认送货单提交成功后，检查：

- 销售订单的已交付数量；
- 物料的仓库库存；
- 销售送货单状态；
- 订单是否变为部分交付或已完成。

### 5.2 需要测试拣货单时

1. 使用尚未交付的销售订单明细。
2. 创建一张拣货单并提交。
3. 从该拣货单创建一张销售送货单。
4. 提交销售送货单。
5. 回到销售订单确认交付数量变化。
6. 不要再次点击“创建销售送货单”或从同一拣货单重新生成整单。

### 5.3 发现“超出订单允许量”时

按以下顺序排查：

1. 打开销售订单，查看该物料的订单数量和已交付数量。
2. 查看关联销售送货单，确认是否已经有提交单据。
3. 查看拣货单是否已经生成过销售送货单。
4. 若已全部交付，结束测试，不再创建新出库单。
5. 若只是部分交付，本次送货数量只能填写“订单数量 - 已交付数量”。

不要为了绕过重复出库提示而直接放宽库存设置中的超量交付比例。

## 6. 后续产品优化建议

### 6.1 第一阶段：先统一业务入口

先不改 ERPNext 标准逻辑，只在操作规范和工作区入口上做简化：

- 将“销售送货单”作为销售订单履约的主入口；
- 将“拣货单”标记为仓库专项入口；
- 在培训文档中明确两条流程不能混用；
- 测试数据每次使用新的销售订单，避免复用已完成订单。

### 6.2 第二阶段：增加一键出库按钮

如果仍希望减少点击次数，可以增加一个自定义按钮：

```text
销售订单 -> 一键创建销售送货单
```

按钮只负责生成草稿销售送货单，不自动提交。用户核对数量后再提交，保留 ERPNext 的库存和权限校验。

### 6.3 不建议的做法

- 不建议强制所有销售订单都经过拣货单；
- 不建议自动重复创建送货单；
- 不建议前端绕过超量交付校验；
- 不建议为了流程“看起来完整”而同时操作拣货单和直接送货单；
- 不建议把已完成交付的销售订单作为重复测试数据。

## 7. 建议的最终业务规则

| 业务场景 | 推荐入口 | 是否需要拣货单 |
|---|---|---|
| 普通单仓库一次出库 | 销售订单 -> 销售送货单 | 否 |
| 多仓库拣货 | 销售订单 -> 拣货单 -> 销售送货单 | 是 |
| 批次/序列号需要提前分配 | 销售订单 -> 拣货单 -> 销售送货单 | 是 |
| 多订单集中拣货 | 拣货单 -> 销售送货单 | 是 |
| 已全部交付的订单 | 查看历史单据 | 不再创建 |

## 8. 与生产补货流程的关系

销售出库和生产领料是两条不同流程：

```text
销售订单 -> 销售送货单提交 -> 销售库存扣减

生产工单 -> 拣货单（可选） -> Stock Entry 提交 -> 生产库存扣减
                                      -> 安全库存检查
                                      -> 必要时自动创建物料需求
```

销售送货单不会替代生产 Stock Entry；生产自动补货仍以生产相关 Stock Entry 提交作为触发点。

## 9. 沉淀结论

当前最简单、最稳妥的销售出库方案是：

```text
销售订单 -> 销售送货单 -> 提交
```

拣货单不作为所有订单的必经步骤，只在确实需要仓库拣货管理时使用。已交付订单不能再次进入有效拣货或出库流程；遇到“超出订单允许量”时，应先检查历史送货单，而不是调整超量控制参数。
