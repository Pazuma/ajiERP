# 供应商编号重复覆盖导入实施方案

## 1. 背景

供应商清单使用 `custom_supplier_code` 作为业务编号。重复导入同一份清单时，如果直接选择“插入新记录”，系统会因为供应商编号唯一或文档名称重复而整行失败。

目标是：导入预览阶段识别已存在的供应商编号，明确提示用户；用户确认后覆盖更新对应供应商，未确认时不修改已有数据。

本方案只针对供应商清单导入，不改变客户、联系人及其他表单的导入规则。

## 2. 核心规则

| 场景 | 处理方式 |
| --- | --- |
| 供应商编号为空 | 按现有导入校验处理；不自动覆盖任何记录 |
| 编号不存在 | 新增供应商；新记录名称使用导入的供应商编号 |
| 编号已存在 | 标记为“待覆盖”，等待用户确认 |
| 用户拒绝覆盖 | 已存在的行跳过；其他新记录仍可按用户选择继续导入 |
| 文件内编号重复 | 标记为文件内部冲突，不允许静默覆盖，要求用户修正文件 |
| 编号前后有空格 | 比较前去除首尾空格，保存规范化后的编号 |

匹配键固定为 `custom_supplier_code`，不使用供应商名称、系统生成的 `SUP-.YYYY.-` 编号或联系人作为匹配条件。

## 3. 覆盖范围

确认覆盖后，只更新本次导入中映射到 Supplier 的字段。未出现在导入文件中的字段保持原值。

默认不使用空白值清空已有数据，避免 Excel 空单元格误删资料；如果后续需要清空字段，应增加单独的“允许空值覆盖”选项并再次确认。

已有供应商的数据库名称默认保持不变。原因是其他采购订单、发票、联系人等单据可能通过该名称建立链接，直接重命名会扩大影响范围。新建供应商才使用供应商编号作为文档名称；已有 `SUP-...` 名称的历史数据如需改名，另行提供迁移方案。

## 4. 用户流程

1. 用户在供应商列表打开导入弹窗并上传 Excel。
2. 系统完成标准字段解析，并按供应商编号查询已存在记录。
3. 预览区显示冲突汇总：新增数量、覆盖数量、文件内重复数量、无编号数量。
4. 存在已编号记录时，显示确认提示：

   > 检测到 {n} 个已存在的供应商编号。确认后将用本文件对应字段覆盖这些供应商，是否继续？

5. 用户选择“确认覆盖并导入”后开始任务；选择“取消”则不启动任务。
6. 导入完成后显示新增、覆盖、跳过、失败数量，并保留标准 Data Import 日志。

文件内部编号重复或编号为空的阻断问题，应在确认按钮前显示，不允许通过覆盖选项绕过。

## 5. 后端实现建议

### 5.1 预览阶段

- 读取文件中的 `custom_supplier_code`，统一转为字符串并去除首尾空格。
- 批量查询 `Supplier.custom_supplier_code`，返回编号到文档名称的映射。
- 对文件内编号计数，区分“已存在”和“文件内重复”。
- 将冲突摘要写入 Data Import 任务的模板选项或专用字段，避免仅依赖浏览器状态。

### 5.2 启动阶段

- 服务端再次执行冲突检查，不能信任前端传入的覆盖结果。
- 未确认覆盖时，拒绝启动包含已存在编号的覆盖任务。
- 确认覆盖时，将已存在编号转换为对应 Supplier 文档并执行更新；新编号继续执行插入。
- 每行写入成功、跳过或失败日志；单行失败不应回滚其他已成功行。
- 保留权限检查、Link 校验、唯一性校验和通知邮件设置。

### 5.3 并发与重复提交

- 启动任务时锁定 Data Import 任务，防止重复点击。
- 更新前再次检查编号对应关系，避免两个任务同时覆盖同一供应商。
- 若编号在预览后被其他用户占用，应将该行记为失败并提示重新预览，而不是覆盖未知记录。

## 6. 前端交互要求

- 预览表格为已存在编号增加“将覆盖”状态标记。
- 状态区同时显示“新增”和“覆盖”数量，不能只显示成功总数。
- 覆盖确认使用明确的危险操作文案，并列出覆盖数量。
- 取消确认后保留文件和预览，允许用户重新选择处理方式。
- 导入完成后提供失败日志入口；失败原因至少包含行号、供应商编号和异常消息。

## 7. 验收标准

1. 新编号导入成功，Supplier 名称等于供应商编号。
2. 已存在编号未确认时不能覆盖。
3. 已存在编号确认后只更新映射字段，未映射字段保持不变。
4. 空白编号不会匹配或覆盖其他供应商。
5. 同一文件内重复编号被阻断并明确定位到重复行。
6. 供应商名称或系统 `SUP-...` 编号变化不会误匹配。
7. 导入中途单行失败时，其他行的新增和覆盖结果可追踪。
8. 重复点击开始按钮不会产生两次导入任务。
9. 无供应商导入权限的用户无法执行覆盖。
10. 已有关联采购单据的历史供应商不会因本功能自动重命名。

## 8. 发布注意事项

该功能上线后需先在测试站点验证新增、覆盖、取消和重复编号场景，再开放给生产用户。部署时清理 Frappe 缓存并重启后台 worker，确保前后端使用同一版本的导入逻辑。
