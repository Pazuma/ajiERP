# 服务器补丁部署更新操作手册

## 1. 适用环境

- Windows 服务器地址：`192.168.77.60`
- Windows 中运行 Ubuntu 虚拟机
- ERP 系统运行在 Ubuntu 的 Docker 容器中
- SSH 用户：`yuewei`
- Frappe 容器：`aki_full_20260930_frappe_1`
- 站点：`aki_test.localhost`
- 系统访问端口：`8300`
- 服务器应用目录：

```text
/srv/aki-erp/deploy-20260930/aki-erp-full-20260929-182611/frappe_docker/development/frappe-bench/apps/client_akivision
```

本手册以以下补丁为例：

```text
purchase_receipt_scan_finance_layout_fix_20261103.tar.gz
```

## 2. 部署原则

1. `scp` 必须在 Windows 命令提示符或 PowerShell 中运行。
2. `tar`、`docker`、`bench`、`sudo` 必须在 Ubuntu SSH 终端中运行。
3. 每次部署必须先查看归档内容，再备份旧文件。
4. `sudo` 提示输入密码时，只输入 Linux 用户密码，不要继续粘贴命令。
5. 一次执行一小段，看到命令提示符返回后再执行下一段。
6. 补丁仅覆盖代码文件，不导入数据库，也不删除业务数据。

## 3. 第一步：从 Windows 上传补丁

在 Windows 命令提示符中执行：

```cmd
scp "D:\share\IT\3.公共目录\yuewei_erp\版本更新\purchase_receipt_scan_finance_layout_fix_20261103.tar.gz" yuewei@192.168.77.60:/home/yuewei/
```

输入 `yuewei` 的 Linux 密码。看到 `100%` 表示上传成功。

注意：不要在 Ubuntu 终端执行带有 `D:\` 的命令。Linux 会把 `D:` 误认为主机名。

## 4. 第二步：登录 Ubuntu

在 Windows 命令提示符中执行：

```cmd
ssh yuewei@192.168.77.60
```

登录成功后，提示符应类似：

```text
yuewei@aki-erp-ubuntu:~$
```

## 5. 第三步：检查补丁并验证 sudo

在 Ubuntu 终端逐条执行：

```bash
ls -lh /home/yuewei/purchase_receipt_scan_finance_layout_fix_20261103.tar.gz
```

```bash
tar -tzf /home/yuewei/purchase_receipt_scan_finance_layout_fix_20261103.tar.gz
```

本次补丁应包含：

```text
client_akivision/hooks.py
client_akivision/public/js/purchase_receipt_quality_gate.js
client_akivision/public/css/purchase_receipt_form_layout.css
```

然后单独验证 `sudo`：

```bash
sudo -v
```

出现密码提示时，只输入密码。密码不会显示在屏幕上，这是正常现象。

## 6. 第四步：设置部署变量

```bash
archive=/home/yuewei/purchase_receipt_scan_finance_layout_fix_20261103.tar.gz
```

```bash
app=/srv/aki-erp/deploy-20260930/aki-erp-full-20260929-182611/frappe_docker/development/frappe-bench/apps/client_akivision
```

```bash
backup=/home/yuewei/purchase-receipt-before-$(date +%Y%m%d-%H%M%S)
```

检查变量：

```bash
printf '补丁：%s\n应用：%s\n备份：%s\n' "$archive" "$app" "$backup"
```

## 7. 第五步：备份旧文件

先创建备份目录：

```bash
sudo mkdir -p "$backup/client_akivision/public/js"
```

```bash
sudo mkdir -p "$backup/client_akivision/public/css"
```

分别备份存在的旧文件：

```bash
sudo cp -a "$app/client_akivision/hooks.py" "$backup/client_akivision/hooks.py"
```

```bash
sudo cp -a "$app/client_akivision/public/js/purchase_receipt_quality_gate.js" "$backup/client_akivision/public/js/purchase_receipt_quality_gate.js"
```

首次部署时，CSS 文件可能不存在。使用下面的条件命令：

```bash
if sudo test -f "$app/client_akivision/public/css/purchase_receipt_form_layout.css"; then sudo cp -a "$app/client_akivision/public/css/purchase_receipt_form_layout.css" "$backup/client_akivision/public/css/purchase_receipt_form_layout.css"; fi
```

查看备份结果：

```bash
find "$backup" -type f -maxdepth 6 -print
```

## 8. 第六步：覆盖补丁文件

```bash
sudo tar -xzf "$archive" -C "$app" --no-same-owner
```

检查新文件是否存在：

```bash
sudo test -f "$app/client_akivision/public/js/purchase_receipt_quality_gate.js" && echo 'JS 已更新'
```

```bash
sudo test -f "$app/client_akivision/public/css/purchase_receipt_form_layout.css" && echo 'CSS 已更新'
```

## 9. 第七步：构建、清缓存和重启

构建前端资源：

```bash
sudo docker exec -w /workspace/development/frappe-bench aki_full_20260930_frappe_1 bench build --app client_akivision
```

等待构建完成并返回命令提示符，再清理站点缓存：

```bash
sudo docker exec -w /workspace/development/frappe-bench aki_full_20260930_frappe_1 bench --site aki_test.localhost clear-cache
```

重启容器：

```bash
sudo docker restart aki_full_20260930_frappe_1
```

等待数秒后检查登录页：

```bash
curl --retry 10 --retry-delay 2 --max-time 20 -s -o /dev/null -w 'HTTP状态码：%{http_code}\n' http://127.0.0.1:8300/login
```

看到 `HTTP状态码：200` 表示 Web 服务已恢复。

本补丁没有 DocType 或数据库结构变更，不需要执行 `bench migrate`。

## 10. 第八步：浏览器验收

1. 打开服务器 ERP 系统。
2. 按 `Ctrl+F5` 强制刷新。
3. 新建采购收货单。
4. 检查表头字段是否紧凑排列。
5. 检查“扫条码”是否显示为“扫描录入”。
6. 检查输入框是否显示扫描枪提示。
7. 检查右侧是否明确标注“摄像头扫码”。
8. 检查采购收货单中的税费、折扣和金额合计区是否隐藏。
9. 检查数量、仓库、扫码入口和物料明细是否仍正常显示。

隐藏仅作用于采购收货单界面。底层金额字段不会被删除，后续采购发票仍可计算和显示财务数据。

## 11. 部署失败时检查

查看容器状态：

```bash
sudo docker ps --format 'table {{.Names}}\t{{.Status}}'
```

查看容器最近日志：

```bash
sudo docker logs --tail 100 aki_full_20260930_frappe_1
```

确认补丁是否已经覆盖：

```bash
grep -n '扫描录入' "$app/client_akivision/public/js/purchase_receipt_quality_gate.js"
```

```bash
grep -n 'purchase_receipt_form_layout.css' "$app/client_akivision/hooks.py"
```

## 12. 回滚方法

将下面的备份路径替换为本次实际生成的 `$backup` 路径：

```bash
rollback=/home/yuewei/purchase-receipt-before-YYYYMMDD-HHMMSS
```

恢复已备份文件：

```bash
sudo cp -a "$rollback/client_akivision/hooks.py" "$app/client_akivision/hooks.py"
```

```bash
sudo cp -a "$rollback/client_akivision/public/js/purchase_receipt_quality_gate.js" "$app/client_akivision/public/js/purchase_receipt_quality_gate.js"
```

如果备份中存在旧 CSS，再恢复：

```bash
if sudo test -f "$rollback/client_akivision/public/css/purchase_receipt_form_layout.css"; then sudo cp -a "$rollback/client_akivision/public/css/purchase_receipt_form_layout.css" "$app/client_akivision/public/css/purchase_receipt_form_layout.css"; fi
```

恢复后重新执行构建、清缓存和容器重启。

## 13. 常见错误

### `Could not resolve hostname d`

原因：在 Ubuntu 中执行了 Windows 的 `scp D:\...` 命令。

处理：退出到 Windows 命令提示符，再执行 `scp`。

### `command not found` 或命令中出现残缺容器名

原因：长命令粘贴时被终端提示或密码输入打断。

处理：按 `Ctrl+C` 回到正常提示符，执行 `sudo -v`，然后按照本手册逐条执行。

### `Sorry, try again`

原因：`sudo` 密码错误，或者在密码提示中粘贴了命令。

处理：只输入 Ubuntu 用户 `yuewei` 的密码。密码输入时屏幕不显示字符。

### 重启后暂时出现 `HTTP 000`

原因：容器仍在启动。

处理：等待数秒，使用带 `--retry` 的 `curl` 命令重新检查。

### 页面仍显示旧效果

依次确认：补丁已覆盖、`bench build` 成功、`clear-cache` 成功、容器已重启，然后在浏览器按 `Ctrl+F5`。
