# 项目关联区创建表单绑定进度节点优化方案

> 文档日期：2026-09-15  
> 当前阶段：方案沉淀，尚未修改代码。  
> 方案原则：小增量、优先新增前端分支、复用现有项目进度联动能力、尽量不改 ERPNext 标准接口、不破坏已有表单创建入口。

## 1. 背景与问题

当前 Project 已经有“流程进度”页签，里面通过 `custom_project_progress_items` 维护项目进度节点，例如截图中的节点 `11`、`22`。

当前也已经有一套基础联动：

- 支持单据字段 `project / custom_progress_project` 关联项目。
- 支持单据字段 `custom_progress_milestone_code` 记录绑定的项目进度节点编码。
- 支持单据字段 `custom_progress_step_name` 保存节点名称快照。
- 支持单据提交后通过 `Project Progress Reference` 汇总项目节点完成状态。

但目前交互还不完整：

- 在 Project 详情页“关联”区域点击 `+` 新建表单时，无法先选择要绑定的进度节点。
- 从采购、销售、生产等其他入口直接新建表单时，虽然可以关联项目，但缺少一个清晰的“绑定项目进度节点”入口。
- 用户希望采购订单、采购送货单等多个表单可以绑定同一个节点；当这些绑定单据完成后，项目进度节点自动完成，并在项目进度中看到完成时间。

## 2. 优化目标

本次优化目标是让“项目进度节点”成为创建业务表单前后的明确绑定对象。

### 2.1 从项目页创建表单

用户在 Project 详情页“关联”区域点击某个表单的 `+` 时：

```text
项目详情页
  -> 关联区域点击 采购订单 + / 采购送货单 + / 销售订单 + / 生产工单 +
  -> 弹窗：绑定进度节点
  -> 用户选择当前项目下的一个未完成节点
  -> 下一步创建目标表单
  -> 目标表单自动带入项目和节点
```

### 2.2 从其他入口创建表单

用户从采购模块、销售模块、生产模块等其他入口新建表单时：

```text
打开新建采购订单 / 采购送货单 / 销售订单 / 生产工单
  -> 表单提供“绑定项目进度节点”按钮
  -> 弹窗先选项目
  -> 再选择该项目下的进度节点
  -> 确认后写入当前表单
```

### 2.3 表单提交后完成节点

业务表单保存只是草稿，不完成项目节点；只有表单成功提交后，才驱动节点完成。

```text
业务表单保存
  -> 只建立绑定关系，节点不完成

业务表单提交
  -> 对应 Project Progress Reference 变为 Completed
  -> 如果该节点绑定的有效单据全部完成
  -> Project Progress Item.status = 已完成
  -> Project Progress Item.actual_completed_on = 最后一张绑定单据的完成时间
  -> Project Progress Item.completed_by = 最后一张完成单据的提交人
  -> Project 汇总进度重新计算
```

## 3. 预期效果

### 3.1 项目页点击关联表单 `+`

以 Project `222 / PROJ-0008` 为例，点击“采购订单 +”后不直接进入采购订单，而是先弹窗：

```text
绑定进度节点

当前项目：222 / PROJ-0008
即将创建：采购订单

绑定进度节点：
[ 11（进行中）        v ]

提示：
该表单提交后，将自动完成绑定的项目进度节点。

[取消] [下一步创建]
```

点击“下一步创建”后进入新建采购订单，并自动填写：

```text
项目 = PROJ-0008
绑定进度节点 = 11
步骤名称 = 11
```

### 3.2 其他入口新建表单

从采购模块直接新建采购订单时，表单顶部或“项目”按钮组中显示：

```text
[绑定项目进度节点]
```

点击后弹窗：

```text
绑定项目进度节点

关联项目：
[ PROJ-0008 / 222      v ]

绑定进度节点：
[ 11（进行中）         v ]

提示：
当前表单提交后，将自动完成绑定的项目进度节点。

[取消] [确认绑定]
```

确认后当前表单写入项目和节点字段。用户继续填写供应商、物料、数量、价格等业务信息，保存后仍为草稿，提交后才完成项目节点。

### 3.3 多表单绑定同一个节点

采购订单和采购送货单允许绑定到同一个节点。

示例：

```text
节点 11 绑定：
  - 采购订单 PO-0001
  - 采购送货单 PR-0001
```

完成口径：

```text
PO-0001 已提交，PR-0001 未提交
  -> 节点 11 仍为进行中

PO-0001 已提交，PR-0001 已提交
  -> 节点 11 变为已完成
  -> 实际完成时间 = PR-0001 提交时间
```

如果节点只绑定了一张单据，则该单据提交后节点即可完成。

## 4. 业务规则

### 4.1 可绑定节点范围

首版建议只允许绑定未完成节点：

- `待开始`
- `进行中`
- `延期`

不允许绑定：

- `已完成`

如果项目尚未开始，即 `custom_project_stage != 进行中`，从项目页点击创建关联表单时提示：

```text
当前项目还未开始，请先点击“项目开始”后再创建关联单据。
```

### 4.2 节点与表单类型匹配

`Project Progress Item` 已有 `reference_doctype` 字段，用于限制节点允许绑定的表单类型。

首版规则：

```text
节点 reference_doctype 为空
  -> 可被任意支持的业务表单绑定

节点 reference_doctype = Purchase Order
  -> 只允许采购订单绑定

节点 reference_doctype = Purchase Receipt
  -> 只允许采购送货单绑定
```

从项目页点击“采购订单 +”时，弹窗只显示：

- `reference_doctype` 为空的节点
- `reference_doctype = Purchase Order` 的节点

从项目页点击“采购送货单 +”时，弹窗只显示：

- `reference_doctype` 为空的节点
- `reference_doctype = Purchase Receipt` 的节点

### 4.3 保存与提交规则

```text
草稿保存
  -> 写入 Project Progress Reference，状态 Draft
  -> Project Progress Item 不完成

提交表单
  -> Project Progress Reference 状态 Completed
  -> 记录 actual_completed_on 和 completed_by
  -> 回写业务表单 custom_progress_actual_completed_on
  -> 重算节点状态
  -> 重算项目进度

取消提交
  -> Project Progress Reference 状态 Cancelled
  -> 清空该单据完成时间
  -> 节点重新计算为 进行中 / 延期 / 待开始
```

### 4.4 一个表单只能绑定一个节点

首版保持现有模型：

```text
一张业务表单 -> 一个项目 -> 一个进度节点
一个进度节点 -> 多张业务表单
```

不做“一张表单绑定多个节点”，避免把表单提交与多个节点完成强耦合，降低首版风险。

## 5. 调用链路

### 5.1 从项目关联区创建

```text
用户打开 Project
  -> 点击“关联”区域的某个表单 +
  -> 前端识别当前项目和目标 DocType
  -> 调用 get_project_progress_steps(project, reference_doctype)
  -> 弹窗展示可绑定节点
  -> 用户选择节点
  -> 前端 route_options 写入：
       project / custom_progress_project
       custom_progress_milestone_code
       custom_progress_step_name
  -> frappe.new_doc(target_doctype)
  -> 目标表单初始化并自动带出项目和节点
  -> 用户补全业务字段并保存
  -> validate_progress_selection 校验节点归属
  -> sync_progress_selection 创建/更新 Project Progress Reference(Draft)
```

### 5.2 从其他入口创建

```text
用户从采购/销售/生产模块新建表单
  -> 表单 refresh
  -> project_progress_reference.js 增加“绑定项目进度节点”按钮
  -> 用户点击按钮
  -> 弹窗选择项目
  -> 根据项目调用 get_project_progress_steps(project, reference_doctype)
  -> 用户选择节点
  -> 前端写入项目和节点字段
  -> 用户保存
  -> validate_progress_selection 校验
  -> sync_progress_selection 写入 Project Progress Reference(Draft)
```

### 5.3 表单提交完成项目节点

```text
业务表单 Submit
  -> Frappe doc_events.on_submit
  -> client_akivision.utils.project_progress.sync_progress_from_reference
  -> 找到 Project Progress Reference
  -> status = Completed
  -> actual_completed_on = now_datetime()
  -> completed_by = frappe.session.user
  -> recalculate_progress_item(project, progress_item)
  -> 如果该节点所有有效绑定单据均 Completed
       Project Progress Item.status = 已完成
       Project Progress Item.actual_completed_on = 最后一张单据完成时间
  -> _persist_project_totals(project)
  -> Project 流程进度页签显示完成状态和完成时间
```

## 7. 受影响模块

### 7.1 Project 项目模块

影响点：

- Project 详情页“关联”区域的 `+` 新建行为。
- Project 流程进度节点选择、显示、完成时间。
- Project 进度汇总字段：
  - `custom_expected_progress`
  - `custom_actual_process_progress`
  - `custom_progress_variance`
  - `custom_progress_health`
  - `custom_progress_last_synced_on`

预期影响：

- 正向影响：用户从项目创建单据时，能明确绑定节点。
- 风险：Frappe 原生关联区 DOM 结构可能随版本变化，前端拦截要做兜底；拦截失败时保留原始创建能力，不阻断业务。

### 7.2 采购模块

首批重点：

- Purchase Order / 采购订单
- Purchase Receipt / 采购送货单

预期效果：

- 两类单据都可以绑定同一个项目进度节点。
- 采购订单提交后只完成自己的绑定记录，不一定立即完成节点。
- 采购送货单提交后，如果同节点绑定单据全部完成，则节点完成。

### 7.3 销售模块

涉及：

- Sales Order / 销售订单
- Delivery Note / 销售送货单
- Sales Invoice / 销售应收单

预期效果：

- 从项目页创建销售单据时先绑定节点。
- 从销售入口创建时也能选择项目和节点。
- 提交后同步项目节点。

### 7.4 生产与库存模块

涉及：

- Work Order / 生产工单
- Material Request / 物料需求
- Stock Entry / 物料出/入库
- BOM / 物料清单

预期效果：

- 表单可以绑定项目节点。
- 表单提交后驱动项目节点完成。
- Material Request 继续使用 `custom_progress_project`，不强行新增标准 `project` 字段。

## 8. 小增量实施计划

### 阶段一：只做表单内“绑定项目进度节点”按钮

范围：

- `project_progress_reference.js`
- 支持 Purchase Order、Purchase Receipt 两个重点表单

目标：

```text
从采购订单入口新建
  -> 点击绑定项目进度节点
  -> 选择项目
  -> 选择节点
  -> 保存后生成 Draft 绑定记录
  -> 提交后更新节点
```

优点：

- 不碰 Project 关联区 DOM。
- 先验证后端绑定与完成口径。
- 风险最低。

### 阶段二：扩展到 Project 关联区 `+`

范围：

- 新增 `project_link_create_binding.js`
- 只在 Project 表单页面生效
- 首批拦截 Purchase Order、Purchase Receipt

目标：

```text
Project -> 关联区 -> 采购订单 +
  -> 弹窗绑定节点
  -> 下一步创建采购订单
  -> 自动带入项目和节点
```

### 阶段三：扩展更多表单

范围：

- Sales Order
- Delivery Note
- Work Order
- Material Request
- Stock Entry
- BOM
- Sales Invoice / Purchase Invoice

目标：

- 将同一套弹窗和绑定逻辑复用到所有已有 `SUPPORTED_REFERENCE_DOCTYPES`。
- 保持每次只扩一到两个表单，逐步验证。

## 10. 回滚方案

首版以新增前端交互为主，不新增核心业务字段。

回滚方式：

```text
1. 从 hooks.py 移除新增 JS 文件注册。
2. 保留已有 custom_progress_* 字段和 Project Progress Reference 数据。
3. 已保存的绑定关系不删除，仍可通过现有后端同步逻辑继续工作。
4. 如果只需要停用 Project 关联区拦截，单独移除 project_link_create_binding.js 即可。
```

## 11. 最终预期闭环

```text
项目开始
  -> 项目阶段 = 进行中
  -> 用户在流程进度维护节点
  -> 用户从项目关联区或业务模块创建表单
  -> 创建前绑定项目进度节点
  -> 表单保存为草稿
  -> 表单提交
  -> 绑定记录完成
  -> 节点完成
  -> 项目进度更新
  -> 项目所有节点完成后，项目阶段可进入已完成
```

这套方案的核心是：项目节点是业务表单与项目进度之间的中间锚点。采购订单、采购送货单、销售订单、生产工单等表单不直接“推进项目”，而是通过提交后完成自己绑定的进度节点，从而让项目进度可追踪、可解释、可回溯。
