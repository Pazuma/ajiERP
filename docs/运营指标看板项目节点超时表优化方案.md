# 运营指标看板项目节点超时表优化方案

## 1. 背景与目标

项目进度节点已经维护了计划完成日期、实际完成时间和备注，但当前运营指标看板没有集中展示“实际完成晚于计划”的节点。本方案在现有运营指标看板中增加一张只读的“项目节点超时”表，用于项目进度复盘和责任追踪。

最终确认采用独立页面方案：在“指标看板”左侧侧边栏中增加“项目节点超时表”，与“运营指标看板”“业务表单总表”并列；不把超时表嵌入运营指标看板内容，也不在运营指标看板的“看板”下拉框中增加选项。

## 2. 已确认的业务口径

### 2.1 超时判定

一条项目进度节点同时满足以下条件时进入超时表：

```text
节点状态 = 已完成
且 日期(实际完成时间) > 计划完成日期
```

计划完成日期是日期类型，实际完成时间是日期时间类型。计划完成日当天完成不算超时，例如计划日期为 2026-09-16、实际完成时间为 2026-09-16 23:00，判定为按时。

首版只统计“已完成但超时”，不把“尚未完成且计划日期已过”的节点混入本表。后者属于当前逾期，需要另行定义展示口径。

### 2.2 表格字段

| 字段 | 说明 |
| --- | --- |
| 项目编号 | 对应 Project 编号，可点击进入项目详情 |
| 项目名称 | 对应 Project 的项目名称，便于识别 |
| 节点名称 | 超时的具体项目进度节点 |
| 计划完成日期 | 节点原计划截止日期 |
| 实际完成时间 | 节点最终完成时间 |
| 备注 | 读取项目节点现有备注，空值显示 `-` |

不新增“超时天数”等派生列，保持本次需求的最小展示范围。

### 2.3 查询范围与排序

- 沿用看板现有的公司、开始日期、截止日期筛选。
- 日期范围按“实际完成时间的日期”筛选，表示筛选期内完成且超时的节点。
- 默认按实际完成时间倒序；同一时间下按项目编号、节点顺序稳定排序。
- 结果建议支持分页；接口可以先返回分页结果及总数，避免项目较多时拖慢整张看板。
- 用户从左侧“指标看板 > 项目节点超时表”进入独立列表页面。

## 2.4 界面风格要求

超时表的表单风格参考用户提供的项目列表截图，采用现有 Frappe 列表页的工作型布局，不设计成大面积指标卡片：

- 顶部保留页面标题、面包屑/当前位置和操作区，视觉层级与项目列表一致。
- 表格占据页面主要区域，使用紧凑行高、浅灰分隔线、清晰的列标题和横向滚动，优先保证信息扫描效率。
- 顶部筛选区使用 Frappe 原生筛选控件风格，支持公司、开始日期、截止日期；筛选条件以轻量输入框/下拉框呈现，不在表格内部增加编辑控件。
- 右上角保留刷新、更多操作和导出入口，按钮尺寸、图标和间距沿用现有看板及 Frappe 列表页规范。
- 项目编号使用列表页链接样式，点击进入对应 Project；项目名称、节点名称、备注为只读文本。
- 计划完成日期和实际完成时间使用统一日期格式；备注较长时单行截断并提供悬停查看完整内容，不能撑大行高。
- 底部提供分页和每页条数选择，风格参考截图中的 `20 / 100 / 500 / 2500` 控件；首版默认 20 条。
- 空数据时显示列表页风格的空态；加载时显示表格骨架，避免页面跳动。
- 不新增渐变背景、装饰性大卡片或与现有 Desk 主题不一致的视觉组件。

## 3. 实现设计

### 3.1 后端查询层

在 `client_akivision.client_akivision.api.operations_kpi` 中新增独立函数，例如 `get_project_progress_timeout_rows(filters)`，不改动 `get_kpi_dashboard_data` 现有字段含义，只在返回值中新增：

```python
"project_progress_timeouts": {
    "rows": [...],
    "total": 0,
}
```

查询来源为 `tabProject Progress Item`，关联父表 `tabProject`，读取：

- Project 编号和项目名称；
- `subject`；
- `expected_end_date`；
- `actual_completed_on`；
- `remarks`。

查询条件至少包括：父类型为 Project、节点状态为“已完成”、实际完成时间非空、实际完成日期晚于计划完成日期、项目所属公司匹配、实际完成日期落在筛选区间内。

实现时应优先使用 Frappe 的权限过滤能力或逐项目校验 `Project` 读取权限，不能因为拥有 KPI 看板角色而看到无权查看的项目。查询结果只读，不回写节点状态或项目汇总字段。

### 3.2 前端看板

新增独立页面 `project_progress_timeout.js`：

1. 使用 Frappe Page 建立独立列表页，不修改 `DASHBOARD_SECTIONS`。
2. 页面独立调用超时表查询接口，不通过运营指标看板主接口加载。
3. 增加字段标签映射：项目编号、项目名称、节点名称、计划完成日期、实际完成时间、备注。
4. 项目编号设置为可点击行或链接，打开对应 Project；不改变现有其他表格的下钻行为。
5. 超时表不提供编辑入口，备注也只读展示。
6. 处理无数据、接口异常和权限过滤后的空结果，沿用现有提示。

建议新增独立的 `project_progress_timeout_table()` 小分支或配置，而不是改写通用 `table()` 的既有调用方式，降低回归风险。

该分支需要复用或抽取现有列表表格的以下能力：筛选条件展示、表头固定/横向滚动、行点击、空态、加载态和分页。若现有看板通用 `table()` 仅支持一次性渲染数组，则新增分页表格分支，不改变其他看板表格的现有行为。

### 3.3 Excel 导出

在 `operations_kpi_export.py` 中新增一个超时表工作表或新增一个表区，使用与页面相同的数据对象和筛选条件。导出列与页面严格一致：项目编号、项目名称、节点名称、计划完成日期、实际完成时间、备注。

现有工作表和列顺序保持不变；新表放在项目/高新相关内容之后或作为独立工作表，具体位置以当前模板顺序为准。

## 5. 调用链路

```text
用户打开/刷新运营指标看板
  -> operations_kpi_dashboard.js 收集公司和日期筛选
  -> get_kpi_dashboard_data(filters)
  -> normalise_filters(filters)
  -> get_project_progress_timeout_rows(filters)
  -> Project Progress Item JOIN Project 权限与超时条件查询
  -> 返回 project_progress_timeouts.rows/total
  -> 前端按看板选择器渲染超时表
  -> 点击项目编号 -> Project 表单

用户点击导出
  -> export_kpi_dashboard(filters)
  -> get_kpi_dashboard_data(filters)
  -> build_kpi_workbook(data)
  -> 写入项目节点超时表
```

节点实际完成时间仍由现有链路产生：业务单据提交或手工完成 -> `project_progress.py` 更新 `actual_completed_on` -> 超时查询只读消费该结果。

## 6. 受影响模块与风险

受影响模块：运营指标看板页面、看板数据接口、看板 Excel 导出、项目进度数据读取、相关翻译和人工验收文档。

不受影响模块：项目节点完成规则、业务单据提交钩子、项目进度汇总计算、原有销售/应收/生产/采购/高新指标及其下钻接口。

主要风险及处理：

- 旧数据没有实际完成时间：直接排除，不推测完成时间。
- 实际完成时间被撤销或节点重新打开：由于状态不再是“已完成”或时间被清空，应自动从表中消失。
- 一个节点存在多个关联单据：沿用现有节点最终完成时间，不在看板重新计算。
- 日期与时区：比较时先将实际完成时间按 Frappe 用户/站点时区转为日期，再与计划完成日期比较。
- 权限：后端过滤优先，前端隐藏不能作为权限控制。
- 数据量较大：查询使用父项目、状态、完成时间条件，必要时分页；不在请求中逐项目加载完整表单。

## 7. 验收与测试

至少准备以下数据：

1. 计划 9 月 10 日、实际 9 月 10 日完成的节点，不应出现。
2. 计划 9 月 10 日、实际 9 月 11 日完成的节点，应出现。
3. 计划日期已过但仍未完成的节点，不应出现。
4. 没有实际完成时间的已完成异常数据，不应出现或应被安全排除。
5. 有备注和无备注的节点，分别验证文本和 `-` 展示。
6. 无权限项目，验证接口和页面均不可见。
7. 点击项目编号能打开正确 Project；Excel 导出列与页面一致。
8. 变更公司、开始日期、截止日期和看板选项，验证结果正确刷新。

## 8. 预期效果

- 管理人员可在指标看板中快速识别已经完成但晚于计划的项目节点。
- 每条记录可追溯到项目，备注可直接支持原因复盘。
- 页面与 Excel 使用同一查询口径，避免展示结果和导出结果不一致。
- 不新增业务字段，不改变项目节点完成流程，不破坏现有看板接口和指标。
- 采用新增返回分支和新增渲染分支，后续可在不影响本表的情况下扩展“当前逾期未完成节点”等其他异常表。
