# 物料折旧汇总小增量实施方案

日期：2026-10-23  
状态：已按本方案完成代码实现，并在 `aki_test.localhost` 定向注册新报表及库存入口。原设计及实施边界保留；实际文件、验证结果和完整业务流见《物料折旧汇总实施记录.md》。未修改库存估值或财务数据。

## 1. 已确认需求与实施边界

- 折旧规则在「物料 → 对应物料 → 折旧物料表」维护，包括仓库、起算日期、免减值月数、周期、比例、累计上限、原始参考单价。
- 「库存 → 物料折旧汇总」仅汇总已经开始折旧的物料，不扩展为所有库存或所有闲置物料清单。
- 汇总只读，不提供规则编辑、批量改价、财务计提或转回操作；点击物料可返回原物料维护。
- 展示未使用时间、数量、折旧前后单价及建议金额；未使用时间是辅助信息，不替代人工设置的减值起算日期。
- 小增量实现：保留老报表、老接口、保存评估和每日评估链路，优先新增独立报表及只读服务。
- 界面沿用用户习惯称「折旧」；内部继续使用现有库存减值字段。此处结果是评估建议，不代表资产折旧或已经完成财务计提。

本文保留设计时的「拟新增」「拟修改」表述作为设计基线，实际交付以实施记录为准。

## 3. 方案选择：新报表，旧链路不变

新增独立 Script Report「物料折旧汇总」，旧「已折旧的物料表」保持原名称、过滤逻辑及调用方式。

新报表的数据源仍为物料下的现有规则，不能从全部 Bin 库存自动生成折旧记录。报表内存计算复用 `calculate_assessment(row, today(), qty)`，只为展示今天的结果，不调用 `assess_item`、不保存 Item、不回写子表。

这样既避免用户打开汇总触发写入，又避免库存数量变化后继续使用昨天的建议金额。报表明确区分「本次测算日期」和「最近保存评估日期」。

第一阶段只支持今日视图，不提供任意历史截止日期；否则不能将历史日期与当前 Bin 数量混用。

## 4. 纳入条件与异常边界

### 4.1 默认纳入条件

同时满足：

1. 子表 `parenttype = Item` 且 `parentfield = custom_inventory_impairment_items`。
2. 父物料未停用，属于库存物料；仓库为有效明细仓库，能确定所属公司，用户有相应读取权限。
3. 子表行 `auto_assess = 1`，且不处于「已计提」「已转回」「建议转回」等保护状态。
4. 现有函数校验规则有效；按今日计算出的累计比例 `impairment_ratio > 0`。
5. 默认当前 `Bin.actual_qty > 0`；将「库存范围」从「仅有库存」切换为「包含零库存」，可查看有效规则下数量为0的记录，明确标记「无库存」。

仅有规则、未来起算、免减值期内、未满第一个减值周期，均不作为已开始折旧的正常行展示。不能只根据启用开关或当前日期晚于起算日判断。

纳入以比例大于0判断，不以金额大于0判断：极小金额可能因金额精度舍入为0，但规则已经开始折旧。

### 4.2 不静默处理的情况

- 同一物料、同一仓库存在多条启用规则：不重复加总，不随意选最新一条；显示异常提示并引导回物料修正。
- 原始单价、比例、日期、仓库不完整或无效：不显示为「折旧0」；报告本次跳过条数及原因，并仅展示用户可见物料。
- 负库存：不按负数计算建议金额，列为异常提示；不以0掩盖负库存。
- 停用自动评估、已计提或转回的历史行：默认不进入新报表自动测算；保留原记录和旧报表，不删除、不重估。
- 物料停用、仓库停用等排除项应有可解释提示，不输出用户无权读取的记录信息。

新报表是当前自动评估视图，不是已计提历史账。将来如需历史审计，应另立需求，不在本次扩展。

## 5. 字段、单价与金额口径

每行粒度为「公司＋物料＋仓库」；公司从仓库读取，规则从该物料该仓库的启用行读取。

| 展示字段 | 数据来源/计算 | 说明 |
| --- | --- | --- |
| 公司 | Warehouse.company | 参与权限过滤及币种识别 |
| 物料编码、名称、单位 | Item.name、item_name、stock_uom | 编码可点击打开物料 |
| 仓库 | 规则 warehouse | 不跨仓合并规则 |
| 当前库存数量 | Bin.actual_qty | 报表查询时读取，不冒用子表旧快照 |
| 当前库存单价 | Bin.valuation_rate | 仅作为账面估值参考，不等于采购价或销售价 |
| 当前库存金额 | Bin.stock_value | 不将原价减值金额当成账面金额 |
| 原始参考单价 | 规则 basis_rate | 人工配置；保留原字段含义，不自动覆盖 |
| 折旧起算日期 | 规则 start_date | 现有计算的时间依据 |
| 累计折旧比例 | 原 calculate_assessment 返回值 | 不重写一套公式 |
| 折旧后参考单价 | 原函数 reference_rate | 基于原始参考单价，不基于 Bin.valuation_rate |
| 建议减值金额 | 原函数 impairment_amount | 当前数量×原始参考单价×累计比例 |
| 最后有效使用日期 | 新增只读流水统计 | 不写回旧字段，不重置 start_date |
| 未使用天数 | 今天－最后有效使用日期 | 无可靠日期时留空并说明原因，不填0 |
| 本次测算日期 | 今天 | 表示本次页面测算时点 |
| 最近保存评估日期 | 规则 assessment_date | 仅代表物料原评估结果的保存时点 |
| 状态 | 规则状态＋只读展示标识 | 不回写为「已计提」等状态 |

第一阶段约定：单价按库存单位、公司本位币展示。现有 `basis_rate` 没有独立币种/单位字段，实施前需抽样确认既有填写口径；无法确认时提示核对，不能自动换算或混币加总。

多公司时不显示跨币种金额总计；数量也不跨不同库存单位强行合计。汇总卡可显示记录数、不同物料数，金额按公司/币种分组。

示例仅用于验收：原始参考单价100元、库存10件、免减值0个月、周期1个月、每周期10%、上限50%；经过完整2个月后应为20%、参考价80元、建议金额200元。即使当前库存估值单价为95元，也不能把原始单价悄悄改成95元。

## 6. 未使用时间：新增只读分支

采用 Stock Ledger Entry 与来源单据的有效库存变化，不采用 Item.modified、Bin.modified 或任意最近交易时间。

建议第一阶段有效使用范围：

| 来源 | 是否计入 | 必要判断 |
| --- | --- | --- |
| Delivery Note 销售出库 | 是 | 已提交、未取消、非退货，对应负向库存流水 |
| Sales Invoice 直接更新库存出库 | 是 | 已提交、update_stock、非退货，对应负向库存流水 |
| Stock Entry：Manufacture | 是 | 仅实际消耗的来源明细，不把产成品入库算使用 |
| Stock Entry：Material Consumption for Manufacture | 是 | 有效负向消耗明细 |
| Stock Entry：Material Transfer / Material Transfer for Manufacture | 否 | 调仓、备料不等于实际消耗 |
| 采购入库、生产入库、销售退货、采购退货 | 否 | 不据此更新最后使用时间 |
| 盘点、估值调整、取消、冲销、未来日期流水 | 否 | 避免错误重置闲置时间 |
| Material Issue、Repack、委外等其他用途 | 首期不自动认定 | 业务用途可能不同，后续单独确认再增分支 |

必须关联来源单据 `docstatus`、退货标记及 SLE `is_cancelled`；仅凭负数流水不能认定为使用。通过 `voucher_detail_no` 验证来源明细与物料、仓库匹配，批量获取每个物料仓库组合的最后有效日期，并保留可核对的来源单据引用。

无有效使用记录时显示「无有效使用记录，待确认」，日期与天数为空；不擅自用首次入库日、建档日或折旧起算日冒充最后使用日。历史 `last_activity_date` 如需展示，单列为「原人工记录」，不混作自动统计结果。

口径限制：仓库级统计不能等同于批次级库存闲置；调入仓库可能没有本仓使用记录。新采购和旧库存混存时，一次使用也不能证明所有旧批次都已消耗。第一阶段不扩展跨仓追溯和批次分层。

## 9. 调用链路

现有写入链路保持：

```text
物料详情维护折旧子表 → 保存 Item
  → hooks：Item.validate
  → assess_item → calculate_assessment + Bin数量
  → 保存原评估结果

每日调度 → scheduled_assess_items
  → 启用规则对应 Item → assess_item → 更新评估子表
```

新增只读链路：

```text
库存侧栏 → 物料折旧汇总（Script Report）
  → execute(filters) → get_summary(filters)
  → 角色与公司/仓库/物料权限校验
  → 批量读取现有启用规则 + Item + Warehouse + Bin
  → 去重、校验 → 原 calculate_assessment（仅内存测算）
  → 过滤已开始折旧 → 批量获取最后有效使用记录
  → 展示只读主表、异常提示、分币种汇总 → 原生导出
```

两条链路无反向写入：看报表不会保存物料，不会触发库存或财务过账。

## 10. 权限、性能及受影响模块

### 权限

- 入口角色初始参考旧报表 Stock Manager、Accounts Manager，但角色匹配不代表可以读取全部公司。
- 必须执行 Item 读取权限及公司、仓库、物料 User Permissions；不能直接沿用旧报表不加限制的 SQL 查询。
- 仅使用 `get_all` 或原始 SQL 不会自动完成上述权限处理；新服务要显式落实，必要时用受权限约束的 `get_list` 生成允许集合，再参数化批量查询。
- 物料和流水原单据链接必须检查目标文档权限；无权限不得输出单号等可识别信息。
- 导出复用同一后端权限和筛选链路，不支持通过传入其他公司绕过限制。

### 性能

- 从启用规则候选集合开始查询，不全量逐物料扫描所有历史库存流水。
- Item、仓库、Bin 和最后使用记录批量读取，禁止每行调用数据库查询；大集合分块参数化查询。
- 第一阶段不新增索引或缓存，先验证查询计划及真实数据量；需要优化再单独增量评审。
- 不使用跨用户共享的未隔离结果缓存，避免公司或物料数据串读。

### 受影响模块

| 模块 | 影响 |
| --- | --- |
| 库存侧栏 | 新增一个报表入口，已有链接不变 |
| 库存报表 | 新增只读报表及导出 |
| 物料管理 | 只读已有规则，原设置方式和保存逻辑不变 |
| 库存流水 | 查询使用时间，不写入、不更改过账逻辑 |
| 销售/制造 | 读取来源单据以识别有效使用，不增加事件钩子 |
| 财务 | 展示建议金额，不产生计提或转回凭证 |
| 采购/销售价格、成本报价单、销售订单 | 不修改价格、成本来源或旧接口 |

## 11. 实施顺序、部署与回退

1. 确认目标站点及 App 已安装情况，备份相关配置；本次不执行。
2. 新增只读服务、测试及独立报表，先验证数据口径，不接入写入链路。
3. 补齐有效使用时间、权限校验和原生导出验证。
4. 小范围增加库存侧栏链接，复用已有迁移同步并验证幂等。
5. 在目标测试站点执行迁移、必要的前端构建与缓存刷新，检查浏览器实际页面和导出，再安排上线；具体命令按现有 Docker/站点部署流程执行。

回退优先隐藏新增入口并关闭新报表访问，恢复本次侧栏窄分支；不删除既有规则或重算历史数据。新服务不写业务数据，因此不需要库存/财务冲销。

## 12. 验收清单

| 场景 | 预期结果 |
| --- | --- |
| 仅配置规则、未到起算日、免减值期内、未满周期 | 不进入已开始折旧正常明细 |
| 刚好满首个周期、月末起算、闰年边界 | 与原 calculate_assessment 完全一致 |
| 达到累计上限 | 比例封顶，不继续增加 |
| 极小金额舍入为0但比例大于0 | 不因金额为0误判为尚未开始 |

| 当前估值单价与 basis_rate 不同 | 分列展示，仍按原始参考单价计算建议金额 |

| 多次迁移同步 | 新入口只有一个，旧入口仍可访问 |
| 回归旧保存、daily、旧报表 | 函数签名、原结果、旧调用方式保持不变 |
