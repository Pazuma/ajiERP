# 中国发票识别入口暂时隐藏方案

## 1. 背景与目标

当前版本暂不使用发票自动识别能力。为了减少无关入口、避免用户误进入尚未启用的流程，本次仅在界面上隐藏以下三处入口：

1. 中国税务发票列表页的“发票操作 -> 识别发票”。
2. 中国税务发票草稿表单的“发票操作 -> 识别发票”。
3. 中国财务侧边栏的“中国发票识别任务”。

目标是让用户继续通过手工录入和保存中国税务发票完成税务处理，同时保留现有识别能力、历史识别任务和后端接口，待后续需要时可以低成本恢复。

## 2. 范围与非目标

### 本次范围

- 隐藏上述三个界面入口。
- 保留“中国税务发票”菜单、手工新建、查看、保存、查验、进项税抵扣等既有操作。
- 保证导航同步或迁移后，被隐藏的侧边栏入口不会自动恢复。

### 明确不做

- 不删除 `China Tax Invoice` 或 `China Tax Invoice Recognition` DocType。
- 不删除已有发票、识别任务、上传文件或识别结果。
- 不修改发票识别服务、外部识别供应商适配器、识别配置和既有后端 API。
- 不增加权限限制，不阻止有权限的用户通过历史链接直接查看已有识别任务。
- 不改税务核算、进项税抵扣、对账、结账、归档、开票申请和红字发票等业务逻辑。

这是一项“暂时隐藏入口”的界面调整，不是下线或删除发票识别功能。

## 3. 当前调用链路

### 3.1 列表页识别流程

```text
中国税务发票列表
  -> 发票操作 / 识别发票
  -> create_recognition(company, direction, source_file)
  -> 新建 China Tax Invoice Recognition 识别任务
  -> recognize_invoice()
  -> run_invoice_recognition() 后台任务
  -> 外部发票识别服务
  -> 识别任务结果
  -> create_tax_invoice_draft_from_recognition()
  -> 生成中国税务发票草稿
```

### 3.2 表单页识别流程

```text
中国税务发票草稿表单
  -> 发票操作 / 识别发票
  -> 上传文件并调用 recognize_invoice_for_form()
  -> 外部发票识别服务（同步）
  -> 返回票面字段和发票明细
  -> 写回当前未保存表单
  -> 用户核对后保存为中国税务发票
```

### 3.3 本次调整后的使用路径

```text
中国税务发票
  -> 手工填写或导入已有业务数据
  -> 保存
  -> 查验 / 进项税抵扣 / 税务核算 / 对账 / 结账
```

调整后，前两条自动识别流程不再从正常界面启动；服务和历史数据仍保留，第三条手工处理路径不受影响。

## 4. 实施原则

1. 小增量：只改三个入口的注册或导航生成，不触碰识别结果、发票数据和税务业务规则。
2. 优先新增分支：增加一个命名清晰、默认关闭的“识别入口是否展示”判断；不改变现有函数签名或后端 API。
3. 双来源同步：侧边栏同时修改运行时导航生成逻辑和静态导航文件，避免迁移、安装或导航同步后入口重新出现。
4. 易恢复：后续启用时只需打开展示开关并同步导航，无需恢复删除的业务代码或迁移数据。

## 5. 计划修改的文件与代码

| 文件 | 计划修改 | 原有接口与行为 |
| --- | --- | --- |
| `china_finance/public/js/china_tax_invoice_form_recognition.js` | 在 `refresh(frm)` 中为“识别发票”按钮增加展示开关分支。`add_input_tax_actions(frm)` 仍照常执行。 | 保留 `open_recognition_dialog`、`recognize_and_fill` 和 `recognize_invoice_for_form` 调用，不改参数或返回值。 |
| `china_finance/public/js/china_tax_invoice_list.js` | 为列表页“识别发票”内嵌按钮增加同一个展示开关分支。 | 保留 `open_recognition`、`create_recognition` 调用和进项税抵扣批次菜单；不改接口。 |
| `china_finance/setup/install.py` | 在“发票管理”导航分组中，通过同一开关决定是否生成 `China Tax Invoice Recognition` 链接。 | 保留 `China Tax Invoice` 链接和导航同步方法；不改工作台、其他导航及业务初始化。 |
| `china_finance/workspace_sidebar/china_finance.json` | 移除静态侧边栏中“中国发票识别任务”这一项，使静态元数据与运行时导航一致。 | 仅删除一个导航项，不调整其他侧边栏项目。 |
| `docs/08-reference/65-hide-invoice-recognition-ui-plan.md` | 记录本方案、调用链、边界、验收和恢复方式。 | 不影响运行时业务。 |

实现时将新增一个集中、可读的前端展示常量或轻量公共判断，例如 `INVOICE_RECOGNITION_UI_ENABLED = false`。其职责仅为控制入口是否注册，默认值为关闭。不会将该开关写入数据库，也不会新增设置字段或数据库迁移。

> 说明：实际代码实施时，将根据项目现有前端共享脚本位置放置该常量；若当前没有合适的公共脚本，则在两个页面脚本中使用相同的明确常量，并在安装导航处使用对应的 Python 常量。该常量不改变任何旧接口，仅增加展示分支。

## 6. 关联模块与影响评估

| 模块 | 是否修改 | 预期影响 |
| --- | --- | --- |
| 中国税务发票列表与表单 | 是，仅隐藏识别入口 | 手工新建、编辑、保存和已有关联操作保持可用。 |
| 中国发票识别任务导航 | 是，仅隐藏导航项 | 普通用户不再从侧边栏进入识别任务；历史任务不删除。 |
| 发票识别服务 `invoice_recognition.py` | 否 | `create_recognition`、`recognize_invoice_for_form` 等原接口继续存在。 |
| 外部识别服务适配器 `invoice_recognition_provider.py` | 否 | 不更换供应商、不改地址、密钥、超时或请求格式。 |
| 中国财务设置 | 否 | 识别开关、供应商和配置字段保留，避免影响将来重新启用。 |
| 税务计算、抵扣、对账、结账、归档 | 否 | 继续消费已保存的中国税务发票，不依赖本次隐藏的界面入口。 |
| 历史识别任务与直接路由 | 否 | 有权限的用户仍可通过已有链接查看；本次不实施权限拦截。 |

需要特别同步的关联点：`install.py` 会在迁移和导航同步时重新生成侧边栏；因此只修改 JSON 文件不够。静态 JSON 和导航生成分支必须同时调整，才能保证隐藏效果持续存在。

## 7. 预期效果

界面效果：

1. 打开“中国税务发票”列表，不再看到“发票操作 -> 识别发票”。
2. 新建或编辑草稿状态的“中国税务发票”，不再看到“发票操作 -> 识别发票”。
3. 中国财务侧边栏“发票管理”下不再显示“中国发票识别任务”。
4. “中国税务发票”入口仍显示，手工建票、编辑、保存仍可完成。
5. 已提交进项蓝票的“确认查验通过”“标记不得抵扣”等进项税操作仍显示并可使用；列表页“创建进项税抵扣批次”仍可使用。

业务效果：

1. 用户不能再通过常规界面发起新的自动识别任务或在表单中上传识别发票。
2. 已有识别任务、识别结果和已经生成的税务发票不被删除或变更。
3. 税务计算、抵扣、对账、结账等基于已保存税务发票的后续流程保持不变。
4. 后端接口仍兼容原调用方，未来重新展示入口后无需恢复服务或迁移数据。

## 8. 验收与回归检查

实施后执行迁移和清理缓存，再使用浏览器强制刷新验证。

1. 进入中国税务发票列表，确认没有“发票操作 -> 识别发票”。
2. 新建中国税务发票，确认草稿表单没有“发票操作 -> 识别发票”。
3. 刷新中国财务侧边栏，确认没有“中国发票识别任务”，且“中国税务发票”仍存在。
4. 执行一次手工新建、填写并保存税务发票，确认保存正常。
5. 对一张符合条件的已提交进项蓝票，确认进项税相关按钮未受影响；列表页确认仍可创建进项税抵扣批次。
6. 执行一次迁移/导航同步后再次检查侧边栏，确认识别任务链接没有被重新生成。
7. 使用已有识别任务地址打开记录，确认历史数据仍能按原权限查看。

建议命令：

```bash
bench --site aki_test.localhost migrate
bench --site aki_test.localhost clear-cache
```

浏览器验证时使用 `Ctrl+F5`，避免旧的 JavaScript 缓存导致入口仍显示。

## 9. 恢复方案

后续正式启用发票识别时：

1. 将识别入口展示开关改为启用。
2. 恢复导航分组中 `China Tax Invoice Recognition` 的链接，或使该链接满足展示分支。
3. 恢复静态侧边栏中的同一导航项。
4. 迁移、清缓存并按识别流程回归测试。

因为本方案不删除服务、配置、任务或数据，恢复不需要数据库数据修复，也不需要变更老接口。

## 10. 实施结论

本方案当前仅为设计沉淀，尚未修改业务代码。待确认后，按上述文件进行最小范围实施：隐藏三个入口，保留全部发票识别能力与原有业务接口。
