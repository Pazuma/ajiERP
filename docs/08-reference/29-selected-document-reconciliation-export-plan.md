# 按选择单据导出对账明细方案

状态：仅方案，未修改业务代码或站点数据。

## 1. 目标与范围

采购人员需要将指定采购订单的物料、价格和数量导出给供应商对账；销售或仓库人员也可能需要将指定出货单导出给客户对账。现有列表导出侧重单据头字段，不能稳定导出“一个单据、多条物料明细”的对账数据，也不能以用户列表勾选的单据作为唯一范围。

本方案新增“已选单据对账导出”分支：用户在单据列表勾选记录后点击导出，系统仅导出所选单据的明细行。导出 Excel 一行对应一条物料明细，而非一行对应一张单据。

一期支持：

| 场景 | 来源单据 | 对账对象 | 核心字段 |
|---|---|---|---|
| 采购订单对账 | `Purchase Order` / `Purchase Order Item` | 供应商 | 采购订单号、订单日期、供应商、物料编码、物料名称、单位、单价、数量、金额、交期 |
| 出货对账 | `Delivery Note` / `Delivery Note Item` | 客户 | 出货单号、出货日期、客户、物料编码、物料名称、单位、单价、数量、金额、仓库 |

“货物单”在本方案中按实际已交付的 `Delivery Note`（销售出库/送货单）处理。若业务所指的是采购收货单，二期只需增加 `Purchase Receipt` 配置分支，不复用或改变一期接口。

## 2. 预期效果

1. 用户在采购订单列表中勾选 1 到多张订单，点击 `导出已选对账明细`，下载的 Excel 只包含这些订单的物料行。
2. 同一采购订单有 3 个物料时导出 3 行；勾选 2 张订单时按单据顺序合并为一份文件。
3. 导出的采购订单明细至少包含：`采购订单号、订单日期、供应商、物料编码、物料名称、库存单位、单价、数量、金额、预计交货日期`。
4. 出货单导出使用对应客户字段，至少包含：`出货单号、出货日期、客户、物料编码、物料名称、库存单位、单价、数量、金额、出库仓库`。
5. 用户未选择单据时不调用服务端，页面提示先勾选至少一张单据。
6. 已取消单据默认不导出；草稿或已提交是否允许导出由单据类型配置明确控制，采购订单一期允许草稿和已提交，出货单一期仅允许已提交。
7. Excel 顶部包含导出时间、导出人和所选单据数；文件名带单据类型和导出时间，便于发给供应商或客户后追溯。
8. 对账双方可依据文件中的单据号、导出时间和“导出说明”工作表还原本次勾选范围；同一批已选单据在单据内容未变化时再次导出，应得到字段口径和明细行一致的结果，避免因列表筛选、分页或手工汇总造成对账版本不一致。

## 3. 数据口径与安全规则

### 3.1 行级数据口径

采购订单数据来自 `Purchase Order` 与 `Purchase Order Item`；只导出非空物料行。金额优先使用订单行 `amount`，单价使用订单行 `rate`，数量使用 `qty`，避免自行重新计算税费或单位换算。

出货单数据来自已提交的 `Delivery Note` 与 `Delivery Note Item`；数量使用实际交付 `qty`，单价和金额使用送货单行保留值。该文件是业务对账明细，不替代发票、税务或应收账款凭据。

### 3.2 选择范围

前端只传递当前列表勾选的单据 `name` 数组。服务端再次执行：

1. 非空、去重和最大数量校验，例如单次最多 500 张单据；
2. 对每一张单据执行当前用户的 `read` 权限校验；
3. 固定 DocType 和子表连接条件，不接受客户端传入 SQL、字段名、过滤条件或任意单据类型；
4. 过滤不符合单据状态的记录，并将跳过原因写入下载文件的“导出说明”工作表；
5. 如果全部单据被跳过，明确报错，不生成空文件。

这样用户不能通过篡改浏览器请求导出无权查看的订单，也不会导出列表当前页以外的任意数据。

### 3.3 字段与格式

首期固定对账字段，不在页面做任意字段勾选，确保供应商和客户每次得到一致结构。日期按站点格式输出，数值保留原始精度，金额使用单据币种和原始金额。跨币种导出时增加 `币种` 列，不强制换算成本位币。

Excel 包含两个工作表：

| 工作表 | 内容 |
|---|---|
| `对账明细` | 每条物料一行的正式对账数据 |
| `导出说明` | 导出时间、导出人、已选单据、成功单据、跳过单据及原因 |

## 4. 交互设计

### 4.1 采购订单列表

在 `Purchase Order` 列表多选操作区新增带下载图标的 `导出已选对账明细`。只有勾选至少一张订单后显示或可用；点击后显示简短确认弹窗，说明“将导出 N 张采购订单的物料明细，不修改订单数据”。确认后开始下载。

不修改原生列表的常规 `导出` 菜单，也不改变现有采购订单列、筛选或批量操作。

### 4.2 出货单列表

在 `Delivery Note` 列表以相同交互新增同名操作。下载前提示只会包含已提交送货单。文件标题显示为“客户出货对账明细”，减少采购和销售文件混用。

### 4.3 空数据与异常

- 无选中记录：提示“请至少选择一张单据”。
- 选中单据无物料行：在说明工作表列出，正式明细不生成空行。
- 部分记录无权限、已取消或状态不符合：允许导出其余合规记录，并在说明工作表展示跳过原因。
- 导出量超过限制：阻止下载并提示缩小选择范围。
- 服务端异常：返回可读错误；不写入业务单据、不创建库存或财务记录。

## 5. 调用链路

```text
采购订单 / 出货单列表勾选记录
  -> 对应 listview JS 读取 checked_items 的 name
  -> 显示确认弹窗
  -> POST /api/method/...selected_document_export.download_reconciliation_export
  -> 服务端校验单据类型、选择数量、读取权限和状态
  -> 查询单据头 + 物料子表，按单据号、行号排序
  -> 生成 Excel：对账明细 + 导出说明
  -> Frappe binary download response
  -> 浏览器下载文件
```

服务端不会调用保存、提交、取消或库存更新接口。调用链路是完全新增的只读分支。

## 7. 新增接口设计

新增单一下载接口，内部根据固定的 `document_type` 分支处理：

```python
@frappe.whitelist()
def download_reconciliation_export(document_type: str, document_names: str):
    """Download selected Purchase Orders or Delivery Notes as fixed reconciliation rows."""
```

参数：

```json
{
  "document_type": "Purchase Order",
  "document_names": "[\"PUR-ORD-2026-0001\", \"PUR-ORD-2026-0002\"]"
}
```

返回为 Frappe 标准下载响应，不定义新的 JSON 数据契约，也不扩展旧 API。前端用 `open_url_post` 触发下载，避免将大量 Excel 二进制内容放进 RPC 响应。

服务端内部建议采用不可变配置表，而不是根据前端字符串动态拼接：

```python
EXPORT_CONFIG = {
    "Purchase Order": {...},
    "Delivery Note": {...},
}
```

新增采购收货对账、销售订单对账或发票对账时，只新增一项明确配置及对应测试分支，不修改现有采购订单和送货单导出行为。

## 8. 受影响模块

| 模块 | 影响 |
|---|---|
| 采购订单列表 | 增加仅多选可用的供应商对账导出入口 |
| 送货单列表 | 增加仅多选可用的客户对账导出入口 |
| 供应商与客户协同 | 获得统一、可发送的明细 Excel；不改变主数据 |
| 权限 | 复用现有单据读取权限，服务端逐单复核 |
| 库存/财务/税务 | 无直接影响，导出是只读行为 |
| Excel 导入 | 无影响，导出接口与导入接口隔离 |

## 9. 验收场景

1. 勾选两张采购订单，每张有两条物料，下载 Excel “对账明细”恰有四行，且没有其他订单数据。
2. 同一订单同一物料有两条不同交期/仓库明细时保留两行，不能错误合并。
3. 不选择任何采购订单时点击导出，客户端提示且不发下载请求。
4. 选择一张取消采购订单和一张有效订单，文件只导出有效订单，说明页注明取消单被跳过。
5. 无读取权限的单据无法被服务端导出，即使手工构造请求也被跳过或拒绝。
6. 勾选已提交送货单，导出文件的客户、出货单号、物料、实际数量、单价和金额与单据行一致。
7. 选择草稿送货单时，说明页显示其状态不符合，不进入正式客户对账明细。
8. 单次选择超过上限时无文件生成，显示限制提示。

## 10. 实施顺序

1. 新增固定配置与服务端采购订单导出，先完成权限、状态、物料行和 Excel 结构测试。
2. 在采购订单列表新增多选导出入口，并用真实选单验证下载范围。
3. 复用新增服务的独立 `Delivery Note` 配置分支和列表入口。
4. 在 `aki_test.localhost` 分别用供应商采购订单和客户送货单验证，并检查导出说明页。
5. 业务确认字段口径后，再考虑新增采购收货单或发票对账配置分支。
