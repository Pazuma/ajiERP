# 物料供应方式驱动生产缺料默认补料方案

日期：2026-10-16  
状态：已于 2026-10-16 按方案实施，实施记录见第 12 节；以下方案章节保留设计口径。

## 1. 目标与业务口径

将“缺料时默认采购还是默认生产”的维护入口，从 BOM 的“缺料时默认发起生产工单”迁移到物料表已有的“半成品/物料供应方式”。同一物料统一维护一次，不再逐个 BOM 配置。

保留现有入口：生产工单开始后，创建生产领料出入库单，发生缺料时打开现有缺料列表弹窗。这里只决定弹窗初始勾选，不在保存物料、保存 BOM 或开始生产工单时自动创建补料单据。用户点击“确认发起”后才生成采购申请或子生产工单。

本次主要调整 `custom_direct_component_supply` 直接组件补料分支。旧分层/混合补料分支仍保留原有供应方式约束，不借此改变旧业务规则。

## 2. 已核实的当前实现

1. 物料已有 `Item.custom_supply_mode`，可选空值、外购、自制、可外购/可自制；物料表布局已包含该字段，不需要新增同义字段。
2. BOM 已有 `custom_default_create_work_order_on_shortage` 勾选项。
3. `get_shortage_details` 返回缺料、库存、已安排量、待安排量、供应方式及子 BOM。
4. 直接组件弹窗另行调用 `get_direct_component_shortage_defaults`，当前根据子 BOM 的旧勾选项决定默认是否创建生产工单。
5. 弹窗确认调用 `allocate_direct_component_shortage`。后端重新计算缺口并校验权限，勾选创建子生产工单，未勾选创建采购申请。
6. 该直接组件接口调用公共分配逻辑时使用 `enforce_supply_mode=False`，因此支持用户覆盖默认采购/自制偏好。旧 `allocate_shortage` 分支仍按供应方式限制可选路线。
7. 当前默认值接口请求失败会被前端捕获并按全不勾选继续；无子 BOM 的行显示“采购申请”。切换默认来源时，需要同步处理这两个异常场景。

## 3. 目标判断规则

| 物料供应方式 | 有有效子 BOM | 弹窗初始状态 | 确认后的目标 |
| --- | --- | --- | --- |
| 外购 | 有或无 | 不勾选生产工单 | 采购申请；仍须允许采购且有创建权限 |
| 自制 | 有 | 默认勾选生产工单 | 子生产工单 |
| 自制 | 无 | 显示异常，要求处理 | 不允许静默按默认值采购 |
| 可外购/可自制 | 有 | 建议默认不勾选 | 默认采购，可人工勾选生产 |
| 可外购/可自制 | 无 | 不勾选，仅允许采购路线 | 校验可采购后发起采购申请 |
| 空值 | 有或无 | 按默认采购处理 | 不回写历史物料，仍校验采购能力 |

“可外购/可自制默认采购”是根据“大部分缺料走采购”的业务偏好提出的方案口径。

直接组件分支中，供应方式是默认偏好，并不替代采购属性、有效 BOM、公司及权限校验：

- 外购物料有有效 BOM 时，用户可主动勾选生产。
- 自制物料允许采购时，用户可主动取消勾选，改走采购。
- 非采购物料不能因为未勾选就创建采购申请，应明确提示选择生产或维护资料。
- 自制物料没有有效 BOM 时，展示“自制物料缺少有效 BOM”；可采购的行需用户明确选择“本次改为采购”才能确认，否则阻止该行提交。

默认来源只读取物料，不再回退读取旧 BOM 勾选值，避免出现两套相互冲突的设置。

### 5.1 后端默认判断示意

以下仅为建议代码结构，实施时按现有代码风格整合：

```python
def _get_item_shortage_default(row):
    mode = row.get("supply_mode") or "外购"
    missing_bom = mode == "自制" and not row.get("bom_no")
    return {
        "default_create_work_order": bool(mode == "自制" and row.get("bom_no")),
        "supply_mode": mode,
        "default_source": "item_supply_mode",
        "default_block_reason": "missing_manufacturing_bom" if missing_bom else "",
    }
```

`get_direct_component_shortage_defaults(entry)` 继续经过 `_entry` 和 `_shortages` 获取服务器实际数据，不接受客户端传来的供应方式或 BOM 作为依据。返回示例：

```json
{
  "rows": [{
    "item_code": "B",
    "warehouse": "生产仓 - XX",
    "default_create_work_order": true,
    "supply_mode": "自制",
    "default_source": "item_supply_mode",
    "default_block_reason": ""
  }]
}
```

保持已有 `rows`、`item_code`、`warehouse`、`default_create_work_order` 不变，其余字段均为增量字段。复用 `_shortages` 已经读取的 `custom_supply_mode`，不增加逐行物料查询，也不再为默认值逐行读取 BOM 勾选字段。

### 5.2 前端新增小分支

1. 正常行继续使用既有 checkbox 和确认接口。
2. 自制且缺少有效 BOM 的行进入新增异常分支：要求维护 BOM 或显式选择本次采购；不能只凭 `false` 默认值直接提交采购。
3. 默认信息加载失败时提示重试，禁用确认；不能沿用当前“失败后全不勾选”的静默降级。重试成功后保留用户已明确修改的选择。
4. 按物料编码和发料仓联合键合并默认值，不只按物料编码匹配。
5. 保留提交中禁用按钮、重复提交保护及已有单据链接。

不新增采购/生产创建接口，不扩展现有决策参数的必填项。显式确认采购是界面交互保护，最终仍传原有 `create_work_order: false`；服务端继续校验采购资格和真实缺口。

## 7. BOM、数量和单据兼容边界

- 子 BOM 仍优先使用父工单 BOM 明细指定的 `bom_no`，没有指定时才使用物料默认 BOM；不因供应方式改变而重新选择最新 BOM。
- 指定 BOM 无效时明确提示，不能静默换用物料最新 BOM。相同物料在父 BOM 中关联多个不同子 BOM 的现有歧义校验继续保留。
- BOM 必须匹配物料、已提交且启用；创建子工单时继续校验公司和读取权限。
- 缺口按物料、仓库及库存单位计算，扣除已安排补料量。用户不能通过前端默认值改变数量或绕过服务端校验。
- 已存在相反路线的待完成补料时，继续要求先处理原安排，不自动取消、切换或重复创建。
- 保留现有整批校验、事务保存点及失败回滚逻辑，不允许部分行异常却留下无提示的部分补料单据。
- 物料供应方式更新后，下次打开适用弹窗读取新值，包括尚未安排补料的历史工单。已生成的采购申请、子工单和补料关联记录不回写、不转换。
- 不改变工单 BOM 快照、BOM 历史版本、领料需求及既有工单模式。

## 8. 完整实际业务流

以成品 A 需要半成品 B、半成品 C 和原材料 D 为例：B 为自制且有有效 BOM，C、D 为外购。

```text
基础维护
  B：供应方式=自制，维护并启用 B 的 BOM
  C、D：供应方式=外购
          ↓
建立 A 的 BOM → 创建并开始 A 的生产工单
          ↓
创建生产领料出入库单 → 检测 B/C/D 库存缺口
          ↓
缺料列表：B 默认勾选生产；C、D 默认采购
          ↓
用户按实际情况调整 → 确认发起
          ├─ B 路线：生成 B 的子生产工单
          │    ↓ B 领料；继续缺料时沿用同样补料流程
          │    ↓ B 生产完成 → 正式生产入库
          └─ C/D 路线：生成采购申请
               ↓ 既有采购下单 → 到货质检 → 合格物料正式入库
          ↓
库存增加 → A 工单重新领料并提交
          ↓
允许按现有规则分批领料、分批组装
          ↓
A 生产完成 → 成品入库 → 按现有工单完成规则流转
```

无尘车间等连续生产场景仍须执行半成品系统入库及后续领用，物理流转按现场管理执行。本次不新增绕过入库直接增加库存的途径。采购质检、入库和成本核算沿用已有流程，不因本次默认值调整改变。

## 9. 历史数据与上线顺序

1. 先输出只读差异清单：物料供应方式、默认 BOM、旧 BOM 勾选情况及父 BOM 引用情况。重点列出“旧 BOM 勾选但物料为外购/空值”“同物料不同 BOM 设置冲突”“自制但无有效 BOM”。只读清单可用运维查询完成，不必新增业务接口或数据表。
2. 由业务人员确认需要自制的物料，并在物料表维护。不能将所有历史勾选 BOM 对应物料自动改为自制。
3. 部署后端兼容返回及异常信息、前端消费和加载失败保护；这两部分应在同一发布窗口生效，避免新默认规则配旧异常处理。
4. 隐藏 BOM 旧入口，保留数据库字段和原值。既有 `hooks.py` 的 `after_migrate` 已调用 `ensure_schema`，复用现有机制更新隐藏元数据，不新增 hook。
5. 按测试清单验收，再开放业务使用。

物料新建时建议明确选择外购；历史空值只在本次直接组件默认判断中按外购解释，不全量改写、不改变旧分层分支对空值的现有行为。不在保存物料时强制要求已经存在 BOM，以允许先建物料再建 BOM。

回退时恢复旧代码、旧字段显示及字段元数据即可，但新维护的物料供应方式不会自动转换为 BOM 勾选。回退前应核对差异，避免误以为旧值与新维护值完全等价。任何回退都不撤销已创建单据。

## 10. 受影响模块

| 模块 | 影响 |
| --- | --- |
| 物料表 | 成为默认补料路线的维护入口；沿用既有字段 |
| BOM 详情 | 隐藏旧勾选项；组件结构、版本、编码和历史查看不变 |
| 生产领料缺料列表 | 默认值来源、提示及异常交互变化 |
| 采购申请、子生产工单 | 创建条件入口默认值变化，创建接口和数据结构保持不变 |
| 旧分层/混合补料 | 只做回归，不改变供应方式能力约束 |
| 库存、生产入库、成本 | 不改记账代码；仍依赖正常单据提交更新库存与成本 |
| 供应商报价、采购质检、对账开票付款 | 不改接口及流程，回归关联路径即可 |

不新增数据表，不新增必填 API 参数，不修改 ERPNext 核心代码，不修改普通采购缺料入口，不重构公共分配算法。

## 11. 验证与验收

后续实施时更新已有单元测试，不以本次文档生成代替功能验证。

| 场景 | 验收结果 |
| --- | --- |
| 自制 + 有效 BOM | 默认勾选，确认生成子工单 |
| 外购、双来源、空值 | 默认不勾选，符合采购资格时生成采购申请 |
| 物料设置与旧 BOM 勾选相反 | 只按物料设置，旧值不参与默认判断 |
| 自制无有效 BOM | 显示异常，不静默采购；明确改购或维护 BOM 后才能继续 |
| 无效/停用/未提交/不匹配 BOM | 不可创建生产工单，显示可理解的提示 |
| 用户取消自制勾选或勾选外购物料生产 | 在有效 BOM、采购资格和权限范围内允许覆盖 |
| 默认值接口失败 | 提示重试，不能全不勾选直接发采购 |
| 重试及手动选择 | 不覆盖用户已明确做出的选择 |
| 同物料不同仓库、部分已有安排 | 联合键正确匹配，只安排剩余缺口 |
| 重复点击、并发、相反路线已有安排 | 不重复建单，沿用现有校验和回滚 |
| 老接口调用及旧混合模式 | 返回既有字段，原供应方式限制不变 |
| 修改物料后再次打开弹窗 | 使用新默认；已创建单据保持不变 |
| 半成品生产完成但未入库 | 不视为可领库存；入库后父工单再按正常流程领用 |

最终效果：业务人员主要在物料表选择外购，仅将确需自产的物料设为自制；生产缺料时系统按这一设置预选路线，用户确认后走既有采购或生产闭环。
