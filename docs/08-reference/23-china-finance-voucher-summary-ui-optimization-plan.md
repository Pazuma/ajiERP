# 中国财务“凭证汇总表”界面优化方案

> 状态：方案沉淀，暂不修改业务代码  
> 版本：v0.1  
> 页面：`/app/china-voucher-summary`

## 1. 优化目标

在不改变凭证汇总口径、查询接口和导航结构的前提下，重构“凭证汇总表”的页面布局和交互，使其与当前 Frappe Desk、中国财务报表和系统侧边栏保持一致，并改善空数据、筛选和小屏体验。

原则：

- 只调整页面 JS、局部 CSS 和必要的前端状态管理。
- 保持 `china_finance.services.voucher_summary.get_voucher_summary` 的接口名称、参数和返回结构不变。
- 不修改 `China Accounting Voucher`、凭证分录、凭证生成和冲销逻辑。
- 优先使用 Frappe 标准控件、DataTable、主题变量及页面操作区。

## 2. 当前界面问题

根据当前截图和源码，主要问题如下：

1. 筛选区使用大面积灰色背景，垂直空间过高，与 Desk 的紧凑工具栏风格不一致。
2. 公司字段使用 Frappe 控件，月份和日期却使用浏览器原生输入框，标签、字体、边框和日期格式不统一。
3. 月份区间与自定义日期同时常驻，用户不清楚哪个条件优先，页面也显得拥挤。
4. 查询、下载、打印和小计开关混在同一行，主次操作关系不明确。
5. 高饱和蓝色表头与系统现有 Query Report/DataTable 的中性表头风格不一致。
6. 统计区域只是单行文字和分隔符，信息层级弱，且白色空条占用空间。
7. 原生 HTML 表格没有稳定列宽、排序、固定表头和统一格式化能力。
8. 无数据时只有“无数据”文字，缺少明确的空状态和当前查询范围。
9. 页面 JS 全部压在少数长行中，筛选、请求、渲染、导出和打印难以独立维护。

## 3. 目标布局

以当前系统“查凭证”页面作为主要视觉和交互基准，而不是另行设计独立报表外观。需要复用其页面标题区、两行筛选网格、右上操作区、查询状态提示、纯白结果区和居中空状态。

```text
Desk 页面标题：凭证汇总表                       [操作⌄] [刷新] [...]

[公司] [期间模式] [起始月份] [截止月份] [关键词] [分类小计]
[自定义起始日期] [自定义截止日期]（仅自定义模式显示）

● 汇总数据已更新                              运行时间：0.008 秒

凭证 12 张    附件 8 张    借方合计 ¥...    贷方合计 ¥...    2026-09-01 至 2026-09-30

科目编码 | 科目名称                         | 借方金额 | 贷方金额
----------------------------------------------------------------------
1001     | 库存现金                         | ...      | ...
         | 流动资产小计                     | ...      | ...
```

- 页面不新增二级导航或额外标题卡片，继续使用与“查凭证”一致的 Desk 原生标题、面包屑和页签区域。
- 筛选区采用与“查凭证”一致的六列网格和灰色输入底色，不再使用整块灰色容器；高级条件按需出现。
- 汇总指标采用一条低高度统计带，不使用四个独立卡片。
- 数据区使用与“查凭证”一致的纯白背景、系统边框和浅灰表头；无数据时保留足够的工作区高度。

## 4. 筛选交互

1. 增加“期间模式”分段选择：`按月`、`自定义日期`。
2. 按月模式仅显示起始月份、截止月份；自定义模式仅显示起始日期、截止日期，避免两组条件同时出现。
3. 公司、日期、关键词改为 Frappe 标准控件，保持标签、必填标记、日期格式和校验反馈统一。
4. 页面主要查询由筛选变化或显式刷新触发；右上角使用与“查凭证”一致的`操作`菜单、刷新按钮和更多菜单。下载、打印放入`操作`菜单，避免占用筛选行。
5. “显示科目分类小计”使用标准 Check 控件；切换后自动刷新，避免用户再次点击查询。
6. 回车触发查询；查询中禁用重复提交并显示加载状态。
7. 切换期间模式时保留另一模式最近一次输入值，但请求只提交当前模式对应字段。

### 4.1 按参考图落位

图一红框中的现有筛选面板整体替换为图二“查凭证”式筛选器，不保留当前字段上方的大字号标签和整块灰色背景。

桌面端第一行：

| 位置 | 字段 | 表现形式 |
|---|---|---|
| 1 | 公司 | Link，默认当前公司 |
| 2 | 期间模式 | Select，选项为“按月”“自定义日期” |
| 3 | 起始月份/起始日期 | 根据期间模式切换字段 |
| 4 | 截止月份/截止日期 | 根据期间模式切换字段 |
| 5 | 关键词 | Data，提示“凭证号/摘要/科目/金额” |
| 6 | 显示科目分类小计 | Check 或标准开关 |

如后续增加凭证字、会计期间、科目范围等高级条件，放入第二行，不拉宽第一行字段。当前一期字段不足两行时允许第二行留空，保持与系统报表统一的网格节奏，但不人为增加无效筛选项。

操作区按图二放置在页面右上角：

- `操作`下拉：下载 CSV、打印。
- `刷新`图标按钮：按当前筛选重新查询。
- `更多`菜单预留，不在一期加入无业务含义的操作。
- 不再在筛选区中显示“查询、下载、打印”三个文字按钮。

筛选区下方增加轻量状态行：左侧显示“汇总数据已更新”或查询错误，右侧显示本次运行时间。凭证数、附件数和借贷合计紧接状态行展示，但不放进独立卡片。

## 5. 表格和状态设计

- 优先使用 Frappe DataTable，列宽固定为约 `150 / minmax / 160 / 160`，金额右对齐并使用公司币种格式。
- 表头使用 `var(--subtle-fg)`、`var(--border-color)` 和系统正文颜色，不再使用整行 `--blue-500`。
- 科目名称列可伸缩；长内容省略并提供 tooltip。
- 分类小计行使用浅灰背景和 `font-weight: 600`，不参与底部总计重复计算。
- 底部合计行保持可见，借贷不平衡时使用系统警告色提示。
- 空状态显示“当前期间暂无凭证汇总数据”，同时保留已应用公司和日期范围，并提供清除关键词动作。
- 空状态图标、字号、颜色和垂直位置参照“查凭证”的居中无数据状态，不再把“无数据”塞在一行表格单元格中。
- 请求失败时保留上一份成功结果，并显示可重试提示，不直接清空表格。
- 首次加载、重新查询和空结果应保持表格区域稳定，避免页面高度明显跳动。
- 查询完成后在筛选区下方显示与“查凭证”一致的小圆点状态提示，例如“汇总数据已更新”；不显示无意义的空白统计条。

## 6. 响应式与视觉规范

- 大于 `1200px`：采用六列筛选网格，字段宽度和行间距对齐“查凭证”筛选器；不足六项时保留自然空位，不把单个字段拉得过宽。
- `768px` 至 `1199px`：筛选区改为三列或两列排列，操作仍位于页面标题栏。
- 小于 `768px`：筛选控件单列，表格横向滚动；金额列不被压缩到换行。
- 页面间距采用当前系统的 8/12/16px 节奏，边框圆角不超过现有 `var(--border-radius)`。
- 不增加大面积深蓝、渐变、装饰卡片或新的色彩体系。
- 图标使用 Frappe/Lucide 已有图标，图标按钮提供 tooltip。

## 7. 计划修改文件

| 文件 | 计划修改 | 说明 |
|---|---|---|
| `china_finance/page/china_voucher_summary/china_voucher_summary.js` | 重构 | 拆分初始化、筛选、请求、指标、DataTable、导出与打印逻辑 |
| `china_finance/public/css/china_voucher_summary.css` | 重构 | 紧凑筛选栏、中性表头、统计带、空状态与响应式样式 |
| `china_finance/services/voucher_summary.py` | 原则上不改 | 仅在前端实现确认发现缺少币种等展示字段时，以兼容方式追加字段 |
| `china_finance/tests/test_voucher_summary.py` | 补充 | 保证期间模式切换后的请求参数和原有汇总结果兼容 |

无需修改 Page JSON、Workspace、Workspace Sidebar、凭证 DocType 和现有“查凭证”报表。

## 8. 前端调用链路

```text
打开 china-voucher-summary
  -> make_app_page 创建标准页面
  -> 初始化 Frappe 筛选控件与默认公司/本月
  -> build_filters 只生成当前期间模式的有效参数
  -> get_voucher_summary（旧接口保持不变）
  -> render_metrics + render_datatable + render_state
  -> 下载/打印复用最近一次成功结果
```

前端建议拆分为 `VoucherSummaryPage` 类，并提供 `setup_page_actions`、`setup_filters`、`get_filters`、`refresh`、`render_metrics`、`render_table`、`render_empty_state`、`export_csv` 和 `print` 等职责明确的方法。

## 9. 受影响模块与兼容性

- 直接影响：凭证汇总表 Page 和该页面局部 CSS。
- 间接影响：China Finance 全局 CSS 构建产物，但选择器全部限定在 `.cf-voucher-summary` 下。
- 不受影响：新增凭证、查凭证、凭证附件中心、电子会计档案、凭证快照同步、财务报表和结账流程。
- 旧书签和入口仍使用 `/app/china-voucher-summary`。
- 旧接口参数继续支持；不删除字段，不改变返回字段语义。

## 10. 验收标准

1. 页面视觉与 Frappe Desk 的按钮、字段、表头、边框和字体一致。
2. 按月与自定义日期不会同时显示或同时提交。
3. 查询、下载、打印和分类小计功能行为保持不变。
4. 有数据、无数据、加载中、请求失败四种状态均明确且布局稳定。
5. `1440px`、`1024px` 和移动端宽度下无控件重叠、文字截断或金额换行。
6. CSV 数据、打印数据与页面最近一次成功查询一致。
7. 原有 `get_voucher_summary` 服务回归测试通过，凭证金额和统计口径不变。
8. 图一红框内的大块灰色面板、纵向字段标签和三个文字操作按钮不再出现。
9. 筛选字段的高度、灰色输入背景、圆角、列间距与“查凭证”页面一致。
10. 下载与打印可从右上`操作`菜单正常执行，刷新按钮能按当前条件重新查询。

## 11. 实施顺序与回滚

第一步重构页面结构和筛选控件；第二步替换表格及统计状态；第三步统一导出、打印和响应式样式；最后执行 JS 语法检查、服务测试、构建和多视口截图验收。

回滚只需恢复凭证汇总页面 JS 和 CSS。由于不涉及数据库结构、凭证记录或接口变更，不需要数据回滚。

## 12. 预期效果

优化后页面将从当前“大块筛选面板 + 蓝色原生表格”调整为标准 Desk 报表工作区：筛选更紧凑、期间模式明确、操作层级清晰、统计信息可扫描、表格风格统一。功能和数据口径保持不变，用户无需重新学习入口或查询规则。

具体视觉结果与图二保持同一套布局语言：页面标题下直接出现横向等宽筛选框，桌面端最多六列；没有额外的灰色容器包裹；右上角集中放置操作、刷新和更多菜单；筛选区与结果区之间只保留状态和汇总信息。相较图一，筛选区高度明显降低，表格能更早进入首屏，可用空间更大。
