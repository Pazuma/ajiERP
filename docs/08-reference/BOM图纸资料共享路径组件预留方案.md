# BOM 图纸资料共享路径组件预留方案

日期：2026-11-04。状态：已实施。本方案已按小增量方式落地，实施记录见本文第 9 节。

## 1. 需求与边界

在 BOM 页面“基本信息”下方预留“图纸资料”组件，记录公司 Windows 共享文件夹或具体图纸文件的地址。图纸已加密，ERPNext 服务器不读取、不解析、不解密文件，也不上传或缓存图纸。

员工复制路径，在自己电脑的 Windows 资源管理器中打开，由现有共享盘权限及本机加密软件决定是否允许访问。首期不安装客户端、不注册专用协议、不调用本机工具，不承诺浏览器点击路径即可打开共享盘或文件。

## 2. 页面位置与展示

组件固定放在当前 BOM“基本信息”区域下方、后续业务区域之前，不另建独立页签，不改变物料明细和成本区域。实施前核对实际表单布局及现有客户端脚本，确定准确插入字段，不能仅凭显示标签猜测字段名。

组件占据完整一行，标题为“图纸资料”。首期每个 BOM 支持一组资料，预留将来扩展多份资料的空间；本期不引入子表或多文件管理。

```text
基本信息
……现有字段……

图纸资料
图纸名称：[装配图                 ]  图纸版本：[Rev.B         ]
图纸地址：[\\文件服务器\工程图纸\产品A\Rev.B\装配图.pdf      ]
                                                    [复制地址]
提示：复制地址后，在 Windows 资源管理器地址栏粘贴并打开。
```

无资料时保留组件空间，显示“暂无图纸地址”，复制按钮禁用。可编辑状态下仍展示输入框，便于补录。长路径允许换行展示或在输入框内完整查看，不因截断导致无法复制。

## 3. 拟新增字段

| 建议字段名 | 类型 | 用途 |
|---|---|---|
| custom_drawing_info_section | Section Break | 图纸资料区域 |
| custom_shared_drawing_name | Data | 图纸名称，可选 |
| custom_shared_drawing_revision | Data | 图纸版本，可选，与 BOM 版本分别记录 |
| custom_shared_drawing_path | Small Text | 单个共享文件夹或文件路径，可选 |
| custom_shared_drawing_actions | HTML | 复制按钮、空态及使用提示 |

以上为拟定名称，实施时先核对现有自定义字段及图纸相关字段，能复用则复用，避免重复建字段。路径不使用 Attach、Attach Image 或 URL 类型，不生成 File 附件记录。

现有图纸号、组件行图纸字段及附件逻辑保持不变；新区域表达的是当前 BOM 的共享资料地址，不替代组件图纸号。

## 4. 输入及复制规则

- 支持 UNC 路径，例如 `\\文件服务器\工程图纸\产品A\Rev.B`，或该目录下的具体文件路径。
- 首期仅支持 Windows UNC 地址，不使用个人映射盘符（如 `Z:\图纸`），不接受 HTTP、file、自定义协议或可执行命令。
- 名称、版本、地址均非必填，不影响已有 BOM 的保存和提交；填写地址时进行格式检查，并拒绝换行、控制字符及多条路径。
- 保存前清理首尾空白；保留内部空格、中文及反斜杠，不自动改写实际路径。
- 不在服务器检查路径存在性、文件内容、加密状态或员工访问权限；保存成功不代表文件一定可访问。
- “复制地址”只复制当前完整路径，不发起网络访问、不打开文件、不启动程序。
- 剪贴板能力受浏览器及 HTTPS/本机安全上下文限制；复制失败时展示可选中的完整路径，提示手动复制，不显示虚假的成功提示。
- 所有显示文本必须转义，不将地址直接拼入 HTML、脚本或命令。

## 5. 权限与版本

查看地址沿用 BOM 的读取权限；编辑地址沿用 BOM 写权限和现有版本管理规则，不为此新增公共查询接口。共享盘和加密软件继续独立控制文件访问，ERPNext 权限不能绕过它们。

共享地址可能包含公司内部目录信息，不默认加入对外邮件、打印格式、PDF 或门户页面；若以后需要对外展示，另行确认范围和权限。标准导出/API 对字段的可见性仍需按实际角色测试。

2026-11-04 追加确认：已提交且有效的 BOM 提供“编辑基本信息”入口，仅用于图纸名称、版本标识纠错及共享地址维护；沿用 BOM 写权限和标准修改日志。已取消或停用 BOM 保持只读。涉及图纸实际内容、物料、用量或工序的变化，继续更新 BOM 版本。新版本可按现有复制流程继承名称、图纸版本和路径，启用前由工程人员核对；不会自动把历史地址重定向至最新图纸。直接维护当前 BOM 地址后，旧工单查看此 BOM 时也会看到修改后的资料。

推荐共享盘按图纸版本分目录，不覆盖历史文件。例如：

```text
\\文件服务器\工程图纸\产品A\Rev.A\装配图.pdf
\\文件服务器\工程图纸\产品A\Rev.B\装配图.pdf
```

路径只能记录地址，不能保证共享盘内容不被覆盖、移动或删除。文件版本维护仍由工程资料管理制度负责。

## 6. 实施范围

后续实施限定在现有 BOM 定制应用：通过可重复执行的字段安装/迁移逻辑建立字段，客户端脚本负责区域展示、复制和提示，服务端校验负责路径格式与保存规则。准确应用目录、钩子和插入点需实施前核实。

不修改 Frappe/ERPNext 核心，不修改工单、生产、库存、成本计算或邮件发送逻辑，不迁移已有附件，不访问 SMB 服务器，不新增 SMB 账号或密码字段。

本方案是对本次确认的 BOM 基本信息区域的增量设计，不改变此前“版本查看页签不新增独立工程资料区域”的约定。

## 7. 验收标准

1. 新旧 BOM 均在基本信息下方显示图纸资料区域，不填写也能正常保存。
2. 可保存带中文、空格的合法共享目录及具体文件地址，重新打开后内容一致。
3. 复制得到完整原始路径；Windows 资源管理器可按员工现有权限打开测试目录及加密图纸。
4. 剪贴板不可用时提供手工复制方式；空路径禁止复制。
5. 非 UNC 地址、多行内容及脚本输入不能绕过服务端校验；页面无脚本注入。
6. 无 BOM 读取权限的用户不能通过新增组件获取路径；无写权限不能维护资料，已提交且有效 BOM 仅开放三个资料字段，取消或停用版本不可修改。
7. 历史 BOM 保留自己的路径，新版本不会回写旧版本；现有版本创建流程正常。
8. 页面加载、保存和复制不会由 ERPNext 服务器读取共享文件，不触发下载、上传或解密。
9. 不影响现有 BOM 明细、图纸号、附件、提交、成本及工单版本固化流程。

## 8. 交付顺序

字段、校验和页面组件已按本方案实施。部署后仍需用一台 Windows 员工电脑完成共享目录及加密图纸的人工验收。多图纸子表、一键打开、预览及文件同步均不在首期范围内。

## 9. 实施记录

- 字段及服务端校验：`client_akivision/utils/bom.py`。字段通过既有 `after_migrate` 调用的 `ensure_schema` 幂等建立，位置锚定 ERPNext v16 BOM 基本信息末尾字段 `uom`。
- 页面组件及复制降级：`client_akivision/public/js/bom.js`。继续通过既有 `doctype_js` 加载，不新增公开接口。
- 自动测试：`client_akivision/utils/test_bom.py`，覆盖中文、空格、共享根目录、空值、盘符、协议、多行、设备路径和缺少共享名等规则。
- 调用链：`bench migrate` → `after_migrate` → `client_akivision.utils.bom.ensure_schema`；BOM 保存 → 既有 `AkivisionBOMMixin.validate` → `validate_bom` → `normalize_shared_drawing_path`。
- 版本行为：既有 `frappe.copy_doc` 自动继承三个资料字段；经追加确认，仅三个资料字段设置 `allow_on_submit=1`。表单仍只读，通过“编辑基本信息”弹窗维护；新接口 `update_basic_drawing_info` 检查写权限、已提交及有效状态后调用标准 `doc.save()`。`before_update_after_submit` 对直接 API 保存同样校验 UNC 路径并禁止修改停用 BOM 的资料。BOM 的 `track_changes=1` 记录修改人、时间与字段前后值。
- 边界保持：未修改 ERPNext/Frappe 核心、现有工程图纸字段、附件、成本、工单或库存逻辑；服务器不会访问共享路径。
- 仍需外部人工验收：在 Windows 员工电脑测试资源管理器访问权限、加密图纸打开行为，以及 HTTP/HTTPS 环境下剪贴板能力。
