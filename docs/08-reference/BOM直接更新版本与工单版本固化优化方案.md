# BOM 直接更新版本与工单版本固化优化方案

日期：2026-10-10  
状态：2026-10-10 已实施核心流程；验证范围及实际差异见《BOM直接更新版本实施记录》。以下保留原设计内容供对照。

## 1. 目标

允许用户在已提交 BOM 页面点击“更新版本”，进入一份可编辑的新版本，直接修改组件、数量、子 BOM 和工序。保存并启用后：

- 修改前已经创建的生产工单继续使用旧 BOM，物料需求和成本依据不变化。
- 修改后创建的生产工单默认使用最新已启用版本。
- 旧 BOM 不取消、不覆盖、不删除，保留为已提交、有效、非默认的历史版本。
- 页面体验接近“修改组件后保存”，后台实际执行“复制旧版本 → 编辑新版本 → 提交并切换默认版本”。

不能直接更新原 BOM 数据。否则已经关联原 BOM 的工单虽然保存了 `bom_no`，但历史结构、成本估算、重算和审计可能失真。

## 2. 预期效果

### 2.1 已提交 BOM 页面

```text
物料清单：BOM-AKY-55R5-CGTC                 当前默认 V1

[更新版本]  [查看版本记录]  [成本估算]

组件
┌────┬──────────────┬──────┬────────────┐
│序号│物料           │用量  │子 BOM      │
├────┼──────────────┼──────┼────────────┤
│ 1  │PE 袋          │ 1    │            │
│ 2  │半成品 B       │ 2    │BOM-B-V1    │
└────┴──────────────┴──────┴────────────┘
```

已提交版本仍只读。点击“更新版本”后，系统复制当前版本并打开新草稿，不在原单上直接解锁表格。

### 2.2 新版本编辑页面

```text
正在编辑 BOM 新版本 V2
来源版本：BOM-AKY-55R5-CGTC（V1）

组件：可增加、删除、修改数量和子 BOM

[保存草稿]  [保存并启用]
```

保存草稿只保存新版本，不影响默认 BOM。保存并启用等价于标准提交新 BOM，并在同一事务中切换默认版本。

### 2.3 版本记录

```text
┌────┬────────────────────────┬────────┬──────┬──────────┐
│版本│BOM 单号                 │状态    │默认  │来源版本   │
├────┼────────────────────────┼────────┼──────┼──────────┤
│ V1 │BOM-AKY-55R5-CGTC       │已提交  │否    │-         │
│ V2 │BOM-AKY-55R5-CGTC-1     │已提交  │是    │V1        │
└────┴────────────────────────┴────────┴──────┴──────────┘
```

旧版本保持 `docstatus=1`、`is_active=1`、`is_default=0`，因此历史工单可以继续引用。新版本为 `docstatus=1`、`is_active=1`、`is_default=1`。

## 3. 版本和工单规则

| 对象状态 | BOM 处理规则 |
|---|---|
| 修改前已创建工单 | 固定原 `bom_no`，不自动切换，不重新生成需求 |
| 修改后新建工单 | 标准取该物料最新有效默认 BOM |
| 草稿工单、尚未执行 | 可人工执行“切换到最新 BOM”，明确确认后重新生成物料和工序 |
| 已提交但未领料工单 | 首版不开放切换，避免计划和审批依据静默变化 |
| 已领料、已生产或已入库工单 | 禁止切换 BOM |
| 旧 BOM | 已提交、有效、非默认，只读保留 |
| 新 BOM 草稿 | 可编辑，不影响生产默认值 |
| 新 BOM 提交 | 成为默认；旧版本只取消默认标记 |

新版本失败、校验未通过或仅保存草稿时，旧版本仍是默认版本。

## 4. 小增量设计原则

1. 不修改 ERPNext 核心代码，不覆盖标准 BOM、Work Order、Stock Entry 控制器。
2. 不改变现有 BOM 保存、提交、成本估算和工单创建接口。
3. 优先新增 `create_update_version` 接口和新版本分支，旧“取消 → 修订”仍可保留作为标准异常处理入口。
4. 复用标准 `frappe.model.document.copy_doc`、BOM 标准 `insert/submit/manage_default_bom` 和工单标准 BOM 获取逻辑。
5. 新旧版本都使用标准 BOM 单据；不建立另一套组件表或库存算法。
6. 历史工单不回写，不批量替换 `bom_no`，不重新计算历史成本。
7. 默认版本切换由服务端事务完成，不能仅依赖前端勾选框。

### 5.3 建议新增字段

| DocType | 字段 | 用途 |
|---|---|---|
| BOM | `custom_version_source`（Link BOM） | 来源版本；允许来源仍为已提交，与标准 `amended_from` 的取消语义分开 |
| BOM | `custom_version_no`（Int，只读） | 同一业务 BOM 的可见版本号 |
| BOM | `custom_version_status`（Select） | 草稿/当前/历史，作为展示辅助，真实状态仍以标准字段为准 |
| BOM | `custom_bom_versions`（已存在） | 展示版本记录，不存业务结果 |

推荐不要滥用标准 `amended_from`：Frappe 标准校验要求其来源必须已取消。新方案要求旧版本继续已提交有效，因此新增 `custom_version_source` 表达版本来源，标准 `amended_from` 继续服务于传统取消修订。

## 6. 服务端接口设计

### 6.1 新增接口

```python
create_update_version(source_bom) -> 新 BOM 草稿
activate_bom_version(bom) -> 提交并切换默认版本
get_bom_version_diff(source_bom, target_bom) -> 组件/工序差异
switch_draft_work_order_bom(work_order, target_bom) -> 重算草稿工单
```

接口要求：

- 检查 BOM 读取/创建/提交权限，禁止 `ignore_permissions` 创建业务单据。
- 来源必须是已提交、有效 BOM；同一来源最多存在一个未取消的更新草稿。
- 新旧版本的物料、公司、业务 BOM 编码一致。
- 服务端复制所有标准 BOM 字段、组件、工序、废料及适用工程资料。
- 清空单据名、提交状态、默认状态和运行时计算字段；设置版本来源及版本号。
- 使用行锁或唯一约束防止两人同时生成相同版本号、同时成为默认版本。
- 提交失败时整个默认切换事务回滚，旧默认不受影响。

### 6.2 不改老接口

- 不修改标准 `BOM.insert/save/submit/cancel` 的调用签名。
- 不修改标准 `make_work_order`、`make_stock_entry` 参数。
- 不修改现有 `get_exploded_structure(bom)`、`get_bom_versions(bom)` 参数。
- 旧的“取消 → 修订”仍使用标准 `amended_from`。
- 新入口只调用新增接口，标准列表、导入和 API 客户端继续可用。

## 7. 调用链路

### 7.1 创建并启用新版本

```text
已提交 BOM V1 页面点击“更新版本”
  → bom.js 调用 create_update_version(V1)
  → 服务端校验权限、来源状态、是否已有更新草稿
  → 锁定同一物料/业务 BOM 版本链
  → copy_doc(V1)，清理单据状态及默认标志
  → 设置 custom_version_source=V1、version_no=2
  → 标准 BOM.insert()
  → 返回并打开 V2 草稿
  → 用户修改组件/数量/子 BOM/工序
  → 保存草稿：标准 BOM.save()，V1 仍默认
  → 点击“保存并启用”
  → activate_bom_version(V2)
      → 标准 BOM 校验（循环、UOM、组件、成本等）
      → 锁定版本链并再次确认 V1/V2
      → 标准 V2.submit()
      → 标准默认 BOM 管理或限定补充逻辑
      → V2 is_default=1，其他版本 is_default=0
  → 刷新版本记录和物料默认 BOM
```

### 7.2 新旧工单选取 BOM

```text
修改前已创建 WO-001
  → 已保存 bom_no=V1
  → 后续领料/生产继续读取 V1

V2 启用后创建 WO-002
  → 标准获取物料当前默认 BOM
  → 保存 bom_no=V2
  → 后续领料/生产固定读取 V2
```

### 7.3 草稿工单人工切换

```text
草稿 WO-001 点击“切换到最新 BOM”
  → 查询当前默认 V2
  → 展示 V1→V2 的组件/工序差异
  → 用户确认
  → 服务端验证 docstatus=0 且没有库存/作业记录
  → 设置 bom_no=V2
  → 调用标准 get_items_and_operations_from_bom()
  → 保存新的需求和工序
```

## 8. 关联模块和相应修改

| 关联模块 | 影响 | 相应处理 |
|---|---|---|
| 生产工单 | 新旧工单必须固定不同版本 | 工单保存 `bom_no`；仅草稿显式确认后可切换 |
| 分层 BOM/子工单 | 父 BOM 必须固定子 BOM 具体版本 | 复制时保留旧引用；用户在 V2 中手工选择新子版本 |
| 生产计划 | 新计划使用当前默认版本，历史计划不静默变化 | 生成工单时固化版本；计划重新取料必须提示差异 |
| 生产领料/入库 | 按工单固化 BOM 生成物料 | 不修改标准库存接口，不动态查“最新 BOM”替换工单版本 |
| 成本估算 | 各版本成本不同 | V2 重新计算；V1 历史成本不回写 |
| 采购/自产缺料 | 自制半成品必须使用父 BOM 中选择的具体子 BOM | 补料弹窗显示版本；创建子工单写入该 `bom_no` |
| 物料默认 BOM | V2 启用后新业务取 V2 | 事务内唯一默认；草稿或失败不切换 |
| 质量/工程图纸 | BOM 版本可能对应不同图纸 | 复制原引用，V2 可更新；历史质检仍追溯原工单和 BOM |
| 销售成本/库存估值 | 不同版本产生不同实际成本 | 仍按实际库存出入库计价，不按最新 BOM 回算历史成本 |
| 报表/导出 | 需要看出工单使用哪个版本 | 显示 BOM 单号、版本号、是否历史/默认 |
| 权限和审计 | 更新版本相当于创建并提交新业务单据 | 分别校验 BOM create/submit 权限，记录创建人和版本来源 |
| MES/外部集成 | 集成可能缓存 BOM 编码 | 保留业务 BOM 编码，同时发送具体 BOM 单号/版本；新增字段不能替换旧字段 |

## 9. 并发、取消和异常规则

- 两人同时点“更新版本”：复用已有草稿或阻止第二次创建，不能产生两个 V2。
- 两个版本同时提交：锁定版本链，只允许一个成为默认，另一张退回提示重新确认。
- V2 草稿删除：不影响 V1；删除前确认没有工单引用。
- V2 已提交后需要再改：从 V2 创建 V3，不能直接编辑 V2。
- V2 提交后不建议取消 V1；V1 可能仍被历史工单引用。
- V2 取消：如果没有业务依赖，可恢复最近一个有效历史版本为默认；存在依赖时遵循标准取消限制。
- 父 BOM A-V1 引用 B-V1；B-V2 启用不会自动修改 A-V1。A 要使用 B-V2，必须创建 A-V2 并明确替换。
- 草稿工单切换版本后若用户未保存，刷新恢复原版本；服务端保存时再次校验。

## 10. 实际业务流

```text
工程人员打开已提交 A-BOM V1
            ↓
点击“更新版本”
            ↓
系统创建 A-BOM V2 草稿，V1 继续默认且可用于生产
            ↓
在 V2 组件表中新增、删除或修改组件
            ↓
需要升级子 BOM 时，明确把 B-V1 改为 B-V2
            ↓
保存草稿、审核差异、重新成本估算
            ↓
点击“保存并启用”
            ↓
系统提交 V2并设为默认，V1改为历史非默认
            ↓
       ┌────┴─────────────────┐
       │                      │
修改前已创建工单          修改后新建工单
继续固定使用 V1          默认使用 V2
       │                      │
按 V1 领料、生产、成本    按 V2 领料、生产、成本
       │                      │
       └──────────┬───────────┘
                  ↓
       报表按各工单实际 BOM 版本追溯
```

## 11. 验收场景

1. V1 被工单引用时仍能创建 V2 草稿，不取消或修改 V1。
2. 修改 V2 组件并保存草稿后，新建工单仍使用 V1。
3. V2 提交启用后，新建工单使用 V2；原工单继续使用 V1。
4. V1/V2 的组件、成本和展开结构分别可查，互不覆盖。
5. 父 BOM 不会因子 BOM 更新而自动改变引用版本。
6. 同时创建或提交版本不会产生重复版本号或多个默认 BOM。
7. 没有创建权限不能更新版本；没有提交权限只能保存草稿。
8. 草稿工单切换 V2 后物料、工序重新计算；已提交或已有库存记录的工单被阻止。
9. 分层补料创建子工单时使用父 BOM 行固定的子 BOM 版本。
10. 旧 API、标准取消修订、导入、成本估算和非版本 BOM 流程继续正常。
11. MES、财务、质量、项目及库存钩子不会被覆盖或重复触发。

## 12. 发布和回退

先对测试物料启用“更新版本”入口，创建 V2 并完成工单前后对照验收。旧的取消修订入口暂不删除。

回退代码时，已经创建的 V2 仍是标准 BOM，不删除数据；关闭新按钮和新接口即可。若要业务回退到 V1，应创建 V3 恢复 V1 的组件结构，或在无业务依赖并经审批后切换默认版本，不能覆盖或删除已被工单引用的 V2。

## 13. 与当前实现的差异

当前已实现的是标准“先取消，再修订”，并增加了版本记录和校验。本方案要求旧版本继续已提交有效，所以实施时需要：

- 新增 `custom_version_source`，不用 `amended_from` 表达并行有效版本来源。
- 将主要入口改为已提交 BOM 上的“更新版本”。
- 放宽“同物料只能有一个未取消 BOM”的当前定制限制，但仍限制只能通过版本入口创建。
- 保留同一时刻唯一默认 BOM，不限制存在多个已提交有效历史版本。
- 调整当前“修订来源必须已取消”的校验，使其只约束标准修订路径。

本方案核心流程已经实施；未完成的验证和设计差异以实施记录为准。
