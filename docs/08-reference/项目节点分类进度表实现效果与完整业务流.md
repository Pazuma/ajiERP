# 项目节点分类进度表实现效果与完整业务流

实施日期：2026-10-20。字段已同步到 aki_test.localhost 测试站点；其他站点需执行应用升级同步字段。

## 实现效果

项目「流程进度」页默认展示十列总览：进度类别、节点名称、进度情况、负责人、权重、计划完成日期、实际完成日期、绑定订单/单据、状态、备注。

- 新增可选类别：光学参数、结构、光源、物料表、其他。历史空类别显示「未分类」，不强制回填。
- 只合并相邻同类别的单元格，不按类别重新排序。同一类别在流程后面再次出现时单独显示，执行顺序始终以原节点行序为准。
- 进度情况直接读取原有 business_summary；不新增计算、填写或自动更新规则。原字段为空时显示「—」。
- 权重、计划完成日期、实际完成时间、备注均复用现有字段。日期总览显示 YYYY-MM-DD，详细完成时间保留在节点详情中。
- 完成日期由原完成流程写入，不允许手工填写；未记录时显示「—」，不会为历史节点编造完成日期。
- 展示现有多单据绑定，并兼容旧单据单字段绑定。链接按源单据读取权限过滤，点击仍由原单据页面校验权限。
- 备注独立展示、支持换行；人工完成节点的现有流程也会将完成说明写入备注。
- 表头左对齐；进度情况、绑定单据、备注加宽；窄屏横向滚动。
- 已保存项目通过「展开/收起节点编辑」维护原始子表，编辑后保存项目。收起编辑时预览当前本地值；保存前这些变更尚未落库。新建项目仍直接显示节点编辑表。
- 应用进度模板及保存为模板均携带进度类别。

## 完整业务流：当前业务完成模式

### 1. 建立项目并配置节点

管理人员新建项目，维护项目计划和项目负责人。新项目默认使用业务完成模式。在「流程进度」中添加节点，或者先保存项目再应用模板。

每个节点维护类别、名称、有效系统用户负责人、权重、计划日期、完成规则、需要的绑定单据及备注。全部节点权重必须合计 100%，原有计划日期校验继续生效。

类别只用于阅读，不表示前置关系；节点行序才是实际推进顺序。需要业务顺序相邻的同类节点可连续配置，不应为了归类打乱执行顺序。

### 2. 保存并开始项目

保存项目后可查看十列总览。点击「项目开始」将项目阶段置为「进行中」，系统同步一次业务进度。当前业务模式中，未满足条件的节点不会因为开始项目而全部自动进入进行中。

### 3. 负责人处理自己的节点

负责人从「项目工作台」进入本人节点。普通用户只能操作自己的节点；管理员按现有权限处理。前置节点未完成或存在异常时，后续节点不能越过执行。项目未启动、暂停、取消或已结束时不能正常推进。

节点可开始处理；维护对应业务单据后，沿用已有绑定入口将订单、工单或其他单据绑定到具体节点。支持多张单据，总览显示有权查看的链接。权限不足的绑定不会在总览中显示，因而空白绑定列不应作为后台没有绑定的判断依据。

### 4. 系统更新进度情况并判断完成

进度情况完全遵循现有业务评估：

| 绑定类型 | 原有进度情况与完成条件 |
| --- | --- |
| 销售订单 | 显示送货、开票百分比；正常路径须送货和开票均达到 100%。免送货、零金额、关闭等特殊路径需核实。 |
| 采购订单 | 显示合格入库完成行数和质检单数；各行合格净入库达到计划，且无未提交质检、未处理不合格退回、必检证据缺失等异常，才能完成。 |
| 生产工单 | 显示工单状态、生产数量、损耗及入库数量；要求工单完成且生产入库数量与工单产出同步。 |
| 其他业务单据 | 提交后显示待负责人确认；负责人填写完成说明并确认，后台继续检查相关绑定单据已提交。 |
| 手工事项 | 沿用「手工事项」进度情况；负责人填写完成说明并确认完成。 |

业务自动完成需全部绑定单据满足条件、全部前置节点完成且无异常、项目仍在进行中。自动完成会写入实际完成时间和完成来源；人工确认会记录完成时间、完成人、完成来源及备注。

原有关联单据事件、工作台同步及项目「重新同步进度」继续生效；现有每十分钟任务作为补充，前提是站点调度与后台任务正常运行。展示本身不额外修改业务状态。

### 5. 汇总项目进度

原有权重计算持续生效：节点完成后，其权重计入项目实际流程进度。例如权重 10%、15%、25% 的前三个节点完成，则实际流程进度为 50%。不另设类别权重。

计划进度、偏差和健康状态沿用原计算。类别、备注和表格显示调整不会改变计算。

### 6. 异常、退回与重新处理

单据取消、退货或业务条件改变，按原业务评估重新同步。已完成节点的业务条件失效时，会保留完成历史并标记需核实，不应仅凭完成日期认定无异常。

管理员可填写原因退回节点；现有退回流程会将该节点转为进行中并清除当前完成时间、完成人及完成来源。修正业务后重新同步或按允许的方式确认完成。此轮没有改变后续节点回退策略。

### 7. 确认结项

所有节点完成且无业务异常后，由具备相应权限的项目管理人员点击「完成项目」。后端再次刷新和校验条件，通过后项目阶段变为「已完成」，记录结项日志。

## 历史交接模式

历史项目继续保留旧逻辑：绑定单据提交后节点进入「待交接」，开始下一个节点时上一个节点才正式完成并记录完成时间；最后节点待交接且前置节点完成后，通过「完成项目」完成最后交接。不能将当前业务模式的自动履约规则套用于旧项目。

本轮只改节点分类及总览，不实施旧项目模式迁移，也不修改已有财务权限策略。
