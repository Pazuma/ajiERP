# 销售订单税费与预计记账预览方案

## 1. 背景

销售订单当前的“税”和“销售税费”区域以 ERPNext 原生税费配置表为中心。财务人员需要在多个区域之间比对净额、税额、含税合计、结算模式和税费科目，无法快速判断：

1. 本订单采用的税务口径及应收确认时点；
2. 未税金额、销项税额和含税总额是否勾稽；
3. 后续开票或结算时预计会形成怎样的会计分录；
4. 当前订单是否已经形成正式凭证，或仅处于业务预览阶段。

本方案只新增一个面向财务审核的**只读预览分支**。销售订单仍是业务单据，不在订单保存、刷新或预览时创建会计凭证、总账分录、销售发票或结算单。

## 2. 目标与边界

### 2.1 目标

在销售订单中新增“财务摘要”和“预计记账预览”，让财务无需跳转即可完成金额勾稽、税费口径审核和应收确认时点判断。

| 区域 | 展示内容 | 目的 |
|---|---|---|
| 财务摘要 | 未税销售额、销项税额、其他销售费用、含税订单额、结算模式、开票/凭证状态 | 一眼确认订单口径 |
| 税费明细优化 | 税种/项目、税率、计税基数、税额、对应科目、凭证方向 | 方便逐行复核税费 |
| 预计记账预览 | 预计发生时点、借贷科目、借方金额、贷方金额、说明 | 判断后续记账方式 |
| 凭证关联状态 | 未生成原因，或已生成销售发票/中国会计凭证入口 | 区分预计与正式入账 |

### 2.2 非目标

- 不改写 `Sales Taxes and Charges` 的计算、税率、科目或税费模板；
- 不修改 ERPNext 的 Sales Order、Sales Invoice、Delivery Note 控制器和总账接口；
- 不新增“订单提交即入账”行为；
- 不替换现有的中国财务销售结算、自动开票、凭证生成和税务对账链路；
- 不修改已有销售订单、发票、凭证和结算单数据；
- 不调整老的 API 入参、Excel 导入字段或外部下单接口。

## 3. 页面方案

### 3.1 位置与层级

在原生“销售税费”表格及其金额合计之后、销售团队之前新增只读的“财务审核”区块；保留原“税”和“销售税费”表格作为配置与明细来源。这样财务完成原始税费录入和金额核对后，紧接着即可看到财务口径。财务审核区块只读取当前单据的已计算数据，不能在此处修改税率或金额。

```text
明细与订单合计
  -> 税（保留原字段：税费模板、税种、免税等）
  -> 销售税费（保留原子表，用于维护税费规则）
  -> 原生税费与订单金额合计
  -> 财务审核（新增，只读）
       -> 财务摘要
       -> 税费明细（财务视角）
       -> 预计记账预览
       -> 开票/凭证关联状态
  -> 销售团队
```

### 3.2 财务摘要

固定以以下等式展示，并按单据币种格式化金额：

```text
未税销售额 + 销项税额 + 其他销售费用 = 含税订单额
```

字段映射：

| 页面标签 | 来源字段/规则 |
|---|---|
| 未税销售额 | `Sales Order.net_total` |
| 销项税额 | `Sales Order.total_taxes_and_charges` 中税费行的合计；首期以订单总税费展示，后续可按税种拆分 |
| 其他销售费用 | 税费行中不属于税项且影响总额的金额；首期没有可靠分类时显示为 `0` 并标注“待科目分类” |
| 含税订单额 | `Sales Order.grand_total` |
| 结算模式 | `custom_china_settlement_mode` |
| 已结算金额 | `custom_china_settled_amount`，仅“对账结算后确认应收”模式显示 |
| 开票/凭证状态 | 通过已提交 Sales Invoice 和 China Accounting Voucher 的关联结果计算 |

金额勾稽失败时，显示“订单金额与税费明细不一致”，并提供差额；不阻断保存或提交，避免预览功能改变现有单据校验边界。

### 3.3 税费明细（财务视角）

新增只读表格，不改变原 `taxes` 子表列：

| 税种/项目 | 税率 | 计税基数 | 税额 | 对应科目 | 凭证方向 |
|---|---:|---:|---:|---|---|
| 增值税销项税额 | 13% | 10,000.00 | 1,300.00 | 应交税费-应交增值税-销项税额 | 贷方 |

数据从 `Sales Taxes and Charges` 行派生：名称使用税费行描述，税率使用 `rate`，计税基数优先使用 `tax_amount_after_discount_amount` 的可解释来源，科目使用 `account_head`。首期不尝试把所有 ERPNext 税费类型自动归类为“税”或“费用”：无法可靠识别的行显示为“其他销售费用/待确认”，避免错误的财务判断。

### 3.4 预计记账预览

预计记账是判断与审核信息，不是正式凭证。

| 结算模式 | 显示规则 |
|---|---|
| `直接确认应收` | 显示“在销售发票或系统配置的应收确认节点提交时预计生成”；预览借应收账款、贷收入科目、贷税费科目 |
| `对账结算后确认应收` | 显示“当前订单不确认应收；完成客户确认和销售结算后预计生成”；展示结算模式与已结算金额 |
| 无法解析科目 | 保留金额，科目显示“待财务配置”，并说明不构成正式凭证 |

科目预览只读取 ERPNext 已配置的收入科目、税费 `account_head` 和客户应收科目。多明细行/多收入科目时按科目汇总，借贷金额必须平衡；缺少配置时不伪造科目。

### 3.5 正式状态

页面显式区分以下状态：

- `预计记账`：订单未形成正式凭证；
- `待客户确认/待内部复核`：对账结算模式下，引用当前确认方式；
- `已生成销售发票`：显示已提交发票号和含税金额；
- `已生成中国会计凭证`：显示凭证号并支持跳转；
- `无法关联`：明确说明仅能在后续发票/结算单据中确认，不把订单误标记为已入账。

## 4. 调用链路

```text
销售订单加载、税费模板/明细/客户/结算模式变更
  -> ERPNext 原有税费计算与金额更新
  -> 新增 sales_order_finance_preview.js 监听 refresh 与 after_calculate_taxes_and_totals
  -> 调用受权限保护的 get_sales_order_finance_preview
  -> 服务端只读读取 Sales Order、Sales Taxes and Charges、已提交 Sales Invoice、China Accounting Voucher
  -> 构建财务摘要、税费明细、预计记账行、正式状态
  -> 返回 JSON
  -> 前端渲染独立的只读“财务审核”区块

销售订单提交/出库/开票/结算
  -> 沿用现有 Sales Order -> Delivery Note -> Sales Invoice / China Sales Settlement 链路
  -> china_finance.services.voucher.on_gl_source_submit 继续在既有正式来源提交后生成凭证快照
  -> 用户重新打开订单时，预览接口只读刷新关联状态
```

预览接口不得调用 `insert`、`save`、`db_set`、`make_gl_entries`、`create_voucher_from_source` 或自动开票方法。

## 5. 建议代码与文件改动

以下为实施阶段的最小改动清单；本次仅沉淀方案，尚未创建这些代码文件。

| 文件 | 改动类型 | 责任 |

| `china_finance/china_finance/services/sales_order_finance_preview.py` | 新增 | 只读汇总、税费行转换、预计记账与关联状态查询；暴露白名单方法 `get_sales_order_finance_preview(sales_order)` |
| `china_finance/china_finance/public/js/sales_order_finance_preview.js` | 新增 | 在 Sales Order 表单渲染独立只读区块，监听金额/税费重算并刷新预览 |

| `china_finance/china_finance/hooks.py` | 增量修改 | 将 Sales Order 的 `doctype_js` 从单字符串改为数组，保留 `sales_order_settlement.js` 并追加新脚本；追加 CSS 资源 |

首期不新增 Sales Order Custom Field，也不改 `china_finance/setup/install.py` 中已有的结算字段定义。前端容器由脚本动态插入，避免迁移时变更全部站点的表单元数据。若后续需要统一表单位置，再单独增加可迁移的 Section Break Property Setter。

## 7. 受影响模块

| 模块 | 影响 |
|---|---|
| 销售订单 | 增加只读财务审核视图，不改变录入字段、保存或提交逻辑 |
| 销售税费模板 | 作为预览数据来源，功能和权限不变 |
| 销售出库 | 不变；预览展示的结算模式与出库校验保持一致 |
| 销售结算 | 不变；对账模式订单只展示已结算金额和待确认状态 |
| 销售发票 | 不变；已提交发票供订单预览显示关联状态 |
| 中国会计凭证 | 不变；仅提供已存在凭证的查询与跳转 |
| Excel/CRM/API 下单 | 不变；新增预览不要求传参，也不写入字段 |
| 权限 | 新接口执行 Sales Order `read` 权限校验；金额和税费仍按现有单据权限可见 |

## 8. 预期效果

1. 财务打开销售订单后可在一个区块内确认未税、税额、含税金额和结算模式，不再横跨原税费表和订单底部汇总查找。
2. 税费行使用“计税基数、税额、科目、借贷方向”表达，减少对 ERPNext 税费类型字段的理解成本。
3. 财务能明确判断订单是“预计记账”还是“已形成正式发票/凭证”，避免订单金额被误认为已入账。
4. 对账结算订单会清楚提示应收确认前置条件，减少提前挂应收或销项税的风险。
5. 所有新增功能为读取与展示分支，不影响已提交单据、税费计算、会计凭证和外部接口。

## 9. 验收场景

1. 新建含税订单：显示未税、税额、含税总额，并满足金额勾稽。
2. 13% 税费模板：税费明细显示税率、基数、税额和 `account_head`，预计记账税费行为贷方。
3. 直接确认应收：显示预计应收确认提示，不创建 Sales Invoice 或 China Accounting Voucher。
4. 对账结算后确认应收：显示待确认说明和已结算金额，不显示“订单已入账”。
5. 已关联已提交销售发票：显示发票号和状态；已关联凭证时显示凭证号。
6. 无税费、免税、多个收入科目或缺少科目配置：页面不报错，不伪造科目，并给出明确待配置提示。
7. 通过 Excel、CRM/API 创建的订单：不增加必填参数；打开订单后可正常生成预览。
8. 无 Sales Order 读取权限的用户：不能调用预览接口读取订单金额或凭证关联信息。

## 10. 实施顺序

1. 先实现服务端纯函数与单元测试，确认金额、税费、结算模式和关联状态的口径。
2. 新增前端只读渲染和样式，优先在草稿、已提交、直接结算、对账结算四种订单中验证。
3. 在测试站点与财务确认“其他销售费用”的分类和预计科目展示口径。
4. 仅在财务确认预览与正式凭证口径一致后再部署生产。
5. 后续如需要快捷“申请税费调整”或从预览跳转至结算/发票，另立需求；不得在本次只读预览中加入写操作。
