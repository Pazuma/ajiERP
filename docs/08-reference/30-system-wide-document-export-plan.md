# 系统业务单据导出能力建设方案

状态：仅方案，未修改业务代码或站点数据。

## 1. 目标与范围

系统当前部分业务表单已有 Excel 导入能力，但缺少与之对应的受控导出能力。新增独立的“导出”分支，覆盖库存、项目、销售、资产、生产、采购和基础资料等模块。导出目录按单据类型分批实施，首批优先覆盖生产领料、库存盘点、工单、采购、库存出入记录，随后接入其他业务和主数据。

导出支持三种入口：列表页勾选后导出所选记录、按当前筛选条件导出全部结果，以及单据详情页导出当前记录。首期固定字段白名单，不开放任意 SQL 或任意字段导出，避免敏感字段、权限绕过和不同用户导出格式不一致。

## 2. 目标效果

1. 用户可在所有纳入目录的业务列表中勾选一张或多张记录，点击“导出已选数据”，下载一份结构稳定的 Excel。
2. 导出范围严格等于用户勾选的单据；分页、筛选和列表排序不会额外带入未选记录。
3. 每张单据的物料明细按行展开，采购、领料、盘点等一张单据包含多条物料时不会被压缩或丢失。
4. Excel 包含“数据明细”和“导出说明”工作表，记录导出人、时间、单据数量、成功数量、跳过记录及原因，便于审计和对外核对。
5. 导出不修改单据、不提交单据、不创建库存或财务凭证；与现有导入接口完全隔离。
6. 同一用户对同一批单据重复导出时，字段口径和行结构保持一致，便于供应商、客户和仓库留存对账版本。
7. 无权限、已取消或状态不符合要求的记录不会被越权导出；部分合规记录仍可正常导出并在说明页列出跳过原因。
8. 用户可以先在列表设置客户、日期、状态、物料、仓库、公司等筛选，再选择“导出筛选结果”；文件导出该筛选范围内的完整结果集，不受当前页面显示条数或分页限制。

第二批中的“客户表”与“供应商表”属于主数据导出，不展开交易明细；“销售订单、送货单、BOM、工单、价目表”属于头表加明细行导出；库存出入记录仍按报表筛选导出。

“库存出入记录”不直接导出任意数据库字段。若现有界面是报表而不是 DocType 列表，应复用该报表的筛选和权限服务，在其上增加导出响应。

## 4. 交互设计

### 4.1 列表页

在各目标列表的“操作”菜单增加“导出已选数据”和“导出筛选结果”。前者未勾选记录时提示先选择；后者读取当前列表实际生效的筛选条件，例如客户、日期、状态、物料、仓库和公司。点击后弹出确认框，显示单据数量或筛选摘要和预计导出内容。确认后通过 POST 下载二进制文件，不把文件内容放入普通 JSON RPC。

“导出筛选结果”不读取浏览器当前页的可见行，也不以当前页面的 20/100/500 条分页数量作为范围。前端只传递允许的筛选条件，服务端根据相同筛选条件、当前用户权限和公司范围重新查询完整结果集后生成文件。

### 4.2 详情页

在目标单据的“更多/操作”菜单增加“导出当前单据明细”。当前单据无权限或状态不符合时由服务端拒绝。详情页入口与列表批量入口共用同一个服务端配置，不复制查询逻辑。

### 4.3 Excel 结构

每种业务固定一个中文工作表名称和字段顺序；金额、数量、日期沿用单据原始精度和站点日期格式，不重新计算税费、汇率或库存成本。文件名包含业务名称与时间戳，例如 `采购订单-对账明细-20260903153000.xlsx`。

## 5. 安全与边界

服务端只接受白名单中的 `document_type`、单据名称数组和已定义的筛选字段；名称去重并限制单次最多 500 张。筛选导出限制最大导出行数、最大日期跨度和必要的公司范围，超过限制时要求缩小条件。每张单据调用现有 `read` 权限校验，库存流水则复用原报表权限和公司隔离。客户端不得传入 SQL、字段名、表名或任意过滤表达式。

导出默认不包含密码、权限配置、内部成本备注、删除标记等敏感字段。对于跨公司的选择、无权限记录、取消记录和空明细，说明页记录明确原因；全部被跳过时返回可读错误，不生成空文件。

## 6. 调用链路

```text
列表勾选 / 当前筛选条件 / 表单当前单据
  -> 对应 list/form JS 收集 document_type、name(s) 或受控 filters
  -> 新增导出接口 POST
  -> 服务端白名单、数量或行数、筛选字段、权限、公司和状态校验
  -> 按配置查询单据头、明细或库存流水
  -> 统一组装数据明细与导出说明
  -> 生成 XLSX binary response
  -> 浏览器下载
```

整个链路不进入保存、提交、取消、库存更新、应收应付或会计凭证流程。

## 8. 新增接口设计

建议新增统一下载接口，内部只允许固定配置分支：

```python
@frappe.whitelist()
def download_document_export(document_type: str, document_names: str | None = None, filters: str | None = None):
    """Download selected records or a whitelisted filtered result as XLSX."""
```

`filters` 适用于支持筛选导出的列表和 `Stock Ledger Entry` 报表，但必须按 DocType 配置解析为允许的日期、公司、客户、供应商、状态、仓库、物料等条件。服务端忽略未声明字段，拒绝任意 SQL 条件；单据名称与筛选条件不可同时为空。已有采购订单对账接口保持兼容，新统一接口可逐步复用其配置，不删除旧入口。

## 9. 受影响模块

采购、生产、库存、仓库盘点、库存报表、项目、销售、资产、基础资料、权限与导出文件服务会增加只读入口；导入、库存事务、财务、税务、审批和单据状态模块不受业务行为影响。前端只增加操作菜单，列表字段、筛选器和分页逻辑保持不变。

## 10. 验收场景

1. 分别勾选两张生产领料单、工单、采购单、销售订单和送货单，导出行数与各单据明细行总数一致。
2. 一张盘点单包含多个物料和仓库时，导出保持“物料 + 仓库”逐行结构，差异原因原样保留。
3. 库存出入记录设置日期、仓库、物料筛选后导出，文件与页面结果集一致。
4. 销售订单按客户、日期和交货状态筛选后，导出文件包含所有符合条件的订单及其明细，不受当前列表分页条数限制。
5. 未勾选记录、超过 500 张、筛选结果超过行数上限、无权限记录、取消记录均按规则提示或写入说明页。
6. 导出操作前后单据 `modified`、库存余额、会计凭证数量不发生变化。
7. 成品状态、样品借出、物料、项目、客户、价目表、固定资产、BOM、工时、供应商等主数据导出字段与页面内容一致。
8. 导入功能、原生“导出”菜单和已有采购对账导出仍可正常使用。

## 11. 实施顺序

1. 先抽取统一服务和测试，不改现有接口。
2. 先接入生产领料、盘点和工单三个内部使用场景。
3. 接入采购订单/采购收货，并复用现有采购对账字段配置。
4. 接入成品状态、样品借出、物料、项目、客户、销售订单、送货单和价目表。
5. 接入固定资产、BOM、工时、供应商及其他基础资料。
6. 最后接入库存出入记录报表，验证筛选与权限一致性。
7. 在 `aki_test.localhost` 完成迁移、构建、缓存刷新和多角色验收后，再扩展其他新增 DocType。

## 12. 生产工单领料单 PDF 模板

生产领料除通用 Excel 外，新增正式的“产品组装领料单 PDF”分支。生产人员在生产工单列表勾选工单后，系统直接按照固定版式生成可打印、可签字的领料单，不需要再人工制作表格。该分支只读取生产工单、BOM 和库存领料数据，不自动提交领料、不扣减库存。

### 12.1 入口和生成规则

- `Work Order` 列表“操作”菜单新增 `生成产品组装领料单 PDF`。
- 支持勾选一张或多张工单；每张工单独立生成一份领料单。勾选多张时生成 ZIP，避免不同工单物料混在同一张签字单中。
- 工单详情页增加同名入口，只生成当前工单。
- 仅导出当前用户有读取权限的工单；取消工单不生成。
- PDF 生成过程不改变工单、库存调拨、领料数量或欠料数量。

### 12.2 预设版式

- 纸张优先采用 A4 横向；物料行较少时保持单页，超过一页自动分页。
- 顶部居中显示 `阿基视觉产品组装领料单`，右上角显示 `AKI VISION / Make it Easy` Logo。
- Logo 源文件为 `/home/cst/frappe_docker/df8baa79f9b81863358a5464f8673abf.png`（`1246 × 616`、RGBA PNG）；实施时复制到 `client_akivision/public/images/aki_vision_logo.png` 后由模板引用，并按原比例等比缩放。
- 左侧工单信息区固定显示：单号、项目、数量/套、日期、型号、备注。
- 右侧明细表固定显示：图纸号、物料名称、用量、领用数、欠料、备注。
- 底部显示送料人、收料人签字栏，以及固定或可配置的领料提示语。
- 多页时重复标题、Logo、工单基础信息和明细表头；签字栏及提示语只出现在最后一页。

### 12.3 数据映射

| PDF 字段 | 建议来源 |
|---|---|
| 单号 | `Work Order.name` |
| 项目 | `Work Order.project`；无项目时留空 |
| 数量/套 | `Work Order.qty` |
| 日期 | `Work Order.planned_start_date` 或实际领料日期 |
| 型号 | 工单生产物料的型号/规格自定义字段；没有时使用 `production_item` |
| 备注 | 工单备注或生产说明 |
| 图纸号 | `Work Order Item`/`Item` 的工程图纸编号或版本字段 |
| 物料名称 | 工单所需物料的 `item_name` |
| 用量 | BOM 单套用量，即 `required_qty / Work Order.qty`；除数为零时禁止生成 |
| 领用数 | 本次选择的领料数量；若从工单直接生成且未指定批次，默认显示累计已领数量并标注口径 |
| 欠料 | `max(需求数量 - 累计已领数量, 0)` |
| 明细备注 | 物料/BOM 明细备注、仓位或工艺说明 |

“领用数”必须在模板中明确是“本次领用”还是“累计已领”。首期从工单直接生成时建议使用累计已领；若以后从具体生产领料 `Stock Entry` 生成，则使用该领料单的实际数量。

### 12.4 欠料高亮

参考目标图，欠料物料整行使用黄色背景突出显示，但不得仅通过颜色表达：`欠料` 列必须同时显示明确数量。欠料为零时显示 `0` 或留空由业务统一选择；建议显示 `0`，便于纸质单据核查。

### 12.5 调用链路

```text
生产工单列表勾选 / 工单详情
  -> 前端收集 Work Order name(s)
  -> 服务端逐单校验读取权限和状态
  -> 读取 Work Order + required_items + BOM/Item 图纸信息
  -> 汇总已提交生产领料 Stock Entry 的累计领用数量
  -> 计算单套用量、领用数和欠料
  -> 填充固定 HTML/CSS 模板并生成 A4 横向 PDF
  -> 单张直接下载；多张打包 ZIP 下载
```

## 13. 采购申请单 PDF 模板

采购人员在 `Material Request`（采购申请）列表勾选一张或多张采购申请后，点击 `生成采购申请单 PDF`，系统按固定版式自动填充并生成可打印审批的采购申请单。该功能仅将已有采购申请数据格式化为 PDF，不自动创建询价单、采购订单、采购收货或付款记录。

### 13.1 入口和生成规则

- 采购申请列表“操作”菜单新增 `生成采购申请单 PDF`；详情页增加同名入口。
- 一张采购申请对应一份 PDF。一次勾选多张申请时生成 ZIP，每份 PDF 以采购申请单号命名，不合并不同申请的物料和审批区。
- 只允许导出当前用户有读取权限的采购申请；取消申请不生成。
- 申请类型优先限制为 `Purchase`。其他申请类型可在标题和模板中明确标识后再纳入，避免将领料、调拨申请误印为采购申请单。
- PDF 生成不修改申请状态、审批流、物料数量、采购订单或库存。

### 13.2 预设版式

- 纸张：A4 纵向；右上角使用已确认的 `AKI VISION / Make it Easy` Logo。
- 标题：居中大字 `采购申请单`；标题下显示公司法定名称“阿基视觉科技（东莞）有限公司”。
- 申请信息：右侧固定显示申请人、申请日期、备注；申请人从申请单 `owner`/员工映射读取，日期取 `transaction_date`/创建日期。
- 明细表字段：部门、项目、单价、数量、总价、单位、供应商、备注。表格自动填充物料行；剩余空行仅用于纸质补写，不作为系统数据。
- 底部：合计金额、采购理由、批准人、批准日期以及表格编号/版本。采购理由来自申请单目的或备注；批准栏为打印后手写/盖章区，不自动伪造审批签名。
- 多页时重复公司抬头、标题、申请基本信息与明细表头；采购理由和批准区仅显示在最后一页。

### 13.3 数据映射与金额口径

| PDF 字段 | 建议来源 |
|---|---|
| 申请单号 | `Material Request.name`，可在页首或文件名显示 |
| 公司名称 | `Material Request.company` 对应 `Company.company_name` |
| 申请人 | `owner` 对应员工姓名；无员工映射时显示用户全名 |
| 申请日期 | `transaction_date`，为空时取创建日期 |
| 部门 | 申请单部门字段或申请人所属部门；无值留空 |
| 项目 | 明细 `project`；无值时取申请单项目 |
| 项目/物料 | `Material Request Item.item_name`，必要时拼接规格型号 |
| 单价/总价 | `rate`、`amount`；未维护采购价格时留空或显示 `待询价`，不得填 0 冒充价格 |
| 数量/单位 | `qty`、`uom` 或 `stock_uom` |
| 供应商 | 明细供应商或申请单建议供应商；未指定留空 |
| 备注 | 明细 `description`/备注字段 |
| 合计 | 仅合计有效金额行；存在待询价行时附注“含待询价项目，最终金额以采购订单为准” |
| 采购理由 | `purpose`、`remarks` 或自定义采购理由字段 |

### 13.4 调用链路

```text
采购申请列表勾选 / 申请详情
  -> 前端收集 Material Request name(s)
  -> 服务端逐单校验读取权限、申请类型和状态
  -> 读取申请头、物料明细、员工/部门、项目和建议供应商
  -> 按已有单价/金额计算合计并标记待询价行
  -> 填充采购申请单 HTML/CSS 模板，生成 A4 纵向 PDF
  -> 单张下载 PDF；多张打包 ZIP 下载
```
