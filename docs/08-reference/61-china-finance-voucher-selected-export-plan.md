# 凭证汇总表按选择凭证导出优化方案

> 状态：方案沉淀，暂不修改业务代码
>
> 页面：`/app/china-voucher-summary`
>
> 目标：在现有凭证汇总表的基础上，增加类似系统 List View 的逐行选择和批量导出能力；用户可以导出指定凭证，而不是只能导出整个查询结果。

## 1. 背景与问题

当前凭证汇总表支持按公司、期间和关键词查询；页面展示 `voucher_rows` 凭证列表，但“下载”在浏览器内将 `rows` 科目汇总生成整表 CSV，并非逐张凭证文件。实际业务中需要导出指定凭证，现有文件无法直接满足。

本次采用小增量方案：保留现有页面、筛选参数、汇总查询和旧导出行为；新增“选择凭证后导出”的分支。选择功能作用于凭证行，不改变凭证数据、凭证快照或会计核算逻辑。

## 2. 预期交互

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 凭证汇总表                                      [刷新] [更多] [操作 ▾]        │
├──────────────────────────────────────────────────────────────────────────────┤
│ 账套：阿基视觉（东莞）  期间：2026-09 至 2026-09  [搜索凭证号/摘要/科目]     │
│                                                                              │
│ 已选择 2 张凭证        [导出所选凭证]  [取消选择]                            │
├────┬──────────┬──────────────┬──────────┬──────────────┬──────────┬──────────┤
│ □  │ 凭证编号 │ 来源单据     │ 日期     │ 摘要         │ 借方金额 │ 贷方金额 │
├────┼──────────┼──────────────┼──────────┼──────────────┼──────────┼──────────┤
│ ☑  │ CNV-0001 │ ACC-JV-00029 │ 2026-09-07 │ CF-CONNECT  │ 100.00   │ 100.00   │
│ □  │ CNV-0002 │ MAT-DN-00045 │ 2026-09-08 │             │ 2.25     │ 2.25     │
│ ☑  │ CNV-0003 │ ACC-PCV-00001 │ 2026-09-08 │ 1           │ 70,832.10│ 70,832.10│
└────┴──────────┴──────────────┴──────────┴──────────────┴──────────┴──────────┘
```

交互规则：

- 表头复选框选择/取消当前页；每行复选框选择单张凭证。
- 顶部显示“已选择 N 张凭证”；没有选择时“导出所选凭证”置灰。
- 切换公司、期间、关键词或刷新后清空选择，避免把旧查询的凭证误带入新查询。
- 当前页面没有分页，表头全选选择本次查询返回的凭证行；未来增加分页时再设计跨页选择和筛选结果全选。
- 导出前显示数量和格式确认；导出成功后保留当前筛选结果，清空已选状态并提示结果。
- 旧“下载”继续保留原有科目汇总 CSV 语义，不因是否勾选而改变。

## 3. 功能边界

本次包含：

- 凭证列表行选择、本次结果全选与取消选择。
- 导出所选凭证的新增入口和数量确认。
- 服务端按凭证 ID 白名单查询并生成导出文件。
- 权限校验、凭证状态校验、空选择和重复 ID 校验。
- 前端、服务端和回归测试所需的小范围关联修改。

本次不包含：

- 不重做凭证汇总的金额统计、科目小计或筛选口径。
- 不修改 `China Accounting Voucher`、`China Accounting Voucher Entry` 或 Journal Entry 数据结构。
- 不修改凭证生成、过账、取消、回收站和电子档案流程。
- 不删除或改变现有整表导出、打印接口。
- 不把汇总行或科目分类小计行当作可导出的凭证；只能选择真实凭证行。

## 5. 建议新增接口

建议新增独立接口，示例：

```text
POST /api/method/china_finance.services.voucher_summary.export_selected_vouchers

{
  "voucher_names": ["CNV-2026-0001", "CNV-2026-0003"],
  "format": "csv",
  "filters": {
    "company": "阿基视觉（东莞）",
    "from_date": "2026-09-01",
    "to_date": "2026-09-30"
  }
}
```

约束：

- `voucher_names` 必须为非空数组，去重后限制最大数量，具体上限在实现评审时确认。
- 服务端按当前用户权限读取凭证，并再次校验公司、日期和 `docstatus`；不能只相信前端传入的 ID。
- 查询使用白名单 ID，不拼接 SQL；未授权、已删除、已取消或不属于当前筛选范围的凭证返回明确错误。
- 新文件列为凭证编号、来源单据、日期、摘要、借方金额、贷方金额；旧科目汇总 CSV 的四列和命名规则保持原样。
- `format` 首期仅支持 `csv`；Excel/PDF 作为后续独立需求。
- 返回标准文件下载响应；旧下载只在浏览器生成 CSV，没有服务端文件生成器可复用。

## 6. 调用链路

```text
用户勾选凭证行
  -> 页面维护 selectedVoucherNames
  -> 更新“已选择 N 张”和导出按钮状态

用户点击“导出所选凭证”
  -> 前端校验非空并弹出数量/格式确认
  -> POST export_selected_vouchers(voucher_names, format, filters)
  -> 服务端校验登录用户、权限、凭证状态、公司/日期范围
  -> 按 voucher_names 查询 China Accounting Voucher
  -> 按现有 voucher_rows 字段口径生成所选凭证明细 CSV
  -> 返回下载文件
  -> 前端下载文件、提示成功、清空选择
```

旧链路保持：

```text
筛选/刷新
  -> get_voucher_summary（不变）
  -> render_metrics / render_table

操作 -> 下载（原科目汇总 CSV）
  -> 页面 export_csv() 使用 latest.rows 在浏览器生成 CSV（不变）
```

## 7. 受影响模块

| 模块 | 影响 | 处理方式 |
|---|---|---|
| 凭证汇总表页面 | 新增选择和批量导出交互 | 局部 JS/CSS 增量修改 |
| 凭证汇总服务 | 新增按 ID 导出路径 | 复用旧格式化逻辑，旧函数不改签名 |
| `China Accounting Voucher` 查询 | 新增白名单读取和权限校验 | 只读，不写入、不改变状态 |
| 权限控制 | 导出前重新校验每张凭证可见性 | 服务端为最终边界，不能依赖前端选择 |
| 凭证生成/过账/取消 | 无业务影响 | 不修改 |
| 查凭证、总账、日账簿、附件中心 | 无接口影响 | 仅做回归验证 |
| 导出文件消费者 | 新增六列凭证明细 CSV，旧四列科目汇总 CSV 不变 | 文件名区分“所选凭证”和“凭证汇总表” |

## 8. 兼容性与失败处理

- 旧接口名称、请求参数和返回结构不变，旧书签、自动化脚本和整表导出不受影响。
- 新接口只增加可选能力，不要求升级数据库表结构，不需要迁移。
- 前端服务调用失败时保留选择状态，允许重试；权限错误显示具体提示，不下载空文件。
- 选择凭证已被取消、删除或权限变化时，服务端返回失败明细，禁止静默导出不完整结果。
- 导出文件生成超时或超过数量上限时，提示用户缩小选择范围；后续可扩展为异步任务，不在首期引入。
- 切换筛选条件后清空前端选择，避免跨查询误操作；服务端仍以传入过滤条件做二次校验。

## 9. 测试与验收

服务端：

- 单张凭证导出成功，导出内容只包含该凭证。
- 多张凭证导出成功，顺序稳定且不重复。
- 空数组、重复 ID、非法格式、超限数量被拒绝。
- 无权限凭证、其他公司凭证、取消凭证不能导出。
- 旧整表导出结果与改造前保持一致。

前端：

- 单行选择、取消选择、表头全选、取消全选状态正确。
- 当前无分页；筛选、刷新后选择清空。
- 未选择时按钮禁用；选择后数量展示准确。
- 导出确认弹窗显示实际数量；成功、失败、重试状态清晰。
- 桌面端和窄屏下复选框、操作条不遮挡表头和金额列。

回归范围：

- 凭证汇总表筛选、汇总金额、科目小计、空状态。
- 查凭证、会计总账、日账簿、凭证附件中心入口和旧导出。
- `China Accounting Voucher` 权限和只读查询性能。

## 10. 预期效果

完成后，用户可以在凭证汇总表中直接勾选目标凭证，看到明确的选择数量，并通过“导出所选凭证”只生成目标凭证文件；不再需要导出整表后再人工拆分。

系统原有按筛选结果导出的能力继续可用，旧接口和下游模块不受影响。新增导出路径以服务端凭证 ID 白名单和权限复核为边界，确保即使前端参数被篡改，也不会导出用户无权访问或不属于当前筛选范围的凭证。

## 11. 实施顺序与回滚

建议实施顺序：

1. 先确认当前旧导出函数、返回格式和权限入口。
2. 在服务层新增白名单导出函数及测试，不接入页面。
3. 在页面增加选择状态和新增导出分支，保留旧按钮逻辑。
4. 补充 CSS 和端到端验收，核对桌面端、窄屏和大数据量场景。
5. 灰度验证后再开放给正式角色。

回滚只需移除前端新增入口和服务端新增 API；不涉及数据库回滚，不影响旧整表导出和凭证业务数据。
