# 销售提成单直属入口与订单弹窗实施记录

日期：2026-10-23。对应方案：90-sales-commission-order-dialog-plan.md。

## 交付效果与业务流

销售模块侧边栏在销售发票之后新增直属“销售提成单”，路由 `/app/sales-commission-orders`。选择公司后，可按订单、客户、业务人员、日期、状态筛选并分页。

销售总监：查询授权范围内的已提交订单，包括未设置提成订单 → 点击订单号或操作按钮 → 选择计提依据和发放条件，填写人员比例 → 刷新试算 → 保存草稿 → 确认提成。已确认记录点击“调整提成”，填写修订原因再保存、确认，保留历史版本。

业务人员：相同入口仅展示本人已确认、待复核或已作废结果；弹窗只读，不返回基数、比例及同事数据。未设置和草稿不展示。财务可只读查询已有记录，回款、发放和追回继续使用原台账。

沿用原有公司和订单权限；毛利基数需要独立授权，不因销售总监角色而绕过。金额由服务端计算。打开弹窗和试算均不创建记录。

## 已知边界

当前列表为保证授权后分页准确，会先读取筛选范围内的全部授权订单，再关联提成并分页；订单量大时可能较慢，后续可增加批量关联查询，保持返回协议不变。未进行移动端、多账号完整浏览器验收。其他站点部署时需要同步两个应用代码并运行相同初始化，不能仅复制前端文件。

## 订单人员及明细补充（2026-10-23）

未设置提成时，列表从订单业务负责人和销售团队去重取得人员，人员筛选使用相同来源；无关联时显示“未关联业务人员”。已有非受限提成继续显示分配人员，受限记录仅显示订单关联人员，不返回受限分配。

详情接口新增 `order_summary` 白名单：订单日期、负责人、币种、未税额、税额、含税总额及本位币金额；商品行仅包含编码、名称、描述、数量、单位、单价、金额。弹窗显示只读概览和可折叠明细表，描述去除 HTML 标签后转义显示。单价和行金额直接取原订单 `rate`、`amount`，规格/描述使用订单行 `description`。没有改动原订单或原提成计算、确认接口。

个人查询仍先校验订单权限和本人提成归属，新增订单信息不含生产成本、毛利、税务科目或同事提成比例。订单金额与计提基数分开展示，外币订单额外显示本位币金额。

补充验证：38项后端测试通过（含继承的旧回归）；覆盖未设置人员及筛选、团队回退、无关联提示、订单金额与明细白名单。浏览器脚本增加只读概览、含税总额和明细表检查。
