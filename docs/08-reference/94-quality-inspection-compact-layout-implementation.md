# 质量检验表单布局优化实施记录

日期：2026-10-23。按确认的文字图调整现有质量检验表单，不修改 ERPNext 核心文件、业务接口或质检状态计算。

## 页面效果

- 基本信息：检验类型、报告日期、状态三列；公司位于下一行。
- 检验来源：参考类型、引用单据、生产工单；引用单据在选择参考类型后显示，已有来源始终保留显示。生产工单在进行中检验或已有工单时显示。
- 检验对象：物料、批次、序列号三列，物料描述单独折叠。
- 检验记录：保留原模板、手工状态及检验结果表，占用完整内容宽度。
- 检验结论：样本/报检数量、合格数量、不合格数量三列。不合格数量大于零或已有原因时显示原因，隐藏不清空数据。
- 检验人员与备注独立保留；编号规则、BOM 和修订来源收纳到其他设置，打印设置默认折叠。
- 宽屏内容最大 1200px，中屏两列，手机单列；长文本默认缩短高度，仍可调整。
- 采购多物料模式继续使用原采购质检明细，隐藏重复的单物料对象和结论区；原采购入库、退货按钮及校验不变。

## 修改文件及调用链

应用根：`development/frappe-bench/apps/client_akivision/client_akivision/`。

- `utils/quality_inspection_layout.py`：幂等创建分组/分列布局字段，通过 Property Setter 重排字段，保留未识别的扩展字段。
- `public/js/quality_inspection_layout.js`：局部样式标识、来源和原因条件显示、默认折叠。
- `public/css/quality_inspection_layout.css`：仅质量检验页面的宽度、间距及响应式样式。
- `hooks.py`：加载新增样式和表单脚本；原采购 schema 后增加布局同步步骤。

部署调用链：原质检字段同步 → 新 ensure_layout → Custom Field/Property Setter → 清理元数据缓存。

页面调用链：原 Quality Inspection 控制器及采购脚本 → 新布局脚本 → 原表单控件显示；保存/提交继续沿用原控制器、生产质检和采购质检校验。

## 后续增量：参考类型改为生产工单

按用户要求，参考类型隐藏 Job Card，新增 Work Order。选择生产工单后切换 In Process，关联 custom_work_order、生产物料，并在报检数量为空时带入工单数量。查询仍保留同公司及非取消限制。
