# 销售订单详细信息布局与业务人员组件方案

## 1. 背景与目标

当前销售订单“详细信息”页签字段排列不够规整。截图红框位置为空，业务人员信息没有独立的选择入口。

本方案只做设计沉淀，暂不修改业务代码和站点数据。目标是：

1. 先按业务录入顺序整理“详细信息”字段；
2. 在红框对应的左侧空位增加“业务人员”选择组件；
3. 业务人员默认从客户负责业务员带出，也允许草稿订单中选择或调整；
4. 尽量复用现有字段、接口和原生销售团队逻辑，不破坏老接口。

## 2. 截图位置与目标排列

红框位于“导入状态”下方、“中国财务结算”区块上方的左侧列。该位置建议放置新的 `业务人员` Link 字段，右侧保持现有的 `交货日期`。

目标顺序如下：

| 左列 | 右列 |
|---|---|
| 公司 | 订单类型 |
| 单据编号模板 | 是否高新收入 |
| 客户名称 | 日期 |
| 客户代码 | 年份 |
| 导入状态 | 月份 |
| **业务人员（新增/移动）** | 交货日期 |
| 中国财务结算区块 | 中国财务结算区块 |

“年份”和“月份”继续由订单日期自动计算并只读展示；“业务人员”放在红框位置，避免插入新的 Tab 或破坏现有区块。

## 3. 字段设计

### 3.1 推荐字段

优先复用已有的 `custom_excel_sales_person`，但将字段从普通文本升级为业务人员选择组件需要谨慎处理。由于现有字段是 `Data` 类型，不能直接改变为 `Link`，否则会影响历史导入数据、数据库列和老接口。

因此推荐新增字段：

| 属性 | 建议值 |
|---|---|
| 字段名 | `custom_sales_person` |
| 标签 | 业务人员 |
| 类型 | Link |
| 关联 DocType | `Sales Person` |
| 插入位置 | `custom_excel_import_status` 之后 |
| 可选范围 | `enabled = 1` 且 `is_group = 0` |
| 草稿可编辑 | 是 |
| 提交后 | 按既有单据权限控制，默认不可修改 |

`custom_excel_sales_person` 作为历史 Excel 原始文本保留，不删除、不改类型、不改变接口含义。新字段是增量分支，供页面选择和新订单逻辑使用。

### 3.2 客户默认来源

客户默认业务人员使用现有字段：

```text
Customer.custom_responsible_sales_person
```

客户选择后，客户端先把该值显示到订单 `custom_sales_person`；服务端保存前再次读取客户字段，保证 Excel、CRM、API 和后台脚本创建订单时结果一致。

## 4. 调用链路

```text
销售订单选择客户
  -> 客户字段变更事件
  -> 新增服务端方法读取 Customer.custom_responsible_sales_person
  -> 返回启用的 Sales Person
  -> 页面设置 Sales Order.custom_sales_person
  -> before_validate 服务端兜底校验/默认
  -> 保存销售订单
  -> 后续销售团队、交付、回款和业绩逻辑按既有链路运行
```

如需同步原生 `sales_team`，建议作为新增分支：当订单销售团队为空且 `custom_sales_person` 有值时，追加一行 `sales_team`，`allocated_percentage=100`。已有手工销售团队行不被无条件覆盖，避免破坏历史和多人分摊订单。

## 5. 代码与文件变更计划

### 5.1 新增/修改文件

| 文件 | 计划改动 |
|---|---|
| `client_akivision/config/excel_form_fields.json` | 新增 Sales Order Link 字段 `custom_sales_person`；配置 `insert_after`、标签和字段校验；不修改旧 `custom_excel_sales_person` |
| `client_akivision/utils/custom_field_schema.py` | 将新字段加入标准字段同步和校验；增加 Sales Order 字段布局同步分支 |
| `client_akivision/utils/sales_order_fields.py` | 新增客户默认业务人员读取、保存前默认和有效性校验函数；保留现有年份/月逻辑 |
| `client_akivision/public/js/sales_order_delivery.js` 或独立 `sales_order_salesperson.js` | 监听客户变化，调用新增方法并刷新业务人员字段；不改旧接口 |
| `client_akivision/hooks.py` | 注册新增客户端脚本和 Sales Order `before_validate` 事件；现有事件改为列表追加，不覆盖旧处理器 |
| `client_akivision/patches/v0_0_1/...` | 可选新增一次性迁移补丁，补齐草稿订单的新字段；先预览数量再写入 |

### 5.2 不改动内容

- 不修改 `custom_excel_sales_person` 类型和接口；
- 不删除原生 `sales_team` 子表；
- 不改变已提交销售订单；
- 不修改销售订单物料查询、价格查询和提交接口；
- 不要求客户端以外的调用方立刻迁移字段名；
- 不覆盖已经存在的手工销售团队分摊数据。

## 6. 数据兼容策略

### 新订单

- 选择客户后，有有效客户负责人则自动填入 `custom_sales_person`；
- 客户没有负责人时允许保存草稿，但提交前给出明确提示；
- 业务员手工选择后，服务端保留该选择，不被客户默认值反复覆盖；
- 只有在订单销售团队为空时，才考虑新增一行原生 `sales_team`。

### 历史订单

- 已提交订单不回写；
- 草稿订单只做只读预览，确认后再按客户负责人补齐；
- 原有 `custom_excel_sales_person` 文本作为历史导入凭证保留；
- 文本名称不能直接模糊匹配 `Sales Person`，需输出待确认清单。

## 7. 受影响模块

| 模块 | 影响 |
|---|---|
| 销售订单表单 | 增加业务人员选择字段，调整详细信息排列 |
| 客户主数据 | 读取现有客户负责人，不新增客户接口 |
| Excel 导入 | 新字段可作为可选映射，旧字段继续兼容 |
| CRM/API 下单 | 保存前服务端自动补齐或校验，不要求调用方立即改造 |
| 销售团队与佣金 | 仅在销售团队为空时按 100% 新增，保留原有分摊和佣金逻辑 |
| 交付、发票、回款 | 不直接改动，通过订单既有业务员归属间接受影响 |
| 业务员业绩报表 | 可继续读取原生 `sales_team`；后续可增加 `custom_sales_person` 缺失预警 |

## 8. 预期效果

1. 详细信息页面按“组织/客户/导入/业务人员/日期”顺序排列，左右列对齐。
2. 红框位置显示“业务人员”下拉/链接选择组件。
3. 选择客户后，客户默认负责人自动显示。
4. 业务员可在草稿订单中明确调整，提交时系统校验有效性。
5. 历史 Excel 字段和老接口继续工作，不因字段类型变更而失败。
6. 订单原生销售团队、佣金和业绩统计逻辑继续使用 ERPNext 标准实现。

## 9. 验收场景

1. 客户 A 有负责人甲：新建订单选择 A，红框位置自动显示甲。
2. 客户 A 无负责人：字段为空，订单可保存草稿，提交时提示维护客户业务人员。
3. 草稿中手工改为乙：保存后仍为乙，不被普通刷新覆盖。
4. 从旧 Excel 导入订单：原 `custom_excel_sales_person` 正常写入，新字段为空时由客户默认逻辑补齐。
5. CRM/API 创建订单：不增加必填参数，服务端仍能按客户带出业务人员。
6. 已有多人销售团队订单：不被新逻辑清空或改写。

## 10. 实施顺序

1. 先增加字段和布局同步，部署后确认页面排列。
2. 增加客户端选择和服务端默认分支。
3. 在测试站点验证客户、Excel、CRM/API 三种入口。
4. 输出历史草稿订单影响清单，确认后再执行补齐。
5. 最后决定是否将新字段同步到原生 `sales_team`，默认采用“仅空表追加”策略。
