# 物料库存汇总清点表方案

## 1. 背景与已确认范围

仓库需要按月或自定义期间定期清点实物库存，并与系统账面库存核对。当前仅有 ERPNext 原生的 `Stock Reconciliation`（库存调账）工具，适合执行库存差异调整，但不适合作为仓库人员日常使用的“盘点汇总单”：缺少清点周期、盘点范围、盘点人、逐行差异原因以及清晰的汇总入口。

本次已确认的业务规则：

| 项目 | 规则 |
|---|---|
| 仓库范围 | 一张清点单可以覆盖多个仓库 |
| 盘点粒度 | 每行唯一键为“物料 + 仓库” |
| 生效方式 | 清点单提交后立即生成并提交库存调整 |
| 差异说明 | 只有数量差异的行必须填写差异原因 |
| 批次/序列号 | 本期不作为汇总行唯一键；批次或序列号管理物料进入标准调账单时仍按 ERPNext 原生规则处理 |
| 操作入口 | 草稿保存后由“更新库存”按钮一键执行库存调整 |
| 盘点录入 | 支持页面逐行录入，也支持 Excel 模板导入后自动比对 |

本方案只沉淀设计，不包含代码、数据库或站点配置修改。

## 2. 目标与边界

### 2.1 目标

1. 提供一张可多仓盘点的“物料库存汇总清点单”，供仓库集中录入实盘数量。
2. 在生成盘点行时固定账面数量快照，明确盘点基准时间，避免录入过程中账面值悄然变化。
3. 自动计算数量差异、差异金额，并要求有差异时记录原因。
4. 提交后立即复用 ERPNext 标准库存调账和库存台账，账实差异即时生效且可追溯。
5. 不替换、不改写既有 `Stock Entry`、`Delivery Note`、采购收货、销售出库等接口与库存逻辑。

### 2.2 非目标

- 本期不新增审批流程；提交权限仍由角色控制，提交即调整库存。
- 不新增一套独立库存余额、成本计算或会计分录引擎。
- 不自动盘点“从未生成到清点单的物料”。盘点范围以生成时选定仓库、物料条件和清单为准。
- 不以“物料 + 仓库 + 批次/序列号”扩展汇总表行。受批次/序列号管控的物料由生成的标准调账单继续校验和录入明细。

## 3. 总体方案

新增自定义单据 `Material Stocktake Summary`（界面名称：物料库存汇总清点单）及子表 `Material Stocktake Summary Item`。它只负责清点组织、账面快照、实盘录入和审计信息；不直接写库存台账。

提交清点单时，服务端将全部行映射到一张 ERPNext 原生 `Stock Reconciliation`：每个清点行生成一条同仓库、同物料的调账明细，实盘数量写入原生 `qty`。随后立即提交该标准单据，由 ERPNext 创建库存台账、库存价值变化和必要的会计影响。

一张汇总清点单对应一张标准库存调账单。原生调账单已支持多仓库行，因此不需要按仓库拆单；保留该关联后，用户既能在清点单查看业务上下文，也能下钻到原生库存和财务凭据。

```text
物料库存汇总清点单（多仓库）
  -> 固化账面库存快照
  -> 仓库录入实盘数量、差异原因
  -> 提交并进行最终并发校验
  -> 创建并提交 Stock Reconciliation（多仓库）
  -> 标准 Stock Ledger / 库存价值 / 会计链路
```

## 4. 单据与字段设计

### 4.1 单据头：物料库存汇总清点单

| 字段 | 类型 | 说明 |
|---|---|---|
| `company` | Link / Company | 必填，库存所属公司 |
| `posting_date`、`posting_time` | Date、Time | 账面快照和库存调整的业务时间；默认当前时间，草稿可改 |
| `set_posting_time` | Check | 是否使用用户指定的业务时间，沿用原生调账语义 |
| `count_period_from`、`count_period_to` | Date | 本次清点周期，仅作业务记录和筛选，不参与库存计算 |
| `warehouses` | Table / 清点仓库子表 | 至少一行，用于声明本单覆盖的多个仓库 |
| `item_scope` | Select | 全部库存物料 / 按物料组 / 手工添加；控制生成盘点行范围 |
| `item_group` | Link / Item Group | 当范围为物料组时使用 |
| `counted_by` | Link / User 或 Employee | 盘点责任人，默认当前用户 |
| `remarks` | Small Text | 清点说明 |
| `stock_reconciliation` | Link / Stock Reconciliation | 提交后回写生成的原生库存调账单，提交后只读 |
| `status` | Select / 派生 | 草稿、已调整、已取消、调整失败；不另建审批状态 |

### 4.2 仓库子表

子表 `Material Stocktake Warehouse` 仅维护 `warehouse`。服务端拒绝重复仓库，并校验仓库属于单据公司、为可用叶子仓库。

### 4.3 清点明细：物料库存汇总清点明细

| 字段 | 类型 | 说明 |
|---|---|---|
| `item_code`、`item_name`、`stock_uom` | Link/Data/Link | 物料及显示信息 |
| `warehouse` | Link / Warehouse | 必填，必须来自单据头的仓库子表 |
| `system_qty` | Float，只读 | 生成行时按盘点基准时间取得的账面数量快照 |
| `counted_qty` | Float | 仓库录入的实盘数量；允许 0，不能为空 |
| `qty_difference` | Float，只读 | `counted_qty - system_qty` |
| `valuation_rate` | Currency，只读 | 快照时的账面计价率，供预估展示；最终以原生调账为准 |
| `amount_difference` | Currency，只读 | 差异数量乘快照计价率，仅作预估 |
| `difference_reason` | Link / Stocktake Difference Reason | 当数量差异不为 0 时必填 |
| `difference_note` | Small Text | 对原因的补充说明，可选 |
| `source_stock_qty_time` | Datetime，只读 | 账面快照取得时间，便于审计 |

明细唯一性由服务端强制为 `item_code + warehouse`。同一物料位于不同仓库时必须分别清点，不能合并成一行。

## 5. 操作流程与页面行为

1. 仓库人员新建清点单，选择公司、盘点基准时间、清点周期，并添加一个或多个仓库。
2. 通过“生成盘点行”选择范围。系统按所选仓库和物料范围读取账面库存，写入 `system_qty`、计价率与快照时间；草稿阶段支持手工增删物料行。
3. 仓库人员可在页面填写每行 `counted_qty`，也可下载盘点模板、线下清点后上传 Excel。系统按“物料编码 + 仓库”匹配明细，生成导入预览并标出新增、覆盖、重复和错误行，用户确认后才写入草稿。
4. 差异为零时不要求原因；差异不为零时，行内必须选择差异原因，否则不能提交。
5. 草稿阶段提供醒目的 `更新库存` 按钮。点击后显示确认弹窗，列出本次涉及的仓库数、物料行数、盈亏数量和预估差异金额；确认即触发本清点单提交，不再要求用户进入原生库存调账单操作。
6. 服务端再次按单据业务时间读取当前账面数量并校验。若账面值已被其他出入库或调账单改变，阻止更新并返回变更的“物料 + 仓库”列表，要求重新生成或确认盘点行，不能在过期快照上盲目调账。
7. 校验通过后创建并提交原生 `Stock Reconciliation`，立即更新库存；回写关联单号和“已调整”状态。按钮随即隐藏或禁用，不能再次调整。
8. 取消清点单时，不自动取消已提交的原生调账单。纠正必须走标准“取消调账单 / 新建反向或重新盘点”流程，保证库存台账审计完整。

### 5.1 Excel 导入与比对

清点单提供 `下载盘点模板` 和 `导入盘点结果` 两个按钮。模板以当前清点单的仓库和物料范围生成，建议包含以下列：

| Excel 列 | 是否必填 | 用途 |
|---|---|---|
| 物料编码 | 是 | 与系统 `Item.item_code` 精确匹配 |
| 物料名称 | 否，只读参考 | 便于线下识别，不作为匹配条件 |
| 仓库 | 是 | 与系统仓库编码精确匹配，且必须属于本清点单范围 |
| 库存单位 | 否，只读参考 | 导入时校验与物料库存单位一致，不进行单位换算 |
| 实盘数量 | 是 | 写入 `counted_qty`，允许 0，不允许空值或非数字 |
| 差异原因 | 有差异时必填 | 按启用的差异原因名称或编码匹配 |
| 差异说明 | 条件必填 | 原因为“其他”时必填 |
| 备注 | 否 | 线下盘点补充信息 |

为支持盲盘，默认模板不导出账面数量、差异数量和估值金额；具有盘点管理权限的用户可选择下载“含账面数量模板”。

导入采用“先校验预览、再确认写入”，禁止上传后直接调整库存：

1. 校验文件格式、必填列、物料、仓库、库存单位和实盘数量。
2. 同一文件内出现重复“物料 + 仓库”时标记错误，不自动相加，也不静默采用最后一行。
3. Excel 中不属于当前清点仓库范围的行禁止导入；系统不存在或已禁用的物料、仓库明确显示错误原因。
4. 对清点单已有行，预览显示“覆盖实盘数”；对范围内尚无明细的有效组合，预览显示“新增明细”。
5. Excel 未包含的原有清点行保持不变，不按零库存处理，避免部分导入误清库存。
6. 预览汇总成功行、错误行、重复行、覆盖行和新增行；仅在无阻断错误且用户确认后写入草稿。
7. 导入完成只更新盘点草稿和差异展示，不自动执行库存调整。用户仍需检查差异原因并点击 `更新库存`。
8. 保存原始文件、导入时间、导入人和结果摘要作为附件/日志，便于追溯。

如需将“Excel 中未出现的物料视为实盘为 0”，必须由用户单独勾选 `未导入行按零库存处理`，并进行二次风险确认；默认关闭。

## 6. 差异原因与权限

新增维护型 DocType `Stocktake Difference Reason`，字段仅包含：原因名称、启用、排序、说明。预置原因建议包括：漏记出入库、收发记录延迟、报废/损耗、计量误差、库位误放、其他。

差异原因必须是启用状态。若选择“其他”，要求同时填写 `difference_note`。服务端校验不可仅依赖前端必填规则。

权限采用最小增量：

| 角色 | 权限 |
|---|---|
| Stock User | 创建、编辑、读取草稿；不具备提交权限 |
| Stock Manager | 创建、编辑、提交、取消、读取；提交即触发库存调整 |
| Accounts User / Accounts Manager | 读取、报表查看；会计处理沿用原生库存调账权限与设置 |

实际角色名称与当前站点既有权限体系冲突时，以站点标准角色为准，不修改既有角色权限。

## 7. 调用链路

```text
清点单表单
  -> 生成盘点行按钮（客户端）
  -> get_stocktake_snapshot（服务端白名单方法）
  -> Bin / Stock Ledger 查询（指定公司、业务时间、物料、仓库）
  -> 写入草稿明细快照

Excel 盘点结果
  -> 上传并解析工作簿
  -> 按物料 + 仓库校验和匹配
  -> 返回新增 / 覆盖 / 重复 / 错误预览
  -> 用户确认后写入实盘数量和差异原因
  -> 保持清点单为草稿

清点单提交
  -> 用户点击“更新库存”并确认
  -> MaterialStocktakeSummary.validate / before_submit
  -> 校验仓库、唯一键、实盘数量、差异原因、快照是否过期
  -> create_stock_reconciliation（新增内部服务）
  -> ERPNext Stock Reconciliation.insert + submit
  -> 标准 update_stock_ledger / 库存价值与会计链路
  -> 回写 stock_reconciliation、status
```

库存最终调整始终只通过 ERPNext `Stock Reconciliation`。自定义清点单不直接新增、更新或删除 `Stock Ledger Entry`、`Bin`、`GL Entry`。

## 9. 关键实现约束与风险处理

### 9.1 账面快照与并发

生成行得到的是盘点基准快照，不是提交时强制覆盖库存的许可。提交前必须重新比对 `system_qty` 与基准时间对应的账面值。出现变更时明确阻断，防止清点期间的出入库被错误覆盖。

### 9.2 成本与会计

汇总单中的差异金额只是展示预估。库存计价、差异账户、成本中心、负库存、冻结库存日期、保留库存等规则全部由提交的 `Stock Reconciliation` 执行；相关账户采用原生默认差异账户或由清点单增加可选的差异账户字段后明确映射。

### 9.3 批次与序列号

对于启用批次或序列号的物料，汇总行只能显示数量差异。提交映射时必须将其转入原生调账所需的批次/序列号明细；信息不完整则不能提交，并提示进入关联的原生调账补齐，而不能绕过原生校验。

### 9.4 失败与幂等

创建或提交原生调账单失败时，清点单保持草稿或标记“调整失败”，记录错误和已创建的关联单据，禁止重复生成成功的调整。重试前先检查关联调账单状态，确保同一清点单不会重复影响库存。

## 10. 受影响模块

| 模块 | 影响 |
|---|---|
| 仓库盘点 | 新增多仓库存汇总清点入口和清单 |
| 库存台账与现存量 | 通过原生调账即时更新，查询接口不变 |
| 库存价值与会计 | 差异金额通过原生调账进入既有会计链路 |
| 批次/序列号 | 继续遵循原生库存调账校验，不降低追踪要求 |
| 库存报表 | 无需改造，调账提交后按既有口径显示 |
| 权限与审计 | 新增清点单权限及清点单到调账单的可追溯关联 |

## 11. 验收标准

1. 一张清点单可添加仓库 A、仓库 B，并能生成两仓的物料行。
2. 同一物料在 A、B 仓各有一行；同仓同物料重复添加会被阻止。
3. 账面 10、实盘 10 的行可提交且不要求填写原因。
4. 账面 10、实盘 8 的行自动显示差异 -2，未填原因时无法提交；填入启用原因后可提交。
5. 草稿中点击 `更新库存` 后，确认弹窗准确展示本次调整摘要；取消确认不会改变库存。
6. 确认更新后自动生成一张关联的原生 `Stock Reconciliation`，其中包含两个仓库的行，且该单据已提交。
7. 更新完成后库存报表、现存量和库存台账立即反映实盘数量，`更新库存`按钮不可再次使用。
8. 盘点生成后发生同物料同仓出入库时，清点单更新库存会被阻止并明确提示受影响行。
9. 已成功调整的清点单重复提交或重试不会生成第二次库存调整。
10. 受批次/序列号管理的物料缺少原生所需明细时不能绕过提交。
11. 下载模板、填写多仓实盘数量并导入后，系统能按“物料 + 仓库”正确生成差异预览。
12. Excel 内重复组合、无效物料、范围外仓库和非数字数量均能定位到具体行，且不会部分写入草稿。
13. Excel 缺少某些原有盘点行时，这些行保持原值；只有明确勾选并二次确认后才能按零处理。
14. Excel 导入确认后库存不会立即变化，只有点击 `更新库存` 并通过最终校验后才调整。

## 12. 实施顺序
