# BOM 单入口直接编辑前端优化方案

日期：2026-10-12。状态：待实施。本次仅生成方案文档，不修改代码或业务数据。

## 1. 已确认的需求

- 主列表中同一业务 BOM 只出现一个入口，不把历史版本当作多张相同 BOM 展示。
- 标题仅显示业务 BOM 编码，例如 `BOM-AKY-55R5-CGTC`，不显示后缀或版本号。
- 用户进入同一 BOM 后，点击编辑，直接增删组件、修改用量，再保存生效；无需理解“创建新版、启用新版”。
- 修改前创建的生产工单继续使用修改前的组件清单；修改后新建工单使用修改后的组件清单。
- 优先调整前端，复用现有后台版本接口，不覆盖已提交 BOM，不修改旧工单。

## 2. 当前逻辑与问题

目前 `bom.js` 中“更新版本”调用 `create_update_version`，创建并跳转至新的标准 BOM 草稿；“保存并启用”调用 `activate_bom_version`。版本启用后，旧版保持有效，新版成为默认。标准 BOM 列表因此同时显示历史版和当前版。

标题已使用 `custom_bom_code`，但组件编辑仍暴露版本创建过程，列表仍逐张展示底层 BOM 单据。需要把底层版本保留用于追溯，前端统一成一个业务入口。

已提交标准 BOM 不支持直接更改组件。仅将表格解锁无法可靠保存，也会破坏旧工单的依据。因此推荐在原页面打开编辑弹窗，后台继续使用现有草稿和提交接口。

## 3. 预期界面

```text
物料清单列表（默认视图）
┌──────────────────────┬──────────────┬────────┬────────┐
│ BOM 编码              │ 物料          │ 状态    │ 总成本  │
├──────────────────────┼──────────────┼────────┼────────┤
│ BOM-AKY-55R5-CGTC     │ AKY-55R5-CGTC│ 当前    │ 357.00 │
└──────────────────────┴──────────────┴────────┴────────┘
默认隐藏历史版本；提供“查看历史版本”切换。

详情标题：BOM-AKY-55R5-CGTC             [编辑物料]
组件明细：显示当前已生效清单

点击编辑物料，弹出：
┌──────────────── 编辑 BOM ───────────────────┐
│ 物料编码 │ 名称 │ 用量 │ 单位 │ 子 BOM │ ... │
│          可添加行、勾选删除、修改组件         │
│ [添加行]                       [取消] [保存]│
└─────────────────────────────────────────────┘
保存确认：修改仅用于后续新建工单，已有工单保持原清单。
```

版本记录默认折叠为“历史记录”，仍可展开查看实际版本、单号、来源和状态。历史版本入口保持只读，不能误将其当作当前 BOM 编辑。

## 4. 列表展示规则

不能只固定过滤 `is_default=1`：这样首次未提交的 BOM 草稿会消失。

默认列表采用前端过滤组合：当前默认版本，或没有 `custom_version_source` 的首次草稿；更新草稿和已取消/历史版本默认不展示。标准首次草稿只作为待完善入口。用户打开“历史版本”后移除该业务过滤，恢复标准列表。

当前有效 BOM 被人为取消默认且没有其他默认版本时，需通过历史视图维护恢复；首版不新增后台聚合查询。前端默认过滤只是展示规则，不是权限控制，也不修改后台查询接口。

列表显示业务编码时，链接、勾选、批量操作必须仍使用实际 `name`。不得将 `doc.name` 或链接值改成业务编码；多个版本同编码不代表同一数据库单据。

## 5. 编辑与保存方案

1. 当前有效默认 BOM 显示“编辑物料”，取代面向业务用户的“更新版本”。已有历史 BOM 显示历史提示和“打开当前 BOM”。
2. 点击编辑调用现有 `create_update_version(current_bom)`，复用当前来源已有草稿，弹窗加载这张草稿。详情不跳转至后缀单号页面。
3. 弹窗编辑标准 `items` 数据。保留现有每行字段，包括子 BOM、库存/采购单位换算、工序、图纸和成本相关字段，不能只保存截图里的几个可见列并丢弃其他信息。
4. 弹窗以标准文档保存路径更新草稿，仅提交用户实际修改的组件及允许的字段；运行标准服务端校验。不得直接使用数据库写入、忽略权限或更改来源/版本号。
5. 点击“保存”先保存草稿，再调用已有 `activate_bom_version`。保存的业务含义是生效，不增加要求用户理解的“启用版本”步骤。
6. 两步成功后关闭弹窗，打开当前已生效 BOM，但标题仍是统一业务编码；刷新默认列表及成本。
7. 首次 BOM 草稿沿用标准草稿编辑/提交，不强制创建更新草稿。标准取消修订入口保留给异常处理。

现有接口将保存与启用分为两个请求，不能宣称二者是同一个数据库事务。启用失败时新组件只保存在草稿，旧默认仍生效；提示“草稿已保存，尚未生效”，允许处理校验后重试。

取消弹窗不切换默认，不删除后台草稿；下次继续已有草稿。取消后未保存的本次页面修改丢弃。已有草稿内容与当前生效清单不同，打开时须提示正在继续未生效修改。

并发沿用版本链锁和过期来源校验，同时保留标准 modified 时间冲突检查。重复点击保存需禁用按钮；默认已被他人切换时提示重新打开当前 BOM，不能强制覆盖。

## 7. 调用链路

```text
BOM 默认列表 → 前端过滤当前/首版草稿 → 实际单号链接
  → 当前 BOM 详情（业务编码标题）
  → 编辑物料 → create_update_version（已有接口）
  → 标准读取新草稿 → 弹窗修改 items
  → 用户保存确认 → 标准文档保存
  → activate_bom_version（已有接口）
  → 标准校验/提交 → 默认 BOM 切换
  → 刷新当前业务入口及列表
```

## 8. 关联模块与边界

| 模块 | 处理 |
|---|---|
| 原生产工单 | 保持具体旧 bom_no，组件、子 BOM 和成本依据不回写 |
| 新生产工单 | 按新默认 BOM 创建，随后固定具体 bom_no |
| 分层生产/半成品补料 | 继续按父 BOM 行的具体子版本创建子工单，不自动升级子版本 |
| 生产计划 | 已保存 BOM 引用不自动替换；新取默认的业务使用新版本 |
| 库存领料、入库、成本 | 沿用工单与库存标准链路，不重算历史库存估值 |
| 图纸、工序、废料 | 复制保留原数据，组件编辑不丢关联；其他复杂字段可走高级编辑 |
| 采购和质量 | 不修改既有采购、质检、入库接口 |
| 导出/报表/MES | 保留实际单号和版本字段；列表展示业务编码不修改接口输出 |
| 权限 | 查看需 read，编辑需 create/write，保存生效需 submit；无提交权限时不展示保存生效按钮，可使用已有草稿入口 |

前端单入口不等于数据库只剩一张 BOM。历史版本仍是标准 BOM，这是已有工单继续使用修改前清单的保障；不会删除目前两条记录。

## 9. 实际业务流

```text
列表打开 BOM-A（只显示一个当前入口）
  ↓ 编辑物料
增删组件、调整用量、必要时明确选择子 BOM
  ↓ 保存并确认
后台保留旧清单并启用修改后的清单
  ├─ 修改前工单 → 原 BOM → 原组件领料/生产/成品入库
  └─ 修改后工单 → 新默认 BOM → 新组件领料
        ├─ 库存足够 → 生产/组装 → 成品入库
        └─ 半成品缺料 → 原补料列表选择外购或自产
              ├─ 外购 → 申请/采购/质检/入库 → 父工单领用
              └─ 自产 → 固定子 BOM 建工单 → 半成品入库
                         → 父工单领用/组装 → 成品入库
```

## 10. 验收与回退

- 同一 BOM 多个有效版本，默认列表只显示一个当前入口；首次草稿可见，历史视图可查看全部。
- 标题只显示业务编码；链接、导出和工单关联仍使用真实单号。
- 增加、删除、修改组件后保存生效，新工单取新清单；已有工单的 bom_no 和需求不变。
- 子 BOM 与图纸等未修改字段完整保留；字段校验失败不切默认。
- 取消编辑、权限不足、保存冲突、启用失败、重复保存都有明确处理。
- 验证移动端表格、标准导出、历史打开、浏览器刷新及两人同时编辑。
- 回退只撤销前端入口/过滤脚本；后台版本和工单引用保留，不删 BOM 数据。

实施前优先验证标准弹窗表格与文档保存方法，实施后需完成浏览器增删组件及新旧工单对照验收。本文为方案，不代表上述界面已实现。
