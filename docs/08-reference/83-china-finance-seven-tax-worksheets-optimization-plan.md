# 中国财务七类税费计算表申报复核优化方案

状态：方案讨论稿；仅沉淀设计，尚未修改业务代码或数据库。参考用户提供的众马云七张计算表截图，借鉴行项目组织方式，不复制其税率、优惠资格或申报口径。

## 1. 目标和边界

在中国财务模块现有“税费计算表”页面提供增值税、附加税费、印花税、工会经费、企业所得税、地方水利建设基金、残疾人就业保障金七张可供财务申报复核的计算底稿。金额需有来源、所属期间、适用规则、计算过程、差异、复核人和版本；缺失基础数据或政策时不得以 0.00 冒充正式结果。系统提供申报复核依据，不代替税务机关申报、核定或自动生成会计凭证。

小增量原则：保持 `china_finance.services.tax_calculation.get_tax_calculation(company, period, tax_type="VAT")` 的参数及既有返回字段；扩展 `rows` 元数据和可选复核信息。税票、抵扣、总账、结账等旧接口不改变签名与状态机；新增独立计算器、政策配置及复核分支。七张表的“可复核”指数据齐备且财务确认口径，不意味着自动保证申报正确。

## 2. 现状与差距（以当前工作区代码为准）

- `china_finance/services/tax_calculation.py`：VAT 对已提交销项 `China Tax Invoice.tax_amount` 按开票日期汇总，**未排除作废票**；进项按 `China Input Tax Deduction Batch.status='Deducted'` 和 `deduction_period` 汇总；上期留抵为空、进项转出为零，当前应纳税额是 `max(销项-进项, 0)` 的测算值，始终 `Incomplete`。
- `SURCHARGE`、`STAMP_DUTY`、`CORPORATE_INCOME_TAX`、`WATER_FUND`、`DISABILITY_FUND` 已有导航入口，但均返回三行通用占位数据；尚无 `UNION_DUES` 工会经费入口。
- 页面 `china_finance/china_finance/page/china_tax_calculation_sheet/china_tax_calculation_sheet.js` 仅呈现“行次/项目/金额”，可切换公司、月份、下载、打印；下载与打印尚未包含政策依据、来源明细及复核版本。
- 现有 `China VAT Ledger` 显示税票明细，`China VAT Return Worksheet` 排除作废票；计算页销项钻取指向台账，但各自口径并未统一。`china_finance/services/tax_reconciliation.py` 已有税票与总账核对能力；`input_tax_deduction.py` 已有查验、勾选、确认抵扣流程。不得把采购发票与抵扣批次重复相加。

## 3. 统一数据和规则

### 3.1 所属期、来源和状态

按公司+税种+所属期查询；VAT、附加税通常按月，所得税以适用预缴季度/累计年度为主，残保金通常依上年度数据和本年度申报期确定，其他税种按公司所在地适用频次配置。前端允许选择对应的期间类型，后端校验起止日期、会计年度和权限。不能将月度数直接当季度/年度申报数。

每行携带稳定 `item_code`、单位（金额/百分比/人数）、来源类型及来源筛选、规则版本、自动/人工/公式属性、缺失原因、差异和状态。`0` 仅代表已确认真实为零；缺数据用 `null` 和 `Incomplete`。可在底稿录入具有凭据的补充项（金额、原因、附件、录入人、时间），不可覆盖自动来源原值。跨期调整单独列示并保留审批痕迹。政策配置按公司、地区、税种/税目、生效区间、税率/征收率、优惠类型和依据存储，检查期间重叠；不默认采用截图数值。金额使用 Decimal 按适用规则舍入，行级和汇总级的舍入策略固定并记录版本。

### 3.2 七张表逐行映射与口径

| 计算表 | 截图行项目与建议扩展行 | 数据源、公式与待核实项 |
| --- | --- | --- |
| 增值税 | 保留销项、可抵扣进项、进项转出、上期留抵；增加本期应交、免交、已预缴、本期应补缴、期末留抵 | 销项：当期已提交且非作废的销项中国税务发票，红票以负税额冲减；进项：所属期已确认抵扣批次。按纳税人类型分支计算，政策项包括简易计税、减免、加计抵减等适用项目；期初留抵须来自上期已确认底稿或有凭据的期初录入。不得以截图 `销项-进项` 覆盖所有情形。 |
| 附加税费 | 当期实际缴纳增值税、消费税、计税依据；城建税、教育费附加、地方教育附加各自税率、减免比例/金额、应交额、已缴与差额 | 税基以适用政策规定的**实际缴纳**增值税、消费税为准，区分本期计提与本期缴纳，来源为缴税凭证/税款台账或经确认的补充记录，VAT 应纳额只作核对候选；三项各自税率与优惠按政策期间解析。没有消费税来源时需明确“已核实无消费税”或待补，不直接推断为零。 |
| 印花税 | 本期应税凭证计税金额（可汇总展示“本期收入”作核对）、分税目税率、减免及应交、已缴 | 优先逐笔关联合同/应税凭证及对应税目、计税金额、发生日期、关联方和凭证 ID；销售收入不能直接等同全部印花税基。缺应税凭证清单时待补，不用一行收入估算替代申报底稿。 |
| 工会经费 | 本期应发工资、费率、减免比例/金额、应计提/应缴、已缴 | 从有效工资单或工资凭证汇总适用工资基数，扣除作废和重复，按当地征收/拨缴政策确定基数、费率及周期；工资数据未配置或未核实则待补。 |
| 企业所得税 | 利润总额、以前年度亏损、实际利润额、计税比例、税率、应纳所得税、累计已预缴、上年汇算补退、本期应补退；增加纳税调整和税收优惠 | 与总账/利润表按年度累计核对；亏损结转、税会差异、优惠和已预缴须有专项台账或凭据；按所得税预缴周期与纳税人适用政策计算，区分累计与本期差额；不把月度会计利润直接当应纳税所得额。 |
| 地方水利建设基金 | 本期计费基数（截图称“本期收入”）、费率、计费比率/减免、应缴、已缴 | 按当地政策选择收入或其他规定税基、是否适用及生效日期；收入取有核对依据的销售/总账口径，不直接以发票额替代；政策停征期间须保留依据。 |
| 残疾人就业保障金 | 上年度在职职工工资总额、年平均人数、规定安置比例、实际安置人数、上年度人均工资、征收费率/减免、应缴、已缴 | 上年度工资与人数来自工资/人事统计核对，残疾人安置人数来自有效证明；按属地政策处理平均人数、上下限、减免、年度计费期。未知安置人数不可默认为零。 |

所有结果除截图行次外，增加来源/公式查看、政策依据、调整记录和复核状态；屏幕默认保持简洁，详细依据通过展开行/钻取展示。税率、人数和金额分别格式化，避免把 `7%` 当 `7` 参与乘法。截图中的印花税率、附加税折扣等仅是示例，不能写入默认配置。

### 3.3 复核与期间锁定

推荐底稿状态 `Incomplete`（缺源/缺政策）→ `Calculated`（规则可执行，未复核）→ `Reviewed`（财务确认）→ `Superseded`（源单据或政策变动后的旧版本）。保存来源单据 ID/汇总哈希、计算时间、规则版本、调整和复核人；已复核版本只读，重算生成新版本并展示差异，不静默覆盖。源单据撤销、补开红票、抵扣批次跨期更正、工资或合同变更时提示对应期间失效，复核前重新取数。不自动更改原始业务单据或已结账期间。

## 4. 调用链路与关联影响

```text
税费计算表(公司/税种/申报期间)
  -> 保留 get_tax_calculation 原入口 -> 新分发器(税种、纳税人类型、地区和期间)
  -> 各税种计算器 -> 只读来源适配器(税票/已抵扣批次/总账/工资/合同/缴税记录)
  -> 生效政策配置 + 有凭据的调整 -> 金额行/来源/警告/核对差异
  -> 页面钻取、下载、打印 -> 新版底稿复核记录(显式操作)
```

关联模块：税务发票、开票申请/销售发票分摊只作溯源；采购端进项查验与抵扣批次只读汇总；财务总账及报表用于税款缴纳、所得税利润及差异核对；工资、合同/采购销售业务、缴税凭证为其余税种提供数据。各模块若没有足够字段或可靠台账，优先新增税务侧“来源登记/调整”与凭证关联，不擅改 ERPNext 核心单据。结账需显示未复核/差异提示；是否作为阻断条件另行决定。既有中国财务工作区入口复用；增加工会经费仅需更新计算表税种导航，不另建一套税务菜单。

### 4.1 业务数据流转与期间边界

| 来源到结果 | 触发、期间与排除条件 | 到达税表及核对点 |
| --- | --- | --- |
| 销售发票/开票申请 → 中国税务发票 | 申请审批和税票提交是不同状态；仅公司一致、开票日落在所属期、已提交且非作废的**销项税票**入选。蓝票正数、已提交红票负数；销售发票和开票申请仅用于追溯，不能与税票叠加。 | 归集 VAT 销项行 → 钻取有效税票明细 → 与增值税申报核对底稿及销项总账发生额比较；票账差异单列，不自动改写税票或凭证。 |
| 采购发票/中国进项税票 → 查验 → 勾选 → 抵扣批次 | 已收票/查验通过/已勾选均不等于可抵扣；仅 `Deducted` 批次按 `deduction_period` 归属。票面日期、采购发票入账日期、抵扣期间可以不同；不得把已抵扣票额和批次税额重复计入。 | 归集 VAT 进项行 → 钻取批次及票据 → 与采购发票分摊/进项总账按**会计入账期间**另行核对，跨期差异解释为期间差而非强制金额相等。 |
| VAT 底稿/实际缴税凭证 → 附加税 | 应纳、已缴、实缴日期分别留存；当期实缴增值税和消费税经凭证核实后进入附加税税基。若纳税所属期和缴纳月份不同，以适用政策规定的归属期处理并保留跨期说明。 | 城建税、教育费附加和地方教育附加各自应用政策及减免 → 与对应税费总账和缴款凭证比对；缺实缴依据时停留 `Incomplete`。 |
| 合同/应税凭证 → 税目认定 | 同一合同或凭证以稳定 ID 去重；按签订/应税行为日期和适用税目、计税金额、优惠归期；变更、解除与补充协议单独追溯。 | 印花税分税目计算 → 核对合同台账、缴税凭证；收入仅是交叉核对指标，不能代替税目计税基础。 |
| 工资单/工资凭证 → 工资汇总；人事/安置证明 → 年度人数 | 工资按申报政策确认的薪酬基数和所属期取数，排除草稿/撤销及重复入账；残保金取上年度工资、平均人数及有效安置证明，不沿用当月工资人数。 | 工会经费取本期工资基数；残保金取上年度数据 → 分别关联工资/人事依据和已缴记录；缺人事证明时不推断安置人数为零。 |
| 总账/利润表 → 税会调整及亏损台账 | 所得税按本年度累计至申报期末的利润及适用预缴周期取数；税会调整、以前年度亏损、优惠和已预缴分别建依据记录；禁止把各月累计数相加。 | 企业所得税累计应纳与本期应补退分列 → 与所得税费用、应交税费和缴税凭证比对；会计利润与应税所得差异保留明细。 |
| 收入明细/总账 → 地方水利政策 | 仅在属地政策规定按收入征收时按适用收入归集，扣除/减免按有效规则执行；不直接重复使用发票含税总额。 | 地方水利基金税基、费率和已缴额可逐层追溯；停征或免征须有政策生效依据。 |

源数据与底稿之间仅通过只读聚合或经审批的来源登记流转，**不因打开页面自动更改发票、采购单、工资单、总账或缴税状态**。每条取数记录保留原单据 ID、日期、状态、金额和归属理由；同一税额在不同环节（票据、会计入账、实际抵扣、实际缴款）可处于不同期间，不用一个日期字段强制贯通。

### 4.2 变更、复核及跨模块反馈

1. 页面选择公司与期间后，服务端验证权限、期间与政策有效期，返回七表中当前税种的计算行、来源清单摘要、未完成事项和账票/缴税差异；页面查询本身不保存快照。
2. 财务人员钻取源单核对，补充确有依据的政策资格、税款缴纳凭证、亏损或调整记录。提交复核时后端重新计算并比对来源指纹/版本，阻止将过时的页面结果直接确认。
3. 确认后生成只读版本；导出、打印均注明公司、税种、期间、来源时间、政策版本、调整理由及复核人。旧版保留，绝不静默更新历史金额。
4. 后续发票冲红/作废、抵扣批次更正、工资/合同撤销、政策回溯或缴税凭证修正时，仅标记相关公司+期间+税种可能失效，并提示差异及重算；原单据的修改仍由原业务模块负责。跨期更正须明确影响原期还是当期，复核后重算生成新版本。
5. 结账与报表只消费复核状态和核对差异提示，不把税表结果自动生成总账凭证或反写开票/抵扣状态；需要阻断结账或自动计提时，作为独立审批的后续变更。

## 6. 分批小增量实施与预期效果

1. **统一合同与 VAT**：冻结现有 API 兼容测试，新增行级状态与单位、修正作废票口径、覆盖红票及已抵扣期间，保留现有报表钻取；预期销项与有效税票合计一致，进项与确认抵扣批次一致，缺留抵时不显示正式应缴额。
2. **政策与复核基础**：新增地区政策规则、来源/调整记录、计算快照及权限，不立即修改发票/抵扣状态机；预期任一数字可追溯，缺来源/费率不通过复核，重算不覆盖旧版本。
3. **附加税费和工会经费**：新增独立计算分支及工资、缴税来源适配；预期展示截图行项目，实际缴纳税基与工资基数有凭据，优惠率按适用期间生效。
4. **印花税、水利基金**：接入逐笔应税凭证与地区政策；预期税目可分组核对，收入与应税税基不混同。
5. **所得税、残保金**：接入年度/累计数据、亏损/优惠和人员证明；预期跨期口径明确，缺上一年度数据不能误报零税额。
6. **关联验收**：完成税票-总账、工资-凭证、应纳-已缴、旧报表与新底稿核对；下载/打印包含来源及复核版本；旧 API、报表、结账、权限及所有七张表回归通过。按公司真实申报期间人工比对后才能启用“已复核”标记。

## 7. 验收用例与风险

- VAT：蓝/红/作废、撤销、跨月开票、跨期抵扣、重复批次、期初留抵、进项转出、小规模与一般纳税人隔离、零票真实零值；金额钻取与计算筛选一致。
- 附加税：应纳与实际缴纳跨期不同、消费税为零但已核实、有无优惠/政策切换、多个费种分别舍入；不可拿 VAT 测算值直接冒充实缴税基。
- 印花税：多税目/多税率、免税凭证、重复合同、未签合同与跨期登记；工资：工资单撤销、补发、地区变动；所得税：累计口径、亏损结转、优惠与已预缴；水利基金：停征政策；残保金：上年度人数及人数取整、证明缺失。
- 权限：普通税务用户查看，授权人员维护政策/调整，财务复核，审计只读；测试导出与打印不泄露无权公司数据。
- 缺资料时状态 `Incomplete`、明确缺项及需要谁补录；政策冲突或来源差异不允许 `Reviewed`。大数据量按公司/期间聚合并复核查询性能。

待业务确认：每家公司注册地区和纳税人类型及生效历史；七税种适用申报周期、政策依据、减免资格；缴税记录/合同和工资数据实际在哪些单据；是否把未复核作为结账阻断（默认只提示）；复核签字与附件保留要求。上述未确认前只能实现可追溯的待复核底稿，不能把截图示例比例设为系统默认值。
