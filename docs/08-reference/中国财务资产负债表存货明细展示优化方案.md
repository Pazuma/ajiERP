# 中国财务资产负债表存货明细展示优化方案

## 1. 文档目的

本文用于沉淀“中国财务 -> 资产负债表”中增加存货明细行的实施方案。本阶段只输出设计和改动边界，不修改业务代码、不执行数据库迁移、不调整现有报表接口。

目标是将资产负债表中的“存货”由单一汇总行扩展为以下明细结构：

- 存货
- 其中：原材料
- 在产品
- 库存商品
- 周转材料
- 减：存货跌价准备

其中“存货”仍为汇总行，明细行用于展示组成和核对，不能造成金额重复计算。

## 2. 当前实现与问题

当前中国财务报表由 `China Financial Statements` Query Report 提供，服务端通过报表模板、科目映射和公式计算资产负债表数据，前端再将资产负债表渲染为左右两侧树形表格。

当前模板存在口径差异：

1. “小企业会计准则”模板已经包含原材料、在产品、库存商品、周转材料等明细行。
2. “企业会计准则”模板当前主要显示“存货”汇总行，因此页面上看不到图二红框中的存货明细。
3. 报表金额不是前端计算，而是由模板行、公式和 `China Financial Statement Mapping` 映射共同决定。
4. 报表同时影响页面展示、Excel 导出、PDF 打印、期末余额、年初余额、比较期和报表勾稽检查。

因此，本需求不能只通过前端增加几行文字实现，否则会出现明细没有金额、合计不一致或导出结果与页面不一致的问题。

## 3. 目标效果

### 3.1 页面效果

在资产负债表左侧“流动资产”区域，将“存货”展示为父行，并在其下显示：

```text
存货
    其中：原材料
    在产品
    库存商品
    周转材料
    减：存货跌价准备
```

显示规则：

- “存货”显示汇总金额并保持现有行次。
- 明细行显示各自的期末余额和年初余额。
- 明细行使用现有缩进、字体、金额格式和粗细规则。
- 无映射或无余额的明细显示为 0，不隐藏报表结构。
- 不新增独立的前端展开按钮，法定报表结构直接展示。

### 3.2 计算效果

存货汇总公式统一为：

```text
存货 = 原材料 + 在产品 + 库存商品 + 周转材料 - 存货跌价准备
```

资产合计、流动资产合计和资产负债表平衡检查继续引用“存货”汇总行，不直接重复累加明细行。

### 3.3 一致性效果

页面、Excel、PDF 和比较期数据应使用同一份服务端结果，避免出现“页面有明细、导出没有明细”或期末/年初口径不一致。

## 4. 推荐实施策略

采用“小增量、新分支、复用旧接口”的方式：

1. 新增或升级资产负债表模板版本，不重写 `build_statement` 主流程。
2. 优先通过模板行和公式增加明细，不在前端拼接虚假数据。
3. 复用现有 `China Financial Statement Mapping`，只补充明细行映射和分类逻辑。
4. 保留原有 `INVENTORIES` 行代码和对外报表接口，避免影响已有调用方。
5. 对“企业会计准则”新增明细模板分支；“小企业会计准则”只校验并补齐已有结构，不重复新增同名行。
6. 如历史模板已经生效，不直接覆盖历史版本，新增版本从指定生效日期开始使用。

## 6. 调用链路

### 6.1 页面查询链路

```text
用户打开“中国财务报表”
    -> 选择“资产负债表”
    -> Query Report: China Financial Statements
    -> china_financial_statements.py::execute
    -> services/financial_statement.py::build_statement
    -> get_template(company, "Balance Sheet", to_date)
    -> get_mappings(company, template, to_date)
    -> get_statement_values(...)
    -> 按模板行公式解析 INVENTORIES
    -> build_balance_sheet_rows(...)
    -> 返回行、期末余额、年初余额、行类型、缩进
    -> china_financial_statements.js 渲染资产负债表树
```

### 6.2 导出链路

```text
页面点击导出 Excel
    -> Frappe Query Report 原生导出
    -> 使用服务端 columns/data

页面点击导出 PDF
    -> export_current_report_pdf
    -> 使用同一组 filters 重新执行报表
    -> 套用 China Financial Statements 打印格式
```

因此，核心改动必须落在模板和服务端数据链路，不能只改 `china_financial_statements.js`。

## 7. 科目映射方案

### 7.1 映射优先级

按以下优先级确定明细归属：

1. 公司当前模板下已审核的 `China Financial Statement Mapping`。
2. 账户编码规则，例如原材料、周转材料、库存商品等标准科目编码。
3. 科目名称关键词和账户类型兜底分类。
4. 无法确定时进入“待复核”，不能静默归入库存商品。

### 7.2 建议行代码

继续沿用现有小企业模板中的稳定行代码：

| 行代码 | 中文名称 | 类型 |
| --- | --- | --- |
| `INVENTORIES` | 存货 | Formula |
| `RAW_MATERIALS` | 其中：原材料 | Detail |
| `WORK_IN_PROGRESS` | 在产品 | Detail |
| `FINISHED_GOODS` | 库存商品 | Detail |
| `TURNOVER_MATERIALS` | 周转材料 | Detail |
| `INVENTORY_PROVISION` | 减：存货跌价准备 | Detail / Credit Positive |

不建议重新创建另一套行代码，避免同一业务在两套模板中产生重复映射和兼容分支。

### 7.3 异常处理

- 同一科目不能同时映射到两个存货明细行。
- 存货明细科目未映射时，配置检查应提示具体科目。
- 存货跌价准备必须按负债方向/贷方正向规则处理，不能被当作普通库存成本。
- 明细合计与“存货”不一致时，应在报表检查或配置检查中明确提示。

## 8. 受影响模块

### 8.1 直接受影响

- 中国财务报表页面
- 资产负债表服务端计算
- 财务报表模板
- 财务报表科目映射
- 报表 Excel 导出
- 报表 PDF 打印
- 中国财务报表单元测试和端到端验收

### 8.2 间接受影响

- 中国财务设置中的会计准则选择
- 科目初始化和中国科目体系分类
- 报表配置就绪检查
- 资产负债表勾稽检查
- 财务报表快照或正式报表生成流程（如果其读取模板行）

### 8.3 明确不修改

- GL Entry 生成逻辑
- Journal Entry 提交和取消逻辑
- 账户主数据结构
- 现有报表请求参数和方法名
- 现金流量表、利润表、权益变动表计算
- 原有历史报表快照内容
- 非存货相关的资产负债表行

## 9. 版本和数据策略

1. 不直接修改已生效历史模板的行结构。
2. 新增一个资产负债表模板版本，设置明确生效日期。
3. 生效日期之前的历史报表继续使用旧模板，避免历史数据重算后发生变化。
4. 生效日期之后的新报表使用带存货明细的新模板。
5. 如业务要求历史期间也显示明细，应通过报表模板版本选择实现，不直接改历史快照。
6. 补丁必须幂等：重复执行不会重复创建模板行、映射或规则。

## 10. 实施步骤

1. 确认当前公司使用的会计准则，以及企业会计准则模板是否允许新增明细。
2. 核对目标公司科目表中原材料、在产品、库存商品、周转材料和跌价准备科目。
3. 设计并创建新的资产负债表模板版本。
4. 增加模板行、公式依赖和行类型。
5. 初始化可确定的标准科目映射。
6. 对无法自动判断的科目生成待复核项。
7. 执行服务端单元测试和报表计算测试。
8. 验证页面、Excel、PDF 的期末/年初余额和行次。
9. 验证资产负债表勾稽关系和现有报表回归。
10. 通过验收后再执行迁移和发布。

## 11. 验收标准

### 功能验收

- 企业会计准则资产负债表显示五个存货组成行及跌价准备行。
- 小企业会计准则现有存货明细不重复、不丢失。
- 期末余额和年初余额均能正确显示。
- 存货汇总金额等于明细公式结果。
- 流动资产合计、资产合计和资产负债表平衡结果不受破坏。

### 一致性验收

- 页面和 Excel 数据一致。
- 页面和 PDF 数据一致。
- 比较期数据使用对应历史模板和映射。
- 科目来源链接仍能定位到实际科目。

### 回归验收

- 利润表、现金流量表、权益变动表不受影响。
- 现有资产负债表非存货项目金额不变。
- 旧模板生效期间的历史报表结果不变。
- 未配置明细映射时有明确提示，不发生重复计算。

## 12. 风险与回滚

主要风险：

- 不同公司的科目编码和名称存在差异，自动分类可能误判。
- 在产品可能由生产成本、半成品或自定义科目组成，不能只依赖一个固定编码。
- 存货跌价准备方向处理错误会导致资产合计偏差。
- 直接修改已生效模板会影响历史报表重算结果。

回滚策略：

1. 停用新增模板版本，恢复使用上一个有效模板。
2. 禁用新增的默认映射，不删除历史人工映射。
3. 保留补丁和模板版本记录，便于重新修订后再次启用。
4. 不回滚 GL Entry、凭证和原始科目数据。

## 13. 待确认事项

实施前需要业务确认以下问题：

1. 明细是否同时适用于“企业会计准则”和“小企业会计准则”。建议统一支持。
2. “在产品”是否包含半成品、委托加工物资或仅包含生产成本余额。
3. 存货跌价准备是否已有独立科目，以及其借贷方向。
4. 新模板的生效日期，是从当前期间开始，还是从下一个会计年度开始。
5. 是否要求历史期间重新按新模板展示明细。

## 14. 预期最终效果

完成后，用户在“中国财务 -> 中国财务报表 -> 资产负债表”中可以直接看到存货的组成明细，结构接近图二红框效果，同时保持现有中国财务报表的查询、导出、打印、勾稽和权限链路不变。

本方案的核心原则是：新增模板和映射分支，复用现有报表接口；前端只负责呈现服务端真实结果，不在页面临时拼接金额；历史模板和历史报表结果保持可追溯、可回滚。
