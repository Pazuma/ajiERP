# BOM 版本下拉查看与启用时间优化方案

日期：2026-10-12。状态：待实施。本次仅沉淀方案，不修改代码、配置或业务数据。

## 1. 需求与范围

在 BOM 详情页“关联”后现有“版本”页签中增加版本下拉框。选择某一版本，在当前页签内查看该版本的具体 BOM、组件及启用时间。选择仅用于查看，不启用、不修改默认 BOM、不改变任何工单。

标题继续只显示业务 BOM 编码。后台保留真实版本单号，保证修改前工单仍引用修改前清单。本方案不实施主列表单入口、组件编辑弹窗或恢复历史版本按钮；这些属于前一份《BOM单入口直接编辑前端优化方案》的独立工作。

## 2. 当前代码与差距

- `utils/bom.py.ensure_schema` 已创建 `custom_bom_version_tab`，位置在 `connections_tab` 后，版本 HTML 字段已位于该页签。
- `public/js/bom.js.render_versions` 当前渲染版本记录表，没有版本选择和独立详情。
- `client_akivision/api/bom.py.get_bom_versions(bom)` 已返回版本单号、版本号、提交/有效/默认状态、来源和创建/修改时间。`is_current` 表示当前打开的单据，并非当前默认版本。
- `utils/bom_version.py.activate_bom_version` 使用标准提交和默认管理；现有代码没有专门持久化启用时间。

创建时间、最后修改时间均不能替代启用时间，需要小范围增加真实时间记录分支。


下拉选项按版本倒序，值必须是真实单号，不能使用业务编码或显示标签作为唯一值。例如：

```text
V3 · 草稿 · 尚未启用
V2 · 当前启用 · 2026-10-12 09:30
V1 · 历史版本 · 启用时间未记录
```

默认选择有读取权限的当前启用版本。若没有可访问的当前版本，选择当前打开的 BOM 并明确提示。历史入口可携带前端选择参数预选该版本；参数只影响显示。

状态从标准字段派生：草稿、已取消、已停用、历史有效、当前启用。“当前启用”要求已提交、有效、默认且与 Item.default_bom 一致；数据不一致时显示提示，不自动修复。所有版本详情只读，草稿也只读预览，编辑仍通过已有入口。

组件明细按用户提供图片固定为五列，不增加物料编码、单位、子 BOM 等可见列。不展示工序、废料或独立工程资料区域；图纸号仅作为组件表的一列。成本区域沿用原方案，未在本次反馈中移除。

五列字段口径：型号优先取当前行关联的原始型号字段，缺失时显示对应物料的型号/编码，不使用带版本后缀的 BOM 单号替代；实施时先核对现有导入字段映射。层级按选中版本具体子 BOM 关系展开，顶层为 0、直接组件为 1，逐层递增，树形顺序展示。物料名称和图纸号取对应版本行保存值，图纸缺失显示“-”，不拼接独立图纸版本列。用量显示相对选中顶层 BOM 产出数量的累计需求，子层按父用量及子 BOM 产出数量换算；直接层保持标准组件用量。不合并不同路径的同物料行，避免层级与用量失去对应。循环、失效或无权限子版本显示明确提示，不能静默改取最新子 BOM。

## 4. 小增量设计

保留既有标准保存/提交接口以及 create_update_version、activate_bom_version、get_bom_versions、get_exploded_structure 的参数和旧返回字段。新增一个只读版本详情接口，不修改标准 BOM 控制器，不引入新组件表。

旧版 BOM/子 BOM、工单及库存链路不回写。前端维护独立的 selected_version 和详情数据，不把所选版本组件写入 frm.doc.items，否则可能污染当前表单和后续保存。

## 6. 启用时间规则

建议新增 BOM 字段 `custom_first_activated_at`：Datetime，只读、no_copy、提交后不允许用户更改。界面标注“首次启用时间”，防止与再次切换默认的时间混淆。

启用定义：该版本首次成功成为已提交、有效的默认 BOM。标准 BOM.on_submit 完成默认管理后，新增文档事件核实 is_active/is_default 与 Item.default_bom 一致，字段为空时写入服务器 now_datetime。写入在提交的同一事务内，失败随事务回滚，不在创建草稿或 before_submit 中提前落地。

覆盖新增版本接口启用与首版标准提交。复制字段必须清空，服务端校验禁止导入/API/UI 伪造时间；使用受控内部标志及字段写入保护，不能仅依赖 read_only。已有时间不因成本更新、保存、取消或默认恢复而覆盖。

历史版本无可靠字段时显示“未记录”；即使单据已提交，也不能推断启用时间等于创建或修改时间。默认不回填历史数据。

现有取消后恢复历史默认仍保留其首次启用时间。首版不新增“每次默认切换时间”及事件流水，也不覆盖标准 manage_default_bom。若以后需审计重复启用时间，应另加启用事件记录，不能把首次时间覆盖成最近时间。

## 7. 新增只读接口与返回

```python
get_bom_version_view(bom, version_bom) -> {
    "summary": {...},
    "items": [{"model": "...", "level": 1, "item_name": "...", "drawing_no": "...", "qty": 1}],
    "costs": {...}
}
```

服务端分别检查基准 BOM 和目标版本的 read 权限；目标必须属于同物料、同公司、同业务编码。版本列表新增分支也按同公司限定，并保留旧字段。无权限版本不出现在选项中，不能通过手工传单号越权读取。

采用明确字段白名单，不直接返回整份 BOM.as_dict。包含版本号、业务编码、真实单号、来源、状态、首次启用时间、产出数量/UOM；组件按树形顺序返回上述五列；成本按标准保存数据返回。不新增工序、废料、工程资料或附件详情返回。具体子 BOM 单号仅作为服务端展开和权限校验依据，不作为可见列。

本页用量口径为选中顶层 BOM 产出数量对应的累计用量，在表格说明中明确，不混用每层局部用量。复用已有展开逻辑及 cumulative_qty，在新增接口中转换五列字段，不修改旧展开接口 qty 的含义。处理子 BOM.quantity 为零的异常。成本属于单据保存的估算，不代表实际库存成本；查看过程不调用成本更新函数。逐层检查子 BOM 读取权限，不能通过展开泄露无权限子版本内容。

列表保留 `is_current` 的原义，追加 `is_current_default` 与 `first_activated_at`，不能将旧字段改为另一种含义。老无版本号单据沿用现有排序兼容规则，标签可补充真实单号避免重复；本次不回写历史版本号。

## 8. 调用链路

```text
BOM refresh → render_versions → get_bom_versions(bom)
  → 服务端权限过滤/同公司同业务链版本列表
  → 前端优先选择当前启用版本
  → get_bom_version_view(bom, selected_version)
  → 两份 BOM 权限及所属链校验 → 只读白名单详情
  → 当前“版本”页签渲染详情

用户选择其他版本 → 只读详情查询 → 替换页签内容
  → 不 save、不 submit、不切默认、不改 frm.doc

已有保存并启用 → activate_bom_version → 标准 submit
  → 标准默认管理 → 新 on_submit 分支核实启用
  → 同事务写首次启用时间 → 返回/刷新版本信息
```

快速切换时使用请求序号，只接受最后一次选择的响应。失败显示明确错误，不残留前一个版本的内容；异步返回前核实当前表单单号未变化。加载期间显示所选版本，禁止将尚未更新的详情误当作新选择。

## 9. 受影响模块与关联处理

| 模块 | 影响及处理 |
|---|---|
| BOM 表单 | 版本页签展示改动；其它页签仍展示当前打开单据，顶部提示所选版本仅作用于版本页签 |
| BOM 默认管理 | 仅追加首次时间记录，沿用标准切换，不主动改默认 |
| 历史版本 | 保持只读、实际单号和未知时间说明，支持打开具体单据 |
| 生产工单 | 原 bom_no、物料需求不改；查看版本不调用工单切换接口 |
| 父子 BOM/缺料自产 | 显示具体子版本链接，不按子物料当前默认替换旧引用 |
| 工程图纸、工序、废料 | 图纸号只读取所选版本对应行；不新增工序/废料/工程资料展示或数据修改，原模块保留 |
| 成本、库存、财务 | 只展示保存的版本成本，不执行成本更新、库存动作或历史重算 |
| 采购、质检、MES | 不改接口/数据链；真实单号继续用于追溯 |
| 权限、导出 | 逐版本 read 校验；标准导出仍导出当前打开单据，不能暗示导出下拉选中版本；需导出所选版本时先打开其详情 |

## 10. 业务流与验收效果

```text
打开统一 BOM 编码详情 → 点击“版本”
  → 默认查看当前启用版 V2 与首次启用时间
  → 选择 V1 → 查看 V1 五列层级组件清单及成本
  → 返回选择 V2 → 展示 V2 清单
  → 查看 V3 草稿 → 显示尚未启用，只读预览

全程当前默认仍为 V2
旧工单仍按 V1 生产；新工单仍按 V2 生产
```

验收至少覆盖：

1. 页签位置正确，下拉列表含可访问的当前、历史、草稿与取消版本，状态区分明确。
2. 组件表严格为型号、层级、物料名称、图纸号、用量五列，数据及成本来自选中版本；多层累计用量换算正确，不展示工序、废料和工程资料区域。
3. 首版标准提交、新版接口启用记录首次时间；草稿不记录，失败不留下时间；修改/成本更新不覆盖时间。
4. 历史未知时间显示未记录，不拿 modified/creation 代替；取消恢复仍显示首次时间。
5. 快速连续切换不串数据，加载/错误/无权限/无可访问默认版本有明确提示。
6. 只读查询前后比较 Item.default_bom、工单 bom_no 与 frm.doc，无变更和脏标记。
7. 越权单号、跨物料/公司/业务链请求被拒绝；展开子 BOM 逐层遵循读取权限。
8. 旧 get_bom_versions 调用仍兼容，原创建/启用/领料接口与钩子保持工作。
9. 桌面和移动端浏览器操作验收，长组件表分页或分段展示不截掉数据。

## 11. 发布、回退与限制

定向安装新增字段、清缓存，先用测试 BOM 验证，业务测试采用回滚或隔离样本。无需为此改动全站业务配置。

回退时恢复原版本表格，停用新增详情与时间钩子；保留时间字段和已有版本数据，不删除 BOM/工单。不新增历史回填，不提供默认恢复按钮，不实现主列表聚合。本方案新增时间字段及事件是为准确显示启用时间所需的最小后台补充，其余以只读前端优化为主。
