# 采购物料表与供应商报价规则小窗优化方案

状态：第二阶段方案沉淀，暂不修改业务代码；文末修订章节优先于前述第一阶段清单

## 1. 目标

在“采购”模块增加独立的“物料表”入口。采购人员点击物料后，不进入完整的物料主数据表单，而是打开采购专用小窗，在小窗内维护供应商关联和供应商报价规则。

本次采用小增量设计：复用现有 `Item`、`Item Supplier`、`Item Supplier Pricing Rule` 和采购比价逻辑，优先新增采购视图、接口和前端分支，不改变现有物料表单、采购比价和采购订单的旧调用接口。

## 2. 预期业务效果

采购人员可以在采购模块内完成以下操作：

1. 查看可采购物料列表。
2. 按物料名称、编码、规格、助记码搜索。
3. 点击物料打开采购专用小窗。
4. 查看物料当前供应商及供应商物料号。
5. 新增或编辑供应商关联。
6. 新增、编辑、停用供应商报价规则。
7. 配置固定价、数量区间价、阶梯价和数量降价规则。
8. 输入测试数量，预览命中档位、计算单价和采购总价。
9. 保存后直接供采购比价和采购订单取价使用。

物料编码、物料名称、库存单位、物料组等主数据在小窗中只读。物料主数据修改仍通过原有物料表单完成。

## 3. 建议入口与界面

### 3.1 采购物料表

新增采购模块入口“物料表”，建议使用独立页面或标准 DocType 列表视图，不替换现有生产、库存或完整物料表。

默认过滤条件：

```text
is_purchase_item = 1
disabled = 0
```

建议列表字段：

| 字段 | 用途 |
| --- | --- |
| 物料编码 | 唯一识别和打开采购小窗 |
| 物料名称 | 采购人员识别物料 |
| 规格型号 | 区分相似物料 |
| 物料组 | 分类筛选 |
| 库存单位 | 显示数量单位 |
| 供应商数量 | 快速判断是否已建立供应商关联 |
| 当前有效报价 | 显示是否存在有效规则 |
| 最近采购价 | 采购参考 |
| 启用状态 | 过滤停用物料 |

### 3.2 采购物料小窗

小窗分为四个区域：

1. **物料信息**：编码、名称、规格、物料组、库存单位，只读。
2. **供应商关联**：供应商、供应商物料号、当前规则摘要、规则状态。
3. **报价规则**：规则类型、币种、计价单位、MOQ、生效/失效日期和数字参数。
4. **价格试算**：测试数量、命中档位、计算单价、总价和提示信息。

供应商新增和报价规则保存应支持同一小窗内完成。编辑已有规则时默认创建新版本，历史规则保留，不直接覆盖已经被采购比价引用的快照。

## 4. 报价规则范围

一期沿用现有报价规则能力，支持：

| 规则类型 | 主要参数 |
| --- | --- |
| 固定单价 | 单价 |
| 数量区间 | 最小数量、最大数量、单价 |
| 阶梯表 | 数量下限、数量上限、单价 |
| 满量降价 | 起始数量、基准价、档位数量、降价比例、最低价 |
| 超额累进降价 | 起始数量、递增数量、降价比例、最低价 |

前端只允许填写数字参数，公式文本由现有安全计算服务生成。服务端重新校验和计算，不能信任前端试算结果。

## 5. 调用链路

### 5.1 打开采购物料表

```text
采购工作区
 -> 采购物料表入口
 -> 采购物料列表接口
 -> 查询 Item（is_purchase_item=1、disabled=0）
 -> 补充供应商数量、有效报价和最近采购价
 -> 渲染列表
```

### 5.2 打开采购小窗

```text
点击物料
 -> 获取 Item 基本信息
 -> 获取 Item Supplier 子表
 -> 获取当前有效 Item Supplier Pricing Rule
 -> 获取报价摘要和历史版本数量
 -> 打开采购物料小窗
```

### 5.3 保存供应商和报价规则

```text
小窗选择/新增供应商
 -> 校验 Item 可采购且用户有采购维护权限
 -> 保存 Item Supplier 关联
 -> 调用现有报价规则预览服务
 -> 服务端重新校验参数
 -> 新建 Item Supplier Pricing Rule 版本
 -> 回写 Item Supplier 当前规则和摘要
 -> 清理 Item、规则和采购推荐缓存
 -> 刷新小窗及采购物料列表
```

### 5.4 采购比价和采购订单

```text
采购申请
 -> Purchase Comparison
 -> 读取当前有效报价规则
 -> 按实际需求数量试算供应商价格
 -> 选择供应商和下单量
 -> Purchase Order
 -> 使用原有取价接口，并增加报价规则复核分支
```

采购物料小窗只维护主数据和报价规则，不直接生成采购订单，不改变采购比价的选商流程。

## 7. 接口兼容策略

1. 不删除或重命名现有 Item、Item Supplier 和报价规则字段。
2. 不修改现有 `run_comparison_for`、采购推荐和采购订单创建方法的必填参数。
3. 新接口通过新增 API 方法提供采购物料列表和小窗上下文。
4. 现有接口返回值只追加可选字段，不改变旧字段含义。
5. 旧物料没有新报价规则时，继续兼容 Supplier Quotation、Pricing Rule 和 Item Price。
6. 采购小窗保存失败时，不能留下半条供应商关联或未完成规则；使用事务或回滚处理。
7. 报价规则保存后只刷新相关物料和供应商缓存，不进行全量重算。

## 8. 权限设计

建议新增两个权限层次：

| 权限 | 能力 |
| --- | --- |
| Purchase User | 查看采购物料、查看供应商和有效报价、试算 |
| Purchase Manager | 新增/编辑供应商关联、保存/停用报价规则、查看历史版本 |

System Manager 保留全部权限。采购小窗不能通过前端绕过服务端权限；所有新增供应商和规则保存接口必须再次校验 Item、Supplier、Item Supplier Pricing Rule 的权限。

## 9. 受影响模块

| 模块 | 影响 |
| --- | --- |
| 采购工作区 | 增加采购物料表入口 |
| 物料主数据 | 保持原页面不变，小窗只读引用基础信息 |
| 供应商 | 复用现有 Supplier，不新增供应商主数据模型 |
| 供应商报价 | 规则维护入口增加采购小窗 |
| 采购比价 | 消费当前有效规则，保存后触发局部刷新 |
| 采购订单 | 继续使用选定供应商和价格，增加来源追溯即可 |
| 采购申请 | 不嵌入报价维护，仅继续进入比价流程 |
| 库存/生产 | 不增加采购小窗入口，不改变其物料页面 |

## 10. 风险与控制

1. **重复供应商关联**：保存前按物料和供应商检查重复，已有记录进入编辑流程。
2. **规则重叠**：调用现有区间重叠校验，阻止同一供应商的有效规则冲突。
3. **报价过期**：小窗显示有效期，比价时再次按日期校验。
4. **权限绕过**：列表可以只读展示，写操作必须由服务端校验。
5. **旧接口回归**：保留旧调用路径，新增分支只在存在报价规则来源时触发。
6. **缓存不一致**：规则保存后只清理相关 Item、供应商规则和采购推荐缓存，并刷新当前页面。
7. **页面性能**：列表只返回摘要；完整规则和历史版本在点击物料后按需加载。

## 11. 验收标准

1. 采购用户能打开采购物料表并搜索可采购物料。
2. 点击物料只打开采购专用小窗，不进入完整物料编辑页面。
3. 小窗中的物料基础信息只读。
4. 有权限的采购人员可以新增供应商关联。
5. 有权限的采购经理可以保存固定价、区间价和阶梯价规则。
6. 试算结果与服务端计算结果一致。
7. 保存后采购比价能读取新规则并按需求数量计算价格。
8. 原有物料表单、供应商报价单、采购比价和采购订单流程不回归。
9. 无权限用户可以查看授权范围内的信息，但不能保存供应商或报价规则。
10. 历史报价规则和已生成的比价价格快照不被覆盖。

列表视觉沿用图 1 的紧凑表头、行密度、筛选条、分页与横向滚动，但列选采购业务字段，不照搬库存字段。行点击只打开小窗，不能意外跳转完整 Item 表单。小窗区分新增/编辑状态，长内容区滚动、底部提交按钮保持可见，切换供应商或规则类型且有未保存输入时提示确认。主数据只读，已有供应商以可选择行展示，而不是拼成一段摘要。固定单价即报价规则类型之一，不并行建立第二套价格源；编辑已有规则创建新版本，保留历史版本和已生成比价单的价格快照。

默认列表仅展示 `is_purchase_item=1` 且 `disabled=0` 的物料，提供编码/名称、物料组、报价状态筛选；启用状态筛选如需查看停用物料，需另行授权且保存接口始终阻止给停用/不可采购物料新增报价。列表返回总数，供应商数和当日有效报价按页批量查询，避免逐行查库。规格只显示安全文本摘要，所有动态内容在浏览器中转义。

### 13.2 完整调用链路

```text
已有 Buying Sidebar Page 入口
 -> purchase-items 页面筛选/翻页
 -> get_purchase_items（Item 行级权限、分页及批量摘要）
 -> 点击物料 -> get_purchase_item_context（物料、供应商行、当前有效规则）
 -> 选择已有供应商或输入新的 Supplier
 -> preview_item_supplier_rule（原有只读计算服务）
 -> 新采购专用 save_purchase_item_supplier_pricing（单次事务）
 -> 服务端校验权限、采购状态、关联去重、币种/UOM、MOQ 和规则参数
 -> 新供应商才追加 Item Supplier；旧供应商复用其行
 -> 复用 item_supplier_pricing 的规则创建/标准价格同步逻辑
 -> 回写当前版本和摘要 -> 清理相关缓存 -> 刷新本行及小窗
 -> Purchase Comparison 按需求量取有效规则 -> Purchase Order 复核选定价格
```

保存必须原子化：新增关联、规则版本、`Item Supplier` 当前规则引用及标准 `Item Price`/`Pricing Rule` 同步任何一步失败，整次请求回滚，不能留下“只有供应商没有报价”的半成品。旧的 `add_purchase_item_supplier` 维持兼容，但新小窗不调用它；旧的 `get_pricing_dialog_context`、`preview_item_supplier_rule`、`save_item_supplier_pricing_rule` 原签名不变。服务器仍需在试算之后重算和校验，不能信任前端预览。规则保存后不静默修改既有比价快照，比价重算和订单生成时继续使用原有复核机制；先通过回归测试确认现有消费者能够读取新规则，仅在确有缺口时添加可选分支。

### 13.4 权限、关联影响与验收

Page 角色只控制入口，读取仍按 Item 行级权限过滤，供应商/规则信息按各 DocType 的读取权限返回；新增/编辑必须在服务端检查 Item 写权限及规则写权限，不靠隐藏按钮授权。Purchase User 可在授权范围内查看和试算；实际保存由 Item/规则写权限决定；Purchase Manager 与 System Manager 在具备对应写权限时维护规则。供应商主档只链接已有 Supplier，不在此创建。

影响模块为采购菜单、Item 供应商子表、规则版本和标准取价载体、采购比价与采购订单取价；采购申请、正式 Supplier Quotation、生产/库存物料页面及原 Item 编辑页保持既有路径。验收需覆盖：列表筛选/分页总数准确；点击物料仅弹窗；已有供应商编辑和新供应商保存；固定价、区间价与阶梯价试算一致；重复供应商不产生新行；错误保存全回滚；无写权限不能写；新规则被采购比价按需求量读取；旧报价和历史比价不回归。桌面及窄屏用 Playwright 检查小窗内容、滚动、按钮和文字无重叠。
