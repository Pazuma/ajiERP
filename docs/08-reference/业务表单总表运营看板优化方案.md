# 业务表单汇总独立页面优化方案

## 1. 文档目的

在“指标看板”模块下提供独立的“业务表单汇总”页面，与“运营指标看板”并列，集中展示所有已提交业务表单的摘要信息，并支持按业务分类、具体表单、状态、提交人和负责人筛选。所有用户共用同一页面，但数据行、详情、导出均必须遵循后端权限；财务类表单额外限制为仅财务角色和管理员可见。

本方案仅用于评审，当前阶段不修改业务代码。

## 2. 页面结构与需求边界

```text
指标看板
├── 运营指标看板       （保留原功能和布局）
└── 业务表单汇总       （新增独立页面）
```

业务表单汇总采用独立 Frappe Page，顶部显示页面标题和操作区，下方提供筛选栏、紧凑表格、状态标签、分页和可点击单据编号；不嵌入运营指标看板内容区域。

### 2.1 数据范围

- 覆盖已登记的所有业务表单，不直接扫描数据库中所有 DocType。
- 第一版默认展示“已提交”记录；草稿不纳入汇总页，已取消记录作为状态筛选项保留。
- 通过表单注册配置逐步纳入新表单，避免一次性改动所有业务模块。

### 2.2 筛选条件

- 时间范围：提交时间、最后更新时间。
- 业务分类：销售、采购、库存、生产、财务及其他业务分类。
- 具体表单：分类下的具体 DocType/表单名称。
- 单据状态：已提交、处理中、审批中、已完成、已驳回、已取消等。
- 提交人、当前负责人、单号/关键词。
- 查看范围：全部可见、我提交的、我负责的。

### 2.3 权限口径

1. 列表查询在后端执行权限过滤，前端筛选器不能突破权限。
2. 非财务表单：沿用原 DocType 读取权限、User Permission、公司/部门/项目等数据范围，并支持提交人、负责人、审批人或待办关系。
3. 财务表单：在汇总查询入口强制要求财务角色或系统管理员；非财务人员不显示财务分类和具体财务表单，也不能通过接口、导出或链接访问。
4. 打开详情时再次调用原单据权限校验；列表可见不等于详情必然可见。
5. 导出复用列表查询和同一权限过滤，禁止单独形成绕过权限的导出接口。

## 3. 目标页面与字段

新增“业务表单汇总”独立页面，建议字段如下：

| 字段 | 说明 |
|---|---|
| 提交时间 | 原单据提交时间或系统提交时间 |
| 表单分类 | 销售、采购、库存、生产、财务等 |
| 具体表单 | 用户可识别的表单名称 |
| 单据编号 | 原单据 name |
| 单据摘要 | 配置的标题/摘要字段，避免返回全部业务字段 |
| 提交人 | 原单据提交人 |
| 当前负责人 | 负责人、审批人或待办人 |
| 业务状态 | 统一展示状态 |
| 最后更新时间 | 原单据 modified |
| 操作 | 有权限时打开原单据，无权限时提示拒绝 |

默认按最后更新时间倒序，分页返回；不在汇总页复制完整单据和附件。

## 4. 推荐技术方案

采用“独立页面 + 统一查询服务 + 表单注册配置 + 原单据权限复核”的小增量方案：

- 新增表单注册配置，描述 DocType、分类、显示字段、状态映射、负责人来源和财务限制。
- 新增汇总查询服务，将不同 DocType 的摘要字段归一化为统一返回结构。
- 查询服务逐个调用/复用 Frappe 原有权限能力，禁止仅依赖 SQL 条件或前端隐藏。
- 详情跳转继续使用原单据路由和权限校验。
- 第一版采用实时查询；当数据量达到性能阈值后，再新增索引表/异步同步分支，不提前引入重复数据。

## 5. 预期新增或修改代码文件

以下为拟议路径，需结合实际自定义 App 名称落地；当前不创建这些代码文件。

| 文件 | 类型 | 计划内容 |

| `apps/<custom_app>/<custom_app>/page/business_form_overview/business_form_overview.json` | 新增 | 注册独立 Page、标题、模块和角色可访问范围 |
| `apps/<custom_app>/<custom_app>/page/business_form_overview/business_form_overview.js` | 新增 | 独立页面、筛选栏、表格、分页、状态标签、详情跳转和导出入口 |
| `apps/<custom_app>/<custom_app>/api/business_form_overview.py` | 新增 | 汇总查询、筛选参数校验、分页、统一字段归一化、后端权限过滤 |
| `apps/<custom_app>/workspace_sidebar/kpi_dashboard.json` | 局部修改 | 在“指标看板”下增加“业务表单汇总”链接，与运营指标看板并列 |

| `apps/<custom_app>/<custom_app>/tests/test_business_form_overview.py` | 新增 | 权限、筛选、财务隔离、分页、状态和接口兼容测试 |

如果现有项目已有运营看板模块，应复用其页面规范和公共能力，但保持“业务表单汇总”为独立 Page，不把页面内容嵌入原看板。

截图中的现有侧栏入口“业务表单总表”在实施时统一改名为“业务表单汇总”；路由 `business-form-overview` 可保持不变，避免无必要的链接兼容改造。

## 6. 接口兼容与调用链路

### 6.1 新增调用链路

```text
用户点击“指标看板 > 业务表单汇总”
  -> Frappe 打开独立 Page business-form-overview
  -> 前端加载筛选项
  -> 新接口：get_business_form_overview(filters, page, page_size)
  -> 参数白名单与分页校验
  -> 判断用户角色及财务访问资格
  -> 读取表单注册配置
  -> 按 DocType 查询摘要记录
  -> 应用原有读取权限、User Permission、业务数据范围
  -> 统一状态/负责人/摘要字段
  -> 返回 rows、columns、filters、has_more
  -> 点击单号
  -> 原单据路由再次执行 Frappe 权限校验
```

### 6.2 兼容策略

- 不修改现有运营指标接口的参数和返回结构。
- 不修改已有业务表单的保存、提交、审批接口。
- 不把汇总逻辑嵌入现有运营指标看板或单据提交接口，使用独立页面和只读查询分支。
- 若需要在提交后触发刷新，前端采用重新查询或已有事件机制，不改变提交事务。
- 新接口仅增加可选筛选参数；未知字段直接拒绝，避免任意 SQL 条件注入。

## 7. 关键实现规则

### 7.1 表单注册

每个纳入汇总页的表单至少配置：

- `doctype`、业务分类、显示名称；
- 是否财务表单；
- 提交时间、状态、摘要字段；
- 负责人来源（字段、当前审批人、ToDo 或组合规则）；
- 是否允许在汇总页打开原单据；
- 状态值到统一状态的映射。

### 7.2 财务隔离

- 配置统一的财务角色白名单和管理员判断方法。
- 后端在获取分类、具体表单选项和数据行之前执行财务权限判断。
- 非财务用户不返回财务表单名称、数量、单号、摘要、导出数据等侧信道信息。
- 财务角色名称不写散落在前端，集中配置并支持后续增补。

### 7.3 “我负责的”

按注册配置解析负责人，优先级建议为：当前待办/审批人 > 明确负责人字段 > 业务负责人字段。没有负责人规则的表单不强行猜测，应在配置中标记不可用或回退为“我提交的”。

## 8. 受影响模块

- 指标看板 Workspace 侧边栏。
- 新增业务表单汇总 Page 及其前端资源。
- 自定义 App 的只读 API/服务层。
- 各业务 DocType 的读取权限、User Permission、工作流待办数据（只复用，不改规则）。
- 角色与权限配置，尤其财务角色和管理员判断。
- 报表导出/分页能力（若现有组件共享导出逻辑，需要增加权限复用分支）。
- 自动化测试、权限验收数据和相关实施文档。

原则上不影响业务单据创建、编辑、提交、审批和现有指标计算逻辑。

## 9. 实施步骤

1. 盘点全部业务表单和现有权限，形成第一版表单注册清单。
2. 确认财务角色名称、管理员判定方式及各表单“完成”定义。
3. 新增注册配置和后端汇总查询服务。
4. 新增独立 Page、筛选器和表格，接入新接口。
5. 在指标看板 Workspace 增加“业务表单汇总”入口。
6. 接入详情跳转和导出，验证二次权限校验。
7. 按角色建立权限测试账号，验证普通用户、负责人、财务用户、管理员。
8. 灰度启用汇总页，观察查询耗时、权限异常和状态一致性。

## 10. 测试与验收

### 功能

- 菜单下存在“运营指标看板”和“业务表单汇总”两个独立入口，不再显示旧名称“业务表单总表”。
- 打开汇总页不加载或改变运营指标看板内容。
- 可按业务分类和具体表单筛选，具体表单选项随分类联动。
- 可按“我提交的”“我负责的”“全部可见”筛选。
- 提交、处理中、完成、驳回、取消状态显示正确。
- 分页、关键词、时间范围和刷新结果正确。

### 权限

- 普通用户仅看到其原有权限范围内的非财务单据。
- 用户无法通过修改参数、接口、导出或单号直接获取无权记录。
- 非财务用户看不到财务分类、具体财务表单及其任何摘要信息。
- 财务角色和管理员可按授权查看财务单据。
- 列表可见但无详情权限时，点击被拒绝且不泄露字段/附件。

### 兼容与性能

- 现有运营指标接口、单据提交和审批流程回归通过。
- 新接口分页查询，避免一次加载全部业务单据。
- 记录按表单类型统计查询耗时；超出阈值后评估索引表方案。

## 11. 预期效果

- 在独立的业务表单汇总页中快速了解各类业务表单的提交和处理进度。
- 可按业务分类和具体表单定位问题，不需要逐个进入模块查询。
- “我提交的”和“我负责的”事项可直接形成个人待办视图。
- 财务数据与其他业务数据严格隔离，满足角色边界和最小权限原则。
- 不复制业务单据、不改变老接口，新增能力可独立灰度和回滚。
- 通过表单注册配置支持后续扩展，新增表单时主要增加配置和对应状态/负责人映射。

## 12. 待确认事项

- 第一批纳入的具体业务表单清单。
- 财务角色的准确名称及是否包含财务主管、会计、出纳等角色。
- 各表单“已完成”的业务定义和状态映射。
- 无负责人字段的表单是否允许出现在“我负责的”视图。
- 已取消单据是否默认展示，及历史数据查询时间范围。
- 是否允许有列表权限但无详情权限的记录显示单号和摘要；默认建议仅显示系统允许公开的摘要字段。
