# 采购申请供应商比价结果与预选供应商优化方案

## 1. 背景与目标

当前供应商比价主要在 `Purchase Comparison`（采购比价单）中执行。采购人员需要离开采购申请，进入比价单查看每个物料的供应商价格，再决定下单供应商。

本方案拟在采购申请界面增加“供应商比价结果”区域，并增加“预选供应商”字段；生成采购订单时保留该预选信息，同时在采购订单列表/表单中可追溯查看。方案只做小增量扩展，优先新增字段、展示分支和传递参数，不改变现有比价、询价和采购订单接口的既有行为。

## 2. 业务范围

### 2.1 本次支持

- 在采购申请抬头增加“预选供应商”；
- 在采购申请明细下方增加供应商比价结果子表；
- 通过现有采购比价引擎获取每个物料的供应商、数量、单价和总价；
- 允许采购人员查看并确认预选供应商；
- 创建采购订单时优先使用预选供应商；
- 采购订单保存采购申请阶段的预选供应商；
- 保留现有系统日志、操作记录和来源关联。

### 2.2 本次不改变

- 不删除或替换 `Purchase Comparison`；
- 不修改现有供应商报价、价格规则、历史采购价的取价规则；
- 不修改原有采购订单创建接口的必填参数和返回结构；
- 不强制所有采购申请必须选择预选供应商；
- 不在第一阶段实现复杂的全局供应商组合优化。

## 3. 建议的数据模型

### 3.1 采购申请抬头字段

新增字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `custom_preferred_supplier` | Link: Supplier | 本采购申请的预选供应商，可为空 |
| `custom_comparison_status` | Select | 未执行、已执行、需重新比价 |
| `custom_last_comparison` | Link: Purchase Comparison | 最近一次采购比价单，可为空 |

第一阶段只要求 `custom_preferred_supplier`；状态和比价单关联字段用于避免展示旧结果，建议一并预留。

### 3.2 采购申请供应商比价结果子表

新增子表 DocType，建议命名为 `Material Request Supplier Comparison`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `material_request_item` | Data/Link | 对应采购申请明细行标识 |
| `item_code` | Link: Item | 物料编码 |
| `item_name` | Data | 物料名称 |
| `required_qty` | Float | 本次需求数量 |
| `supplier` | Link: Supplier | 候选供应商 |
| `recommended_qty` | Float | 推荐采购数量 |
| `recommended_rate` | Currency | 推荐单价 |
| `recommended_total` | Currency | 推荐总价 |
| `price_source` | Data/Select | 报价单、价格规则、Item Price、历史采购价等 |
| `supplier_quotation` | Link: Supplier Quotation | 报价来源，可为空 |
| `purchase_comparison` | Link: Purchase Comparison | 比价来源 |
| `is_best_item` | Check | 是否为该物料推荐供应商 |
| `selected` | Check | 是否纳入后续采购订单 |

结果子表只读展示价格字段；`selected` 是否允许手工修改，需要结合现有比价单权限确认。采购申请抬头的预选供应商用于统一选择，结果子表保留每个物料的候选明细。

## 4. 功能与交互设计

### 4.1 采购申请界面

在现有明细表格上方增加“预选供应商”字段，在明细表格下方增加“供应商比价结果”区域。

增加按钮：

```text
执行供应商比价
刷新比价结果
```

首次执行时创建或复用采购比价单，并将结果同步到采购申请结果子表。采购申请物料或数量发生变化后，将比价状态置为“需重新比价”，提示用户刷新结果。

### 4.2 预选供应商选择规则

供应商选择优先级建议为：

```text
明细行预选供应商（后续扩展）
    > 采购申请抬头预选供应商
    > 采购比价单推荐供应商
    > 该物料推荐总价最低供应商
```

第一阶段只实现采购申请抬头级别的预选供应商。抬头字段为空时，继续使用现有比价推荐结果；没有报价的物料仍按现有逻辑标记为无报价，并可创建询价单。

### 4.3 创建采购订单

采购订单创建时新增一个可选参数或上下文值 `preferred_supplier`，不改变旧调用方式：

- 有预选供应商时，优先按该供应商生成订单；
- 预选供应商无对应有效报价时，提示用户确认，不能静默使用过期或无效价格；
- 未填写预选供应商时，完全沿用原有选中行和推荐供应商逻辑；
- 生成订单后记录采购申请、采购比价单和预选供应商来源。

采购订单增加字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `custom_preferred_supplier` | Link: Supplier | 采购申请阶段的预选供应商 |
| `custom_material_request` | Link: Material Request | 来源采购申请（如现有字段不足则新增） |
| `custom_purchase_comparison` | Link: Purchase Comparison | 来源采购比价单（如现有字段不足则新增） |

标准 `supplier` 字段仍表示实际下单供应商。若后续人工改换供应商，标准供应商记录实际结果，预选供应商字段保留原始决策。

## 5. 调用链路

```text
采购申请打开/保存
    ↓
读取采购申请物料明细和未下单数量
    ↓
执行供应商比价（复用现有 Purchase Comparison）
    ↓
purchase_comparison.py 读取价格规则、供应商报价、Item Price、历史采购价
    ↓
生成 Purchase Comparison 明细及供应商汇总
    ↓
将候选结果映射到采购申请供应商比价结果子表
    ↓
用户选择/确认预选供应商
    ↓
创建采购订单草稿
    ↓
优先应用预选供应商，保留实际供应商和来源关联
    ↓
采购订单列表/表单展示预选供应商
```

## 7. 受影响模块

| 模块 | 影响 | 处理方式 |
|---|---|---|
| 采购申请 | 增加预选供应商和比价结果展示 | 新增字段/子表，旧明细保留 |
| 采购比价 | 被采购申请调用并提供结果映射 | 复用现有取价和推荐逻辑 |
| 询价单 | 无报价物料仍可创建询价 | 不改变现有入口 |
| 供应商报价 | 作为价格来源展示 | 不改变报价提交流程 |
| 采购订单 | 记录预选供应商和来源 | 新增可选字段，兼容旧订单 |
| 采购订单列表 | 支持查看预选供应商 | 增加列表字段/筛选字段 |
| 权限与日志 | 记录选择、刷新和下单动作 | 复用 Frappe 文档版本和活动日志 |
| 报表/接口 | 可能读取采购订单字段 | 新字段为空时保持旧结果 |

## 8. 兼容与风险控制

1. 现有比价单仍是价格计算唯一来源，采购申请只保存展示快照和关联关系。
2. 所有新增参数使用可选参数，旧接口不传参时行为完全不变。
3. 预选供应商无有效报价时必须明确提示，不自动使用失效价格。
4. 重新比价前提示用户：旧的比价结果和手工勾选可能被刷新。
5. 采购订单的实际供应商与预选供应商分开保存，避免后续改供应商后丢失决策记录。
6. 价格、数量、币种和有效期仍由现有公式价格核验逻辑负责。

## 9. 预期效果

实施后，采购人员无需离开采购申请即可看到每个物料对应的供应商、报价数量、单价、总价和推荐状态，并可设置预选供应商。

生成采购订单时，系统在有预选供应商的情况下优先按预选结果处理；没有预选供应商时保持现有比价推荐逻辑。采购订单同时保留实际下单供应商、原始预选供应商、采购申请和采购比价单，形成完整的追溯链路。

验收重点：

- 多个供应商报价能按物料正确展示；
- 无报价物料不会生成虚假价格；
- 预选供应商能传递到采购订单；
- 预选供应商为空时旧流程结果不变；
- 修改采购申请数量后能提示重新比价；
- 采购订单列表可查看和筛选预选供应商；
- 选择、刷新、生成订单等操作均保留系统日志。
