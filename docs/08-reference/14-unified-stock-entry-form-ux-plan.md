# 统一出入库表单体验优化方案

版本：v1.0  
状态：方案确认中，尚未实施  
适用范围：ERPNext `Stock Entry`（物料出/入库）及采购收货入口

## 1. 背景

现有“新建物料出/入库”页面同时展示了库存移动的业务字段、ERPNext 原生字段及 Excel 历史导入字段。字段纵向堆叠，且“出库类型”“入库类型”“出库单号”等概念并列，用户需要先理解系统内部数据结构才能录入单据，页面主次不清。

本方案将新建单据的操作收束为“方向 -> 原因 -> 关联单据 -> 物料明细”，并将历史导入追溯信息移出主流程。

## 2. 已确认的产品决策

| 主题 | 决策 |
| --- | --- |
| 类型入口 | 合并现有“出库类型”和“入库类型”为一个 `出/入库方向` 字段，值为“出库”“入库”。 |
| 原因选择 | 新增或重命名为 `出入库原因`，其候选项由方向联动过滤。 |
| 单号 | 新建单据由系统自动生成编号，用户不手工填写。 |
| 历史单号 | `出库单号`、`镜片入库单/退料单`等 Excel 导入追溯字段保留数据，不作为新单据录入字段。 |
| 采购入库 | 业务入口保持为“采购收货单”；界面可在统一的出入库导航中呈现，但后台不把采购收货硬改为库存移动单。 |
| 内部调拨 | 不归入出库或入库。应作为独立的“内部调拨/仓库调拨”入口或第三种方向处理。 |

## 3. 新建单据的目标交互

### 3.1 主流程

```text
选择出/入库方向
        -> 选择该方向下的出入库原因
        -> 系统确定库存业务类型、必需关联单据和仓库规则
        -> 填写物料明细
        -> 保存草稿 / 提交
```

### 3.2 建议页面布局

```text
[基本信息]
公司 | 出/入库方向 | 出入库原因 | 出入库日期 | 单号（系统生成，只读）

[关联单据]（按原因动态显示）
生产类：生产工单
采购类：供应商、送货单、采购订单 / 采购收货单
外发类：外发采购单或外发单
借样类：样品借出 / 借入单

[物料明细]
物料编码 | 物料名称 | 数量 | 单位 | 源库位 | 目标库位 | 批次/序列号

[补充信息]（默认折叠）
操作员 | 对账日期 | 机种 | 备注 | 历史导入信息
```

页面保持双列栅格：业务核心字段优先显示在首屏，物料明细紧随其后；不再将十余个低频字段以单列连续排列。关联单据区只显示当前原因需要的字段，避免空字段造成视觉干扰。

## 4. 方向与原因映射

以下为第一版建议。最终名称应以实际业务术语确认后固化。

| 出/入库方向 | 出入库原因 | ERPNext 底层用途 | 关联字段 / 规则 |
| --- | --- | --- | --- |
| 出库 | 生产领料 | `Material Issue` | 生产工单；填写源库位 |
| 出库 | 生产补料 | `Material Issue` | 生产工单；填写源库位 |
| 出库 | 外发领料 | `Send to Subcontractor` | 外发采购单；填写源库位 |
| 出库 | 产线借用 | `Material Issue` | 借用对象或关联工单；填写源库位 |
| 出库 | 其他领用 | `Material Issue` | 领用部门/人员或备注；填写源库位 |
| 入库 | 生产退料 | `Material Receipt` | 生产工单；填写目标库位 |
| 入库 | 生产入库 | `Manufacture` | 生产工单；原料消耗与成品入库按现有生产流程处理 |
| 入库 | 借样归还 | `Material Issue` 或借样回库专用流程 | 必须关联样品借入单；库存方向按现有借样设计执行 |
| 入库 | 采购入库 | `Purchase Receipt` | 供应商、送货单、采购订单；不直接创建 `Stock Entry` |
| 独立入口 | 内部调拨 | `Material Transfer` | 同时要求源库位与目标库位 |

“生产入库”和“借样归还”的底层流程不能仅根据中文名称判断，实施前需复核当前 ERPNext `purpose`、样品模块和生产工单的既有校验；界面层可统一为“原因”，不改变已有库存会计逻辑。

## 5. 单号策略

`Stock Entry` 已配置 ERPNext 命名系列，当前可见格式为 `MAT-STE-.YYYY.-`。新表单应：

- 将“单号”显示为只读提示，例如“保存后自动生成”；首次保存后显示实际编号。
- 继续使用 `Stock Entry.name` 作为库存移动业务单号，避免新增平行编号来源。
- 采购入库使用 `Purchase Receipt.name` 的命名系列。
- 历史 Excel 中的 `custom_excel_outbound_no`、`custom_excel_lens_receipt_no` 仅用于导入记录查询、对账和追溯，不参与新建单据编号。
- 如未来需要更易识别的编号前缀，应通过 ERPNext Stock Settings 的命名系列配置处理，而不是由前端拼接编号。

## 6. 字段分层与迁移原则

### 6.1 首屏保留字段

- 公司
- 出/入库方向
- 出入库原因
- 出入库日期、时间
- 单号（只读）
- 当前原因所需的关联单据

### 6.2 明细区保留字段

- 物料、数量、单位
- 源库位或目标库位，按方向显示
- 批次、序列号、成本等 ERPNext 需要的字段

### 6.3 默认折叠的补充字段

- 操作员、机种、对账日期、备注
- 送货单、供应商等不适用于当前原因的字段
- Excel 导入来源行、原始数量、原始单号、历史分类和历史说明

### 6.4 不删除的历史字段

现有 `custom_excel_*` 字段承载导入映射、报表和历史数据，第一期不删除、不改字段名、不改变旧报表口径。实施时仅调整其展示位置、只读属性和新建表单的显示条件。

## 7. 技术实施边界

- 不修改 ERPNext 核心 `Stock Entry` DocType；通过自定义字段、Property Setter、Client Script 和自定义 app 服务实现。
- `出/入库方向` 可以是界面层字段；保存时由“原因”映射到既有 `Stock Entry Type` 与 `purpose`，避免破坏库存账务、报表和导入。
- 原项目已限制可见的 `Stock Entry Type`，并维护“类型 -> ERPNext purpose”映射。新交互应复用这一映射，而不绕过它直接写入 `purpose`。
- 原有 Excel 导入保持兼容：导入数据可继续直接写入既有 `stock_entry_type` 和 `custom_excel_*` 字段；新建手工单据不显示这些导入字段。
- `Purchase Receipt` 和 `Stock Entry` 仍为不同的后台单据类型。统一的是用户入口和交互语言，不是把两类库存业务强行合表。

## 8. 实施分期

### 第一期：表单降噪与基本联动

1. 增加 `出/入库方向` 与 `出入库原因` 的界面字段。
2. 按方向过滤原因，按原因映射现有 `Stock Entry Type`。
3. 将自动编号改为只读展示；隐藏新单据中的历史导入单号字段。
4. 对字段分区、双列布局和“补充信息”默认折叠进行调整。

### 第二期：原因驱动的业务校验

1. 按原因动态显示并校验生产工单、供应商、采购单、借样单等关联字段。
2. 依据方向自动设置源库位/目标库位的必填规则。
3. 从统一入口跳转或创建采购收货草稿，保留来源关系。

### 第三期：入口与报表统一

1. 统一出入库列表的筛选和展示语言。
2. 将历史“出库清单”“入库清单”报表统一按方向、原因、单号检索。
3. 评估是否需要按原因配置默认仓库、审批流和打印模板。

## 9. 验收标准

1. 新建库存移动单时，用户在首屏可完成方向、原因、日期和关联单据选择。
2. 选择“出库”后只出现出库原因和源库位规则；选择“入库”后只出现入库原因和目标库位规则。
3. 切换方向时，不兼容的原因、关联字段和仓库值被清空并给予明确提示。
4. 保存前不要求手填业务单号；保存后系统生成唯一单号。
5. 采购入库仍能完整保留供应商、采购订单、送货单、质检和应付关联。
6. 已导入的历史数据、导入任务和现有出/入库报表保持可查询，字段映射不失效。
7. 原有生产、外发、样品借用和调拨的库存校验与账务方向不发生变化。

## 10. 实施前待确认项

1. “生产入库”是否只允许从生产工单创建，还是允许手工补录。
2. “其他领用”是否需要强制选择部门、成本中心或领用人。
3. “产线借用”与“样品借用”是否需要保留不同单据及审批流程。
4. 入库原因中的“采购入库”是否在统一导航中直接跳转至采购收货新建页，或先在统一向导中收集上下文后创建草稿。
5. 是否需要为不同原因设置独立编号前缀，例如生产领料、退料、外发领料。
