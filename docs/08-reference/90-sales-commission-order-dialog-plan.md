# 销售提成单直属入口与订单弹窗方案

日期：2026-10-23。状态：已实施，详见 [实施记录](./91-sales-commission-order-dialog-implementation.md)。下文保留原方案，实际交付及验证范围以实施记录为准。

## 1. 需求与现状

销售模块侧边栏直接显示“销售提成单”，与销售订单、送货单、销售发票同级。进入后按订单展示，点击对应订单打开弹窗设置该订单的提成分配，无须跳到原始提成单表单。

已有 `Sales Commission Sheet` 主/子表、草稿/确认/修订服务、五种基数、回款和发放台账以及个人白名单报表继续复用。当前入口是 `Sales Commission Management` 报表，被 Selling 分组逻辑放入折叠“报表”组；本次以新增 Page 承载交互，不改旧报表接口或统计口径。

“全部”指总监在既有公司、订单授权范围内的全部订单，不通过提成角色绕过原订单权限。毛利基数仍需独立毛利阅读授权。

## 2. 预期页面与业务流

```text
销售侧边栏
  客户
  销售订单
  送货单
  销售发票
  销售提成单  ← 新增直属入口

销售提成单页面
  筛选：公司、订单、客户、日期、提成状态；总监可额外按业务人员筛选
  订单号 | 客户 | 订单日期 | 业务人员 | 提成状态 | 提成金额 | 操作
  SO-001 | 客户A | … | 张三、李四 | 未设置 | — | 设置提成
  SO-002 | 客户B | … | 张三 | 已确认 | 200 | 查看 / 调整提成
```

销售总监：进入页面 → 查询已提交订单（包括未设置提成的订单）→ 点击订单行/“设置提成” → 弹窗填写 → 保存草稿 → 核对计算结果 → 确认提成 → 刷新当前行。

订单号单元格触发提成弹窗，另提供“查看销售订单”链接跳原订单，避免点击同一位置同时跳转和弹窗。未设置金额显示“—”，来源缺失显示原因，不能把未计算当作零提成。

业务员：进入相同页面 → 仅显示已确认且归属本人的提成结果 → 点击订单打开本人只读弹窗。未设置/草稿不向业务员展示他人的分配过程。待复核展示冻结金额、历史支付及提示，不列为可新发放金额。若人员被新版本移除但有历史支付，应保留其支付/待追回结果。

财务：查询已设置的授权订单并只读查看可授权数据；继续通过原台账登记回款、发放和追回，不在本弹窗改比例。

## 3. 弹窗字段与行为

| 区域 | 销售总监 | 业务人员 |
| --- | --- | --- |
| 订单、客户、公司、本位币 | 只读 | 只读显示本人对应订单信息 |
| 计提依据、发放条件、回款含税口径 | 草稿可选，已确认只读 | 不返回规则、基数和比例 |
| 当前计提基数、来源状态 | 按授权显示；手工分支允许填基数及原因 | 不返回 |
| 人员分配表 | 业务人员、个人比例、预计提成、备注 | 只展示本人的提成结果，不展示他人行 |
| 操作 | 刷新试算、保存草稿、确认；已确认提供调整提成 | 只读关闭 |

五种依据：订单未税额、已开票未税额、实际回款、财务确认毛利、手工指定基数。发放条件保留已有三个选项，不另创计算公式。

默认候选人员取订单负责人及销售团队去重，不自动把团队贡献比例用作提成比例。新增额外参与人必须说明原因。公式为基数 × 各人比例 / 100；例如基数10,000元，甲2%、乙1%，提成分别200元和100元；不是把总提成池按2:1拆分。

已确认时必须先点击“调整提成”并填写修订原因；点击调整本身只打开编辑态，保存时才调用现有修订服务。所有金额由服务端计算，确认后保留历史版本，按订单及人员累计扣除历史净发放。

毛利分支先检查独立授权。无毛利权限的总监不能通过弹窗查看或修改毛利版本；展示受限提示，不能返回基数再由前端隐藏。财务批准仍走已有批准接口/表单，不在本期重复制作批准流程。

## 4. 权限及查询分支

- 新 Page 的角色允许销售用户、销售经理、销售总监、兼容提成经理和提成财务进入；角色允许访问页面不等于拥有数据权限。
- 总监查询从已授权 Sales Order 开始，再关联提成状态，保证无提成记录的已提交订单也能出现。分页、计数和筛选在授权之后处理，避免先全表分页再逐行丢弃导致漏单。
- 个人查询必须由服务端根据当前登录用户解析唯一有效 Sales Person；客户端传入 `sales_person`、`personal=false` 或订单号不能提升权限。无法唯一绑定时明确提示管理员修正。
- 个人接口只返回本人计提、可发、净发放、待追回及状态，不返回完整 Document、同事、基数、比例、毛利、来源快照；继续不授予业务员原始提成单的 REST/导出读取权限。
- 财务走独立只读投影；管理写入同时检查总监角色、订单权限、毛利权限、版本及时间戳。没有毛利授权的财务不得通过通用详情读取基数。
- 当前累计仍以公司和本位币分组；首期必选公司，不提供跨币种总金额。

## 6. 新接口及调用链路

以下为建议接口，实施时确定最终参数。GET 只读；写操作 POST。不要在 GET 打开弹窗时调用现有 `create_commission_draft()`，避免浏览即创建空草稿。

```text
Selling 侧栏 -> sales-commission-orders Page
  -> list_commission_orders(filters, start, page_length) [GET]
     -> 服务端角色分支 -> 授权订单/本人人员 -> 分页白名单

点击订单 -> get_order_commission_dialog(sales_order) [GET]
  -> 总监：现有草稿/当前版本白名单，未设置时返回候选与默认值
  -> 业务员：仅本人结果，编辑字段不返回
  -> 财务：只读投影及原台账入口

弹窗刷新试算 -> preview_order_commission(payload) [GET/只读调用]
  -> 校验编辑权限及字段白名单
  -> 在内存构造候选规则 -> sources.get_context + calculate_people
  -> 返回试算及来源指纹，不落库

保存草稿 -> save_order_commission_dialog(payload, modified) [POST]
  -> 授权、锁订单、重读状态
  -> 未设置：create_commission_draft
  -> 已有草稿：检查修改时间，更新允许字段并标准 doc.save
  -> 已确认调整：校验旧版/原因 -> create_commission_revision
  -> doc.save 复用服务端计算、校验，返回新草稿名/modified/投影

确认提成 -> 已有 confirm_commission(name, modified) [POST]
  -> 来源重查、版本锁、固定人员比例与快照
  -> 重新请求详情并刷新订单行
```

试算只接受有限字段：计提依据、发放条件、回款口径、手工基数/原因及人员/比例/备注。拒绝客户端设置 status、active_key、审批信息、employee、beneficiary_user、金额或来源快照。试算不得吞掉 PermissionError；来源不完整只能提示，不能作为零基数确认。

保存/确认分两步：草稿保存成功、确认失败时保留草稿并显示真实状态，不宣称全部失败或全部成功。包装保存中建草稿/建修订及填写明细在同一请求事务完成，失败回滚；多人并发先锁订单再重读，旧 `modified` 拒绝覆盖。客户端一次试算返回晚于下一次编辑时丢弃旧结果；按钮需等待当前请求，服务端继续兜底检查。

## 7. 受影响模块与兼容边界

| 模块 | 影响与边界 |
| --- | --- |
| 销售导航 | 新增同级 Page 链接并固定位置；不能仅写数据库，必须处理启动分组逻辑 |
| 销售订单 | 只读已提交订单；不新增必填、不改提交/取消、不自动建提成 |
| 销售提成 | 新弹窗替代日常跳表操作；底层主子表、版本和公式复用 |
| 人员权限 | 复用用户—员工—业务人员绑定；无授权不返回他人行 |
| 毛利核算/发票 | 只读已有服务；不扩大成本、税费、基数权限，不改核算确认接口 |
| 回款/发放 | 保留既有台账及跨版本累计；本期不新增付款或银行/工资集成 |
| 原报表 | 保留报表路由和筛选，不改其返回契约；直属页不是统计接口重写 |

取消订单不进入“未设置待配置”列表；已存在提成历史的取消订单可通过历史状态查看只读结果，并沿用现有作废/追回流程。第一期不在弹窗另建取消、作废或毛利审批功能。

## 8. 实施与验收

1. 先实现新白名单查询/试算/保存包装服务，验证无权限提升。
2. 新增 Page 和弹窗，复用已存在的确认/修订规则；旧入口继续可用。
3. 幂等注册新 Page，插入 Selling 并调整顶层分组；不删除其他侧栏项。
4. 在测试站点同步 Page/清缓存，按总监、财务、业务员分别验证后写实施记录。

验收重点：

- 销售发票下直接看见“销售提成单”，无须展开报表；刷新/重新登录/重复初始化后位置稳定且不重复。
- 已提交未设置订单可找到，打开关闭弹窗不创建数据；总监可设置多人比例并保存、确认、修订。
- 10,000元基数、2%和1%分别算200元/100元；试算、保存和确认服务端结果一致。
- 业务员只能看本人；伪造角色模式/业务人员/订单号、直调接口及导出均无法拿到他人数据或修改比例。
- 总监角色不额外开放原订单或毛利权限；财务不能通过包装保存修改比例。
- 同订单并发保存/确认、过期时间戳、来源变化、缺失回款/毛利均正确拒绝，不重复创建版本或重复计提。
- 小屏弹窗支持滚动、长人员表可操作；关闭未保存弹窗提醒，保存失败保留输入。
- 原销售订单、报表、提成确认、回款/发放和财务核算回归通过。

## 9. 首期预期效果

总监在销售模块即可按订单完成“找到订单—弹窗设置—核对—确认”，无需先理解底层提成单和报表之间的区别。业务员打开同一入口只看自身结果，财务维持现有核实与发放流程。新增页面及包装分支承担交互，不改老业务接口及既有账务流程。
