# 客户往来对账单 PDF 导出方案

## 1. 状态与目标

本文为实施前沉淀文档。本次目标是在“中国财务 -> 对账单”的已保存客户对账单中提供正式 PDF 导出，格式与现有业务单据导出能力一致，供客户核对、确认和归档。

导出的数据必须来自已保存的 `China Reconciliation Statement` 快照，不在导出时重新查询或重算账务。这样已导出的内容才能与该对账单版本、确认附件和后续审计记录一一对应。

## 2. 使用范围与入口

- 仅适用于 `statement_type = Customer` 的对账单；
- 对账单保存后，在表单“对账”操作组提供“导出客户对账单 PDF”；
- 沿用现有下载接口 `download_saved_customer_reconciliation_statement(statement_name)`，避免影响已经使用该接口的订单/送货对账单；
- Customer 且 `statement_basis = Ledger` 时，使用客户往来对账 PDF 模板；历史 Delivery 快照继续使用原商品/送货模板；
- 仅对用户有读取权限的已保存对账单开放；PDF 中不展示用户无权读取的来源单据内容。

## 3. 数据边界

导出内容由当前对账单的快照字段和子表构成：

| 区块 | 数据来源 | 作用 |
| --- | --- | --- |
| 基础信息 | 对账单主表、Company、Customer | 识别客户、公司、期间、币种和版本 |
| 余额汇总 | 主表余额字段 | 展示期初、本期、截止日期余额 |
| 订单账单明细 | `order_billing_rows` | 展示订单、交付、开票、已结和未结情况 |
| 期初未结账单 | `opening_documents` | 解释起始日前形成且未结的账款 |
| 财务对账明细 | `lines` | 展示本期凭证、借贷及滚动余额 |

订单金额和财务余额的口径必须分开：订单/送货信息用于业务追溯；应收余额以已保存的总账流水快照为准，不得把未开票订单重复计入客户应收。

## 4. PDF 内容

### 4.1 页眉与基础信息

页眉显示“客户往来对账单”、公司名称和对账期间。基础信息至少包括：

- 客户名称；
- 公司名称；
- 对账起始日期和截止日期；
- 币种；
- 对账单编号与版本；
- 凭证数、财务流水行数、订单账单明细数；
- 导出日期。

### 4.2 余额汇总

应展示下列金额：

| 字段 | 口径 |
| --- | --- |
| 期初余额 | 起始日期前的客户往来余额 |
| 本期借方 | 所选期间内总账借方合计 |
| 本期贷方 | 所选期间内总账贷方合计 |
| 所选期间余额 | `本期借方 - 本期贷方` |
| 截止日期余额 | `期初余额 + 本期借方 - 本期贷方` |
| 已结金额 | 对账单订单账单明细的 `paid_amount` 合计 |
| 未结金额 | 对账单订单账单明细的 `outstanding_amount` 合计 |
| 未开票金额 | `订单金额合计 - 已开票金额合计` |

“已结金额”和“未结金额”按订单账单明细的已保存快照汇总，截止日不得晚于该对账单 `to_date`。它们用于说明订单/发票收款状态，不能替代总账的截止日期余额。

### 4.3 订单账单明细

按订单商品行导出，字段包括：

- 订单日期、销售订单、客户订单号；
- 产品编码、产品名称、单位；
- 订购数量、已交数量、已开票数量；
- 订单金额、已开票金额、已结金额、未结金额；
- 关联送货单、销售发票；
- 开票状态、收款状态。

订单行存在时，PDF 应显示该区块和汇总；没有订单行时不输出空表。

### 4.4 期初未结账单

存在期初未结账单时导出：发票日期、销售发票、原始金额、起始日前已结金额、期初未结金额、关联销售订单和送货单。

该区块仅解释期初余额，不能再次并入本期借方或贷方。

### 4.5 财务对账明细

输出已保存的财务流水，字段包括：日期、业务类型、凭证类型、凭证号、科目、摘要、借方、贷方和滚动余额。

PDF 底部再次显示截止日期余额、订单账单已结金额、订单账单未结金额，并保留客户确认/盖章和日期区域。

## 5. 金额与展示规则

1. 金额沿用对账单币种并保留两位小数；负数使用系统现有格式。
2. 已结金额只统计截止日期前有效付款核销的 `paid_amount`；不包含截止日期后的收款。
3. 未结金额为 `billed_amount - paid_amount`，不把未开票订单计为应收。
4. 未开票金额为订单金额减已开票金额，仅反映业务待开票规模。
5. 订单可能对应多张送货单、发票或收款单，PDF 以逗号分隔的关联单据列表展示，不截断为单个单据。
6. 无期初账单、订单账单明细或财务流水时，隐藏对应表格，但仍保留基础信息与余额汇总。

## 6. 实施范围

预计修改：

| 文件 | 改动 |
| --- | --- |
| `client_akivision/utils/customer_reconciliation_pdf.py` | 从已保存客户 Ledger 对账单快照组装基础信息、订单账单、期初账单、已结和未结汇总。 |
| `client_akivision/templates/customer_account_statement_pdf.html` | 扩展 PDF 版式、汇总区和三类明细表。 |
| `china_reconciliation_statement.js` | 保持已保存客户对账单的导出入口；如当前入口不完整，仅补充该按钮的显示条件。 |
| `docs/08-reference/71-customer-account-statement-pdf-export-implementation.md` | 完成后记录实际修改、验证结果和兼容性影响。 |

不修改销售订单、送货单、销售发票、付款单、总账或历史对账单的数据；导出仅读取已保存的快照。

## 7. 验收标准

1. 已保存客户 Ledger 对账单可下载 PDF，文件名包含客户与对账期间。
2. PDF 显示公司、客户、期间、币种、余额摘要、已结金额和未结金额。
3. 有数据时，订单账单明细、期初未结账单和财务对账明细均完整显示。
4. 已结、未结和未开票金额与该对账单 `order_billing_rows` 快照汇总一致。
5. 截止日期余额与主表 `closing_balance` 一致，不因导出时来源单据变化而改变。
6. 历史 Delivery 类型客户对账单仍使用原商品/送货 PDF 模板。
7. 无权限用户无法通过导出接口读取对账单内容。
