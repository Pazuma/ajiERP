# 供应商报价物料关联与波动阶梯价格优化方案

状态：已按方案完成第一阶段代码实现；真实站点迁移和端到端回归待具备完整 Frappe 环境后执行  
目标：让用户在“物料 > 采购 > 物料供应商”中新增或编辑供应商时，通过弹窗先选择报价规则、再填写数字参数，由系统生成可预览、可校验的价格公式；采购比价按需求数量消费对应物料供应商的规则。

## 1. 现状与问题

当前物料采购页使用标准 `Item.supplier_items` 子表，子表 DocType 为 `Item Supplier`，现有字段只有供应商和供应商物料号。`custom_filters/public/js/item.js` 已挂载到物料表单，可在不修改 ERPNext 核心文件的前提下扩展该表格的新增/编辑交互。

仓库同时已有 `custom_filters` 供应商报价价格同步能力：提交 `Supplier Quotation` 后，
同一物料存在多个数量点时生成供应商专属的购买型 `Pricing Rule`；只有一个数量点时生成供应商专属 `Item Price`。采购推荐也会读取已提交供应商报价的数量/价格点。

主要缺口：

1. `Item Supplier` 只有供应商基础关联，没有报价规则入口。
2. 录入报价时不能即时看到公式、命中区间、计算单价和降价百分比。
3. 采购订单使用价格规则后，难以追溯到具体供应商报价及报价行。
4. 报价取消、重报、有效期和多币种/价格表场景需要更清晰的优先级与回滚约束。

### 1.1 本方案的采购比价口径

本需求的核心计算顺序固定为：**先有采购数量，再按该数量计算每个供应商的价格，最后进行比价**。

例如采购物料 A，需求数量为 300：

| 供应商 | 报价规则 | 数量 300 的计算结果 |
| --- | --- | --- |
| 供应商甲 | 1-99：10 元；100-499：9 元；500+：8 元 | 单价 9 元，总价 2,700 元 |
| 供应商乙 | 基准价 10 元，每满 100 个下降 4%，最低 8 元 | 单价 8.80 元，总价 2,640 元 |
| 供应商丙 | 固定单价 9.20 元，MOQ 500 | 推荐数量 500，单价 9.20 元，总价 4,600 元 |

系统不能只比较报价单上展示的第一档单价，也不能只比较单价。默认按满足本次需求和 MOQ 后的推荐采购总价排序，同时展示需求数量、实际推荐数量、计算单价、总价、有效期、交期和付款条件，供采购员最终选择。

### 1.2 比价功能放置位置与模块职责

完整的供应商比价放在**采购申请之后、采购订单之前**，由现有独立单据 `Purchase Comparison` 承担。采购申请提供需求，采购订单接收已经确认的选商结果；不在采购订单内重新建设一套完整比价页面。

| 模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 采购申请 `Material Request` | 确定物料、需求数量、UOM、目标仓库；提供“供应商比价”入口 | 不保存各供应商报价计算结果，不直接选价下单 |
| 供应商比价 `Purchase Comparison` | 获取采购申请剩余数量；代入各供应商公式；比较价格、MOQ、交期和付款条件；选定供应商 | 不产生库存或应付，不替代正式采购订单 |
| 采购订单 `Purchase Order` | 承接选中供应商、最终数量、最终价格及来源；创建前复核价格，之后进入审批、收货和发票流程 | 不负责展示所有候选供应商或重新完成选商 |

标准业务主链路：

```text
采购申请提交
 -> 点击“供应商比价”
 -> 创建或打开 Purchase Comparison
 -> 读取采购申请未下单数量
 -> 按数量计算每个供应商价格并完成比价
 -> 采购员选择供应商
 -> 按供应商生成 Purchase Order 草稿
 -> 按最终数量复核选中供应商价格
 -> 采购订单审批、收货、发票
```

采购订单中的价格复核仅是防止数量变化、报价过期或报价取消导致旧价失效，不是第二次完整比价。若复核失败，应返回比价单重新计算和确认，不能在采购订单中静默切换供应商。

## 2. 推荐业务模型：用户选规则、填参数、系统生成公式

一期将报价规则入口放在物料信息页的“采购 > 物料供应商”表格。用户点击“添加行”或编辑某个供应商行时弹出“供应商报价规则”小窗，按以下顺序操作：

```text
选择供应商
 -> 选择报价规则类型
 -> 小窗按规则类型显示对应数字参数
 -> 输入参数和有效期
 -> 系统生成公式文本及典型数量试算
 -> 校验通过后保存物料供应商行和报价规则
```

小窗顶部必须先展示本次报价归属的基本信息，避免在多个物料或相似供应商之间录错：

| 分组 | 字段 | 类型/状态 | 来源与行为 |
| --- | --- | --- | --- |
| 物料信息 | 物料编码 | Link，只读 | 当前 `Item.name`，可点击打开物料 |
| 物料信息 | 物料名称 | Data，只读 | 当前 `Item.item_name` |
| 物料信息 | 规格型号 | Data，只读，可选 | 当前物料规格/描述摘要，存在时显示 |
| 物料信息 | 库存单位 | Link，只读 | 当前 `Item.stock_uom`，作为数量换算基准 |
| 供应商信息 | 供应商编码 | Link，新增时必填、编辑时只读 | `Item Supplier.supplier` |
| 供应商信息 | 供应商名称 | Data，只读 | 选择供应商后从 `Supplier.supplier_name` 自动带出 |
| 供应商信息 | 供应商物料号 | Data，可编辑 | `Item Supplier.supplier_part_no` |
| 报价规则 | 规则类型 | Select，必填 | 固定单价、数量区间、满量降价、超额累进降价、阶梯表 |
| 报价规则 | 计价单位 | Link，必填 | 默认物料库存单位，可选择合法采购 UOM |
| 报价规则 | 币种 | Link，必填 | 默认公司币种 |
| 报价规则 | MOQ | Float，可选 | 供应商最小采购数量 |
| 报价规则 | 生效日期/失效日期 | Date | 控制规则有效期 |
| 规则参数 | 基准价、档位数量、降幅、最低价或区间表 | 动态数字字段 | 根据所选规则类型动态显示 |
| 计算预览 | 生成公式 | Small Text，只读 | 系统根据参数生成，不允许手工执行代码 |
| 计算预览 | 测试数量、计算单价、总价、命中档位 | 输入 + 只读结果 | 用户输入测试数量后实时试算 |
| 来源 | 来源供应商报价 | Link，可选 | 关联正式 `Supplier Quotation` 作为凭证 |
| 来源 | 备注/附件 | Small Text / Attach，可选 | 保存报价说明或供应商文件 |

物料编码、物料名称、库存单位和供应商名称只用于确认上下文，不允许在报价小窗内直接修改主数据。需要更换物料时退出小窗回到对应物料；编辑已有供应商规则时供应商编码不可变，更换供应商应新增一条 `Item Supplier` 记录。

`Item Supplier` 继续承担“该物料有哪些供应商”的轻量关联。复杂且有生命周期的报价规则建议使用新增独立 DocType `Item Supplier Pricing Rule` 保存，并通过 `item_code + item_supplier_row + supplier` 关联，避免把可变规则 JSON 全部塞入标准子表，也便于权限、有效期、停用和历史追溯。

一条物料供应商记录可有多版报价规则，但同一公司、币种和日期只能有一个生效版本。供应商正式报价单仍可作为规则的来源凭证和附件，不再是唯一的规则录入入口。

建议支持以下规则类型：

| 规则类型 | 用户填写 | 系统生成的公式示例 | 适用场景 |
| --- | --- | --- | --- |
| 固定单价 | 基准数量、单价 | `数量 >= 1 -> 单价 10` | 普通报价 |
| 数量区间单价 | 最小数量、最大数量、单价 | `1 <= 数量 <= 99 -> 10；100 <= 数量 <= 499 -> 9` | 分段报价 |
| 满量降价 | 起始数量、基准单价、每档数量、每档降幅、最低单价 | `单价 = max(基准价 * (1 - floor(数量/档位)*降幅), 最低价)` | 每增加一定数量下降百分比 |
| 超额累进降价 | 起始数量、基准单价、每超出数量、降幅、最低价 | `超出起始量的每 N 个，单价下降 P%` | 超过门槛后持续下降 |
| 阶梯表 | 多行“数量下限 + 单价/降幅” | 按最大匹配下限取值 | 供应商直接给出多档价格 |

公式只能从系统提供的安全函数和字段中组合，用户填写数字和规则参数，不允许直接输入 Python、SQL 或 JavaScript。公式保存为结构化 JSON，展示为只读文本。

`Item Supplier` 建议只追加摘要和关联字段：

| 字段 | 建议 | 说明 |
| --- | --- | --- |
| `supplier` | 沿用标准 Link | 物料对应供应商 |
| `supplier_part_no` | 沿用标准 Data | 供应商物料号 |
| `custom_active_pricing_rule` | 新增 Link | 当前生效的 `Item Supplier Pricing Rule` |
| `custom_pricing_rule_summary` | 新增只读 Data | 表格中显示“区间价 / 满量降价”等摘要 |

`Item Supplier Pricing Rule` 保存规则头信息：物料、供应商、规则类型、UOM、币种、公司、有效起止日期、MOQ、基准价、最低价、参数 JSON、生成公式、启用状态、来源供应商报价。数量区间/阶梯表的多行参数使用子表 `Item Supplier Pricing Tier` 保存，字段为数量下限、数量上限、单价或降幅。

兼容模式：物料供应商未关联新规则时，继续读取现有 `Supplier Quotation`、`Pricing Rule` 和 `Item Price`；不要求历史物料和报价补录规则。

## 3. 公式生成与计算原则

1. 用户选择规则后只填写数字参数，前端实时生成公式、示例结果和校验提示。
2. 服务端重新解析结构化参数并计算，前端结果只用于预览，不能作为最终价格来源。
3. 数量统一换算为 `stock_qty` 后计算，回写报价行和采购订单时换算到采购 UOM。
4. 公式计算必须使用 Decimal/ERPNext 精度规则，明确舍入位数和最低价保护。
5. 计算结果可展开为标准数量阶梯，继续同步为 `Pricing Rule`；无法安全展开的连续公式先在报价中计算命中价，并在采购订单取价分支中调用同一计算服务。
6. 禁止负数数量、负价格、降幅小于 0 或大于 100、档位为 0、最低价高于基准价等非法参数。
7. 同一物料同一报价只能选择一种规则来源，避免固定单价、区间和公式同时竞争。

## 4. 价格计算规则

1. 数量统一换算为 `stock_qty` 后比较；回写报价行和采购订单时再换算到采购 UOM。
2. 区间规则命中：`min_qty <= quantity <= max_qty`；无上限档只检查下限。
3. 同一供应商、物料、价格表、币种、有效期内，区间按报价日期/提交时间倒序取最新有效报价；同一报价内同数量后行覆盖前行。
4. `custom_discount_percent` 仅作为录入辅助，保存时计算并锁定 `rate`，避免采购结算依赖动态基准价。
5. 仍生成标准购买型 `Pricing Rule`（阶梯）或 `Item Price`（单价），不改变 ERPNext 原生取价接口。
6. 规则含仓库、混合物料、赠品、累计历史数量等复杂条件时，一期只提示并跳过自动覆盖，保留原有价格。

## 6. 调用链路

### 6.1 物料页报价规则维护

```text
打开 Item -> 采购 -> 物料供应商
 -> 点击添加行或编辑行
 -> item.js 打开“供应商报价规则”Dialog
 -> 先选择供应商，再选择规则类型
 -> Dialog 动态显示该规则所需数字参数
 -> 调用 preview_pricing_formula（新接口）
 -> pricing_formula.py 校验 schema、生成公式并安全计算
 -> 返回公式、命中规则、单价、降幅、警告
 -> 小窗展示典型数量试算
 -> 保存 Item Supplier Pricing Rule
 -> 回写 Item Supplier.custom_active_pricing_rule 和摘要
 -> 可展开的规则同步为 Pricing Rule / Item Price
```

小窗交互要求：打开后先渲染物料名称等只读基本信息；新增供应商行时，选择供应商后立即带出供应商名称，再选择报价规则。规则类型未选择前不显示无关数字字段；切换规则时清空不兼容参数并二次确认。保存按钮仅在物料、供应商、规则、必填参数、币种、UOM 和有效期校验通过后可用。已有规则的供应商行点击编辑时打开当前规则，可查看历史版本、复制为新版本或停用，不直接覆盖已被采购比价引用的历史版本。

### 6.2 供应商报价单关联

```text
物料供应商报价规则
 -> 可关联 Supplier Quotation 作为来源凭证
 -> Supplier Quotation 提交时继续执行原有同步
 -> 若报价行匹配同一物料 + 供应商，可选择“更新物料供应商规则”
 -> 生成新版本并停用旧版本，不覆盖比价历史快照
```

### 6.3 采购订单消费与追溯

```text
Purchase Order 标准 get_item_details/apply_pricing_rule
 -> 读取供应商专属 Pricing Rule / Item Price
 -> 回写采购订单行 rate
 -> 新增 quotation 来源字段（若标准字段可承载则只补充显示）
 -> Purchase Receipt / Purchase Invoice 沿用标准订单行价格
```

采购订单若启用仓库内同物料合计阶梯价，继续复用既有采购订单专用分支；该分支只消费标准价格规则，不直接依赖新接口。

这里的采购订单只消费已经选定供应商的结果并复核最终价格。所有候选供应商的比较、排序和选商均已在 `Purchase Comparison` 完成。

### 6.4 供应商比价关联

现有 `Purchase Comparison` 从采购申请或 BOM 得到物料需求数量，复用采购推荐引擎读取 `Pricing Rule`、供应商报价和 `Item Price`，再按物料推荐最低价供应商，并按供应商汇总整篮金额。公式报价接入后，比价不能只读取报价行上的静态 `rate`，必须使用每一条需求的实际比较数量试算公式。

```text
采购申请/BOM -> Purchase Comparison.items（物料、需求数量、UOM）
 -> run_comparison_for（保留旧接口）
 -> 采购推荐引擎收集每个物料的供应商有效报价
 -> 新增 evaluate_supplier_formula 分支
 -> 按供应商 + 物料 + 比较数量 + UOM + 日期计算命中单价
 -> 统一单位、币种及价格精度
 -> 写入 Purchase Comparison Row 的报价快照
 -> 按物料总价排序，并按供应商汇总整篮总价/覆盖率
 -> 用户选择供应商或调整下单数量
 -> 新接口 recalculate_comparison_row 重新试算该行及供应商汇总
 -> 创建采购订单前服务端再次计算并校验快照是否仍有效
 -> 将最终数量、单价、供应商报价来源带入 Purchase Order
```

比价必须使用以下数量规则：

1. 初次运行以 `demanded_qty` 作为公式输入，若报价 MOQ 大于需求数量，则以满足 MOQ 的 `recommended_qty` 再试算一次。
2. 用户修改 `order_qty` 后，不能只计算 `order_qty * recommended_rate`；必须重新命中公式并更新单价、总价、节省金额及供应商汇总。
3. 同一物料被多条需求行拆分时，一期按每条需求行分别试算；若采购订单启用“同物料合计阶梯价”，创建订单前按同供应商、同物料合计数量再复核并提示价差。
4. 已过有效期、币种无法转换、UOM 无换算率或公式参数无效的报价不参加推荐，但保留明确的不可用原因。

### 6.5 采购数量驱动的供应商价格生成

新增共享计算入口（名称为拟定，不改变现有接口）：

```python
def get_supplier_prices_for_qty(item_code, qty, uom, company, pricing_date):
    """返回该数量下所有有效供应商的计算价格，仅计算、不保存。"""
```

服务端处理顺序：

1. 将采购数量从需求 UOM 换算为库存数量。
2. 查询该物料所有供应商在比价日期有效的最新报价规则。
3. 对每个供应商分别代入数量；如 MOQ 大于需求数量，使用 MOQ 作为推荐采购数量并重新计算。
4. 将报价币种转换为公司币种，保留来源币种、汇率和计算日期。
5. 计算 `推荐总价 = 推荐数量 × 计算单价`，同时返回交期、付款条件、报价有效期和来源报价单。
6. 按推荐总价排序；最低总价仅作为默认推荐，采购员仍可结合交期、付款条件和供应商表现选择。
7. 结果写入 `Purchase Comparison Row` 快照；价格规则本身仍保存在供应商报价中。

数量发生变化时的行为：

```text
修改采购申请剩余数量 / BOM 数量
 -> 重新运行供应商比价
 -> 所有供应商按新数量重新计算

修改比价行 order_qty
 -> 只重算当前物料下所有候选供应商
 -> 刷新单价、总价、排名和供应商整篮汇总

创建采购订单
 -> 按最终下单数量再次计算选中供应商价格
 -> 与比价快照一致才生成采购订单草稿
 -> 不一致则显示原价、新价及原因，要求重新确认
```

同一供应商、同一物料存在多个有效报价时，按“公司、币种/价格表、有效期匹配后，报价日期和提交时间最新”选择；不得把不同供应商的区间拼接成一套价格，也不得用供应商甲的公式计算供应商乙的价格。

比价行建议新增只读快照字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `supplier_quotation` | Link | 来源供应商报价 |
| `supplier_quotation_item` | Data/Link | 来源报价明细或行标识 |
| `pricing_rule_type` | Data | 本次采用的公式类型 |
| `pricing_formula` | Small Text | 本次生成的可读公式快照 |
| `matched_tier` | Data | 命中的区间/档位 |
| `calculation_qty` | Float | 公式实际使用的标准数量 |
| `source_rate` | Currency | 报价币种下的计算单价 |
| `source_currency` | Link | 报价币种 |
| `exchange_rate` | Float | 比价日使用的汇率 |
| `calculated_at` | Datetime | 试算时间，供过期和重算判断 |

这些字段保存的是比价时快照，不能代替供应商报价原始记录。点击报价单号可回到来源报价；重新运行比价会清空并生成新快照。

## 7. 受影响模块

| 模块 | 影响 | 控制 |
| --- | --- | --- |
| 物料 / Item Supplier | 新增报价规则弹窗、当前规则和摘要 | 标准供应商、供应商物料号字段保留 |
| Item Supplier Pricing Rule | 新增物料供应商规则及版本数据 | 独立 DocType，不修改 ERPNext 核心表结构 |
| 供应商报价 | 作为正式报价凭证和可选规则来源，可生成规则新版本 | 旧报价行按数量点继续同步 |
| Pricing Rule / Item Price | 继续由报价提交同步 | 规则带来源标记，取消时禁用并回滚上一份有效报价 |
| 采购推荐/比价 | 可显示命中区间和报价来源 | 只追加返回字段，旧报表字段不变 |
| 采购申请 | 继续作为比价发起入口并提供剩余需求数量 | 不在申请表内新增完整比价界面 |
| Purchase Comparison | 按需求/下单数量调用公式，刷新逐项排名和供应商汇总 | 保留 `run_comparison_for`，新增行级重算分支 |
| Purchase Comparison Row | 增加报价、公式、档位、币种和计算时间快照 | 只追加只读字段 |
| 采购订单 | 承接选商结果、增强来源展示并做最终价格复核 | 不改原生接口，不承担完整比价 |
| 收货、发票、库存、应付 | 无业务逻辑改动 | 继续以采购订单/收货单为准 |

## 8. 兼容性与增量策略

- 旧 `Item Supplier` 行无需迁移；未绑定新规则时继续走旧价格来源。
- 旧供应商报价 `qty + rate` 数据无需迁移，仍按现有数量点同步。
- 新接口全部使用新增方法名和追加返回字段，旧客户端继续按原字段工作。
- 现有 `sync_quotation_tiers`、取消回滚和手工“Sync Tier Prices”按钮保留，仅把区间解析替换为共享函数。
- 现有 `run_comparison_for`、`create_po_drafts` 参数和返回结构保留；公式结果以追加字段写入比价行。
- 新增 `recalculate_comparison_row`，只供修改 `order_qty` 后局部重算，避免改变旧的整单比价接口。
- 转采购订单前仍调用现有 `create_po_drafts`，在其内部增加公式复核分支；报价已取消、过期或计算结果变化时阻止静默使用旧价并要求确认后重新比价。
- 不删除已有 `custom_tier_sync_status`、Item Price 或 Pricing Rule；历史规则按原 marker 管理。
- 发生校验失败时阻止当前报价提交并指出具体物料/行号；同步异常仍沿用现有“提交成功、状态 Sync Failed、可重试”策略。

## 9. 预期效果

采购员在物料信息的“采购 > 物料供应商”中点击添加或编辑供应商，即可在小窗中选择“固定单价”“数量区间”“每增加 N 个下降 P%”“最低价保护”等规则，只填写数字参数，系统自动生成公式并展示试算结果。例如选择“每 100 个下降 5%，基准价 10 元，最低价 7 元”，系统生成 `单价 = max(10 * (1 - floor(数量 / 100) * 5%), 7)`，并在数量 100、200、500 时显示对应单价。

关闭小窗后，物料供应商表格直接显示当前报价规则摘要；采购员无需离开物料页面另建报价配置。正式供应商报价单可关联并更新规则版本，采购比价、采购推荐和采购订单统一消费当前有效版本，同时历史比价仍保留当时的公式和价格快照。

业务人员从已提交采购申请发起供应商比价，系统依据采购申请的剩余数量一次性算出各供应商在本次数量下的真实单价和总价。完成选商后才生成采购订单；采购订单只复核最终价格并保留采购申请、比价单和供应商报价三层来源，职责清晰且不会出现“订单已经选了供应商，却又在订单里重新比价”的流程冲突。

## 10. 验收场景

1. 同物料三档区间边界分别命中 99、100、499、500，单价准确且无重叠。
2. 两行相同数量时后行覆盖并给出提示；不同 UOM 按库存数量换算。
3. 单档报价仍生成 Item Price，旧采购订单取价不回归。
4. 新报价提交后旧自动规则被禁用；取消后恢复上一张同供应商、公司、币种、价格表的有效报价。
5. 采购推荐显示 quotation 来源与命中区间，既有导出字段仍可用。
6. 非法区间、负数量、折扣与单价冲突、已过期报价均有明确校验或警告。
7. 用户只填写参数不能注入任意代码；公式文本、试算结果和服务端最终价格一致。
8. 满量降价达到最低价后继续增加数量，单价不再下降。
9. 比价需求数量分别为 99、100、500 时，各供应商按各自公式得到正确单价、总价和排名。
10. 修改比价行 `order_qty` 跨越档位后，单价、行总额、节省金额和供应商汇总同步刷新。
11. 从比价创建采购订单前取消或修改来源报价时，服务端发现快照失效并阻止沿用旧价。
12. 创建采购订单后，订单可追溯到 Purchase Comparison 和 Supplier Quotation，数量、单价与最终试算结果一致。
13. 采购申请可以发起或返回同一张未完成比价单；未提交、零星采购或无剩余数量时不能发起。
14. 采购订单页面不出现完整候选供应商比价表；价格失效时提示返回原比价单重新比价。
15. 在物料采购页新增供应商时自动打开报价规则小窗，未选择规则前不显示参数且不能保存报价规则。
16. 选择不同规则时只显示对应参数；合法参数生成的公式和 3 个典型数量试算正确。
17. 保存后物料供应商行显示当前规则和摘要；重新编辑可查看当前版本和历史版本。
18. 修改已被比价引用的规则时生成新版本，旧比价快照不被改写。
19. 物料供应商没有新规则时，原 Supplier Quotation、Pricing Rule、Item Price 取价保持可用。
20. 打开报价规则小窗时，物料编码、物料名称、规格型号、库存单位、供应商编码和供应商名称显示正确；编辑已有行时基本信息与当前物料供应商一致。
21. 新增供应商后选择供应商，供应商名称自动带出；更换物料或供应商只能回到主表操作，不能在小窗内修改只读基本信息。
22. 比价行能够回显小窗保存的物料名称、供应商名称、规则摘要和来源报价单，计算结果与规则小窗测试结果一致。
