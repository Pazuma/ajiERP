# 中国财务凭证回收站方案

版本：v1.0  
状态：方案沉淀，暂不修改业务代码  
范围：中国财务 > 凭证

## 1. 目标与原则

在中国财务凭证区域增加“凭证回收站”，用于查看、恢复和彻底删除被用户移入回收站的凭证。页面字段参考产品截图：凭证日期、凭证编号、删除人、删除时间、操作，并支持批量删除、批量恢复和按期间筛选。

设计原则：

1. 小增量、先新增分支。回收站使用独立 Page、服务和回收站记录，不改造旧凭证查询接口。
2. 保持审计快照不可变。`China Accounting Voucher` 不直接物理删除；回收站保存对原凭证的引用和必要展示快照。
3. 恢复优先恢复“可见性”，不重复过账。恢复后原凭证重新出现在查凭证、汇总表和附件中心。
4. 老接口零侵入。现有 `get_voucher_summary`、凭证账簿、附件中心、`create_voucher_from_source` 和 GL hooks 的参数及返回结构不变。
5. 所有操作服务端鉴权、记录审计日志，并在事务中完成。

## 2. 页面与字段

入口：`中国财务工作台 -> 凭证 -> 凭证回收站`，路由建议为 `/app/china-voucher-recycle-bin`。

页面布局参考截图：顶部显示红色保留策略提示；右侧提供“批量删除”“批量恢复”；主体为紧凑列表；右侧/顶部保留会计期间筛选；底部显示分页大小和总条数。

### 2.1 系统风格适配

回收站页面应与现有“凭证汇总表”和“凭证附件中心”保持同一套 Desk 视觉语言，不复刻截图中的独立品牌皮肤：

- 沿用 Frappe Desk 全局导航、页面标题栏、主题变量和标准按钮尺寸；页面根节点使用独立 `.cf-voucher-recycle-bin` 命名空间，避免污染其他页面。
- 内容区采用浅灰页面背景、白色主列表区域和细灰分隔线；不增加多层嵌套卡片、渐变背景或大面积装饰图形。
- 筛选区使用与“查凭证/凭证汇总表”一致的紧凑横向网格，宽屏一行展示公司、期间、关键词和状态，窄屏自动换行。
- 表头使用现有列表风格的中性/主题色表头，固定行高和列宽；凭证编号使用标准 Link 样式，删除时间和删除人保持普通文本对齐。
- “批量恢复”使用标准次要按钮，“批量删除”使用危险色按钮并配合二次确认；单行操作优先使用图标按钮，悬停显示中文 Tooltip，避免堆叠长文本按钮。
- 红色保留策略提示只表达期限和数量规则，字号、行高与现有提示条一致，不占用过高首屏空间。
- 空状态、加载态、无权限和操作失败提示复用现有页面的状态样式；分页栏沿用附件中心的底部布局。

建议新增样式文件 `china_voucher_recycle_bin.css`，仅定义回收站根节点下的布局、表格和状态样式；不修改全局 Bootstrap/Frappe 选择器。

| 页面字段 | 类型 | 来源/说明 |
| --- | --- | --- |
| 选择框 | Checkbox | 支持全选当前页，批量操作前二次确认 |
| 凭证日期 | Date | 原凭证 `posting_date` |
| 凭证编号 | Data/Link | 原凭证 `statutory_number`，无字号时回退内部编号；点击打开只读详情 |
| 删除人 | Link User | 执行移入回收站的用户，不允许前端指定 |
| 删除时间 | Datetime | 服务端生成 |
| 操作 | Actions | 单条恢复、彻底删除；权限不足时隐藏 |
| 会计期间 | Select/Date | 默认当前期间，可按月或自定义区间查询 |

默认策略：每个账套仅保留最近 15 天数据，最多 500 张；超出数量时按删除时间从旧到新淘汰。策略应放在“中国财务设置”或独立配置中，首期可使用默认值并预留字段。淘汰前必须有审计日志，彻底删除需单独权限。

## 3. 数据模型建议

新增 DocType：`China Voucher Recycle Bin Item`（名称可在实现评审时确认）。建议字段：

| 字段 | 说明 |
| --- | --- |
| `company` | 账套，必填、索引 |
| `voucher` | Link `China Accounting Voucher`，唯一约束 |
| `posting_date` / `statutory_number` | 删除时复制的展示快照，避免原记录变更影响列表 |
| `deleted_by` / `deleted_at` | 操作者和时间 |
| `status` | `In Recycle Bin`、`Restored`、`Purged` |
| `restored_by` / `restored_at` | 恢复审计信息 |
| `purged_by` / `purged_at` | 彻底删除审计信息 |
| `snapshot_json` | 可选，保存字号、摘要、借贷合计等只读展示数据；禁止作为过账来源 |

不建议给 `China Accounting Voucher` 增加可变的删除状态字段，避免触发快照校验、唯一键和下游报表歧义。现有凭证列表查询在实现阶段只需新增“排除存在有效回收站记录”的过滤分支；旧接口默认行为和返回字段保持不变。

## 4. 调用链路

```text
凭证回收站 Page
  -> list_recycle_bin(filters, page, page_size)
  -> 服务端按公司/期间/权限查询 China Voucher Recycle Bin Item
  -> 返回列表、总数、保留策略

查凭证/汇总表/附件中心
  -> 原接口保持不变
  -> 新增可选 include_recycled=false 分支
  -> 默认排除 status=In Recycle Bin 的凭证

凭证详情的“移入回收站”
  -> move_to_recycle_bin(voucher_names)
  -> 校验删除权限、凭证归属、状态和是否存在有效回收记录
  -> 创建回收站记录并写审计日志
  -> 不删除 GL Entry，不调用取消/冲销 hooks

单条/批量恢复
  -> restore_from_recycle_bin(item_names)
  -> 校验恢复权限和账套
  -> 将回收记录标记 Restored
  -> 原凭证重新可见，不重新创建 Journal Entry/GL Entry

定时清理
  -> daily purge_recycle_bin()
  -> 按 15 天/500 张策略选取过期记录
  -> 权限受控地清理回收站记录及其快照附件，保留不可删除的操作日志
```

### 删除语义

“移入回收站”是业务可见性操作，不等同于 ERPNext `cancel`。已过账凭证不能通过回收站规避结账、冲销或审计要求；如产品要求撤销过账，必须继续使用现有冲销流程。草稿凭证可在未来单独支持物理删除，但不应与已过账快照共用接口。

## 6. 受影响模块

| 模块 | 影响 | 控制措施 |
| --- | --- | --- |
| 凭证列表/查凭证 | 默认隐藏回收中的凭证 | 新增过滤分支，保留原参数 |
| 凭证汇总表 | 汇总不重复计算回收凭证 | 服务端默认排除，增加回归测试 |
| 凭证附件中心 | 回收凭证附件默认不可见 | 通过凭证状态过滤；恢复后可见 |
| 总账、现金流、报表 | 不删除、不回滚既有过账数据 | 回收站不写 GL、不触发 hooks |
| 结账/审计 | 仍能追溯删除和恢复行为 | 操作日志不可随回收记录清理 |
| 权限 | 新增查看、恢复、彻底删除权限 | Page 权限 + 服务端权限双校验 |

## 7. 预期效果与验收

- 用户可按期间看到回收站列表，字段与截图一致；空数据有明确空状态。
- 批量恢复后，凭证在查凭证、汇总表、附件中心恢复显示，数量和金额不重复。
- 移入回收站不会改变 Journal Entry、GL Entry、现金流分配或凭证字号。
- 非授权用户无法查看其他账套、恢复或彻底删除记录。
- 重复点击删除/恢复具有幂等性；部分失败返回逐条结果，不影响成功项。
- 定时任务按“15 天/500 张”执行，保留策略提示与实际清理结果一致。
- 老接口的请求参数、默认结果结构和既有页面行为通过回归测试。

### 7.1 页面预期效果

实现后用户进入回收站应获得以下体验：

1. 页面打开即显示中国财务工作台标准标题栏和“凭证回收站”标题；主体列表在首屏可见，不需要先展开复杂面板。
2. 顶部以紧凑提示条明确“仅保留最近 15 天、每账套最多 500 张”，提示颜色醒目但不遮挡筛选控件。
3. 公司、会计期间、凭证号/摘要关键词和状态筛选与现有凭证页面对齐；点击刷新后保留筛选条件并显示加载状态。
4. 列表表头稳定显示“选择、凭证日期、凭证编号、删除人、删除时间、操作”，行间有细分隔线，悬停时有轻微高亮；长编号和人员名称不撑破布局。
5. 未选择记录时批量按钮禁用；选择记录后显示选中数量，恢复和删除均弹出明确的影响范围与不可逆提示。
6. 无数据时保留筛选区和表头结构，在内容区显示居中的标准空状态；加载失败时显示可重试入口，不留下半渲染表格。
7. 在 1200px 以上桌面宽度保持单行筛选和完整操作列；在窄屏下筛选项换行、表格允许横向滚动，按钮和文字不重叠。
8. 恢复成功后给出绿色提示并从当前列表移除该记录；回到查凭证或汇总表即可看到原凭证，金额、字号和附件数量不发生重复。
9. 彻底删除仅对具备权限的用户显示，执行后给出成功/失败条数；审计日志仍可追溯操作者和时间。

## 8. 实施顺序

1. 评审字段、状态、权限和“已过账凭证是否允许移入”的产品规则。
2. 新增 DocType、服务和 Page，先只读列表与恢复能力。
3. 接入凭证入口及可选过滤分支，运行旧接口回归测试。
4. 增加移入回收站、批量操作和每日清理任务。
5. 灰度验证账套隔离、审计日志、结账期间和异常回滚，再决定是否开放彻底删除。
