# 项目协作与财务成本权限隔离方案

日期：2026-10-20  
状态：基础权限隔离已实施；附件分类与多账号验收待补。

## 1. 背景与目标

当前给项目节点分配负责人时，页面出现“负责人无项目读取权限，请先配置项目成员和权限”的提示。项目执行人员需要查看基础信息、处理节点，但不应因此获得项目预算、成本、收入和利润的访问权。

将项目协作权限与项目财务信息权限分开：普通成员能够参与获授权的项目；项目财务信息仅财务和管理员可见。项目负责人身份本身不授予财务信息权限。

本文描述目标行为，不代表当前系统已经实现这些规则。

## 2. 已确认的信息边界

财务敏感范围包括预算总金额、预算明细、材料成本、采购金额、人工成本、工时费率、费用、收入、利润、毛利率，以及可推算上述金额的单价、金额汇总和明细。预算信息与实际成本采用相同的可见性限制。

非财务协作信息包括项目名称、计划日期、项目阶段、节点名称、负责人、权重、进度、业务数量、完成状态和耗时。工时数量可用于协作，费率及工时金额属于财务敏感信息。

## 3. 权限矩阵

| 信息或操作 | 节点负责人／普通成员 | 项目负责人 | 财务、管理员 |
|---|---|---|---|
| 项目基础信息 | 仅参与项目可见 | 仅负责项目可见 | 按项目和公司授权范围可见 |
| 节点、进度、数量、耗时 | 参与项目可见 | 负责项目可见 | 按授权范围可见 |
| 开始、完成节点 | 仅本人负责且符合条件的节点 | 按项目管理权限操作 | 按管理权限操作 |
| 调整节点、权重、负责人 | 不允许 | 按项目管理权限操作 | 按管理权限操作 |
| 预算、成本、收入、利润、费率 | 不可见、不可修改 | 不可见、不可修改 | 按财务授权查看或修改 |
| 成本核算页、财务报表和财务导出 | 不允许 | 不允许 | 按财务授权使用 |
| 关联业务单据 | 检查原业务权限 | 检查原业务权限 | 检查原业务权限 |
| 确认项目结项 | 不因节点负责人身份获得权限 | 按项目管理权限操作 | 按管理权限操作 |

财务可见性不等于财务修改权，也不等于跨公司或全部项目读取权。实施前应核对现有角色，明确实际财务角色和管理员角色名单；不得把所有项目管理角色自动视作财务角色。

## 4. 负责人和项目成员授权

1. 有项目管理权限的人员分配节点负责人，保存成功后建立对应的项目成员关系，授予该项目的基础读取及本人节点操作能力。
2. 接受负责人前检查用户有效性、可用角色及公司范围，不通过全局放开 Project 读取权限解决报错。
3. 项目成员资格不授予整个项目任意写入权限，不授予预算和成本查看权，也不自动授予关联业务单据权限。
4. 更换或移除负责人时，检查其是否仍负责其他节点、是否为项目负责人、是否存在手工成员授权等关系。只有不存在其他访问依据时，才撤销此次分配产生的访问权。
5. 自动授予和撤销应记录来源，保留人工授权；重复保存不重复授权。项目保存失败时不遗留成员权限。
6. 已有项目提供一次可审查的成员关系核对和补齐流程，不扩大无关项目访问范围。

## 5. 页面与使用体验

普通成员和不具备财务角色的项目负责人，保留基础信息、允许访问的项目文件及流程进度；隐藏预算总额、预算明细、成本核算页和其他财务字段，隐藏后不保留空白占位。

项目工作台展示本人或授权范围内的节点、业务状态和数量。例如“生产完成 10/20”“合格入库完成 3/4 行”，不包含单价、金额、成本或利润。

点击关联采购订单、生产工单、销售订单等时，仍按原业务权限检查。无权限时给予明确提示，不为查看项目而自动开放业务单据。已在原业务模块获得的权限继续由该模块管理，本方案不自行撤销或扩大。

业务完成模式继续依据实际业务条件计算节点进度。计算过程可在后台读取必要业务证据，但返回给普通成员的结果必须经过财务信息过滤；不得返回完整业务单据或敏感业务详情。

## 6. 后台保护要求

页面隐藏只负责展示，权限必须在服务端生效。

- 项目详情、列表、搜索、工作台、进度摘要和自定义接口统一检查项目范围与财务信息权限。
- 标准文档读取、子表读取、报表查询和自定义查询均纳入核对，未授权用户的响应中不包含财务字段及预算子表数据。
- 非财务用户保存基础信息或推进节点时，不得修改、清空或覆盖已有财务值。直接提交敏感字段修改应由服务端拒绝。
- 打印、下载、导出、后台导出任务重新检查权限；普通成员只允许获得经过过滤的非财务内容。
- 财务附件、项目文件、预览和下载入口执行文件权限检查；公开文件链接不能承载受限财务资料。
- 评论、变更记录、通知、邮件和异常提示避免暴露金额及财务字段历史值。
- 按用户权限区分缓存，不让财务用户生成的缓存结果被普通成员读取。
- 子表和新增财务字段纳入同一规则，避免新增字段默认公开。

## 7. 建议实施路径

1. 盘点 Project 字段、预算子表、成本核算、工作台、关联摘要、报表、附件与导出入口，形成敏感字段及接口清单。
2. 根据实际角色配置统一的财务权限判断，结合字段权限和服务端接口过滤；若现有数据结构无法可靠隔离，再评估将财务数据迁入独立受限文档。
3. 实现有来源记录的成员授权与回收规则，解决负责人缺少项目读取权限的问题。
4. 调整项目页面和工作台，普通成员使用精简视图，财务使用获授权的完整视图。
5. 检查读取、写入、打印、导出、附件和历史记录全部路径，验证后再上线。

实施应保留现有业务完成规则、节点顺序约束和结项检查，不通过绕过业务校验解决权限问题。

## 8. 验收标准

| 场景 | 预期结果 |
|---|---|
| 分配有效节点负责人并保存 | 自动建立所需项目访问关系，不再出现无项目读取权限提示 |
| 普通成员打开参与项目 | 基础信息和进度可见，预算、成本、收入、利润不可见 |
| 非财务项目负责人打开项目 | 可管理授权范围内的节点，仍不可见财务信息 |
| 财务或管理员打开授权项目 | 可按权限查看财务信息，修改仍按独立授权判断 |
| 无关用户直接访问项目或接口 | 拒绝访问，不返回项目数据 |
| 普通成员直接读取项目、预算子表或工作台详情 | 不返回财务敏感值 |
| 普通成员保存项目或直接提交财务字段修改 | 基础操作可按权限执行；财务值不被覆盖，越权修改被拒绝 |
| 普通成员操作其他人的节点 | 未获管理授权时拒绝 |
| 普通成员点击无权限关联单据 | 不开放业务单据，提示权限不足 |
| 打印、导出、文件下载、历史记录及通知 | 无越权财务信息泄露 |
| 移除负责人但仍有其他访问依据 | 保留其合法访问权 |
| 移除负责人且已无其他访问依据 | 回收自动产生的访问权 |
| 切换用户或角色后使用已有缓存 | 不读取其他权限用户的财务数据 |
| 业务节点满足完成条件 | 正常推进，权限隔离不影响业务计算 |

至少使用管理员、财务、非财务项目负责人、节点负责人和无关用户五类账号验证，覆盖同公司与跨公司访问、页面与直接接口访问。

## 9. 实施记录

- 财务角色采用站点现有的 `Accounts User`、`Accounts Manager`；`System Manager` 和 `Administrator` 作为管理员。未纳入采购、库存、制造和项目管理角色。
- Project 的预算、成本、收入、毛利及工时金额汇总字段设置为字段权限级别 9。财务角色获得该级别只读权限；项目成员和负责人不因协作身份获得财务字段权限。
- Project 读取范围限定为 Project User 成员、项目负责人及项目管理/系统管理员；节点负责人保存后自动建立项目成员关系。系统仅回收带自动授权标记且不再负责其他节点的成员行。
- `Projects User` 获得 Project 基础权限级别的只读能力，权限查询仍按项目成员/负责人/项目管理员过滤；不会获得项目任意写入权。
- 非财务用户提交项目时，服务端拒绝财务值变更；工作台不返回业务详情原始数据或异常信息。项目开发申请 PDF、项目收入明细报表另做财务角色检查。
- 研发项目清单 SQL 增加项目范围过滤，Project 打印在非财务权限下移除敏感字段。
- ERPNext 项目物料跟踪、工时计费汇总报表限定为财务角色；未按项目成员过滤的标准项目汇总限定为项目管理角色。
- 权限 schema 由 `after_migrate` 建立，避免只在当前站点手工配置。

- `test_project_permissions`：3 项通过；`test_project_workbench`：5 项通过；`test_project_cost`：7 项通过。
- 测试站点现有角色已核对，并成功重复执行权限 schema 初始化；研发项目清单查询可执行。

- 项目文件目前没有“财务附件”分类字段。现有 PDF 文件都作为普通项目文件处理，不能可靠区分财务附件；需后续增加分类及对应列表、下载权限，才能完成附件隔离要求。
- 评论/通知历史中的财务字段变更内容、所有自定义导出与打印模板仍需按实际启用配置继续审计。
