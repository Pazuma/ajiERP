# 多层 BOM 与半成品生产闭环实施记录

日期：2026-10-10；站点：aki_test.localhost。

## 已落地内容

- 公司增加“允许分层组装”，默认关闭；工单增加“分层组装”和根/父工单关联。
- 物料增加独立供应方式字段：外购、自制、可外购/可自制。
- 新模式要求关闭多层 BOM 展开，并拒绝与工序半成品跟踪混用；已执行库存操作的旧单不得切换模式。
- 生产领料缺料弹窗新增列表，显示本次需求、可用、缺口、已安排、待安排、供应方式、采购和自产数量及关联单据。
- 服务端按实际库存、其他工单预留和已有补料记录计算数量；重复明细、超量、非直接组件、跨公司仓库和不允许的供应方式会阻断。
- 采购部分创建标准采购申请草稿，并保留现有缺料采购来源字段和分摊明细；自制部分创建标准独立子工单草稿，关联父工单。
- 本次选定自产 BOM 优先使用父 BOM 明细的子 BOM，否则使用物料有效默认 BOM。
- 工单行锁串行处理补料分配，采购与自产待入库量共同抵扣待安排缺口。实际库存仍需正式入库。
- 分层工单增加“本批生产入库”“查看子工单”；保留标准生产入库单生成接口。
- 新模式人工费按本批计划数量比例分摊；子工单通过根工单追溯，禁止重复关联销售订单归集。
- 销售成本的新分支采用根工单已提交成品行实际金额，保留旧工单成本路径。
- 安全库存补货识别本工单尚未履约的补料记录；采购合并下单的来源分摊纳入待入库数量计算。
- 若 BOM/生产入库单要求质检，则新模式必须选已提交的本工单合格质检，按剩余额度校验；从已保存生产入库草稿可创建本批完工质检。
- BOM 结构 API 增加 `cumulative_qty`，保留旧 `qty` 和接口参数不变。

## 首次使用准备

1. 在公司设置勾选“允许分层组装”，仅为准备试用的公司开启。
2. 维护 B、C、D 的供应方式及标准采购许可；维护 B/C 的有效已提交 BOM，并将其关联到 A 的直接 BOM 明细。
3. 新建 A 工单勾选“分层组装”，关闭“使用多层 BOM”；准备实际发料、在制、成品仓库。旧工单继续旧模式。
4. 刷新浏览器加载新增脚本，先按样例验收后再扩大使用。

## 完整业务流示例

A 计划生产 100 套，每套 B×2、C×1、D×3。现有 B=80、C=50、D=300。

1. 提交并开始 A 工单，生成生产领料单；若本次拟领全部计划量，服务端发现 B 缺 120、C 缺 50。
2. 缺料列表中 B 为“可外购/可自制”，填写采购 40、自制 80；C 为“自制”，填写自产 50。
3. 确认后生成 B 的采购申请草稿、B 子工单草稿、C 子工单草稿。原 A 领料单仍未提交。
4. 采购申请经原审批、供应商选择和下单，B 到货质检后将合格 40 正式采购入库。
5. 提交、开始 B/C 子工单；按各自直接 BOM 领料。底层缺料继续使用缺料列表采购或创建下层工单。
6. B/C 生产完工，按本批数量创建生产入库草稿；要求质检时先保存草稿，从草稿创建本批完工质检，填写实际合格/不合格数量并提交。
7. 返回生产入库草稿选择质检单，提交 B 80、C 50 的合格入库，系统更新库存、成本及子工单状态。
8. A 可以先按库存齐套数量人工确认第一批 40 套领料：B80、C40、D120；未补齐前不得提交全量领料。
9. 第一批组装后通过“本批生产入库”输入 40；按适用质检政策完成并提交 A40 入库。
10. 补料正式入库后，继续领用剩余 60 套所需的 B120、C60、D180，组装并提交 A60 入库。
11. 无损耗情况下，A 累计入库100后由标准逻辑完成；存在损耗时按标准产量和损耗规则计算。

现场连续生产可以不搬运半成品，但第7步系统正式入库不能省略。新增补料单据未入库的数量只能减少再次申请量，不能支持上层领料。

## 调用链

`Stock Entry 库存不足 → shortage_dialog 生产场景检查 → 新列表 → get_shortage_details → allocate_shortage（锁工单、重算）→ 标准 Material Request/Work Order.insert → 分配追踪 → 标准采购/生产入库提交 → 既有库存台账、工单同步、财务/MES钩子 → 原工单重新领料 → 分批成品入库`。

关闭公司开关会阻止新切换/新建分层工单，但已经进入执行的新模式单据仍按模式快照继续执行，不通过关闭开关抹除其业务关系。

## BOM 版本更新补充

已按标准修订机制补充 BOM 版本支持：

- `client_akivision/utils/bom.py`：校验修订必须来自已取消的旧版本、型号和业务 BOM 编码一致。
- `client_akivision/client_akivision/api/bom.py`：新增 `get_bom_versions`，返回同物料同业务编码的版本链。
- `client_akivision/public/js/bom.js`：已提交版本显示锁定提示；已取消版本显示“创建修订版本”；新增版本记录表。
- BOM schema：增加 `custom_bom_versions` HTML 只读展示字段。
- `utils/test_bom.py`：增加修订来源型号一致性测试。

实际操作仍是：已提交 BOM 先取消，再点击标准“修订”或新增“创建修订版本”，修改后保存提交。系统使用标准 `amended_from` 产生版本名称，原版本和历史工单不回写；新版本提交后由标准 `is_active/is_default` 逻辑管理后续新工单。正在被生产单据使用的 BOM 不能绕过库存和单据依赖强制取消。

BOM 版本测试 3 项通过，真实站点版本查询和新增字段已验证；未取消当前生产 BOM，也未创建测试版本。
