# 销售订单字段与结算模式调整方案

## 1. 背景

销售订单当前存在三个使用问题：

1. “年份”和“月份”字段显示为 `0`，不能根据订单日期自动填入。
2. 原生“销售团队”模块位于“更多信息”，销售人员在查看订单主要信息时不容易找到。
3. “销售结算模式”字段为只读，销售人员无法在订单中直接选择结算方式。

本方案只描述目标行为和实施方式，确认方案后再修改代码和站点数据。

## 2. 当前实现分析

### 2.1 年份和月份

`custom_excel_year` 和 `custom_excel_month` 是 Sales Order 的 Int 类型自定义字段，最初主要服务于 Excel 导入。当前没有针对 Sales Order 的默认值、日期变更联动或服务端自动派生逻辑，因此新建订单可能显示为 `0`。

建议以销售订单“日期”字段 `transaction_date` 作为唯一来源。

### 2.2 销售团队

`sales_team` 是 ERPNext 原生的 Sales Order 子表，不是新增的自定义业务字段。标准 Sales Order 字段顺序将它放在 `more_info` Tab Break 之后，因此当前页面显示在“更多信息”中。

销售团队表本身应继续使用 ERPNext 原生实现，以保留业务员、贡献比例、佣金率和 100% 分摊校验。

### 2.3 财务结算模式

当前字段 `custom_china_settlement_mode` 在安装元数据中设置为只读。销售订单创建时，服务端根据“中国财务设置”和客户级“销售结算规则”自动计算模式并写入订单。

当前已有的“覆盖结算模式”操作还受到以下限制：

- 只有指定财务角色可以看到操作；
- 只允许草稿订单；
- 已有已提交销售出库后不能修改；
- 必须填写覆盖原因。

因此页面中的灰色不可选状态是现有设计导致的，不是前端加载异常。

## 3. 目标方案

### 3.1 年份和月份自动填充

规则如下：

| 来源日期 | 年份 | 月份 |
|---|---:|---:|
| `transaction_date = 2026-08-28` | `2026` | `8` |

触发时机：

- 新建销售订单时使用订单日期自动填充；
- 用户修改订单日期时同步更新；
- 服务端保存时再次计算，保证 Excel 导入、接口调用和批量操作结果一致。

字段建议继续保留为 Int 类型，并设置为只读展示，避免用户手动填写出与订单日期不一致的值。

历史数据处理：

- 年份或月份为空、为 `0` 的订单，根据 `transaction_date` 补齐；
- 已有非空值但与订单日期不一致的数据，实施前需要确认是覆盖还是保留。

默认建议：正常订单以订单日期为准；历史特殊数据如需保留，应单独登记，不在自动规则中长期保留不一致状态。

### 3.2 销售团队移动到详细信息

调整 Sales Order 的字段布局，将 ERPNext 原生的以下字段移动到“详细信息”Tab：

- `section_break1`：销售团队区块；
- `sales_team`：销售团队子表。

不复制字段、不创建第二张销售团队表，也不改变子表结构。原有数据、业务员查询、贡献比例和佣金计算逻辑全部保留。

布局调整应通过可迁移的 Property Setter/迁移补丁完成，而不是只在单个站点手工拖动字段，避免部署或升级后丢失。

### 3.3 销售人员直接选择结算模式

销售结算模式改为“可编辑下拉框 + 默认值”：

- 字段类型：Select；
- 选项：
  - `直接确认应收`；
  - `对账结算后确认应收`；
- 新建销售订单默认：`直接确认应收`；
- 销售人员可在提交前修改；
- 提交后不可修改；
- 已生成销售出库或销售发票的订单不允许通过普通编辑改变模式。

服务端逻辑调整为：

- 订单已有结算模式时，保留用户选择；
- 订单为空时，写入默认值；
- 不再由公司设置或客户规则无条件覆盖销售人员已选择的值；
- 销售出库、销售结算和销售发票流程继续读取订单最终保存的模式。

现有“中国财务设置”和“客户结算规则”可以保留，后续可作为默认值来源，但不能覆盖销售人员已经明确选择的订单值。

## 4. 权限与状态边界

1. 销售角色可以在草稿订单中选择结算模式。
2. 订单提交后，结算模式作为业务快照保存，不允许普通编辑修改。
3. 已有出库、结算或发票关联的订单不进行模式切换。
4. 如果未来确需修改已提交订单，应另行设计冲销、重开或审批流程，不在本次需求中放开。

## 5. 预期实施步骤

1. 新增 Sales Order 年份/月自动派生的客户端和服务端逻辑。
2. 增加历史 Sales Order 年份/月补齐脚本，并先输出影响数量供确认。
3. 通过迁移补丁调整 `sales_team` 区块到“详细信息”Tab。
4. 修改结算模式字段元数据，增加默认值并取消只读。
5. 调整结算模式服务端解析逻辑，避免覆盖用户选择。
6. 检查销售出库、销售结算、销售发票流程对两种模式的兼容性。
7. 清理缓存并在测试站点验证页面布局和权限。

## 6. 测试与验收标准

### 年份和月份

- 新建订单日期为 `2026-08-28` 时自动显示年份 `2026`、月份 `8`；
- 修改日期后两字段同步变化；
- 通过 Excel 导入或接口创建的订单也能正确生成；
- 历史空值订单补齐成功，数量可核对；
- 年份/月不能被普通用户编辑成与订单日期不一致的值。

### 销售团队

- “销售团队”在“详细信息”中可见；
- 原“更多信息”中不再出现重复表格；
- 可新增、删除和编辑销售团队行；
- 贡献比例不为 100% 时，原有校验仍然生效；
- 已有销售订单的销售团队数据不丢失。

### 结算模式

- 新建订单默认显示“直接确认应收”；
- 销售人员可切换到“对账结算后确认应收”；
- 保存和重新打开后选择保持不变；
- 公司默认设置或客户规则不会覆盖用户已选值；
- 提交后字段不可修改；
- 两种模式分别触发既有的出库、结算和开票流程。

## 7. 实施前需确认

1. 历史订单中已有非零年份/月但与订单日期不一致时，是否统一以订单日期覆盖？
2. “直接确认应收”是否确定为所有公司的统一默认值，还是需要按公司配置默认值？
3. 销售人员是否只允许在草稿阶段选择，还是允许提交前的特定审批状态修改？

本方案默认采用：订单日期派生年份/月、默认“直接确认应收”、仅草稿订单可修改结算模式。
