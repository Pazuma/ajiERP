# 中国财务“税费计算表”方案

## 1. 文档状态

- 阶段：方案沉淀，暂不修改业务代码、数据库和运行站点。
- 目标：在“中国财务 -> 税务”增加“税费计算表”，交互参考众马会计税费计算表，并适配当前 Frappe Desk 视觉规范。
- 原则：小增量、只读测算优先、复用既有税票与总账数据、保留老接口、按税种新增独立计算分支。

## 2. 需求理解

税费计算表是一个按公司和税款所属期查看税种测算结果的工作台，不直接替代税务机关申报系统，也不直接生成或提交会计凭证。

页面左侧提供税种导航，右侧展示当前税种的行次、项目、金额、计算依据和状态。第一期完整支持“增值税计算表”，并提供附加税费、印花税、企业所得税、地方水利建设基金和残疾人就业保障金的可扩展计算器结构。

### 2.1 本期范围

- 新增独立 Page：`china-tax-calculation-sheet`，中文标题“税费计算表”。
- 在中国财务“税务”分组增加入口。
- 提供公司、税款所属期和税种切换。
- 增值税自动读取销项税、可抵扣进项税并计算应纳税额。
- 附加税费以应纳增值税为基础，按公司配置的税率计算。
- 其他税种允许填写或读取计税基础、税率和调整额，显示“测算值”及数据完整性提示。
- 支持刷新、下载和打印；金额明细可钻取到来源报表或单据。
- 不修改现有 `China VAT Ledger`、`China VAT Return Worksheet`、发票导入和抵扣接口。

### 2.2 非目标

- 不自动向税务机关申报、缴税或调用电子税局接口。
- 不自动生成计提税费或缴税凭证。
- 不宣称测算结果等同于正式纳税申报表。
- 不在第一期实现复杂税收优惠、加计抵减、留抵退税、跨地区分摊、汇总纳税等全部法定规则。
- 不重构现有税务发票、抵扣批次、税务科目映射和财务报表。

## 3. 现有能力与复用边界

| 现有能力 | 本功能用途 | 是否修改 |
| --- | --- | --- |
| `China Tax Invoice` | 销项、进项发票金额和税额来源 | 不修改 |
| `China Input Tax Deduction Batch` | 确认所属期内允许抵扣的进项税额 | 不修改 |
| `China Tax Account Mapping` | 税务科目及总账核对 | 不修改 |
| `China VAT Ledger` | 金额钻取和明细核验 | 不修改 |
| `China VAT Return Worksheet` | 增值税申报工作底稿数据对照 | 不修改 |
| `tax_reconciliation.py` | 税票与总账销项/进项税核对 | 复用现有函数；原则上不修改 |
| `GL Entry` | 非增值税税种的计税基础辅助来源 | 只读，不修改 |

增值税可以自动计算；其他税种的数据基础并不完整，因此必须在界面明确显示“自动计算”“需补充”“手工调整”或“仅供测算”。

## 4. 总体设计

采用独立 Frappe Page，而不是新增六个报表。Page 负责税种切换和统一布局，服务端提供单一兼容入口 `get_tax_calculation(company, period, tax_type)`，内部再按税种分派到新增计算器。

```text
get_tax_calculation
  -> VATCalculator
  -> SurchargeCalculator
  -> StampDutyCalculator
  -> CorporateIncomeTaxCalculator
  -> WaterFundCalculator
  -> DisabilityFundCalculator
```

这样新增税种只需注册新分支，不改变既有税种的输入、返回和计算逻辑。

## 5. 税种与计算口径

### 5.1 增值税计算表

| 行次 | 项目 | 默认口径 |
| --- | --- | --- |
| 1 | 本期销项税额 | 所属期内已提交销项 `China Tax Invoice.tax_amount` 合计，并与销项税总账核对。 |
| 2 | 本期可抵扣进项税额 | 所属期为当前期间且状态已抵扣的 `China Input Tax Deduction Batch.tax_amount` 合计。 |
| 3 | 进项税额转出 | 第一阶段默认 0，可由手工调整项录入并留痕。 |
| 4 | 上期留抵税额 | 从上一所属期已确认计算快照读取；无快照时需手工录入。 |
| 5 | 本期应纳增值税 | `max(销项税额 - 可抵扣进项税额 + 进项转出 - 上期留抵, 0)`。 |
| 6 | 期末留抵税额 | `max(可抵扣进项税额 + 上期留抵 - 销项税额 - 进项转出, 0)`。 |

小规模纳税人不能套用一般纳税人口径。服务端根据 `China Finance Settings` 或新增配置识别纳税人类型，进入独立 `small_scale_vat` 分支；未配置时阻止计算并提示完善设置。

### 5.2 附加税费计算表

以本期实际应纳增值税为计税基础，分别计算城市维护建设税、教育费附加和地方教育附加。税率不得硬编码，按公司和生效日期读取配置。

```text
附加税费 = 应纳增值税 × 适用税率 - 减免额 + 调整额
```

### 5.3 其他税种

| 税种 | 第一阶段建议口径 | 风险提示 |
| --- | --- | --- |
| 印花税 | 应税合同/凭证计税金额 × 税率；计税金额可从配置科目汇总或手工录入 | 合同类型和减免政策需人工确认 |
| 企业所得税 | 累计会计利润 + 纳税调整增加 - 纳税调整减少，乘适用税率后减已预缴 | 仅作季度预缴测算，不替代汇算清缴 |
| 地方水利建设基金 | 配置的收入基础 × 地区适用费率 - 减免额 | 地区政策差异大，必须配置生效区间 |
| 残疾人就业保障金 | 上年用人单位在职职工工资总额、人数、安置比例等参数计算 | 人事数据不完整时必须手工补录 |

第一期若缺少可靠基础数据，相关页仍可显示，但状态为“需补充数据”，金额不默认为正式应缴数。

```python

	"is_estimate": True,
	"rows": [
		{
			"line_no": 1,
			"item_code": "OUTPUT_VAT",
			"label": "本期销项税额",
			"amount": 12500.00,
			"source_type": "China VAT Ledger",
			"source_filters": {"direction": "销项"},
			"editable": False,
		}
```

后续新增字段只能采用可选字段，不能改变 `rows` 的既有字段含义。接口只接受白名单税种、`YYYY-MM` 期间和有权限公司，不接受任意 SQL 条件。

## 8. 拟修改代码

### 8.1 统一服务入口

`services/tax_calculation.py`：

```python
import frappe
from frappe import _

from china_finance.services.tax_calculators import CALCULATORS


@frappe.whitelist()
def get_tax_calculation(company, period, tax_type="VAT"):
	validate_company_permission(company)
	year, month = validate_period(period)
	calculator = CALCULATORS.get(tax_type)
	if not calculator:
		frappe.throw(_("不支持的税种"))
	return calculator(company=company, year=year, month=month).calculate()
```

### 8.2 计算器注册表

```python
CALCULATORS = {
	"VAT": VATCalculator,
	"SURCHARGE": SurchargeCalculator,
	"STAMP_DUTY": StampDutyCalculator,
	"CORPORATE_INCOME_TAX": CorporateIncomeTaxCalculator,
	"WATER_FUND": WaterFundCalculator,
	"DISABILITY_FUND": DisabilityFundCalculator,
}
```

每个计算器只负责一个税种。新税种通过新增类和注册项接入，不在一个大型函数中持续追加条件分支。

### 8.3 页面骨架

```javascript
frappe.pages["china-tax-calculation-sheet"].on_page_load = (wrapper) => {
	frappe.ui.make_app_page({
		parent: wrapper,
		title: __("税费计算表"),
		single_column: true,
	});
	new ChinaTaxCalculationSheet(wrapper);
};
```

页面类使用 `frappe.ui.form.make_control` 创建公司和月份控件，通过 `frappe.call` 调用新增接口。下载和打印读取当前内存中的标准结果，不为每种导出格式再写一套计算逻辑。

### 8.4 导航增量

`setup/install.py` 的“税务”分支新增：

```python
("china-tax-calculation-sheet", "税费计算表", "Page"),
```

Workspace 与 Sidebar 的 `link_to` 必须同为 `china-tax-calculation-sheet`，并继续使用现有幂等导航同步函数。

## 9. 调用链路

### 9.1 查询链路

```text
用户点击“中国财务 -> 税务 -> 税费计算表”
  -> Frappe 加载 china-tax-calculation-sheet Page
  -> 默认公司 + 当前税款所属期 + VAT
  -> get_tax_calculation(company, period, tax_type)
  -> 权限、期间、税种白名单校验
  -> CALCULATORS 分派对应税种计算器
  -> 读取税票/抵扣批次/总账/公司税率配置
  -> 返回统一 rows、warnings、status 和来源钻取参数
  -> 页面渲染金额、状态、下载和打印
```

### 9.2 增值税数据链路

```text
销售/采购业务单据
  -> China Tax Invoice / Allocation
  -> China Input Tax Deduction Batch
  -> China VAT Ledger / VAT Return Worksheet / tax_reconciliation
  -> VATCalculator 汇总并交叉核对
  -> 税费计算表
```

### 9.3 后续确认链路

```text
测算结果
  -> 用户核对警告和来源明细
  -> 可选：保存 China Tax Calculation Snapshot
  -> 后续独立需求：生成计提凭证或申报底稿
```

本期到“测算与核对”为止，不自动写入会计凭证。

### 10.1 视觉规则

- 页面内左侧税种菜单宽度约 180px，与内容区使用一条浅灰分隔线，不使用独立浮动卡片。
- 当前税种使用 Frappe 的浅色选中背景和左侧主题色标识。
- 表头使用中性浅灰背景；金额右对齐，项目名称左对齐，行次居中。
- 核心应纳税额行使用加粗文字和轻量背景，不使用整行高饱和蓝色。
- 自动计算金额可点击时显示链接样式，悬停提示“查看来源明细”。
- “需补充数据”“存在差异”“仅供测算”使用标准橙/红/灰状态标签。
- 页面不嵌套卡片；标题字号与系统列表、报表页面一致。
- 1024px 以下税种菜单改为顶部 Select；表格保持最小列宽并允许横向滚动。

| 场景 | 预期效果 |

### 10.3 预期交付效果

交付后，用户在“中国财务 -> 税务”可以直接进入“税费计算表”。页面不新增第二套应用导航，不改变既有报表入口；它以系统原有的页面标题、筛选控件、表格、按钮和状态标签组织税费测算。

默认进入增值税计算表时，财务人员可以在同一屏完成以下工作：选择公司和税款所属期，查看销项税额、可抵扣进项税额、进项转出、上期留抵、本期应纳增值税和期末留抵；点击有来源的金额即可追溯到现有税务台账、抵扣批次或总账核对数据。应纳税额作为结果行突出显示，但仍保持 Frappe 报表的克制样式。

切换到附加税费、印花税、企业所得税、水利建设基金或残保金后，页面保留相同的筛选区、行次表格和操作区，只改变税种计算依据及行次。可靠数据自动带入；缺少配置或来源数据时，页面明确显示“需补充数据”或“仅供测算”，金额展示为 `--`，不制造已计算完成的假象。

预期最终呈现为：

- 一个可日常使用的只读税费测算工作台，而不是静态说明页。
- 一张适合财务核对、打印和导出的紧凑行次表，而不是多层卡片式看板。
- 一条从金额结果返回来源凭据和现有报表的可追溯路径。
- 一个可按税种新增计算器的结构，后续增加税种不需要改动现有增值税或税务单据接口。

## 11. 权限与审计

- 查看：`China Tax User`、`China Finance Manager`、`China Finance Auditor`、`Accounts Manager`、`System Manager`，并叠加公司用户权限。
- 配置税率和计税基础：仅 `China Finance Manager`、`Accounts Manager`、`System Manager`。
- 审计角色只能查看和导出，不能改税率或手工调整。
- 所有查询使用参数绑定；税种、期间、公司和钻取目标均使用白名单。
- 若启用快照，保存计算时间、计算版本、来源摘要、操作人和调整原因；历史快照不可静默覆盖。

## 13. 风险与控制

1. **税法口径风险**：页面必须标注“测算”，正式申报前由财务人员复核。
2. **重复计算风险**：销项按已提交税务发票汇总，进项按已抵扣批次汇总，禁止同时把采购发票税额和抵扣批次重复计入。
3. **纳税人类型风险**：一般纳税人和小规模纳税人走独立分支，未配置时不猜测。
4. **地区政策风险**：附加税、水利基金等税率必须带公司、地区和生效区间，禁止写死在代码中。
5. **期间锁定风险**：若保存快照，已确认期间重算必须生成新版本并记录原因。
6. **性能风险**：默认单月查询；聚合按公司和日期过滤，复用现有索引，禁止一次加载全部发票明细。
7. **样式污染风险**：CSS 全部以 `.cf-tax-calculation-sheet` 开头，不覆盖通用 `.page-form`、`.datatable` 或侧边栏类。

- 附加税费按多税率、生效日期、减免和调整计算。
- 数据缺失时返回 `Incomplete` 和 warning，而非错误的零值。
- 税票与总账核对差异。
- 旧税务接口回归测试保持通过。

- 1440x900、1280x720、768x1024、390x844 下无文本重叠或操作遮挡。

移除新增 Page、计算服务、局部 CSS、配置 DocType 和导航链接，再执行 migrate/build/clear-cache。由于第一期只读测算且不修改老接口、不生成凭证、不改变税票与总账数据，回滚不会影响历史业务数据。

## 17. 待业务确认

- 公司属于一般纳税人还是小规模纳税人，是否可能按期间变化。
- 增值税是否需要纳入加计抵减、即征即退、简易计税和预缴税额。
- 附加税、水利基金的公司所在地、适用税率和减免政策。
- 印花税的应税合同分类和计税数据来源。
- 企业所得税是只做季度预缴测算，还是要覆盖年度汇算清缴。
- 是否需要保存正式计算快照，以及后续是否从快照生成计提凭证。
