# 业务表单总表独立页面优化方案

## 1. 目标

在“指标看板”模块下新增独立的“业务表单总表”页面，与“运营指标看板”并列，不嵌入运营指标看板内容区域。

总表集中展示已提交业务单据的摘要信息，支持按业务分类、具体表单、状态、提交人和负责人筛选；所有用户共用页面，但列表、详情、导出均遵循后端权限。财务类表单固定仅财务角色和系统管理员可见。

本文件为评审方案，当前阶段不修改业务代码。

## 2. 页面结构

```text
指标看板
├── 运营指标看板       （保留原功能和布局）
└── 业务表单总表       （新增独立页面）
```

独立页面建议采用 Frappe 标准 Page，页面风格参考项目列表：顶部标题和操作按钮、横向筛选栏、紧凑表格、状态标签、分页和可点击单据编号。

## 3. 功能范围

### 3.1 数据范围

- 覆盖登记在表单注册配置中的所有业务 DocType。
- 默认只显示已提交单据；已取消作为状态筛选项，草稿默认不显示。
- 不复制完整单据数据，仅返回列表所需摘要字段。
- 默认按最后更新时间倒序分页展示。

### 3.2 筛选项

- 提交时间/最后更新时间范围。
- 业务分类：销售、采购、库存、生产、财务及其他。
- 具体表单：随业务分类联动。
- 单据状态：已提交、审批中、处理中、已完成、已驳回、已取消等。
- 提交人。
- 当前负责人。
- 查看范围：全部可见、我提交的、我负责的。
- 单号或关键词。

### 3.3 权限

1. 后端执行 DocType 读取权限、User Permission、公司/部门/项目等数据范围过滤。
2. “我提交的”按提交人过滤；“我负责的”按负责人字段、当前审批人或 ToDo 规则解析。
3. 财务表单必须同时满足财务角色或系统管理员条件；非财务用户不返回财务分类、表单选项、记录、数量或导出内容。
4. 点击单据编号后再次执行原始单据权限校验；无权时只提示拒绝，不返回字段和附件。
5. 导出复用列表查询服务和同一权限过滤，不能新增绕过权限的导出逻辑。

## 4. 建议字段

| 字段 | 来源/说明 |
|---|---|
| 提交时间 | 原单据提交时间 |
| 业务分类 | 表单注册配置 |
| 具体表单 | DocType 显示名称 |
| 单据编号 | 原单据 name |
| 单据摘要 | 配置的标题、客户、供应商或业务摘要字段 |
| 提交人 | owner 或业务提交人字段 |
| 当前负责人 | 负责人、审批人或待办人 |
| 状态 | 工作流/业务状态统一映射 |
| 最后更新时间 | modified |
| 操作 | 有权限时打开原单据 |

## 6. 调用链路

```text
用户点击“指标看板 > 业务表单总表”
  -> Frappe 打开独立 Page business-form-overview
  -> 前端加载筛选项
  -> 新接口 get_business_form_overview(filters, page, page_size)
  -> 校验参数、用户角色和财务访问资格
  -> 读取表单注册配置
  -> 对每个纳入的 DocType 检查 read 权限
  -> 应用 User Permission、组织/公司/项目数据范围
  -> 按提交人/负责人视图追加条件
  -> 查询已提交单据摘要并统一字段、状态
  -> 返回 rows、columns、forms、categories、分页信息
  -> 用户点击单据编号
  -> 原单据路由再次执行标准权限校验
  -> 有权限打开详情；无权限提示拒绝
```

## 7. 接口兼容策略

- 不修改 `get_kpi_dashboard_data` 及现有运营指标导出接口。
- 不修改销售、采购、库存、生产、财务单据的创建、保存、提交和审批接口。
- 总表使用全新只读接口和独立前端页面。
- 原有运营指标看板不增加总表渲染逻辑，避免页面性能和回归风险。
- 新增筛选字段采用白名单校验；未知参数拒绝或忽略，不拼接任意 SQL。
- 后续新增表单优先通过注册配置扩展，不改动调用方接口结构。

## 8. 受影响模块

- 指标看板 Workspace 侧边栏。
- 新增业务表单总表 Page 及其前端资源。
- 自定义 App 只读 API/服务层。
- 各业务 DocType 的读取权限、User Permission 和工作流待办数据（仅复用）。
- 财务角色配置和管理员判定。
- 列表分页与导出能力。
- 自动化测试、权限验收和实施文档。

运营指标计算、原有 KPI 页面布局、业务单据生命周期和历史接口不应受到影响。

## 9. 小增量实施步骤

1. 盘点并确认第一批业务表单、字段、状态和负责人来源。
2. 确认财务角色名称及管理员判定规则。
3. 新增表单注册配置和后端总表查询接口。
4. 新增独立 Page、筛选栏、表格和分页。
5. 在指标看板 Workspace 增加独立入口。
6. 接入原单据详情跳转和权限二次校验。
7. 复用权限过滤实现导出。
8. 使用普通用户、业务负责人、财务用户、管理员进行验收。

## 10. 测试与验收

### 功能验收

- 菜单下存在“运营指标看板”和“业务表单总表”两个独立入口。
- 打开总表不加载或改变运营指标看板内容。
- 分类与具体表单筛选联动正确。
- “我提交的”“我负责的”“全部可见”结果正确。
- 状态、提交时间、提交人、负责人和更新时间显示正确。
- 分页、刷新、关键词查询和导出正常。

### 权限验收

- 普通用户只看到其原有权限范围内的非财务单据。
- 非财务用户完全看不到财务分类、表单选项和记录信息。
- 财务角色和管理员可按授权查看财务单据。
- 修改接口参数、单号、分页或导出请求不能获得无权数据。
- 列表可见但详情无权时，点击被拒绝且无字段/附件泄露。

### 回归验收

- 运营指标看板原有接口和页面功能保持不变。
- 各业务单据提交、审批和工作流无回归。
- 新接口分页查询，避免一次加载全部单据。

## 11. 预期效果

- 在“指标看板”模块中提供一个独立、统一的业务单据总览入口。
- 用户可按业务分类和具体表单快速定位提交记录及处理状态。
- 个人可直接查看自己提交或负责的事项。
- 财务数据严格按角色隔离，详情和导出均无法越权。
- 原有运营指标看板保持原布局和接口，新增功能可独立灰度、回滚和扩展。
- 通过表单注册配置降低后续新增业务表单的改造成本。

## 12. 待确认事项

- 第一批纳入的全部业务表单清单。
- 财务角色的正式名称和范围。
- 各表单“已完成”的统一映射规则。
- “我负责的”是否以 ToDo/工作流待办为主。
- 已取消单据是否默认展示。
- 无详情权限时列表允许显示的最小摘要字段。
