# 中国财务“凭证附件中心”界面优化方案

> 状态：方案沉淀，暂不修改业务代码  
> 版本：v0.1  
> 页面：`/app/china-voucher-attachment-center`

## 1. 优化目标

将凭证附件中心调整为与当前 Frappe Desk、“查凭证”页面一致的报表工作区，删除右侧辅助栏，让筛选、文件列表和分页占满主内容区。本次优化不改变电子档案数据、上传归档接口和权限逻辑。

## 2. 明确删除内容

截图红框范围整体删除，包括：

- “附件空间”标题和已使用容量。
- 空间进度条。
- “凭证附件”文件夹入口。
- “当前期间”标题及日期范围。
- 右侧栏的边框、背景、固定宽度和响应式折叠逻辑。

删除后不在页面其他位置重复展示空间容量。当前查询期间已经由顶部月份/日期筛选表达，无需再次显示在右侧。

## 3. 目标布局

```text
Desk 页面标题：凭证附件中心                           [上传文件]

[公司] [期间] [起始日期] [截止日期] [文件名/凭证号/摘要] [搜索]

文件名称 | 文件大小 | 文件类型 | 关联凭证 | 上传日期 | 状态 | 操作
----------------------------------------------------------------------
                         居中空状态或附件数据

共 0 条                                             [上一页] [下一页]
```

- 页面使用单列全宽布局，不再使用“主表格 + 右侧栏”的双列网格。
- 文件表格宽度扩展至整个 `.layout-main-section`，操作列保持固定宽度。
- 文件数据采用标准列表行形式，表头在列表滚动时保持可见，行悬停使用系统高亮色。
- 顶部筛选结构参照“查凭证”的灰色标准字段和紧凑间距。
- 空结果使用系统居中图标及“当前期间没有凭证附件”，不在表格单元格中显示简陋空行。
- 上传文件继续作为右上角主操作。

## 4. 交互调整

1. 公司、期间、起止日期和搜索保留在顶部。
2. 期间月份与自定义日期采用互斥模式，避免月份和日期同时生效。
3. 搜字段改变后不自动发起多次请求；通过搜索、回车或刷新统一查询。
4. 分页区域固定在页面内容区底部，显示当前范围和总条数；少量数据或空数据时也不紧跟在首行之后。
5. 上传、预览、下载、关联凭证跳转和验真功能保持不变。
6. 删除右侧栏只影响展示，不删除服务端返回的 `total_size`，以维持旧接口兼容；前端不再消费该字段。

|---|---|---|
| `china_finance/page/china_voucher_attachment_center/china_voucher_attachment_center.js` | 修改 | 删除 aside DOM、空间容量渲染和期间重复渲染，调整为空状态组件 |
| `china_finance/public/css/china_voucher_attachment_center.css` | 修改 | 删除双列网格、右侧栏、进度条和文件夹样式，主表改为全宽 |

不修改 Page JSON、Workspace、侧边栏分类、`China Electronic Document`、Frappe `File` 和归档服务。

## 6. 调用链路

```text
打开附件中心
  -> 创建标准 Desk Page
  -> 渲染顶部筛选 + 全宽表格
  -> get_voucher_attachments（旧接口）
  -> 渲染附件行或居中空状态
  -> 渲染底部分页
```

服务端仍可返回 `total_size`、`from_date` 和 `to_date`，保证其他潜在调用方不受影响；新页面只使用日期字段构造查询状态，不再生成右侧展示。

## 7. 受影响范围

- 直接影响：凭证附件中心页面布局和局部 CSS。
- 不受影响：上传归档、私有文件、附件哈希、验真、公司权限、凭证关联、导航分类和其他中国财务页面。
- 页面路由保持 `/app/china-voucher-attachment-center`。

## 8. 验收标准

1. 红框中的右侧辅助栏及其所有内容完全消失。
2. 文件表格填满原主表和右侧栏释放后的内容宽度。
3. 筛选区、表头、分页和空状态与“查凭证”的视觉语言一致。
4. `1440px`、`1024px` 和移动端下没有残余空列、异常右边距或横向溢出。
5. 上传、查询、分页、下载、凭证跳转和验真功能回归通过。
6. 后端接口参数和返回字段不变，电子档案数据不迁移、不删除。

## 9. 本轮列表与底部分页优化

### 9.1 列表形式

- 文件区继续使用横向字段明确的列表，而不是卡片或文件缩略图宫格。
- 每个附件占一行，列顺序保持：文件名称、文件大小、文件类型、关联凭证、上传日期、状态、操作。
- 表头固定在列表滚动区域顶部；数据行使用系统分隔线和悬停高亮。
- 文件名、凭证号保留可点击链接；文件类型过长时省略并通过 tooltip 查看完整内容。
- 列表自身滚动，页面标题、筛选区和底部分页不会随大量数据产生无序位移。

### 9.2 底部分页

- 红框中的总数和翻页栏放在当前页面内容区底部，不紧跟最后一条附件。
- 列表容器采用纵向 Flex 布局，并以 `min-height: calc(100vh - 页面标题与筛选区高度)` 使用剩余视口空间。
- 分页栏通过 `margin-top: auto` 或等价布局自然贴底，不使用 `position: fixed`，避免遮挡内容或脱离 Desk 主区域。
- 左侧显示“第 1-1 条，共 1 条”，右侧显示上一页、下一页；按钮禁用状态延续现有逻辑。
- 数据超过一页时只滚动列表主体，表头吸顶，分页栏保持在列表底部可见。
- 移动端取消视口强制高度，恢复自然流布局，避免软键盘或小屏导致内容被截断。

## 11. 调用链路与影响

```text
页面加载/执行查询
  -> get_voucher_attachments（不变）
  -> render_rows（不变）
  -> 列表主体根据可用视口高度伸展
  -> footer 在主容器底部显示总数与翻页按钮
```

直接影响仅限附件中心布局 CSS，不改变上传、查询、下载、验真、凭证跳转、权限或电子档案数据。桌面端列表和分页位置发生变化，移动端保持自然滚动。

## 12. 预期效果

优化后，附件中心呈现为与系统标准列表一致的连续行视图：附件字段对齐、表头清晰、行间关系明确。无论当前有 0 条、1 条还是多条数据，红框中的记录总数和上一页/下一页始终位于页面内容区底部，不会悬在页面中部。

在数据较多时，用户滚动的是附件列表主体，仍能看到表头和底部分页；在 `1440px`、`1024px` 桌面视口下页面充分利用纵向空间，在移动端则自动切换为自然高度，避免遮挡或溢出。

## 13. 回滚

仅恢复附件中心 JS 和 CSS 即可恢复旧布局，不涉及数据库或业务数据回滚。
