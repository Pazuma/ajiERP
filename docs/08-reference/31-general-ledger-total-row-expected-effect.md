# 会计总账“总数”行预期效果

## 1. 目标

在中国财务入口打开的现有“会计总账”页面中，于列表表头筛选行之后、当前“期初”行之前插入一条固定的“总数”汇总行。该行只汇总当前筛选条件下的查询结果，不创建新的报表、数据表或接口。

## 2. 预期视觉

```text
┌────┬──────────┬───────────────┬────────────┬────────────┬────────────┬──────────┐
│ 序号 │ 过账日期 │ 科目            │ 借方 (CNY) │ 贷方 (CNY) │ 余额 (CNY) │ 凭证类型 │
├────┼──────────┼───────────────┼────────────┼────────────┼────────────┼──────────┤
│    │          │ 总数            │ CNY 34,560 │ CNY 21,800 │ CNY 12,760 │          │
├────┼──────────┼───────────────┼────────────┼────────────┼────────────┼──────────┤
│ 1  │          │ 期初            │ CNY 0.00   │ CNY 0.00   │ CNY 0.00   │          │
│ 2  │ 2026-08-04 │ 1405 - 库存商品 │ CNY 0.00   │ CNY 2,695  │ CNY -2,695 │ Delivery │
└────┴──────────┴───────────────┴────────────┴────────────┴────────────┴──────────┘
```

视觉规则：

- “总数”行使用与普通行一致的列宽、滚动行为和金额右对齐，不引入独立卡片。
- 行背景使用轻量强调色或加粗字体，和“期初”行有明确区分；不使用高饱和色。
- 序号、过账日期、凭证类型、源凭证业务类型、凭证号、对方科目等明细字段留空。
- 总数行不参与排序、筛选、分页序号和明细点击/钻取。

## 3. 汇总口径

| 列 | 计算方式 |
| --- | --- |
| 借方（CNY） | 当前筛选结果中明细行借方金额之和，不含“期初”行。 |
| 贷方（CNY） | 当前筛选结果中明细行贷方金额之和，不含“期初”行。 |
| 余额（CNY） | 期末余额 = 当前结果的期初余额 + 借方合计 - 贷方合计；不得累计相加每条明细行的余额列。 |

金额币种、精度、负数显示和千分位格式必须复用现有会计总账的 formatter。筛选条件为空或结果为空时仍显示总数行，三项金额显示为 `CNY 0.00`；若现有页面不返回期初余额，则余额按借方合计减贷方合计显示。

## 4. 交互预期

```text
调整公司 / 账簿 / 日期 / 科目 / 凭证号筛选
        -> 复用现有会计总账查询
        -> 返回期初与明细行
        -> 前端或兼容的新分支计算总数行
        -> 总数行固定显示在期初行前
```

刷新、筛选、导出、打印及分页时，总数必须始终反映当前查询范围。分页场景的总数应基于完整筛选结果而不是当前页；若既有接口只返回当前页，需要在实施方案中明确采用报表已有 totals 字段或新增兼容的汇总分支，不能通过仅当前页前端累加伪造总数。

## 5. 非目标

- 不修改总账凭证、GL Entry、会计科目或余额计算业务规则。
- 不新增数据表、DocType 或替代会计总账报表。
- 不改变现有查询接口的字段含义、权限校验或其他入口的默认行为。
- 已按本文实施前端增强分支：新增中国财务静态脚本，在现有 General Ledger DataTable 渲染后插入总数行；未修改总账 Python 查询接口或数据库结构。

## 6. 待确认项

- 导出与打印是否也需要增加“总数”行；默认建议与屏幕口径一致。
- 分页时是否必须统计全部筛选结果；默认建议必须统计全部结果。
- 多币种/展示币种场景下，是否按报表现有币种分栏或仅按当前显示币种汇总；默认建议完全复用报表当前展示币种逻辑。
