# 中国财务模块完整测试计划

## 1. 文档目的

本计划用于指导中国财务模块的端到端验收。目标不是只确认页面能打开，而是验证：

1. 用户能按正常业务流程创建、保存、提交和取消单据。
2. 业务单据能正确进入 ERPNext 会计凭证和 `GL Entry`。
3. 中国财务凭证快照、现金流、发票、对账和结账链路数据一致。
4. 页面权限、公司隔离、期间限制和异常提示符合预期。
5. 每个问题都有复现步骤、原因、修复方法和优化建议。

本计划只适用于测试数据库。生产环境不得使用本计划中的测试数据。

### 包含

- 中国财务设置
- 新增凭证、查凭证、凭证汇总、凭证附件中心
- Journal Entry 到 GL Entry 的正式过账链路
- 中国会计凭证和中国会计凭证分录
- 现金流量指定单及现金流量指定明细
- 会计总账、日账簿、中国财务报表
- 中国税务发票及发票明细
- 发票附件、发票业务分摊
- 对账单和对账差异
- 中国结账检查、期末结账
- 权限、公司隔离、日期限制、取消和回滚

### 不包含

- 真实税务平台查验或开票
- 生产环境数据
- 未经确认的自动删除历史数据
- 与本模块无关的销售、采购、库存功能回归

## 8. 端到端执行场景

### 场景 A：手工凭证完整链路

1. 打开“中国财务 -> 新增凭证”。
2. 选择真实公司和当前会计期间。
3. 录入统一测试标识。
4. 录入借方银行/现金科目 `100.00`。
5. 录入贷方应收或合法对手科目 `100.00`。
6. 检查借贷平衡、币种、汇率、客户和成本中心要求。
7. 保存，记录草稿编号。
8. 提交，记录正式凭证编号。
9. 查询 Journal Entry、GL Entry、中国会计凭证和分录快照。
10. 在查凭证、凭证汇总、会计总账和日账簿中查询。

通过标准：来源凭证、GL Entry、中国凭证和报表金额一致，且只出现一次。

### 场景 B：现金流量指定

1. 从凭证或现金流量指定单列表进入指定单。
2. 检查来源凭证、现金科目、公司和日期。
3. 选择模板中的有效现金流明细项目。
4. 方向与现金分录一致，指定金额合计等于可指定金额。
5. 保存并确认。
6. 查询现金流量表和现金流覆盖率。

通过标准：指定金额与现金类 GL Entry 一致；报表金额不重复、不遗漏。

### 场景 C：中国税务发票

1. 打开“中国税务发票 -> 新建”。
2. 选择公司、进销项、发票类型和日期。
3. 录入唯一测试发票号，避免与现有发票重复。
4. 录入销售方、购买方、税号和金额。
5. 添加发票明细，检查未税金额、税率、税额和价税合计。
6. 上传测试 PDF/图片附件。
7. 保存并按系统规则提交。
8. 查询发票列表、附件和业务分摊。

如果使用 OCR，先验证文件选择器、识别结果和人工确认；识别成功不得被当作税务查验或自动入账成功。

### 场景 D：对账和结账

1. 在对账单中按测试客户或测试凭证查询。
2. 检查已结算、未结算和差异金额。
3. 打开中国结账检查。
4. 确认测试期间的未提交单据、未指定现金流和未完成对账提示。
5. 只有测试期间没有其他待处理业务时，才执行期末结账。
6. 检查重复结账、跨期新增凭证和取消凭证行为。

## 9. 异常和边界测试

| 类别 | 测试 | 预期 |
| --- | --- | --- |
| 借贷 | 借贷不平 | 禁止保存或提交 |
| 金额 | 零、负数、超过精度 | 清晰提示并拒绝 |
| 科目 | 群组科目/其他公司科目 | 禁止选择或提交 |
| 日期 | 早于启用日期/已结账期间 | 禁止提交 |
| 重复 | 重复发票号、重复现金指定 | 拒绝或明确提示 |
| 权限 | 无提交权限用户 | 只能查看或保存草稿 |
| 公司 | 切换公司后保留旧科目 | 应清空或重新校验 |
| 现金流 | 指定金额超过可指定金额 | 禁止确认 |
| 取消 | 取消已提交凭证 | 余额和报表反映取消结果 |
| 附件 | 不支持格式、超大文件 | 拒绝并说明限制 |
| 并发 | 两个窗口同时确认 | 不得产生重复有效单据 |
| 空结果 | 无数据筛选 | 有明确空状态，不显示旧结果 |

## 13. 回滚方案

1. 测试凭证完成后优先执行系统“取消”，不要直接删除。
2. 重新查询 GL Entry，确认取消状态和余额影响。
3. 作废或取消现金流量指定单，确认现金流报表恢复。
4. 测试发票如已提交，按系统允许的作废流程处理。
5. 测试附件保留或按测试环境约定删除，并记录文件名。
6. 不删除原有业务数据，不修改正式配置，不执行生产迁移。

## 14. 最终验收结论

只有同时满足以下条件，才能判定中国财务模块主链路通过：

- 所有 P0 表单可打开并完成正常提交；
- Journal Entry、GL Entry、中国凭证和报表金额一致；
- 现金流指定单能正确生成、确认、作废和重新创建；
- 发票金额、税额、附件和业务分摊一致；
- 对账和结账能识别未完成事项；
- 权限和公司隔离有效；
- 没有未解释的 5xx、关键控制台错误或数据重复；
- 所有问题都有记录、责任归类、解决方案和复测结论。

## 18. 全量完成标准

“整个中国财务模块已测试”必须同时满足：

1. 第 15 节所有 DocType 至少完成一次合法读取和一次适用的写入/状态测试。
2. 所有子表都通过父表保存后的明细一致性检查。
3. 第 16 节所有报表都用已知测试数据核对来源和结果。
4. 每张表都明确写入来源和下游消费者，不能只记录“页面可打开”。
5. 所有失败项均有问题编号、原因、解决方法、优化方案和复测结果。
6. 测试数据完成取消、作废或回滚，不能污染后续验收。
7. 未执行项目明确标记为“未执行”，不得标记为通过。
