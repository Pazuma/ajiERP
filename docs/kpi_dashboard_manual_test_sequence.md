# 运营指标看板人工测试顺序

## 1. 测试目的

确认本轮 KPI 看板、KPI Target 配置、权限下钻、Excel 导出和移动端布局可以正常使用，指标字段完整，计算结果符合已确认的业务口径，异常场景有明确提示。

本文件用于真实 Frappe 站点人工验收。Playwright 模拟验证不能替代本文的真实业务数据、角色权限和 MariaDB 复测。

## 2. 测试准备

### 2.1 环境

1. 完成代码部署、站点迁移和缓存刷新。
2. 使用测试站点，不要直接修改生产业务单据。
3. 准备至少一个有销售、财务、采购、库存、生产和项目数据的公司。
4. 准备浏览器桌面窗口和手机/浏览器移动模拟视口。
5. 记录测试站点、公司、测试人、测试时间、代码版本和数据库备份点。

### 2.2 测试角色

至少准备以下账号：

| 账号 | 用途 |
| --- | --- |
| System Manager | 全权限基准测试 |
| Sales User/Manager | 销售和业务员指标权限 |
| Accounts User/Manager | 回款、应收和财务下钻权限 |
| Purchase User/Manager | 采购延迟指标权限 |
| Stock User/Manager | 库存、安全库存权限 |
| Manufacturing User/Manager | 生产和工单权限 |
| 无 KPI 角色账号 | 看板访问拒绝测试 |

### 2.3 最小测试数据

准备或找到以下可追溯单据，并记录单号：

- 一个无交货销售订单。
- 一个部分交货销售订单。
- 一个所有明细均已交货的销售订单。
- 一张未结清销售发票、一张已结清销售发票、一张部分核销发票。
- 一笔收款和一笔跨期间收款。
- 一个多销售员分摊的销售订单，分摊比例合计 100%。
- 一个已到期且准时到货的采购订单、一个延期采购订单、一个未到期采购订单。
- 一个有计划数量和实际产量的工单。
- 一个有库存余额、安全库存和采购在途的物料。
- 至少一个高新收入订单、一个普通收入订单、一个研发项目及其费用来源。

## 3. 执行顺序

### 第 1 步：部署与入口检查

操作：

1. 登录 Desk，执行站点迁移和缓存刷新。
2. 打开“运营指标看板”页面。
3. 检查左侧工作区是否能看到“运营指标看板”“KPI Target”“KPI Metric Definition”。

预期：

- 页面可以打开，无 JS 报错、白屏或权限异常。
- 只有配置了页面角色的用户可以看到并访问看板入口。
- 浏览器开发者工具 Console 没有新增错误。

失败记录：记录账号、页面 URL、错误截图、Console 错误和服务器日志时间。

### 第 2 步：KPI Metric Definition 配置

操作：

1. 新建一条指标定义，例如 `total_sales_amount`。
2. 填写指标名称、所属分区、数据类型、来源单据、计算公式、统计范围、周期、评价方向和下钻报表。
3. 保存后重新打开，检查字段是否持久化。
4. 分别输入大写、空格和非 snake_case 的指标编码，尝试保存。

预期：

- 合法指标定义可以保存并重新打开。
- 当前金额、数量、达成率不在该表单中录入。
- 非法指标编码不能保存，并显示明确校验信息。
- 同一指标编码不能重复保存。

### 第 3 步：KPI Target 配置

按以下顺序测试：销售额、交付订单数、应收余额、生产完工率、采购及时率、高新收入占比。

操作：

1. 新建目标，选择公司、指标编码、周期类型和周期值。
2. 填写目标值、评价方向、预警阈值、危险阈值和备注。
3. 保存并重新打开，检查指标名称是否自动带出。
4. 对同一公司、同一指标、同一周期再次新建目标。
5. 测试月度 `YYYY-MM`、季度、年度格式和空目标值。

预期：

- 指标名称按编码自动带出且不能随意改写。
- 合法目标可以保存。
- 周期格式错误、未知指标编码、重复目标不能保存。
- 没有目标的指标在看板显示“未设置”，不会导致整页失败。

### 第 4 步：看板基础加载与筛选

操作：

1. 使用 System Manager 打开看板，确认默认公司、开始日期和截止日期。
2. 依次修改公司、开始日期、截止日期，观察页面是否自动刷新。
3. 选择一个没有数据的日期区间。
4. 将开始日期设置为晚于截止日期。
5. 连续快速修改两次日期。

预期：

- 页面出现加载骨架，随后展示数据或空态。
- 公司和日期筛选会传给接口，结果随筛选变化。
- 无数据时显示“没有符合当前筛选条件的数据”，不显示伪造 0 以外的业务数据。
- 日期逆序时显示明确错误和 Retry，不发起错误查询。
- 快速刷新后只保留最后一次请求结果，旧请求不会覆盖新结果。

### 第 5 步：销售与订单交付指标

使用第 2.3 节中的三个销售订单逐一核对。

操作：

1. 记录数据库/订单列表中的订单数和订单金额。
2. 在看板核对“总订单数”“总销售额”“高新收入金额”“高新收入占比”。
3. 核对“整单已完成”“整单未完成”“已交货”“交货中”“未交货”。
4. 点击销售订单相关卡片进入下钻报表。

预期：

- 总订单数和金额与当前公司、日期范围内的已提交销售订单一致。
- 全部明细交货的订单才计入整单已完成。
- 至少一条明细有交货的订单计入已交货；部分交货同时属于交货中，不计入整单完成。
- 无交货订单计入未交货。
- 卡片显示的筛选条件与当前看板一致。

### 第 6 步：业务员 Top10/全部和分摊

操作：

1. 默认选择“Top 10”，核对最多 10 行。
2. 切换为“全部”，核对所有有业务员数据的行。
3. 检查送货条数、送货金额、个人已回款、个人应收、交付率、回款率。
4. 对多业务员订单手工计算分摊金额。

预期：

- Top 10 最多显示 10 行，按送货金额降序。
- 全部模式显示完整业务员行，并将 `salesperson_limit=all` 发送到接口。
- 分摊金额符合 Sales Team 比例；总分摊金额与来源单据一致。
- 回款率分母为个人已回款加个人应收；分母为 0 时显示无数据或 0，不出现 NaN/Infinity。
- 回款率超过 100% 的数据必须进入异常核查，不得直接作为正常业务结论。

### 第 7 步：回款、应收和账龄

操作：

1. 核对已收款总额、应收款余额、已结清单据数、未结清单据数。
2. 核对平均应收天数、超 90 天逾期、应收款周转天数。
3. 检查账龄分布金额、占比和逾期客户 TOP10。
4. 在 30/31/60/61/90/91/180/181 天边界分别准备发票并刷新看板。
5. 点击应收卡片和客户 TOP10 行下钻。

预期：

- 已收款按已提交 Receive 类型收款核销金额统计。
- 应收余额按未结清销售发票余额统计，已结清单据不计入未结清。
- 账龄边界只落入一个区间，区间无重叠或断档。
- 逾期客户按逾期金额降序取 TOP10，风险等级与账龄规则一致。
- 应收周转天数当前是加权账龄近似值；若财务确认严格周转公式不同，记录差异并暂停上线结论。

### 第 8 步：同比和对账预警

操作：

1. 选择跨年度期间，核对上年同期销售额、销售同比和应收同比。
2. 使用闰年 2 月 29 日附近日期进行同比测试。
3. 准备状态为 Completed、Closed、To Deliver、To Deliver and Bill、Partially Delivered 的订单，分别制造状态与明细交货事实不一致。
4. 核对未完成订单和状态不一致条数，并点击下钻。

预期：

- 同比期间按自然年/月/日平移 12 个月，不使用固定 365 天。
- 上期为 0 时不显示无限增长。
- 状态不一致覆盖完成、待交货和部分交货等状态，不只检查 Completed。

### 第 9 步：生产、采购、库存和高新合规

操作：

1. 核对生产计划数量、实际产量、完工率和月度趋势。
2. 核对采购及时率，确认未到期订单不进入分母。
3. 核对实时库存金额、安全库存预警数量和采购在途金额。
4. 核对高新收入、总营收、高新占比、研发项目数、研发费用和研发费用占比。
5. 检查三年趋势和研发项目 TOP10 的收入占比。

预期：

- 生产趋势按月份展示，计划量为 0 时不出现除零错误。
- 延迟供应商 TOP10 的延迟天数和风险等级符合采购规则。
- 库存借出仓排除策略符合业务配置。
- 高新项目占比为项目高新收入/高新收入总额；高新收入为 0 时不出现 NaN。
- 高新总营收当前沿用 Sales Order 口径，财务确认改用发票口径时必须单独记录变更。

### 第 10 步：权限、下钻和导出

操作：

1. 分别使用销售、财务、采购、库存、生产账号登录。
2. 点击各自有权限和无权限的指标卡、表格行。
3. 点击“导出 Excel”，打开下载文件。
4. 检查每个工作表的公司、日期、业务员行数筛选值。
5. 核对导出字段与页面字段，尤其是研发项目占比。

预期：

- 无 KPI 角色账号不能调用看板 API。
- 有底层 Report/DocType 权限时可下钻；无权限时保持普通不可点击样式。
- 导出文件可以打开，无损坏、无重复列或空标题。
- 导出与页面使用相同公司、日期和业务员范围。

### 第 11 步：移动端与浏览器兼容

操作：

1. 在 1440px、1024px、768px 和 390px 宽度分别打开看板。
2. 检查卡片、图表、表格、状态标签和按钮是否重叠或被截断。
3. 在 390px 宽度横向查看表格，确认只在表格内部滚动。
4. 使用 Chrome/Edge 最近版本各测试一次。

预期：

- 页面主体不出现横向滚动条。
- 表格过宽时只表格容器可横向滚动。
- 图表有实际绘制内容，不是空白容器。
- 长客户名、供应商名、项目名不覆盖相邻字段。

## 4. 结果记录模板

每个场景记录以下字段：

| 字段 | 示例 |
| --- | --- |
| 用例编号 | KPI-DEL-002 |
| 执行账号/角色 | sales_user / Sales User |
| 公司与期间 | 示例公司 / 2026-01-01 至 2026-08-22 |
| 前置单据 | SO-0001、SI-0002、PE-0003 |
| 实际结果 | 页面显示已交货 237 |
| 预期结果 | 页面显示应为 237 |
| 结论 | 通过 / 失败 / 阻塞 |
| 证据 | 截图、导出文件、日志时间 |

发现问题时必须同时记录：问题现象、复现步骤、实际值、预期值、根因判断、临时规避方案、代码/配置解决方案、复测结果。

## 5. 通过标准

- 第 1-4 步全部通过，页面无白屏、Console 错误和接口错误。
- 第 5-9 步的指标与业务明细逐项核对通过，差异均有口径说明。
- 第 10 步不同角色的权限和下钻结果符合授权矩阵。
- 第 11 步四种宽度下无布局重叠，图表和表格可读。
- 所有失败项有责任人、解决方案和复测记录后，才能标记为“人工验收通过”。
