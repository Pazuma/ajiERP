# 项目预期进度、流程模板与业务表单联动优化方案

> 文档日期：2026-09-11  
> 当前阶段：方案沉淀，暂不修改代码。  
> 需求理解：“能保存未模板”按“能保存为模板”设计；即项目中的进度节点可保存为模板，并复用于其他项目。

## 1. 目标

在 ERPNext 标准 Project 的“进度”页签增加一套项目流程进度能力：

- 项目同时显示“预期进度”和“流程实际进度”。
- 项目可以维护多个进度节点，每个节点可关联一种业务表单及具体单据。
- 关联单据成功提交后，对应进度节点自动完成。
- 关联单据取消提交后，节点自动恢复为未完成，避免留下假进度。
- 一组进度节点可以保存为项目进度模板，新项目可从模板生成节点。
- 项目列表可直接看到预期进度、实际进度和是否延期。
- 保留 ERPNext 原有“完成百分比法”和“已完成%”，不修改标准 Task Completion 逻辑。

## 2. 进度口径

### 2.1 保留标准任务进度

ERPNext 标准字段继续按原规则工作：

```text
Project.percent_complete
  = 已完成或已取消 Task 数量 / 项目 Task 总数
```

标准字段不改名、不改公式，保证 ERPNext 项目、任务、工时和标准报表兼容。

### 2.2 新增流程实际进度

每个项目进度节点配置权重，所有有效节点权重合计必须为 100%。

```text
流程实际进度 = 已完成节点权重合计 / 全部有效节点权重合计 × 100%
```

节点完成依据：

- 完成规则为“单据提交”：关联单据 `docstatus = 1` 时完成。
- 完成规则为“手工确认”：由有权限用户确认完成，并记录完成人和时间。
- 单据为不可提交 DocType 时，只允许使用“手工确认”，不能用保存状态冒充完成。
- 单据取消提交后，对应节点恢复为“进行中/待开始”，并记录最近同步时间。

### 2.3 新增预期进度

推荐采用节点计划日期和权重计算，不用简单的项目起止日期线性百分比：

```text
当前日期 < 节点计划开始日：该节点预期贡献 0
当前日期 >= 节点计划完成日：该节点预期贡献 = 节点权重
处于开始与完成日期之间：按经过天数线性计算该节点预期贡献
项目预期进度 = 各节点预期贡献之和
```

没有计划开始日时，可使用项目 `expected_start_date`；没有计划完成日的节点必须提示配置，不参与预期进度计算。

项目状态建议：

- 实际进度 >= 预期进度：正常。
- 实际进度落后预期进度，但没有逾期节点：关注。
- 存在计划完成日已过且未完成节点：延期。
- 全部节点完成：已完成。

## 3. 数据模型

### 3.1 新增 Project Progress Item 子表

建议新建 `Project Progress Item`，挂载到 Project：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `milestone_code` | Data | 节点编码，项目内唯一 |
| `subject` | Data | 节点名称 |
| `sequence` | Int | 显示顺序 |
| `weight` | Percent | 节点进度权重 |
| `expected_start_date` | Date | 计划开始日期 |
| `expected_end_date` | Date | 计划完成日期 |
| `completion_rule` | Select | `Document Submitted` / `Manual` |
| `reference_doctype` | Link | 关联表单类型，指向 DocType |
| `reference_name` | Dynamic Link | 关联的具体单据 |
| `status` | Select | 待开始、进行中、已完成、延期、已取消 |
| `actual_completed_on` | Datetime | 实际完成时间 |
| `completed_by` | Link | 完成人 |
| `last_synced_on` | Datetime | 最近联动时间 |
| `source_template_item` | Data | 模板来源行，便于追溯 |
| `remarks` | Small Text | 备注 |

不建议只保存 `reference_name`。必须同时保存 `reference_doctype`，通过 Dynamic Link 形成稳定的跨表单关联。

### 3.2 新增 Project Progress Template

单独新增 `Project Progress Template`，不复用 ERPNext 标准 `Project Template`：标准模板的核心语义是批量生成 Task，直接扩展会把“任务模板”和“业务表单节点模板”混在一起。

模板头字段：模板名称、项目类型、启用状态、版本、说明。

模板子表 `Project Progress Template Item` 包含：节点编码、名称、顺序、权重、相对开始天数、相对完成天数、完成规则、关联 DocType、备注。

模板只保存关联 DocType，不保存具体 `reference_name`，因为具体单据属于某一个项目。

### 3.3 Project 新增字段

通过 Custom Field 增量增加：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `custom_progress_template` | Link | 使用的 Project Progress Template |
| `custom_project_progress_items` | Table | 项目进度节点 |
| `custom_expected_progress` | Percent | 当前预期进度，只读 |
| `custom_actual_process_progress` | Percent | 流程实际进度，只读 |
| `custom_progress_variance` | Percent | 实际减预期，只读 |
| `custom_progress_health` | Select | 正常、关注、延期、已完成，只读 |
| `custom_progress_last_synced_on` | Datetime | 最近计算时间，只读 |

这些字段放入现有 Project “进度”页签，不调整标准字段位置和含义。

## 4. 表单功能

### 4.1 Project 表单

新增以下操作：

- “应用进度模板”：选择模板并生成项目节点。
- “保存为进度模板”：将当前节点结构保存为新模板，不保存具体关联单据和实际完成状态。
- “关联单据”：在节点行选择 DocType 后选择具体单据；查询条件优先限制为当前项目相关单据。
- “创建关联单据”：对支持映射的 DocType 新建草稿，并自动写入 Project 或项目自定义字段。
- “重新同步进度”：读取所有关联单据当前状态，幂等更新节点及项目汇总。
- 节点点击具体单据编号可直接跳转到关联表单。

模板应用规则：

- 项目没有节点时直接应用。
- 已有节点时必须选择“追加缺失节点”或“替换未关联节点”。
- 已关联单据或已完成的节点默认不可被模板覆盖。
- 按 `milestone_code` 幂等识别，重复应用不会重复创建节点。

### 4.2 关联业务表单

关联单据表单增加项目进度提示：

- 显示“关联项目：项目名称 / 节点名称”。
- 草稿状态提示“提交后将完成项目节点”。
- 提交后显示“项目节点已完成”。
- 取消后显示“项目节点已恢复”，并触发项目进度重算。
- 一个单据可以关联多个项目节点时，提交/取消应批量同步全部节点。

首期建议允许关联已有 `project` 字段或明确具备项目语义的表单，例如 Task、Sales Order、Purchase Order、Material Request、BOM、Work Order、Delivery Note、Purchase Receipt、Sales Invoice、Purchase Invoice、Stock Entry。其他 DocType 通过白名单逐步开放。

### 4.3 Project 列表

列表增加：

- 实际进度：如 `60%`。
- 预期进度：如 `75%`。
- 进度状态：正常、关注、延期、已完成。
- 指示器示例：`实际 60% / 预期 75%`，延期显示红色，关注显示橙色。

列表默认标准状态过滤不变；新字段只是附加展示和筛选条件。

## 5. 调用链路

### 5.1 应用模板

```text
Project 表单“应用进度模板”
 -> client_akivision.utils.project_progress.apply_progress_template(project, template, mode)
 -> 读取 Project Progress Template Item
 -> 按项目预计开始日换算节点计划日期
 -> 按 milestone_code 幂等新增/更新 Project Progress Item
 -> recalculate_project_progress(project)
 -> 保存 Project 并刷新表单
```

### 5.2 保存为模板

```text
Project 表单“保存为进度模板”
 -> save_project_progress_as_template(project, template_name)
 -> 校验节点编码、顺序、权重和日期
 -> 日期转换为相对项目开始日的天数
 -> 创建 Project Progress Template + Items
 -> 返回模板名称并回填 custom_progress_template
```

### 5.3 关联单据提交

```text
业务单据 Submit
 -> doc_events on_submit
 -> sync_progress_from_reference(doc.doctype, doc.name, submitted=True)
 -> 查询 reference_doctype + reference_name 对应的项目节点
 -> 节点状态=已完成，记录 completed_by/actual_completed_on
 -> recalculate_project_progress(project)
 -> db_set Project 流程实际进度、预期进度、偏差、健康状态
```

### 5.4 关联单据取消

```text
业务单据 Cancel
 -> doc_events on_cancel
 -> sync_progress_from_reference(..., submitted=False)
 -> 清除节点完成信息，按日期恢复待开始/进行中/延期
 -> 重算项目汇总
```

### 5.5 列表展示

```text
打开 Project List
 -> Project 列表附加 custom_* 进度字段
 -> get_indicator() 组合实际/预期/健康状态
 -> 点击进度可按项目或健康状态筛选
```

## 7. 服务接口设计

新增接口，不改老接口：

```text
get_project_progress(project)
get_progress_reference_options(project, reference_doctype, txt)
apply_progress_template(project, template, mode="append")
save_project_progress_as_template(project, template_name)
recalculate_project_progress(project)
link_progress_reference(project, row_name, reference_doctype, reference_name)
set_manual_progress_complete(project, row_name, completed, reason=None)
```

所有写接口要求 Project 写权限；保存模板要求 Project Manager/System Manager 权限；读取关联单据前校验对应 DocType 的 read 权限。

## 8. 小增量与兼容策略

- 标准 `percent_complete` 继续表示 Task 完成率，新流程不覆盖它。
- Project 仅新增 `custom_*` 字段和子表，不覆盖标准控制器。
- 模板单独建模，不修改 ERPNext Project Template。
- 表单提交/取消联动只登记明确支持的 DocType；新增表单类型通过白名单扩展。
- 提交事件只做状态同步和轻量汇总，不创建财务、库存或业务凭证。
- 联动必须幂等，同一事件重复触发不会重复增加进度。
- 自动更新使用数据库级字段更新，并避免再次触发关联单据业务流程。
- 已完成节点的关联关系、权重和计划日期默认锁定；需调整时先解除完成状态并记录原因。
- 模板调整不反向覆盖已创建项目，项目需要显式选择重新应用。
- 旧项目没有节点时，新字段显示 0 或“未配置”，不影响保存和现有项目列表。

## 9. 受影响模块

直接影响：Project、Project 列表、Project Progress Template、项目进度子表。

关联影响：Task、Sales Order、Purchase Order、Material Request、BOM、Work Order、Delivery Note、Purchase Receipt、Sales Invoice、Purchase Invoice、Stock Entry，以及后续加入白名单的可提交 DocType。

需要重点回归：

- Project 原任务完成率、成本核算、预算明细和开发申请 PDF。
- `project_cost_detail.js` 与新增 Project 表单脚本是否重复注册或互相覆盖。
- `document_export_list.js` 的项目导出动作是否仍然存在。
- 单据提交失败时不得提前完成节点。
- 单据取消、修订后重新提交的状态恢复。
- 删除草稿单据、改名及无权限用户访问关联节点。
- 模板重复应用、版本变化和并发提交。

## 11. 验收标准

- 新项目能从模板一次生成全部进度节点，日期按项目开始日正确换算。
- 当前项目节点能保存为新模板，模板不携带具体单据和完成状态。
- 关联表单保存草稿不会完成节点，成功提交后才完成。
- 关联表单取消后节点恢复，实际进度同步下降。
- 预期进度按计划日期和权重自动变化，实际进度按完成权重变化。
- 项目列表展示实际/预期进度和延期状态，并支持筛选。
- 标准 Task Completion 的 `percent_complete` 计算结果不变。
- 原项目成本、预算、PDF 导出、列表导出功能无回归。
- 无节点的历史项目可正常打开、保存和查询。
- 所有新增接口具备权限校验、幂等测试和提交/取消回归测试。

## 12. 实施前确认项

1. “保存未模板”是否确实指“保存为模板”。
2. 预期进度是否采用本文的“节点权重 + 计划日期线性计算”，还是只统计已到期节点权重。
3. 首期允许关联哪些业务表单；建议先限制在现有常用可提交单据。
4. 一个节点是否只允许关联一张单据；本文按“一节点一单据”设计，多个单据应拆成多个节点。
5. 项目最终状态是否仍由标准任务进度决定；本文建议不自动改 Project.status，仅展示流程健康度。

- 新增 `Project Progress Template`、`Project Progress Template Item`、`Project Progress Item`。

- 增加每日重算任务，保证预期进度随日期变化。
- 未修改 ERPNext Project 标准控制器、标准 `percent_complete` 字段、Task Completion 逻辑和 Project Template。

已通过 Python 编译、DocType JSON 格式检查。当前环境未提供 Node/bench 命令，未执行浏览器交互和站点 migrate；上线前需执行 `bench --site <site> migrate`、资源构建和项目模板/节点回归测试。
