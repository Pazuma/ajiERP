# 供应商十三列表头导入

## 模板及效果

供应商列表 → 导入 → 下载推荐模板，输出：

供应商编号、供应商名称、联系人、联系电话、供应商地址、合作状态、供应商评级、账期天数、备注、简称、银行账号户名、银行账号、开户行名称。

- 供应商编号、名称必填，编号直接写入 Supplier.name，同时保留 custom_supplier_code。编号、电话、银行账号请在 Excel 中设置为文本，已被 Excel 截断或丢失的数字不能恢复。
- 联系人及电话创建/关联 Contact；供应商地址创建/关联账单 Address，并设置供应商默认联系人与主地址。
- 完整地址原样保存，城市暂设为“待补充”，国家采用系统默认国家或 China，预览有提示。
- 合作状态按系统现有选项校验（合作中、暂停合作、终止合作）；账期必须为非负整数，包括 0。
- 评级写入现有 custom_supplier_rating；后续系统自动评级仍可按原规则重新计算。账期保存到 custom_credit_days，不擅自替换正式付款条件模板。
- 简称写入新增 custom_supplier_short_name。
- 银行三列同时填写或同时留空；开户行不存在时按原名称创建 Bank；创建供应商往来 Bank Account，并设置 default_bank_account。账户不标记为公司自有账户，不生成凭证。
- 新增模式不覆盖已有编号，更新模式按编号匹配、空白值保留原数据。旧外部编号与系统编号不一致时提示人工核对，不自动重命名。
- 更新复用同一供应商的同名联系人、相同地址、相同银行及账号；歧义会提示错误。
- 预览只校验和读取。实际执行逐行事务，关联创建失败时该行全部回滚，写入行级失败日志。
- 沿用当前登录用户的主档及联系人、地址、银行、银行账户权限；权限不足会记录失败，不绕过权限。

## 文件与调用链

1. `client_akivision/utils/supplier_excel_import.py`：新增简称字段、13 列识别/预检/导入/关联/日志。
2. `client_akivision/client_akivision/api/data_import.py`：新增供应商模板下载接口，原预览与后台执行接口增加供应商分支。
3. `client_akivision/public/js/inline_data_import.js`：推荐模板下载、13 列预览，复用客户平面表预览逻辑。
4. `client_akivision/hooks.py`：after_migrate 注册简称字段初始化。
5. `client_akivision/utils/test_supplier_excel_import.py`：真实 XLSX 及导入链路集成测试。

调用链：供应商列表导入弹窗 → 下载供应商推荐模板 → 上传 → preview_inline_import → supplier_excel_import.preview → start_inline_import → run_inline_import → supplier_excel_import.run → Supplier / Contact / Address / Bank / Bank Account → 导入日志。

识别包含供应商编号、供应商名称、联系电话的表头后进入专用分支，校验完整 13 列。其余标准模板及供应商回顾保留原路径。不改变原公开接口参数，不改变全局供应商命名规则。

## 部署

同步新增模块及改动文件时合并服务器独立修改。需要初始化新增简称字段，可执行：

```bash
bench --site <实际站点> execute client_akivision.utils.supplier_excel_import.ensure_schema
bench --site <实际站点> clear-cache
```

也可以在正常 migrate 时通过 after_migrate 初始化。重启 Python Web/worker，浏览器强制刷新加载 JS。不恢复数据库，不覆盖 site_config.json。

本地已通过供应商专项 4 项集成测试及 JavaScript 语法检查；服务器需另行同步部署并用真实文件验收。
