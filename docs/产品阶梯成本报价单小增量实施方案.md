# 产品阶梯成本报价单小增量实施方案

日期：2026-10-21  
状态：2026-10-22 已按第15、16节完成本轮代码实现并在 `aki_test.localhost` 定向同步及验收；实际范围、差异和限制见第17节。第15、16节保留设计阶段措辞以便追溯。  
范围：新增独立单据、只读来源适配、三类表单入口及双版本 Excel 导出。项目实际分摊、剩余投入及报价税务口径需业务人员确认后方可提交。

## 1. 目标与实施边界

新增独立的「产品成本报价单」（拟用英文 DocType：Product Cost Quotation），按产品归集 BOM、供应商阶梯价、标准工时、项目投入，计算不同数量下的预计成本和报价。可从产品、研发项目、生产工单进入，也可独立新增。导出首张工作表沿用 `docs/模板.xlsx` 的布局。

采用小增量方案：新单据、新接口、新前端脚本、新模板导出分支；老接口签名、返回结构、事件行为和计算口径保持现状。业务上不得因为创建或确认成本报价单而改写物料价格、BOM、项目成本、工单实际成本、库存或财务凭证。

本功能是内部成本核算与报价底稿，不替代 ERPNext Quotation、销售订单、项目预算及正式财务实际成本。第一阶段不自动生成销售订单或对外发送文件。

## 5. 三条完整业务流

### 5.1 从项目开始

```text
研发项目 → 选择关联产品/暂定型号 → 新建成本报价草稿
 → 读取已提交研发工时、项目手工成本、项目预算参考
 → 确认哪些费用直接归属产品，哪些属于共用投入
 → 填写分摊比例/金额、预计剩余投入、已回收金额
 → 有BOM：带入材料及标准工序；无BOM：补充临时明细
 → 输入50/100/200/500等批量 → 匹配阶梯价及制造费率
 → 处理缺价、税率、MOQ、研发回收方式
 → 核算 → 调整最终报价并记录原因 → 确认版本
 → 内部完整模板 / 客户报价区域导出
 → 项目或BOM后续变化：复制新版本，主动刷新再核算
```

项目预算是计划上限或计划分项，不等于剩余投入。默认不以“实际 + 全额预算”计算；预计剩余投入由负责人确认，或在分项映射明确后辅助计算并确认。已发生、预计、摊销及已收取金额分别存储。

### 5.2 从生产工单开始

```text
生产工单 → 新建成本报价 → 带入产品、公司、工单BOM
 → 读取计划用料，以及可确认的实际领退料、人工和报工
 → 标记实际数据完整程度、完工数量及参考日期
 → 输入未来报价批量 → 按BOM/核算明细重新匹配当前阶梯价
 → 标准工时与历史实际工时并列展示
 → 用户可“采用参考工时到本单”，填写原因，不回写原标准
 → 可选关联研发项目，补充一次性投入
 → 核算 → 最终报价 → 确认快照 → 模板导出
```

原工单实际只做参考；不能按原采购均价直接外推所有批量。工单未完工、凭证未齐、实际完工数量为零时，禁止展示为最终完整实际单位成本。材料成本按实际消耗归集，区分调拨/领料/生产耗用，防止同批材料流转重复累计。

### 5.3 直接新增

```text
列表新建 / 产品档案新建 → 选择产品或暂定型号
 → 可选BOM、项目、参考工单（均可后续补充）
 → 选择公司、批量、币种及报价条件
 → 读取已有材料价格、工序标准；缺失部分有依据地补录
 → 确认供应商、采购余量处理、工时及一次性投入
 → 核算与风险检查 → 保存 → 确认 → 导出
```

不强制为直接核算创建项目、工单或采购单。三条流程只在初始上下文与可调用资料上不同，后续使用同一计算与导出引擎。

## 6. 拟新增数据模型

采用一个主单和四个子表，优先不为每个物料、每个批量建立独立主单，减少维护入口。

| 拟用 DocType | 主要字段 |
| --- | --- |
| Product Cost Quotation | company、item_code、provisional_model、product_name、bom_no、source_type、reference_work_order、customer、contact、quotation_date、currency、exchange_rate、tax_rate、minimum_sales_qty、pricing_method、target_margin、cost_ratio、terms、previous_version、calculation_version、source_refreshed_at、snapshot_hash |
| Product Cost Material（子表） | item_code、category、qty_per_unit、stock_uom、purchase_uom、conversion_factor、loss_method/rate、supplier、pricing_rule、manual_rate、price_basis、surplus_policy、manual_reason、source_refs、calculation_details_json |
| Product Cost Operation（子表） | operation、workstation、charging_basis（按台/按批）、standard_hours、hourly_rate、included_cost_scope、tier_overrides_json、source_refs、manual_reason |
| Product Cost Investment（子表） | project、expense_type、actual_amount、remaining_estimate、allocation_basis、allocation_value、recovered_amount、recovery_method、amortization_qty、rd_markup_rate、source_doctype/name/row、source_key、manual_reason |
| Product Cost Scenario（子表） | quantity、material_unit_cost、manufacturing_unit_cost、investment_unit_cost、full_unit_cost、suggested_price_with_rd、suggested_price_without_rd、final_tax_inclusive_price、gross_margin、batch_gross_profit、payback_qty、completeness、warnings、detail_snapshot_json |

多个项目通过 Investment 子表关联，不将一个产品限制为一个项目；表头主项目只作默认值和查询入口，可后续按需求增加。金额字段明确本币/报价币种，汇率与精度进入快照。JSON仅保存可重建明细和来源快照，不用来代替主业务筛选字段。

采用可提交单据：草稿 docstatus=0、已确认=1、已取消=2。取消保留记录；新版本使用复制/修订，不覆盖历史。提交时服务端重算并核验必填项与完整性，不能仅信任浏览器结果。估算数据必须显式确认，关键缺价未补全则阻止正式确认；草稿导出带“未确认/数据不完整”标记。

## 7. 核算规则及异常处理

1. 多层 BOM 按 BOM.quantity 和单位换算展开，合并同物料需求，检测循环；保留子件路径。委外或直接采购子装配明确采用模式，避免同时计入子装配和其子件。
2. 材料损耗在单一环节计入，区分模板的“按成本增加报废附加”与“按数量补料”，不可同时套用。
3. 用物料采购单位数量匹配阶梯，考虑MOQ与包装倍数；默认指定/优选供应商，缺省时要求选择，不未经确认跨供应商拼最低价。
4. 价格需校验公司、币种、单位、有效期、禁用状态；现有记录缺少税务或有效期口径时提示补充，不能自行假定。缺价为未完成而非零。
5. 同时展示消耗成本、采购投入和结余金额；结余选“可复用”或“本次全部承担”，保存选择依据。
6. 按台工时乘数量；按批工时只计一次。分钟统一换算小时，批量效率调整只作用于本单。小时费率包含范围需明确，避免人工、设备及间接费用重复。
7. 单台完整成本＝批次消耗/承担材料及制造费用÷数量＋单台一次性投入摊销。样品批量可独立设置单价和摊销策略。
8. 模板定价兼容分部模式：未税建议售价＝量产单位成本÷成本占售价比例＋研发单台分摊×(1＋研发加价率)；另提供整单目标毛利率模式，二选一，避免混算。目标毛利率须小于100%，成本占售价比例须大于0。
9. 未税销售单价＝含税价÷(1＋税率)；毛利率＝(未税价－同口径单位成本)÷未税价；批次毛利＝单位毛利×数量。零售价不计算有效毛利率。
10. 回本数量用尚需回收的一次性投入÷单台贡献毛利向上取整，贡献毛利不重复扣同一研发摊销。分开单收的费用先扣减待回收投入。贡献不为正则显示无法回本。
11. 不调用项目总计后再累加工时/项目子表；对每笔来源建立唯一键，重复引用拦截。来源没有足够证据时提示人工确认，不声称可以完全自动判断重复费用。
12. 预计成本与历史实际成本并排保存、分别标记。采购价上涨、用量偏差、工时偏差分别解释，不混成一个不透明总差额。

模板已发现的修正点：含税售价直接减未税成本、含税价乘87%去税、50阶梯另引用20数量、部分分摊额额外除1.5、左侧报价混用含/不含研发口径、外部VLOOKUP。保留外观但需将这些隐含规则显式化，修正公式；不承诺逐个复制原公式结果。

## 8. 拟新增接口与调用链路

接口均放在新命名空间 `client_akivision.api.product_cost_quotation`；以下签名为设计稿。

| 新接口 | 行为 |
| --- | --- |
| `get_source_context(source_type, source_name, item_code=None)` | 检查来源读取和新单创建权限，返回可选产品及预填上下文，不落库 |
| `preview_source_refresh(name)` | 对已保存草稿读取来源并返回差异，不覆盖手工项 |
| `apply_source_refresh(name, expected_modified, selected_changes)` | 校验并发与写权限，仅按确认差异更新目标草稿 |
| `preview_calculation(name, expected_modified)` | 服务端按当前已保存草稿返回计算预览，不写来源单据 |
| `get_line_detail(name, child_row, scenario_qty)` | 检查主单和来源权限，返回该行阶梯及核算依据 |
| `export_cost_quotation(name, audience)` | audience 限 internal/customer，基于同一快照导出，检查对应导出权限 |

保存/提交继续使用 Frappe 标准文档接口，新 controller 的 validate/before_submit 调用新计算服务，避免另造通用保存接口。

```text
Item / Project / Work Order 入口脚本
  → get_source_context（读取权限、公司、产品校验）
  → frappe.new_doc("Product Cost Quotation", 预填值)
  → 标准保存接口 → ProductCostQuotation.validate
                      → product_cost_sources（只读来源适配）
                      → product_cost_pricing（阶梯规则适配）
                          → 现有 get_item_supplier_pricing_overview
                          → 现有 evaluate_rule（只读求值）
                      → product_cost_calculation（确定性运算）
                      → 主单结果与来源快照
  → 标准提交 → before_submit复核、锁定版本
  → export_cost_quotation → product_cost_export
      → 读取本单快照 → 模板映射 → XLSX响应
```

来源适配读取 Project/Timesheet/项目明细/预算、BOM、Work Order/Stock Entry/人工记录，但不调用重算写回函数。计算层尽量不依赖数据库，便于针对公式与边界验证。预览和提交一致使用同一个引擎，金额用 Decimal 和明确舍入策略。

## 15. 单品双页版后续改造方案（设计稿，承接第14节）

> 本节记录后续 UI/导出改造方向；本轮仅沉淀方案，没有修改业务代码。本文前文描述的是当前已实现版本，不能据此认为双页 UI 已上线。

### 15.1 目标与边界

一张「产品成本报价单」只对应一个产品。主单拆成两个页签：**对客报价**与**成本核算**。第一页维护客户可见的商务信息和最终选定的批量报价；第二页维护内部来源、成本明细、完整阶梯和核算结果。两页仍是同一主单、同一保存/提交/版本快照，不拆成两个互相同步的单据。

本轮结构调整不改变“一个产品”的既有模型。批量数量是同一个产品的报价阶梯，不是多个产品。客户导出只读取第一页的已选展示阶梯和商务条款；内部导出可以额外包含第二页的成本、来源及风险数据。

若截图中的我方联系人不是现有 `contact`（其语义目前是客户联系人），需增加独立的我方联系人字段并明确其来源/权限；避免复用一个字段同时表示客户与我方联系人。客户、联系人自动联动维持现有选择客户后自动识别联系人逻辑。

### 15.6 影响范围与兼容策略

- **用户界面**：仅影响 Product Cost Quotation 表单内的信息分组与成本矩阵；Item、Project、Work Order 的入口保持现状。
- **持久化数据**：若新增场景布尔字段，历史记录采用明确默认值。建议迁移时将已有全部场景设为展示，避免升级后客户导出突然没有阶梯；是否按报价单状态/既有选择回填需在迁移前审计。
- **计算与来源**：不更改现有计算公式、供应商价格解析、BOM 来源键和来源刷新协议。产品/BOM切换后的待刷新保护仍是成本页关键状态。
- **导出与权限**：客户导出默认白名单映射，不通过“隐藏列”或复制内部工作簿来隔离成本。内部导出维持成本权限和完整快照；不因增加客户预览而放宽 API 权限。
- **接口兼容**：旧接口名、参数、返回结构、HTTP 方法及副作用不变；若需新行为，新增方法或仅新增可选字段/参数，并保持缺省行为与现有一致。
- **改造顺序**：先字段/默认值与兼容测试，再表单双页排布，再客户导出筛选，最后页面与端到端验收。每步可独立回退；不进行历史报价单重算或静默重写。

### 15.7 验收标准

1. 一张报价单只绑定一个产品；同一产品的多个批量阶梯均在一张单内，不出现多产品报价行。
2. 两个页签分别呈现对客信息与内部成本；切页不清空未保存值，刷新后内容一致。
3. 成本页场景数量及最终报价是同一套数据；对客展示选择仅控制客户页/客户文件的可见批量，不影响成本计算和内部文件。
4. 成本页纵向显示材料类别、损耗、工时/制造成本、研发相关项、含/不含研发建议售价、最终毛利和回本量；展开明细可追溯到行级来源和公式快照。
5. 更换产品/BOM后旧来源显式标记待刷新；刷新预览错误、竞态响应或取消操作不得应用旧产品数据。仅应用用户勾选的来源组，无来源键手工行保留。
6. 客户导出只包含已选展示阶梯及商务信息，不含采购单价、来源明细、项目投入、毛利、成本、内部风险或快照 JSON；内部导出继续包含核算资料。
7. `preview_source_refresh`、`apply_source_refresh`、`preview_calculation`、`get_line_detail`、`export_cost_quotation` 的既有调用方无需修改，既有权限和错误处理回归通过。
8. 已有报价单在升级后可打开、保存、复制版本、提交/取消及导出；不批量改价、不自动提交、不写回来源业务记录。

### 15.8 待业务确认

- 截图中的“调节系数 0.400”表示成本占含税售价、未税售价，还是单纯经验系数？此前文档定价公式按成本占售价比例处理，但必须业务确认后才能沿用。
- 研发投入是否纳入客户报价单价、单独收费，或两者并行；“含研发/不含研发”字段和回本数量采用哪一种毛利口径？
- 截图上方与下方批量数字不一致（例如50与20）是否为录入错误，还是成本计算批量与客户报价批量允许不同？建议统一引用同一场景集合，业务若要求不同集合需另行设计映射。
- 客户页是否显示“调节系数”、内部成本项目名称、税率等字段；默认报价是否含税；是否展示未勾选阶梯的预览入口？
- “我方联系人”的人员来源、联系电话取值规则，以及报价备注和付款/交付/包装条款的字段拆分方式。
- 材料分类是沿用 Item Group、BOM 项目类别还是本单手工分类；损耗按金额增加还是数量补料，避免重复计入。
- 旧单据客户导出默认展示全部历史阶梯还是需要人工选择；建议迁移默认全选以保持兼容，并在首次编辑时允许调整。

本节后续实施仍遵守总原则：小增量、优先新增分支、尽量不动老接口、无业务来源回写、服务端权限和核算为准。本轮只更新文档，没有修改业务代码或数据。

## 10. XLSX模板映射与导出效果

模板核实：一个工作表“1741”，有效内容位于A～X列，左侧A～K为对外报价，M～X为内部核算；存在合并单元格与外部产品查找公式。

| 模板位置 | 业务映射 |

| A1:H2、A4:D6、G5:I6等 | 公司抬头、客户、联系人、日期及电话；最终以现有合并区域逐项映射 |
| A9:K13 | 左侧产品及批次报价，F～J按选定对外批量排布 |
| M1:V2 | 产品、研发人工、各类夹治具、总投入、研发加价率、报废率、组装/测试小时费率 |

| 第13～22行 | 材料、损耗、制造、研发摊销及完整成本 |
| 第23～30行 | 含/不含研发售价、毛利、回本数量 |

内部导出可附“物料阶梯明细”“制造工时”“项目投入及来源”工作表。客户文件必须是独立生成的干净工作簿，只保留左侧报价内容；不能仅隐藏右侧成本列或内部工作表，避免取消隐藏后泄露。两种文件均不得残留样例客户、原样例金额和电话；实际抬头及条款来自本单/公司配置。

| 销售/对外报价 | 新增报价底稿和导出 | 不自动替代标准Quotation，不自动发送 |
| 项目/工单原报表 | 原计算保留 | 新增功能关闭时原流程照常运行 |

拟新增“成本报价核算员/成本报价主管”职责，最终映射现有角色评审。拥有新单权限不自动获得供应商/项目/工单敏感成本权限。普通销售可使用审核后的客户报价文件，不默认读取内部子表和快照JSON；仅靠前端隐藏不构成权限隔离。内部导出要求独立核算权限；客户文件导出也需服务器校验本单可读及客户导出权限。

默认不开放 Guest；批量来源查询使用权限过滤，服务端验证子表属于当前主单、来源公司一致、产品与BOM/工单一致。不得无条件使用 ignore_permissions。跨公司成本读取阻止，跨币种需明确汇率及日期。

## 12. 小增量交付顺序

1. 第一增量：新增主单及子表、直接新增/产品入口、手工数据核算、BOM展开、阶梯价格调用、内部模板导出。交付可用最小闭环。
2. 第二增量：项目入口、工时/项目成本/预算只读适配，分摊、去重和来源详情，明确不齐全项目的提示。
3. 第三增量：工单入口、历史实际参考、标准/实际对比，适配现有人工与库存口径。
4. 第四增量：确认快照、版本/刷新差异、完整权限及客户干净导出、列表统计，完成三入口端到端验收后上线。

各增量可单独验证，但正式面向业务上线前必须完成确认锁定、导出隔离和权限；不能把这些必要项当后续可选优化。成交后自动关联订单并完整核算实际毛利作为下一阶段，避免第一阶段扩大为财务成本重构。

迁移只新增表和入口，不批量改写历史产品/项目/工单。入口通过新脚本控制；需停用时移除新增挂载/导航即可停止业务入口，保留历史单据及附件，不删表、不回滚财务数据。原接口不受停用影响。

## 14. 实施前待确认事项

- 产品与项目现有实际关联字段、项目多产品及费用归属能否自动识别。

- 模板左侧是否允许各批量分别采用含/不含研发策略，以及对外批量超过预留列时的续页样式。

## 16. 单品双页表单导入导出增量方案

### 16.1 范围与界面预期

一张单据仅一个产品，两页共用阶梯、报价和核算数据。导入导出按钮放在主单顶部，切换页签不改变操作对象。首期只支持受控 XLSX 模板，不承诺任意 Excel 排版均可识别。客户可读文件与机器可导入模板明确区分，避免将排版复杂的报价展示文件当作数据交换模板。

```text
产品成本报价单 PCQ-0001 · ABC-001            [保存] [导入 ▾] [导出 ▾]
┌───────────────────────────────────────────────────────────────────┐
│ 对客报价                         成本核算                          │
├───────────────────────────────────────────────────────────────────┤
│ 对客报价：客户/联系人 → 产品 → 展示阶梯及最终价 → 备注与条款       │
│ 成本核算：来源/状态 → 定价参数 → 阶梯矩阵 → 明细/风险/估算确认     │
└───────────────────────────────────────────────────────────────────┘
导入 ▾                              导出 ▾
  下载客户报价导入模板                客户报价单（仅对客内容）
  下载内部核算导入模板                内部完整核算（含明细与风险）
  导入客户报价数据                    可回导数据包（内部权限）
  导入内部核算数据
```

不另设含义模糊的“导出当前页”：客户报价、内部核算和可回导数据包分别定义用途。现有 `export_cost_quotation(name, audience)` 保留；新增数据包导出方法，不给旧 audience 增加不兼容含义。

### 16.2 模板及字段范围

| 类型 | 可导入内容 | 不接受的内容 |
| --- | --- | --- |
| 客户报价数据 | 客户、绑定联系人、报价日期、有效期、条款、已有批量的最终报价与展示选择 | 产品切换、采购价、项目费用、来源键、计算结果及快照 |
| 内部核算数据 | 允许编辑的主单定价参数、手工材料/工时/投入、场景数量和手工报价依据 | BOM等来源行覆盖、来源引用、服务端计算字段、审批/提交状态 |
| 可回导数据包 | 白名单可编辑字段及稳定行标识；来源/计算结果可作为只读参考单独输出 | 将只读参考表当作导入数据；凭文件建立可信来源引用 |

模板包括说明、主单、场景；内部模板额外包括手工材料、手工工时、手工投入。元信息记录模板类型、版本、产品、币种及可选目标单号，不作为鉴权凭据。系统先校验表头和版本，再逐行做类型、单位、币种、客户联系人关系、数值范围及必填项校验；可编辑金额单元格不接受公式，服务端计算结果不从文件回填。

现有导出中的固定 PCS 仅是当前实现表现；后续模板应核实产品单位并校验，不将固定单位扩大为业务约束。客户联系人不得根据 Excel 内容自动创建，产品、客户、供应商等主数据同样只读取已有且有权使用的记录。

### 16.3 导入方式与覆盖保护

首期建议仅导入到已保存草稿，不自动建单、不自动换产品、不自动提交。无单号模板可导入当前草稿；含目标单号时必须与当前单据一致。产品、公司、币种不匹配则阻止应用，需用户另行创建对应草稿。

默认只更新文件明确提供的字段，缺列不清空原值；清空需预览中显式确认。场景以单据内唯一数量匹配，手工明细优先使用服务器校验过的本单行ID；无ID的新行仅追加。行ID不属于本单、指向来源行或文件中重复则报错。首期不支持通过文件隐式删除行，也不按物料编码合并不同供应商/价格依据的行。

来源行仅能通过现有来源刷新流程变更，无来源键手工行才进入导入更新范围。重导同一批无ID新行存在重复风险，预览须提示；首期通过应用后预览失效、并发版本检查以及建议重新导出带行ID模板来避免误操作，不声称任意重复上传都自动幂等。

```text
上传私有XLSX → 校验模板/文件限制 → 检查当前草稿及权限
 → 解析白名单字段 → 按行生成新增/修改/跳过/错误
 → 选择报价信息、场景、手工成本等导入分组 → 确认应用
 → 校验并发版本与文件完整性 → 原子更新 → 标准保存/重新核算
 → 返回变更汇总 → 刷新两页
```

```text
导入预览：内部核算模板 · ABC-001
范围   [☑ 定价参数] [☑ 场景] [☑ 手工材料] [☐ 工时] [☐ 项目投入]
动作   工作表/行号      字段           当前值       文件值
修改   场景/第3行       最终含税价     100          110
新增   手工材料/第2行   物料           —            电容A
错误   手工材料/第5行   价格币种       —            缺失
提示：发现错误，暂不能应用；来源明细不受本次导入覆盖。
                                             [取消] [确认应用]
```

有错误时不部分写入。预览、应用均在服务端鉴权；应用以私有文件原始内容和服务端重新生成的差异为准，不信任浏览器提交的解析结果。文件摘要、单据 modified、所选分组和预览绑定，任一改变要求重新预览。保存异常整批回滚，禁止只导入一半后留下不一致数据。

```text
   ├─ 定价参数、估算确认及缩小的说明框
   ├─ 横向阶梯矩阵：材料分类、损耗、工时、报价与风险
   └─ 可展开的阶梯、材料、工时、项目投入及核算依据

导出：客户报价 / 内部核算 / 可回导数据包
导入：下载客户或内部模板 → 私有上传 → 差异预览 → 分组确认 → 服务端重算
```

客户导出只包含选中的展示阶梯，内部导出保留全部阶梯。换产品或BOM后，已记录来源上下文不匹配的材料/工时会提示待刷新，并在提交、展示导出时阻止继续使用。来源刷新继续保留无来源键的手工行。

### 17.4 本轮边界

- 展示文件和导入模板分开；仅支持受控XLSX模板。客户导入更新已有批量，不新增客户阶梯；内部包仅交换手工明细，不覆盖来源明细。
- 空单元格不覆盖，不提供显式清空或隐式删行。内部无ID新行会新增，重新上传前须核对以免重复。
- 上限为上传5MB、解压总量25MB、6个工作表、每表2000行；拒绝公式、宏和外链。预览凭据10分钟有效且成功应用后失效。
- 我方联系人/电话为手工填写字段；未自行引入员工或用户自动绑定规则。成本计算口径保持原引擎，不擅自改动研发分摊政策。
- 权限沿用内部成本报价权限；标签切换不构成权限隔离，未向普通销售开放内部核算。
- 历史未记录来源上下文的单据，无法追溯升级前已经发生的错误产品切换；应重新预览并刷新来源后核对。
