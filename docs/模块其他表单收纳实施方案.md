# 按业务模块收纳“其他表单”实施方案

## 1. 文档目的

当前系统同时提供 ERPNext 标准表单、`client_akivision` 自定义表单、报表、设置和工具。所有链接平铺在模块工作区后，日常用户需要在大量低频入口中寻找客户、订单、库存等高频表单。

本方案将各模块工作区中的低频、辅助和专项表单收纳到一个统一的“其他表单”分组，同时保留高频主流程入口的可见性。目标是让页面更简洁，但不改变业务对象本身。

本方案是导航和信息架构调整方案，实施边界如下：

- 表单仍属于原业务模块，仍使用原 DocType、URL、权限和工作流。
- 只调整 Workspace/Workspace Sidebar 中链接所在的分组，不迁移数据、不复制表单、不改字段。
- Excel 模板涉及的表单继续保留在主流程或既有专项分组，不因低频而移动。
- 报表、看板、系统设置、子表和系统日志不放入“其他表单”；它们继续留在“报表”“设置”“工具”等语义明确的分组。
- 用户仍可通过全局搜索、权限允许的直接链接和关联记录打开被收纳的表单。

## 2. 现状基线与术语

### 2.1 Excel 表单边界

当前 `excel_import_tables.json` 登记 23 张工作表，其中 19 张可导入业务/主数据表，4 张为只读统计结果。它们是 Excel 导入向导的业务入口，本次不移动：

| 模块 | Excel 表单（保持原分组） |
| --- | --- |
| Selling | 客户清单、销售订单、送货清单 |
| Buying | 供应商清单、采购清单、入库清单 |
| Stock | 产品清单、安全库存参数、出库清单、成品状态、借出样品清单、借回样品清单 |
| Accounts | 收款模式清单、回款记录、采购付款记录表 |
| Projects | 研发项目清单、工时记录 |
| Manufacturing | BOM 表 |
| Assets | 固定资产清单 |
| 只读统计入口 | 供应商回顾、实时库存、汇总计算、各项指标汇总或看板数据 |

“只读统计入口”不是可编辑表单，也不是“其他表单”候选项。它们应继续出现在报表/看板位置，并保持不可下载导入模板的状态。

### 2.2 本文的分组定义

| 类型 | 定义 | 导航处理 |
| --- | --- | --- |
| 主流程表单 | 日常高频、构成 Excel 导入链路或直接影响订单/库存/财务的表单 | 保留在模块首个业务分组 |
| 其他表单 | 非 Excel 主表、低频辅助单据、专项配置和偶发操作入口 | 放入对应模块新增的“其他表单”分组 |
| 报表/看板 | 查询或计算结果，不直接维护业务事实 | 保留在“报表/其他报表/看板”，不改名为表单 |
| 设置/系统单例 | 模块参数、权限、编号和系统行为配置 | 保留在“设置”或模块设置入口 |
| 子表/内部 DocType | 仅作为父表明细或内部存储，不应单独导航 | 不创建菜单链接 |

### 2.3 收纳判定规则

满足以下任一条件的链接可进入“其他表单”：

1. 不在 Excel 工作表中，且不是日常主流程的必经入口。
2. 仅在特定客户、供应商、资产、生产或财务场景使用。
3. 主要用于初始化、规则维护、异常处理或专项业务。
4. 低频但仍需要独立列表和权限控制，不能简单隐藏。

以下条件优先级更高，命中后不得收纳：

1. Excel 工作表对应的可导入表单。
2. 订单、收货、送货、发票、收付款、库存过账等主交易入口。
3. 用户每天需要访问的主数据入口（客户、供应商、物料、仓库、项目）。
4. 已有清晰业务语义的专用分组（例如 POS、借出清单、BOM、报表、设置）。

## 3. 总体导航结构

各模块工作区采用以下稳定结构，实际名称可根据当前中英文翻译显示：

```text
模块工作区
  -> 主流程/主数据（保留高频入口）
  -> 既有专项分组（例如物料与价格、BOM、借出清单、设置）
  -> 其他表单（本方案新增）
  -> 报表/其他报表/看板（只读分析入口）
```

“其他表单”建议放在业务 DocType 分组之后、报表分组之前。每个模块只创建一个同名分组，避免出现“其他表单1”“杂项”“更多”等多个入口。

收纳链接时按稳定的 `link_type + link_to` 去重，不按显示标签去重。中英文标签、翻译变化和用户自定义标签都不能导致同一个 DocType 出现两次。

## 4. 按模块的收纳清单

下表是第一版实施清单。`保留`表示不进入“其他表单”；`收纳`表示移动到对应模块的“其他表单”；`不导航`表示不新增链接。

| 保留 | Item、Item Group、Price List、Item Price | 物料与价格 | 物料/价格日常检索和订单录入依赖 |
| 收纳 | Blanket Order | Selling/其他表单 | 仅部分客户使用的长期框架订单 |
| 收纳 | Sales Partner | Selling/其他表单 | 渠道合作资料，非日常订单入口 |

| 收纳 | Coupon Code、Loyalty Program、Loyalty Point Entry | Selling/其他表单 | 当前业务非主流程，保留权限可控的入口 |

### 4.8 其他模块与自定义表单

系统可能启用 CRM、Quality、Support、Maintenance、Subcontracting、HR 等其他标准模块。原则与上述模块一致：

- 模块存在高频主流程时，先保留其客户、工单、服务单、质检单等主入口。
- 低频规则、模板、导入工具、评分配置和专项维护表单进入该模块的“其他表单”。
- 没有独立工作区的自定义 DocType，不建立新的桌面模块；按业务归属挂到 Selling、Buying、Stock、Accounts 或 Manufacturing 的“其他表单”。
- 只有 `istable=1` 的子表不创建链接。`issingle=1` 的设置单例保留在设置入口。

当前 `client_akivision` 自定义表单建议按以下业务归属处理：

| 自定义表单 | 入口归属 | 处理 |
| --- | --- | --- |
| Sample Loan Out、Sample Loan In、归还单、Finished Goods Status | Stock | Excel/既有借出清单保持可见；归还单可放 Stock/其他表单 |
| Purchase Comparison、Supplier Quote Import、Supplier Rating Standard/Record、Purchase Delay Risk Rule | Buying | 放 Buying/其他表单 |
| Misc Purchase Invoice Request | Buying 或 Accounts | 按实际审批责任选择一个入口，不重复挂载；其 `Misc Purchase Request Item` 为子表 |
| Engineering Drawing、Engineering Drawing Settings、Work Order Labor Item | Manufacturing | 图纸和设置放 Manufacturing/其他表单；Labor Item 不导航 |
| Aging Period Rule、KPI Target | Accounts/KPI Dashboard | 规则和目标值放设置区或 Accounts/其他表单 |
| Quote LLM Settings | Buying/其他表单 | 作为报价辅助配置，不放销售订单主流程 |
| 各类 `*_item`、`*_row`、`*_summary` 子表 | 父表所属模块 | 不创建独立链接 |

## 5. 明确不收纳的对象

### 5.1 不收纳但保留在主流程的表单

除 23 张 Excel 工作表外，下列对象即使不是 Excel 表，也应保留，因为它们是 ERP 业务链路的常用节点：

- Selling：Quotation、Sales Invoice、Customer、Delivery Note。
- Buying：Material Request、Request for Quotation、Supplier Quotation、Purchase Invoice。
- Stock：Item、Warehouse、UOM、Stock Entry、Stock Reconciliation、Delivery Note、Purchase Receipt。
- Accounts：Account、Company、Cost Center、Mode of Payment、Bank Account、Payment Entry。
- Projects：Project、Task、Timesheet、Activity Type。
- Manufacturing：BOM、Work Order、Job Card、生产库存单据。
- Assets：Asset、Asset Category、Location。

这些入口被收纳会增加日常点击成本，也可能使新用户误以为系统没有完整的标准流程。

### 5.2 不进入“其他表单”的非业务入口

- 报表、Query Report、Dashboard、Number Card、趋势图和只读数据页。
- Workspace Settings、Selling/Buying/Stock/Manufacturing/Projects Settings 等单例设置。
- 权限、用户、角色、公司、会计期间等平台级管理入口。
- 子表、内部关联表、系统日志、导入任务明细和自动生成的库存/会计流水。
- 需要审批或高风险过账但有明确“工具”分组的表单，如 Stock Reconciliation、Period Closing Voucher；除非业务确认工具分组过于拥挤，否则不移动。

## 6. 技术实施设计

### 6.1 推荐实现位置

使用现有 `Workspace Sidebar`/`Workspace` 链接机制实现，不修改 ERPNext 官方工作区源码。当前应用已有 `workspace_sidebar.py` 及多项幂等迁移补丁，应沿用同一模式：

1. 在 `client_akivision/config/form_grouping.json`（建议新增）登记模块、目标工作区、收纳链接和保留理由。
2. 在应用迁移补丁或统一同步函数中读取配置。
3. 对每个目标工作区创建一个 `其他表单` Section Break/Card Break。
4. 按 `link_type + link_to` 将收纳链接移动到该分组，删除原分组中的重复链接。
5. 保留未列入收纳清单的原有链接和顺序。
6. 运行 `frappe.clear_cache()`，让新的 Sidebar 在下次加载时生效。

如果当前 Frappe 版本的用户侧菜单来自 `Workspace Sidebar`，以其为最终显示来源；如果某模块仍使用旧版 `Workspace.links`，同步两处，但必须使用同一份配置，避免一个入口移动、另一个入口重复。

### 6.2 配置建议

配置只描述导航，不描述权限和数据迁移。例如：

```json
{
  "Selling": {
    "workspace": "Selling",
    "section_label": "其他表单",
    "links": [
      {"link_type": "DocType", "link_to": "Blanket Order", "reason": "低频长期订单"},
      {"link_type": "DocType", "link_to": "Sales Person", "reason": "辅助档案"}
    ]
  }
}
```

实现要求：

- 目标 DocType/Report/Page 不存在时记录警告并继续迁移，不阻断整个站点。
- 已存在“其他表单”时复用，不重复创建。
- 已在其他模块显示的同一个 Link 不跨模块复制；需要跨模块访问时使用详情页关联或全局搜索。
- 用户无权限时仍由 Frappe 正常过滤，配置不能授予权限。
- 不能通过显示标签删除链接；删除和移动必须基于稳定目标。
- `hidden=1` 的链接不应被强制显示，除非原配置明确要求。
- 每次迁移只处理配置声明的链接，不重排用户自定义的其他链接。

### 6.3 兼容和回滚

迁移补丁必须幂等，可重复执行而不产生重复分组或重复链接。回滚只删除本方案新增的“其他表单”分组及其配置声明的链接，并按迁移前快照恢复原 `idx`；不能删除 DocType、数据或用户自定义工作区。

建议在补丁执行前记录：工作区名称、链接目标、原分组、原 `idx`、目标分组和操作者。这样可以在用户反馈后精确恢复单个链接，而不是整体重置工作区。

## 7. 权限和数据安全

本方案不变更角色权限、不开放导入权限、不改变 DocType 的 `module`、`is_submittable` 或工作流。菜单收纳后：

- 有权限的用户仍可从“其他表单”打开和新建记录。
- 无权限的用户不会看到链接，直接访问 URL 仍由 Frappe 权限拦截。
- Excel 导入接口继续按 `excel_import_tables.json` 过滤；新增的导航配置不能让只读表变成可导入表。
- 交易单据的提交、取消、库存过账和财务分录逻辑完全不变。

## 8. 实施分期

### 阶段一：确认清单

1. 以当前站点实际显示的 Workspace/Sidebar 为准核对链接目标。
2. 业务负责人确认各模块主流程和“其他表单”候选。
3. 确认未启用的模块（POS、委外、订阅、股权、质检等）是否只按权限隐藏，还是仍保留可配置入口。

### 阶段二：先实施低风险模块

### 阶段三：同步前端显示和缓存

1. 执行迁移补丁，创建各模块的“其他表单”。
2. 清理重复链接，确认报告仍在 Reports/Other Reports。
3. 清理 Desk、Workspace Sidebar 和浏览器缓存。

新增 DocType 时先判断是否为主流程；低频表单加入配置并注明理由。每季度根据访问次数、业务反馈和模块新增功能复核一次，不以“表单数量少”为理由随意创建新的模块或分组。

## 10. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 把主流程单据误收纳 | 日常操作变慢，用户找不到入口 | 以 Excel 表和主流程豁免清单双重校验，业务确认后再迁移 |
| 报表被当作表单处理 | 用户误以为可以编辑计算结果 | 按 `link_type` 区分 DocType、Report、Page，报表不进入收纳清单 |
| 同一 DocType 在两个工作区重复出现 | 页面仍然拥挤，用户不确定入口 | 以稳定 Link 目标去重；跨模块访问依赖详情关联或全局搜索 |
| 修改 DocType `module` 造成权限/导入变化 | Excel 导入、角色和路由回归 | 只改 Workspace/Sidebar 子表，不改 DocType 元数据 |
| 迁移补丁重复执行 | 菜单出现重复分组/链接 | 使用幂等查询和唯一目标，执行后做结构审计 |
| 用户自定义工作区被覆盖 | 个性化菜单丢失 | 只处理配置声明目标，保存迁移前快照，不执行整体重建 |
| 新增表单没有归类 | 菜单逐渐重新变乱 | 新 DocType 上线评审必须增加主流程/其他表单归属和理由 |

## 11. 结论

本方案建议把“其他表单”作为每个业务模块内部的导航收纳层，而不是新建一个“杂项”模块。Excel 相关表单、主交易单据、常用主数据、报表和设置分别保持原有语义；低频辅助表单集中在对应模块的“其他表单”中。这样既能降低工作区视觉和认知负担，又不会破坏原有模块、权限、导入和业务链路。
