# 项目成本明细实施方案

## 1. 目标与范围

项目模块需要在项目详情的“成本核算和结算”区域记录无法从工时、采购发票、库存移动直接归集的补充成本。成本支出既可能是物料消耗，也可能是测试费、认证费等非物料费用，因此采用“统一成本行 + 可选物料关联”的设计。每条成本明细包含：

- **成本类型**（物料消耗、测试费、其他费用）
- **物料编码**（可选；物料消耗时必填）
- **费用说明（物料名称）**
- **金额**
- **日期**
- **版本**

表格交互沿用 Frappe/ERPNext 子表（与现有 P2 明细的可编辑网格体验一致）：逐行展示、行内编辑、添加/删除行、列配置和自动行号。页面同时展示“成本明细合计”。

本轮采用小增量方案：新增一个项目子表和一个汇总字段，保留 ERPNext 标准项目成本字段、标准方法签名及既有调用方。成本明细合计先作为独立的手工成本指标，不自动并入标准 `total_costing_amount` 或毛利公式，避免改变现有 Timesheet/采购/库存成本口径。

## 2. 当前基线

当前业务代码位于 `development/frappe-bench/apps/client_akivision`，Project 使用 ERPNext 标准 DocType：

- 标准“成本核算和结算”区字段包括 `estimated_costing`、`total_costing_amount`、`total_purchase_cost`、`total_consumed_material_cost` 等。
- `erpnext.projects.doctype.project.project.Project.validate()` 会调用 `update_costing()`，该方法从已提交 Timesheet、采购发票、销售单据和库存移动更新标准汇总值。
- 自定义字段通过 `create_custom_fields(..., update=True)` 创建，并由 `client_akivision.hooks.after_migrate` 和 `utils/custom_field_schema.py` 做幂等同步。
- 应用已有同类实现：`utils/work_order_labor.py` 创建子表字段并在 `hooks.py` 的 `validate` 事件中计算汇总，可作为实现风格参考。

## 3. 推荐数据模型

### 3.1 新增子表 DocType：`Project Cost Detail`

文件：

`development/frappe-bench/apps/client_akivision/client_akivision/client_akivision/doctype/project_cost_detail/project_cost_detail.json`

建议配置：

| 字段名 | 标签 | 类型 | 必填 | 列表显示 | 说明 |
|---|---|---|---:|---:|---|
| `cost_type` | 成本类型 | Select | 是 | 是 | `物料消耗`、`测试费`、`其他费用`；用于区分物料和非物料支出 |
| `item_code` | 物料编码 | Link: Item | 条件必填 | 是 | `cost_type=物料消耗` 时必填；测试费/其他费用可为空 |
| `expense_description` | 费用说明（物料名称） | Data | 是 | 是 | 物料行默认带出 Item 名称，非物料行填写测试项目/服务说明；保留文本快照，不因 Item 改名而变化 |
| `amount` | 金额 | Currency | 是 | 是 | 允许 0，不允许负数；币种沿用 Project 公司默认币种 |
| `cost_date` | 日期 | Date | 是 | 是 | 成本发生日期；前端可默认当天，服务端仍校验有效日期 |
| `version` | 版本 | Data | 否 | 是 | 物料/方案版本；非版本类费用可以留空，是否必填作为待确认项 |

DocType 属性建议为 `istable=1`、`editable_grid=1`、模块 `Client Akivision`。子表无需单独业务权限，沿用父 Project 的读写权限。暂不增加数量、单位等字段，金额直接记录本次成本；后续若要按数量核算，再以新字段分支扩展。

### 3.1.1 物料与非物料行规则

不建议仅通过“物料编码是否为空”判断费用类型：空值既可能表示测试费，也可能表示物料行漏填。推荐使用以下规则：

| 场景 | 成本类型 | 物料编码 | 费用说明 | 版本 |
|---|---|---|---|---|
| 物料消耗 | 物料消耗 | 必填，Link 到 Item | 自动带出 Item 名称；允许补充用途/批次 | 建议填写物料版本 |
| 测试/认证 | 测试费 | 留空 | 填写测试项目、报告或供应商服务说明 | 可填写测试标准版本，也可留空 |
| 其他支出 | 其他费用 | 留空 | 填写运费、服务费、差旅等说明 | 可留空 |

表格中物料编码列始终显示，保持 P2 明细的稳定列宽；是否必填由成本类型决定并在服务端强校验。选择物料编码后只在费用说明为空时自动填充 `Item.item_name`，保存的是说明快照，不会因后续物料改名而改变历史成本描述。一个支出同时包含物料和测试费时拆成两行，避免一行混合两个口径。

### 3.2 Project 新增字段

通过 Custom Field 增加，不直接修改 ERPNext 标准 `project.json`：

| 字段名 | 标签 | 类型 | 位置 | 说明 |
|---|---|---|---|---|
| `custom_project_cost_details_section` | 成本明细 | Section Break | 成本核算区 `cost_center` 后 | 将新表格和标准毛利区分开，保持原字段顺序稳定 |
| `custom_project_cost_details` | 成本明细 | Table | Section Break 后 | options=`Project Cost Detail`，支持行内编辑 |
| `custom_project_cost_detail_total` | 成本明细合计 | Currency | 子表后 | 只读，由明细行金额求和；币种为 `Company:company:default_currency` |

字段名全部使用 `custom_` 前缀，避免与 ERPNext 后续标准字段冲突。现有项目没有明细时合计为 `0`，不回填历史数据。

### 4.2 新增后端 schema/计算工具

文件：`client_akivision/utils/project_cost.py`

职责：幂等创建 Project Custom Fields、校验明细、计算合计。只通过文档对象设置新字段，不覆盖标准成本字段。

```python
import frappe
from frappe import _
from frappe.custom.doctype.custom_field.custom_field import create_custom_fields
from frappe.utils import flt


def ensure_schema():
    create_custom_fields(
        {
            "Project": [
                {
                    "fieldname": "custom_project_cost_details_section",
                    "label": "成本明细",
                    "fieldtype": "Section Break",
                    "insert_after": "cost_center",
                },
                {
                    "fieldname": "custom_project_cost_details",
                    "label": "成本明细",
                    "fieldtype": "Table",
                    "options": "Project Cost Detail",
                    "insert_after": "custom_project_cost_details_section",
                },
                {
                    "fieldname": "custom_project_cost_detail_total",
                    "label": "成本明细合计",
                    "fieldtype": "Currency",
                    "options": "Company:company:default_currency",
                    "read_only": 1,
                    "insert_after": "custom_project_cost_details",
                },
            ]
        },
        update=True,
    )
    frappe.db.updatedb("Project")
    frappe.clear_cache(doctype="Project")


def calculate_project_cost_detail_total(doc):
    allowed_types = {"物料消耗", "测试费", "其他费用"}
    total = 0
    for row in doc.get("custom_project_cost_details") or []:
        if row.get("cost_type") not in allowed_types:
            frappe.throw(_("成本明细第 {0} 行必须选择有效的成本类型。").format(row.idx))
        if row.get("cost_type") == "物料消耗" and not row.get("item_code"):
            frappe.throw(_("成本明细第 {0} 行为物料消耗时必须填写物料编码。").format(row.idx))
        if row.get("cost_type") != "物料消耗" and row.get("item_code"):
            frappe.throw(_("成本明细第 {0} 行为非物料费用时不能填写物料编码。").format(row.idx))
        if not row.get("expense_description"):
            frappe.throw(_("成本明细第 {0} 行必须填写费用说明。").format(row.idx))
        if not row.get("cost_date"):
            frappe.throw(_("成本明细第 {0} 行必须填写日期。").format(row.idx))
        if flt(row.get("amount")) < 0:
            frappe.throw(_("成本明细第 {0} 行金额不能为负数。").format(row.idx))
        total += flt(row.get("amount"))

    doc.custom_project_cost_detail_total = total
    return total


def validate_project_cost_details(doc, method=None):
    """Project validate hook; leaves standard costing fields untouched."""
    calculate_project_cost_detail_total(doc)
```

金额精度使用站点 Currency 精度，服务端重新计算作为最终值，不能信任浏览器提交的合计。

### 4.5 前端自动合计

文件：`client_akivision/public/js/project_cost_detail.js`；在 `hooks.py` 的 `doctype_js` 增加 `"Project": "public/js/project_cost_detail.js"`。

```javascript
function recalculate_cost_detail_total(frm) {
    const total = (frm.doc.custom_project_cost_details || []).reduce(
        (sum, row) => sum + flt(row.amount),
        0
    );
    frm.set_value("custom_project_cost_detail_total", total);
}

frappe.ui.form.on("Project", {
    refresh(frm) { recalculate_cost_detail_total(frm); },
    validate(frm) { recalculate_cost_detail_total(frm); },
    custom_project_cost_details_add(frm) { recalculate_cost_detail_total(frm); },
    custom_project_cost_details_remove(frm) { recalculate_cost_detail_total(frm); },
});

frappe.ui.form.on("Project Cost Detail", {
    cost_type(frm, cdt, cdn) {
        const row = locals[cdt][cdn];
        if (row.cost_type !== "物料消耗") {
            frappe.model.set_value(cdt, cdn, "item_code", "");
        }
        recalculate_cost_detail_total(frm);
    },
    item_code(frm, cdt, cdn) {
        const row = locals[cdt][cdn];
        if (!row.item_code) return recalculate_cost_detail_total(frm);
        frappe.db.get_value("Item", row.item_code, "item_name").then((r) => {
            if (r.message && !row.expense_description) {
                frappe.model.set_value(cdt, cdn, "expense_description", r.message.item_name);
            }
        });
        recalculate_cost_detail_total(frm);
    },
    amount(frm) { recalculate_cost_detail_total(frm); },
    expense_description(frm) { recalculate_cost_detail_total(frm); },
    cost_date(frm) { recalculate_cost_detail_total(frm); },
    version(frm) { recalculate_cost_detail_total(frm); },
});
```

前端计算只用于即时反馈；保存/提交前由服务端 hook 再次校验和计算。

## 5. 调用链路

```text
用户打开 Project 表单
  -> Frappe 加载 Project 元数据和 custom_project_cost_details 子表
  -> 成本核算区显示可编辑网格 + 成本明细合计

用户新增/编辑/删除明细行
  -> project_cost_detail.js 监听子表事件
  -> 汇总 amount 并刷新 custom_project_cost_detail_total（前端即时反馈）

用户点击保存
  -> 标准 Project.validate() 保持原链路：Timesheet/采购/销售/库存成本更新
  -> doc_events.Project.validate
  -> validate_project_cost_details()
       -> 校验说明、日期、非负金额
       -> 汇总明细金额写入 custom_project_cost_detail_total
  -> Frappe 保存 Project 与子表 tabProject Cost Detail

用户再次打开/刷新
  -> 读取已保存子表
  -> 前端重算显示；只读合计与数据库值一致
```

迁移链路：`bench migrate` -> `after_migrate.ensure_schema`；已有站点同时执行 `patches.txt` 中的补丁。两条路径均幂等，便于新站点安装和旧站点升级。

## 6. 受影响模块与接口边界

| 模块 | 影响 | 处理 |
|---|---|---|
| Projects / Project 表单 | 增加成本明细区、子表和合计 | 新增字段和前端脚本，保留标准布局及操作 |
| client_akivision schema/migrate | 新增子表 DocType、Custom Fields | after_migrate + patch 双保险，均可重复执行 |
| Project 服务端校验 | 保存时校验并计算新合计 | 新增 doc event 分支，不改 `Project.validate` 签名 |
| Timesheet、采购发票、库存移动 | 无行为变化 | 不读取/写入新字段，不改变既有汇总口径 |
| 项目报表/看板 | 本轮不增加列 | 后续如需要再新增报表字段或查询分支，避免现有 SQL 接口变化 |
| 权限 | 沿用 Project 权限 | 子表 `permissions=[]`，不开放独立菜单入口 |
| Excel/Data Import | 本轮不纳入导入 | 避免先定义“项目一行多成本明细”的导入协议；后续可新增专用子表导入模式 |

明确不修改：`erpnext/projects/doctype/project/project.py`、标准 `project.json`、`update_costing_and_billing` API、标准字段 `total_costing_amount`/`total_purchase_cost`/`gross_margin`。

## 7. 预期效果

在项目详情的“成本核算和结算”区，标准成本字段下方出现“成本明细”网格：

| 成本类型 | 物料编码 | 费用说明（物料名称） | 金额 | 日期 | 版本 | 操作 |
|---|---|---|---:|---|---|---|
| 物料消耗 | ITEM-001 | 镜片 A | CNY 1,200.00 | 2026-08-27 | V2 | 行内编辑/删除 |
| 测试费 | 留空 | 高低温测试 | CNY 800.00 | 2026-08-26 | Test-01 | 行内编辑/删除 |

底部提供“添加行”，多行金额录入后“成本明细合计”立即刷新；保存后重新打开仍保持相同明细和合计。物料消耗行选择 `Item` 后仅在费用说明为空时自动带出物料名称，允许用户补充批次/用途；测试费等非物料行不填物料编码，只填写费用说明。空明细时合计显示 `CNY 0.00`。表格宽度、行高、圆角、列配置和批量编辑能力由 Frappe 原生 editable grid 提供，与现有 P2 明细体验一致，无需新增独立页面。

## 9. 发布、回滚与后续问题

发布顺序：

1. 部署应用代码和子表 JSON。
2. 执行 `bench --site <site> migrate`，清理缓存并刷新 Desk。
3. 用测试项目录入、修改、删除明细，核对标准成本字段未变化。

回滚只需移除 Project 上三个 Custom Field 和子表 DocType；删除前应先导出 `tabProject Cost Detail` 数据。若暂时停用功能，可先移除 Project 的 `doctype_js` 和 `doc_events` 注册，历史数据不会被删除。

需要业务确认的两个问题：

1. “版本”是否所有成本行必填？本方案默认非必填，以支持没有版本概念的测试费、服务费。
2. 成本类型是否需要增加“差旅费、认证费”等固定选项？建议先保留“其他费用”，后续按报表需求扩展 Select 选项。
3. 后续是否要把成本明细合计纳入毛利/实际成本？本轮默认不纳入；如确认纳入，应单独增加新汇总字段或新计算分支，并补充报表口径、历史数据和权限评审，不直接改写 ERPNext 标准 Timesheet 成本。

## 10. 迁移未执行时的排查

如果浏览器提示“找不到字段 `custom_project_cost_detail_total`”，说明前端资源已经更新，但站点数据库/DocType 元数据还没有执行本功能的迁移。进入 bench 所在环境执行：

```bash
cd /workspace/development/frappe-bench
bench --site aji_test.localhost migrate
bench --site aji_test.localhost clear-cache
bench build --app client_akivision
```

然后刷新 Project 页面；生产环境按实际 site 名称替换 `aji_test.localhost`。若仍显示旧资源，再执行 `bench restart` 并使用浏览器强制刷新。前端脚本已包含兼容分支，在迁移完成前会保持标准 Project 表单可用，不会反复弹窗。
