# 项目关联创建表单节点绑定丢失修复方案

> 文档日期：2026-09-15  
> 当前阶段：修复方案沉淀，尚未修改代码。  
> 问题范围：从 Project 关联区域点击 `+` 创建业务表单，弹窗选择进度节点后，新表单保存/提交成功，但项目进度节点里仍看不到绑定单据。

## 1. 问题现象

用户操作链路：

```text
打开项目 PROJ-0008
  -> 在关联区域点击某个业务表单的 +
  -> 弹窗选择绑定进度节点，例如 STEP-001 / 11
  -> 点击“下一步创建”
  -> 进入新建业务表单
  -> 保存或提交业务表单
  -> 返回项目进度节点
  -> 对应节点里没有出现绑定单据
```

实际数据库检查结果：

```text
最近提交的生产工单：
MFG-WO-2026-00036
  project = 空
  custom_progress_milestone_code = 空
  custom_progress_step_name = 空

MFG-WO-2026-00035
  project = 空
  custom_progress_milestone_code = 空
  custom_progress_step_name = 空
```

`Project Progress Reference` 没有生成对应记录。

说明问题不是项目进度页展示失败，而是业务表单保存时没有带上项目和节点字段。

## 2. 已排除原因

### 2.1 不是项目节点不存在

项目 `PROJ-0008` 下存在进度节点：

```text
STEP-001 / 11 / 进行中
STEP-002 / 22 / 待开始
```

### 2.2 不是业务表单缺少字段

以下表单均存在自定义字段：

```text
Work Order
Stock Entry
Purchase Order
Purchase Receipt
```

字段包括：

```text
custom_progress_milestone_code  关联步骤
custom_progress_step_name       步骤名称
```

### 2.3 不是后端同步入口完全缺失

`hooks.py` 已经为支持的业务表单挂载了项目进度相关事件：

```text
validate  -> validate_progress_selection
on_update -> sync_progress_selection
on_submit -> sync_progress_from_reference
on_cancel -> sync_progress_from_reference
on_trash  -> remove_progress_selection
```

只要业务表单保存时存在：

```text
project / custom_progress_project
custom_progress_milestone_code
```

后端就可以创建或更新 `Project Progress Reference`。

## 3. 根因判断

当前根因是：

```text
从项目关联区选择的节点，进入新业务表单后被前端项目变更事件清空了。
```

现有前端链路：

```text
project_link_create_binding.js
  -> 用户在弹窗选择节点
  -> 写入 frappe.route_options
  -> frappe.new_doc(doctype)
```

写入内容类似：

```js
frappe.route_options = {
  project: "PROJ-0008",
  custom_progress_milestone_code: "STEP-001",
  custom_progress_step_name: "11"
};
```

但是目标业务表单加载后，`project_progress_reference.js` 中存在项目变更处理：

```js
function handle_progress_project_change(frm) {
  frm.set_value("custom_progress_milestone_code", "");
  frm.set_value("custom_progress_step_name", "");
  setup_progress_selection(frm);
}
```

因此会出现：

```text
route_options 刚把节点带到新表单
  -> project 字段触发 change
  -> handle_progress_project_change 执行
  -> custom_progress_milestone_code 被清空
  -> 保存时没有节点
  -> 后端无法生成 Project Progress Reference
```

这个解释与数据库结果一致：

```text
业务表单保存成功
但 project / custom_progress_milestone_code 为空
```

## 4. 修复目标

本次修复目标不是重做整套项目进度逻辑，而是小增量修复“从项目关联区创建业务表单时绑定信息丢失”的问题。

修复后应满足：

```text
1. 项目关联区点击 +
2. 弹窗选择项目下的进度节点
3. 新建业务表单自动带入项目、节点编码、节点名称
4. 表单保存后生成 Project Progress Reference，状态 Draft
5. 表单提交后 Project Progress Reference 变为 Completed
6. 项目进度节点里能看到关联单据
7. 对应节点根据绑定单据状态重算状态和完成时间
```

## 5. 修改原则

```text
小增量修改
不改 ERPNext 标准接口
不改老接口签名
优先新增前端保护分支
后端同步逻辑尽量复用已有函数
不影响普通业务表单手工选择项目后的清空逻辑
```

核心思路：

```text
普通手工切换项目：
  -> 仍然清空旧节点，避免节点属于旧项目

从项目关联区创建新表单：
  -> 识别这是一次“待绑定创建”
  -> 不让项目 change 事件清掉节点
  -> 表单加载完成后再次强制写入项目和节点
```

## 6. 拟修改文件

### 6.1 `client_akivision/public/js/project_link_create_binding.js`

用途：

```text
负责拦截 Project 关联区 + 按钮，弹窗选择进度节点，并打开新业务表单。
```

拟修改点：

#### 6.1.1 新增 pending binding 存储

在点击“下一步创建”前，除了设置 `frappe.route_options`，再写入 `sessionStorage`：

```js
sessionStorage.setItem("client_akivision_pending_progress_binding", JSON.stringify({
  doctype,
  project: frm.doc.name,
  milestone_code: step.value,
  step_name: step.step_name || step.label,
  created_at: Date.now()
}));
```

原因：

```text
frappe.route_options 可能在表单初始化和字段 change 中被消费或覆盖。
sessionStorage 作为一次性补偿机制，用于目标表单加载后再次恢复绑定。
```

#### 6.1.2 保留 route_options

继续保留现有 `frappe.route_options`：

```js
frappe.route_options = {
  custom_progress_milestone_code: step.value,
  custom_progress_step_name: step.step_name || step.label,
};
```

原因：

```text
route_options 仍是 Frappe 标准新建表单预填方式。
sessionStorage 只作为兜底，不替代标准行为。
```

### 6.2 `client_akivision/public/js/project_progress_reference.js`

用途：

```text
负责业务表单上的项目进度绑定字段、绑定弹窗、节点选项、保存提交后的提示。
```

拟修改点：

#### 6.2.1 新增 pending binding 读取函数

新增函数：

```js
function get_pending_progress_binding(frm) {
  const raw = sessionStorage.getItem("client_akivision_pending_progress_binding");
  if (!raw) return null;

  const binding = JSON.parse(raw);
  if (binding.doctype !== frm.doctype) return null;
  if (Date.now() - binding.created_at > 5 * 60 * 1000) return null;

  return binding;
}
```

用途：

```text
只在目标 doctype 匹配，并且是最近一次创建行为时生效，避免误写到其他表单。
```

#### 6.2.2 新增 apply pending binding 函数

新增函数：

```js
function apply_pending_progress_binding(frm) {
  if (!frm.is_new()) return;

  const binding = get_pending_progress_binding(frm);
  if (!binding) return;

  frm._client_applying_pending_progress_binding = true;

  const project_field = progress_project_field(frm);
  const updates = {};
  updates[project_field] = binding.project;
  updates.custom_progress_milestone_code = binding.milestone_code;
  updates.custom_progress_step_name = binding.step_name;

  frm.set_value(updates).then(() => {
    setup_progress_selection(frm);
    sessionStorage.removeItem("client_akivision_pending_progress_binding");
    frm._client_applying_pending_progress_binding = false;
    frappe.show_alert({
      message: __("已带入项目进度节点：{0}", [binding.step_name || binding.milestone_code]),
      indicator: "green"
    });
  });
}
```

重点：

```text
只对新建表单生效
只对 doctype 匹配的表单生效
写入成功后立即清除 sessionStorage
增加 frm._client_applying_pending_progress_binding 标记，避免项目 change 事件误清空
```

#### 6.2.3 修改项目变更处理

现有逻辑：

```js
function handle_progress_project_change(frm) {
  frm.set_value("custom_progress_milestone_code", "");
  frm.set_value("custom_progress_step_name", "");
  setup_progress_selection(frm);
}
```

拟改为：

```js
function handle_progress_project_change(frm) {
  if (frm._client_applying_pending_progress_binding) {
    setup_progress_selection(frm);
    return;
  }

  frm.set_value("custom_progress_milestone_code", "");
  frm.set_value("custom_progress_step_name", "");
  setup_progress_selection(frm);
}
```

效果：

```text
从项目关联区创建新表单时，不清空系统刚带入的节点。
普通手工切换项目时，仍然清空原节点。
```

#### 6.2.4 在 refresh 中应用 pending binding

在 `refresh(frm)` 中新增：

```js
apply_pending_progress_binding(frm);
setTimeout(() => apply_pending_progress_binding(frm), 300);
```

原因：

```text
部分表单字段初始化较晚，延迟执行一次可以保证字段控件和 doc 都已准备好。
```

#### 6.2.5 业务表单绑定弹窗改为下拉

当前业务表单里的“绑定项目进度节点”弹窗仍使用 `Autocomplete`，并给了对象数组 options，容易出现选择值与实际值不一致。

拟改为 `Select`：

```js
{
  fieldname: "progress_step",
  fieldtype: "Select",
  label: __("绑定进度节点"),
  reqd: 1,
  options: "",
}
```

加载选项时：

```js
dialog.set_df_property(
  "progress_step",
  "options",
  steps.length ? ["", ...steps.map(step => step.label)].join("\n") : ""
);
```

确认时通过 label 或 value 反查：

```js
const step = current_steps.find(
  row => row.label === values.progress_step || row.value === values.progress_step
);
```

效果：

```text
项目关联区弹窗和业务表单内弹窗都统一为下拉选择。
用户选择更稳定，前端取值更明确。
```

## 11. 风险与回滚

### 11.1 风险

风险点：

```text
sessionStorage 中 pending binding 没有及时清理，可能误应用到同类型下一个新表单。
```

控制方式：

```text
1. doctype 必须匹配
2. 只对 frm.is_new() 生效
3. 设置 5 分钟有效期
4. 成功应用后立即 removeItem
```

### 11.2 回滚

如果出现异常，可以回滚：

```text
1. 删除 project_link_create_binding.js 中 sessionStorage 写入逻辑
2. 删除 project_progress_reference.js 中 pending binding 读取和应用逻辑
3. 恢复 handle_progress_project_change 原逻辑
```

回滚后只影响“项目关联区 + 创建表单自动带节点”的增强能力，不影响已有业务表单保存提交。

## 12. 本次修复后的最终预期

修复完成后，用户从项目关联部分创建新表单时，应该看到完整闭环：

```text
项目关联区点击 +
  -> 弹窗选择项目步骤
  -> 新表单自动带出项目和步骤
  -> 保存后项目步骤出现绑定单据
  -> 提交后项目步骤更新完成状态
  -> 项目进度和完成时间同步更新
```

这次重点解决的是：

```text
“我明明在弹窗里选了节点，但是保存提交后项目步骤里没有绑定”
```

根因是前端初始化时把节点清空；修复方向是在目标表单加载后补偿写入，并保护这次系统带入不被项目 change 事件清掉。
