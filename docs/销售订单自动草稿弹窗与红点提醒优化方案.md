# 销售订单自动草稿弹窗与红点提醒优化方案

## 1. 目的与范围

销售订单提交后，系统会按库存自动生成草稿销售送货单和/或草稿生产工单。本方案只补齐生成完成后的可见提醒：当前页面小弹窗，以及对应单据入口红点。

本次不处理销售订单取消、下游单据撤销、库存二次规划、采购申请或草稿自动提交。自动生成的所有单据继续保持草稿，由人工核对后提交。

## 2. 预期效果

```text
销售订单提交
  → 后台生成草稿 Delivery Note / Work Order
  → 当前销售订单页面弹出结果窗口
  → 送货单或生产工单入口显示红点
  → 人工点击入口，查看草稿并自行提交
```

完成弹窗示意：

```text
新增草稿已生成

草稿销售送货单：DN-XXXX
草稿生产工单：WO-XXXX、WO-YYYY

以上单据尚未提交，请人工核对后提交。
```

红点规则：

- 新建草稿 Delivery Note 后，在“送货单”入口显示红点；
- 新建草稿 Work Order 后，在“生产工单”入口显示红点；
- 仅对当前有权限查看对应单据的用户展示；
- 用户进入对应列表或打开对应草稿后，前端重新查询待处理草稿数；数量为零时隐藏红点；
- 红点是待处理草稿提醒，不代表单据已经提交或业务已完成；
- 标准顶部通知铃铛继续保留，作为生产工单的补充提醒。

## 3. 小增量实现方案

### 3.1 后端完成事件

修改文件：`client_akivision/utils/sales_order_auto_fulfilment.py`

保留现有 `sales_order_auto_fulfilment_complete` realtime 事件，扩展返回内容：

```json
{
  "sales_order": "SAL-ORD-XXXX",
  "delivery_note": "DN-XXXX",
  "work_orders": ["WO-XXXX", "WO-YYYY"],
  "issues": [],
  "refresh_badges": ["Delivery Note", "Work Order"]
}
```

事件必须在后台任务完成后推送给实际提交销售订单的用户，而不是 Worker 会话用户。无论成功生成草稿还是生成失败，均推送处理结果，避免页面无反馈。

新增只读统计接口建议：

```python
get_auto_draft_badge_counts()
```

返回当前用户有权限处理的自动生成草稿数量，例如：

```json
{
  "delivery_note": 1,
  "work_order": 2
}
```

统计只计算自动生成且未取消的草稿。为准确区分自动生成与人工创建的单据，后续新增轻量来源标记，例如 `custom_auto_fulfilment = 1` 和来源销售订单字段；不通过时间线文字或单号前缀猜测来源。

### 3.2 前端弹窗与红点

修改文件：`client_akivision/public/js/sales_order_delivery.js`

- 页面加载时注册 realtime 事件；
- 收到本用户的完成事件后弹出中文结果窗口；
- 窗口显示新建送货单、全部新建工单和异常原因；
- 单据编号可直接跳转；
- 收到 `refresh_badges` 后调用红点刷新函数。

新增文件建议：`client_akivision/public/js/auto_fulfilment_badges.js`

职责：

- 读取后端草稿统计；
- 找到 Desk 左侧“送货单”及“生产工单”入口；
- 数量大于零时渲染红点；
- 进入 Delivery Note / Work Order 列表或打开单据后重新统计；
- 不修改标准模块导航数据、不覆盖现有侧栏图标逻辑。

修改文件：`client_akivision/hooks.py`

- 只新增前端 JS 引入；
- 不修改 Sales Order 的既有 `on_submit` hook；
- 不替换现有送货单、生产工单、侧栏相关脚本。

### 3.3 来源标识

拟新增 Custom Field/补丁文件：

| DocType | 字段 | 用途 |
|---|---|---|
| Delivery Note | `custom_auto_fulfilment` | 标记由销售订单自动履约生成 |
| Work Order | `custom_auto_fulfilment` | 标记由销售订单自动履约生成 |
| Delivery Note / Work Order | `custom_auto_fulfilment_sales_order` | 保存来源销售订单，便于统计和跳转 |

自动建单服务在创建草稿时仅在字段存在时写入。字段不存在则保留现有建单能力，但不启用红点统计，避免误把人工草稿算入提醒。

## 4. 调用链路

```text
Sales Order 提交
  → on_submit 入队
  → Worker 生成草稿 Delivery Note / Work Order
  → 写来源标识、时间线和标准生产通知
  → realtime 推送给提交人
  → Sales Order 页面弹出生成结果
  → 前端刷新送货单 / 生产工单红点
  → 用户进入对应列表或草稿
  → 前端重新查询草稿数，更新或清除红点
```

## 5. 受影响模块

| 模块 | 影响 | 风险控制 |
|---|---|---|
| 销售订单 | 显示完成弹窗 | 不改提交校验和自动建单口径 |
| 销售送货单 | 自动草稿红点 | 仅统计有来源标记的草稿 |
| 生产工单 | 自动草稿红点和标准铃铛 | 仅生产角色/有权限用户可见 |
| Desk 侧栏 | 新增小红点 | 独立脚本渲染，不修改导航配置 |
| 权限 | 统计按用户单据读取权限过滤 | 无权限不返回数量、不显示红点 |
| 后台队列 | 完成后额外发送 realtime | 通知失败不回滚已创建草稿 |

明确不受影响：ERPNext 核心、库存台账、销售订单取消流程、原有“一键创建销售送货单”接口、人工草稿单据、草稿提交流程。

## 6. 测试与验收

1. 库存充足订单：生成草稿 Delivery Note，页面出现弹窗，送货单入口出现红点。
2. 多个成品缺货订单：生成多张草稿 Work Order，弹窗列出全部编号，生产工单入口出现红点。
3. 混合订单：送货单和生产工单入口同时显示红点。
4. 无法生成草稿：页面显示失败原因，不显示无意义红点。
5. 点击单据编号可打开正确草稿，所有草稿 `docstatus = 0`。
6. 打开对应列表/草稿后，红点依据最新待处理数量刷新；没有自动草稿时隐藏。
7. 人工创建的草稿不进入自动履约红点统计。
8. 非生产权限用户看不到生产工单红点或生产单据数据。
9. 后台 realtime 失败不影响草稿生成，错误写入日志。

## 7. 实施顺序

1. 增加来源标识字段和自动写入逻辑。
2. 增加按权限统计草稿数量的只读接口。
3. 扩展 realtime 完成事件并验证提交人推送。
4. 实现页面结果弹窗。
5. 实现侧栏红点和进入列表后的刷新。
6. 使用真实订单和 Playwright 完成浏览器验收。
