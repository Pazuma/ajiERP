# 项目最后节点完成与项目完成闭环优化方案

> 文档日期：2026-09-16  
> 当前阶段：方案沉淀，尚未修改代码。  
> 关联方案：`项目进度节点交接式完成规则优化方案.md`。  
> 目标：在“下一个节点开始时，上一个节点才算结束”的新规则下，补齐最后一个节点没有下一个节点可触发完成的问题，并形成项目完成闭环。

## 1. 背景

项目进度节点已经调整为交接式完成规则：

```text
非最后节点：
当前节点表单完成
 -> 当前节点进入待交接
 -> 下一个节点开始
 -> 当前节点正式完成
```

这个规则适合中间节点，因为中间节点都有“下一节点开始”作为结束依据。

但最后一个节点没有下一个节点，因此不能继续套用：

```text
最后节点表单完成
 -> 最后节点进入待交接
 -> 没有下一个节点
 -> 无法自动判断最后节点正式完成
 -> 项目无法自然进入已完成
```

所以需要为最后节点增加一个人工确认收口动作。

## 2. 本次优化目标

本次只解决最后节点和项目完成闭环，不改变前面节点的交接式规则。

目标：

```text
最后节点关联表单完成后，进入“待交接”。
项目负责人点击“完成项目”。
系统完成最后节点，并将项目阶段改为“已完成”。
```

最终效果：

```text
最后节点进行中
 -> 最后节点关联表单提交
 -> 最后节点待交接
 -> 页面出现“完成项目”入口
 -> 人工确认
 -> 最后节点已完成
 -> 项目流程进度 100%
 -> 项目阶段 已完成
```

## 3. 设计原则

本次仍然按小增量改造：

```text
1. 不改 ERPNext 标准 Project 状态逻辑。
2. 不改变已有业务表单提交逻辑。
3. 不推翻“下一个节点开始才完成上一个节点”的规则。
4. 不自动关闭项目，必须人工确认。
5. 优先新增后端方法和前端按钮，不大改老接口。
6. 历史已完成项目不重新计算、不回滚。
```

## 4. 业务规则

### 4.1 最后节点什么时候进入待交接

沿用现有交接式规则：

```text
最后节点关联表单提交/完成
 -> 最后节点 status = 待交接
 -> 不写 actual_completed_on
 -> 不计入已完成权重
 -> duration_display = 待交接，已进行X天
```

说明：

```text
表单完成只代表最后节点的业务动作做完，
不代表项目负责人确认整个项目可以关闭。
```

### 4.2 完成项目按钮出现条件

项目详情页新增按钮：

```text
进度 -> 完成项目
```

按钮出现条件建议为：

```text
1. 项目不是新建状态。
2. 项目未取消。
3. 项目阶段 = 进行中。
4. 项目存在进度节点。
5. 最后一个节点状态 = 待交接。
6. 最后一个节点之前的所有节点状态 = 已完成。
```

也就是说，只有流程确实走到最后，并且最后节点已经完成业务表单后，才允许确认项目完成。

### 4.3 点击完成项目后的处理

点击按钮后弹窗确认：

```text
确认完成最后节点并结束项目吗？
```

确认后系统执行：

```text
最后节点 status = 已完成
最后节点 actual_completed_on = 当前时间
最后节点 completed_by = 当前用户
最后节点 duration_days = 当前时间日期 - actual_started_on 日期 + 1
最后节点 duration_display = X天

Project.custom_actual_process_progress = 100
Project.custom_progress_health = 已完成
Project.custom_project_stage = 已完成
Project.custom_current_progress_step = 已完成
Project.custom_current_progress_duration = -
Project.custom_progress_last_synced_on = 当前时间
```

### 4.4 判断项目完成的统一口径

项目完成的判断条件：

```text
所有 Project Progress Item.status 都是“已完成”
```

只要存在以下任意状态，项目就不算完成：

```text
待开始
进行中
待交接
延期
```

### 4.5 没有关联表单的最后节点

如果最后节点是手工节点，建议同样走人工完成项目：

```text
最后节点为 Manual
 -> 手工更新节点到待交接或直接进入完成项目确认
```

首期建议保持简单：

```text
Manual 节点由“手工更新节点”进入待交接。
再由“完成项目”关闭最后节点。
```

如果后续需要，也可以把“手工更新最后节点”和“完成项目”合并成一个动作，但首期不建议扩大范围。

## 6. 调用链路

### 6.1 最后节点业务表单提交

```text
业务表单 Submit
 -> hooks.py doc_events on_submit
 -> client_akivision.utils.project_progress.sync_progress_from_reference(doc)
 -> 更新 Project Progress Reference.status = Completed
 -> recalculate_progress_item(project, progress_item)
 -> _update_row_status(submitted=True)
 -> 最后节点 status = 待交接
 -> _persist_project_totals(project)
 -> 项目仍保持进行中
```

### 6.2 页面判断是否显示完成项目按钮

```text
打开 Project Form
 -> public/js/project_progress.js refresh(frm)
 -> 读取 frm.doc.custom_project_progress_items
 -> 判断最后节点是否为待交接
 -> 判断前面节点是否都已完成
 -> 满足条件则显示：进度 -> 完成项目
```

### 6.3 点击完成项目

```text
用户点击 进度 -> 完成项目
 -> 前端弹窗确认
 -> 调用 client_akivision.utils.project_progress.complete_project_from_last_step(project)
 -> 后端再次校验权限和节点状态
 -> 最后节点写入已完成、实际完成时间、完成人
 -> 计算最后节点耗时
 -> _persist_project_totals(project)
 -> Project.custom_project_stage = 已完成
 -> 返回结果
 -> 前端 reload_doc
 -> 弹出提示：项目已完成
```

## 7. 拟修改文件

### 7.1 后端核心逻辑

文件：

```text
client_akivision/utils/project_progress.py
```

预计新增：

```text
complete_project_from_last_step(project)
```

职责：

```text
1. 校验用户对 Project 有 write 权限。
2. 校验项目不是已取消/已完成。
3. 获取项目进度节点并按 idx 排序。
4. 校验最后节点 status = 待交接。
5. 校验最后节点之前所有节点 status = 已完成。
6. 将最后节点改为已完成。
7. 写入 actual_completed_on、completed_by、last_synced_on。
8. 调用 _sync_row_duration 计算耗时。
9. 调用 _persist_project_totals 更新项目汇总。
10. 返回完成结果。
```

预计复用：

```text
_ordered_progress_rows(doc)
_sync_row_duration(row, ended_on)
_persist_project_totals(project)
```

不建议修改：

```text
start_progress_step(project, row_name=None, milestone_code=None)
```

原因：

```text
start_progress_step 负责节点启动和中间节点交接。
complete_project_from_last_step 负责最后节点和项目收口。
两个动作语义不同，拆开更清晰。
```

### 7.2 前端项目进度页面

文件：

```text
client_akivision/public/js/project_progress.js
```

预计新增：

```text
1. can_complete_project(frm)
   判断是否显示完成项目按钮。

2. complete_project(frm)
   弹窗确认并调用后端 complete_project_from_last_step。
```

预计修改：

```text
refresh(frm) 中，在“进度”菜单下增加按钮：
  进度 -> 完成项目
```

按钮显示条件：

```text
can_complete_project(frm) === true
```

### 7.3 项目列表展示

文件：

```text
client_akivision/public/js/project_list_stage.js
```

预计不需要大改。

原因：

```text
项目完成后，后端会写入：
custom_project_stage = 已完成
custom_current_progress_step = 已完成
custom_current_progress_duration = -
```

现有列表展示可以继续复用。

如果测试发现列表仍显示最后节点，可以小改 formatter，优先展示后端字段。

### 7.4 DocType 字段

文件：

```text
client_akivision/doctype/project_progress_item/project_progress_item.json
```

预计不需要新增字段。

原因：

```text
已经有：

```

可以满足最后节点完成闭环。

## 8. 受影响模块

### 8.1 直接影响

```text
Project 项目详情
Project 项目进度节点子表
Project 项目总览/项目列表
项目进度联动后端逻辑
```

### 8.2 间接影响

所有已接入项目节点绑定的业务表单，包括但不限于：

```text
Sales Order
Purchase Order
Material Request
BOM
Work Order
Delivery Note
Purchase Receipt
Sales Invoice
Purchase Invoice
Stock Entry
```

说明：

```text
这些表单提交最后节点时，只会让最后节点进入待交接。
项目是否完成由 Project 页面人工确认。
```

### 8.3 不应影响

```text
ERPNext 标准 Project.status

PDF 导出
销售订单自动生成草稿逻辑
项目编号生成逻辑
```

## 9. 权限与安全

后端必须再次校验：

```text
doc.check_permission("write")
```

并且不能只依赖前端按钮显示条件。

后端校验失败场景：

```text
1. 项目不存在。
2. 用户无写权限。
3. 项目已经取消。
4. 项目已经完成。
5. 项目没有进度节点。
6. 最后节点不是待交接。
7. 最后节点之前存在未完成节点。
```

## 10. 历史数据兼容

历史项目可能存在：

```text
所有节点都已完成
项目阶段仍是进行中
最后节点已经有 actual_completed_on
```

处理原则：

```text
1. 本次功能只对新点击“完成项目”的项目生效。
2. 不主动回滚历史项目节点。
3. 不主动把历史项目改成已完成，除非用户执行重新同步或点击完成项目。
4. _persist_project_totals 仍可在所有节点已完成时把项目阶段更新为已完成。
```

## 11. 异常场景处理

### 11.1 最后节点还在进行中

按钮不显示。

如果用户直接调用接口，后端返回：

```text
最后节点尚未待交接，不能完成项目。
```

### 11.2 前面节点还有待交接/进行中

按钮不显示。

如果用户直接调用接口，后端返回：

```text
前置节点尚未完成，不能完成项目。
```

### 11.3 项目已经完成

按钮不显示。

后端返回：

```text
项目已经完成。
```

### 11.4 最后节点业务表单取消提交

如果最后节点还是待交接：

```text
取消提交
 -> 最后节点恢复为进行中/延期
 -> 完成项目按钮消失
```

如果项目已经完成后，最后节点业务表单再取消：

```text
首期不自动回滚项目完成状态。
建议提示人工处理。
```

原因：

```text
项目关闭后再取消末端表单属于异常业务操作，自动回滚项目风险较高。
```

## 13. 实施顺序建议

建议按两步实现：

### 第一步：后端能力

```text
1. 新增 complete_project_from_last_step(project)。
2. 增加严格后端校验。
3. 完成最后节点并刷新项目汇总。
4. 跑 Python 编译检查。
```

### 第二步：前端入口

```text
1. 新增 can_complete_project(frm)。
2. 新增 complete_project(frm)。
3. refresh 中按条件显示“完成项目”按钮。
4. 跑 JS 语法检查。
5. 清缓存并用页面验证。
```

## 14. 最终闭环

最终完整流程为：

```text
项目开始
 -> 第一个节点进行中
 -> 第一个节点表单完成
 -> 第一个节点待交接
 -> 第二个节点开始
 -> 第一个节点已完成
 -> 第二个节点进行中
 -> ...
 -> 最后节点进行中
 -> 最后节点表单完成
 -> 最后节点待交接
 -> 项目负责人点击完成项目
 -> 最后节点已完成
 -> 项目已完成
```

用户能看到的最终效果：

```text
中间节点：由下一节点开始来关闭。
最后节点：由项目负责人确认关闭。
项目完成：所有节点已完成后才成立。
```
