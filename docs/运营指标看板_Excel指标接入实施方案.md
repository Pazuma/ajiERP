# 运营指标看板 Excel 指标接入实施方案

## 1. 结论与边界

目标文件：

`/home/cst/frappe_docker/ERP表格模板(2)(1)_各项指标汇总或看板数据.xlsx`

本文件只沉淀按 Excel 原表接入看板的方案，当前不修改代码、不导入 Excel 示例数值、不创建客户/供应商/项目/订单等演示业务数据。

这些看板的定位是“系统数据自动汇总看板”：用户选择公司、日期等筛选条件后，页面调用看板接口读取系统中已提交的业务单据，按 Excel 中的指标和分区计算并展示当前值、目标、达成率、状态和明细入口。看板本身不保存也不依赖 Excel 汇总值。

Excel 应被视为“指标样例和验收基线”，而不是业务事实表。上线后看板当前值必须由已提交业务单据重新计算；目标值和预警规则由配置表单维护。本方案不设置历史快照。

“自动”表示系统按当前数据自动查询和计算，不表示绕过单据状态或自动补造数据：草稿、取消单据、无权限数据不应进入 Excel 已列出的指标；数据刚发生变更后的可见时间取决于单据提交、数据库事务和页面刷新时点。

### 本次范围固定

- 只设置 Excel 中已有的 9 个分区和已有指标；
- 不新增 Excel 之外的指标、图表、统计维度或业务模块；
- 不把 Excel 横向表格扩展成新的“看板数据”录入表单；
- 不导入 Excel 中的示例数值、客户A、供应商A、研发项目A等占位数据；
- 只补充这些 Excel 指标所必需的系统数据关联和自动计算规则。

## 4. 指标与数据关联方案

### 4.1 销售整体指标

| Excel 指标 | 建议编码 | 计算口径 | 关联/下钻 |
| --- | --- | --- | --- |
| 总订单数 | `total_orders` | 已提交 Sales Order，按公司和交易日期去重计数 | Sales Order List |
| 总销售额 | `total_sales_amount` | 已提交订单 `grand_total` 汇总；需确认含税/未税口径 | Sales Order List |
| 高新收入总额 | `high_tech_revenue` | Sales Order 高新标记为真时的金额汇总 | High-tech Revenue Analysis |
| 高新收入占比 | `high_tech_ratio` | 高新收入 / 总销售额；分母为 0 显示无数据或 0，需统一 | High-tech Revenue Analysis |

Excel 样例值为 260、100000、0、0，均只用于验收，不直接写入系统。

### 4.2 订单完成状态

以 Sales Order Item 的 `qty` 和 `delivered_qty` 为事实，订单号和产品型号只作为人工核对辅助，不应依赖模糊名称关联。

| 指标 | 判定 |
| --- | --- |
| 整单已完成 | 订单所有明细均 `delivered_qty >= qty` |
| 整单未完成 | 存在任一明细未完成 |
| 已交货 | 至少一条明细 `delivered_qty > 0` |
| 交货中 | 至少一条已交货且不是整单完成 |
| 未交货 | 所有明细 `delivered_qty = 0` |

必须区分“至少有交货”和“全部完成”。Excel 样例中的 126、134、237、1、1 不能在未确认数据集前强行相加或回填。

### 4.3 回款与应收

| 指标 | 计算口径 | 事实关联 |
| --- | --- | --- |
| 已收款总额 | 已提交 Receive 类型 Payment Entry 的发票核销金额汇总 | Payment Entry Reference.reference_name -> Sales Invoice |
| 应收款总额 | 已提交 Sales Invoice 的 `outstanding_amount` 汇总 | 以截止日余额为准，需确认是否包含期间外发票 |
| 已结清/未结清单据数 | `outstanding_amount = 0` / `> 0` 的发票数 | Sales Invoice |
| 平均应收天数 | 未结清余额加权账龄，不使用简单发票平均值 | 截止日 - due_date |
| 超 90 天逾期应收 | 账龄大于 90 天的未结清余额 | Aging Period Rule |
| 应收款周转天数 | 财务确认公式后固化；不能默认等同加权账龄 | Sales Invoice、销售收入 |

Excel 说明写的是“回款清单来源为已送货订单”。实施前必须确认：回款事实以送货单、销售发票还是 Payment Entry 核销为准。建议以 Payment Entry 核销为金额事实，以订单/送货作为业务追溯链路。

### 4.4 业务员业绩

业务员关联使用单据 Sales Team 的 `sales_person` 和 `allocated_percentage`。多业务员单据必须按已配置比例分摊，并校验分摊比例是否为 100%。

| 指标 | 口径 |
| --- | --- |
| 送货条数 | 按 Delivery Note 去重后，按销售团队规则计数 |
| 送货业绩金额 | Delivery Note Item 金额按团队比例分摊 |
| 个人已回款 | 发票核销金额按团队比例分摊 |
| 个人应收款 | 发票未收余额按团队比例分摊 |
| 交付率 | 个人送货金额 / 个人订单金额 |
| 回款率 | 个人已回款 /（个人已回款 + 个人应收款） |

Excel 样例回款率为 `214.5438%`，超过 100%，应作为数据质量异常处理，先核对期间混用、重复核销和销售团队分摊，不能直接作为目标或状态依据。

### 4.5 同比与对账预警

- 同比按当前筛选期间向前平移 12 个自然月，处理闰年和月末边界；不要简单减 365 天。
- 销售同比：`(本期销售额 - 上年同期销售额) / 上年同期销售额`。
- 应收同比必须先确定比较期末余额还是期间平均余额。
- 状态不一致需同时检查订单状态与明细交货事实，输出订单号、客户、状态、已交量、应交量和异常原因。

### 4.6 应收核心管控与账龄

账龄区间由 `Aging Period Rule` 维护，初始建议：0-30、31-60、61-90、91-180、181+ 天。规则必须校验不重叠、不缺段；金额和占比由发票余额计算，不在规则表中手工填写。

逾期客户 TOP10 按客户汇总未结清余额，输出客户、逾期金额、最大逾期天数和风险等级，并可下钻 `Receivable Aging Analysis`。Excel 中“客户A-客户J”是占位名称，不得创建为正式客户。

### 4.7 生产采购运营

| 指标 | 来源与公式 | 评价方向建议 |
| --- | --- | --- |
| 本月生产计划完工率 | Work Order 实际产量 / 计划产量 | 越高越好 |
| 采购到货及时率 | 已到评价截止日的采购订单中按时完成数 / 应评价订单数 | 越高越好 |
| 实时库存总金额 | Bin 数量 × 估价；排除规则需与库存报表一致 | 依经营策略 |
| 安全库存预警物料数 | 低于物料/仓库安全库存的组合数 | 越低越好 |
| 采购在途金额 | 未收数量 × 采购价，排除取消/关闭单据 | 越低越好或按策略 |
| 生产领料超耗率 | `max(实际消耗 - 标准需求, 0) / 标准需求` | 越低越好 |

采购订单与收货通过 Purchase Order Item / Purchase Receipt Item 关联；不能只按供应商和日期推断。生产趋势按 Work Order 计划开始月份分组。供应商 TOP10 输出延迟订单数、平均延迟天数和 `Purchase Delay Risk Rule` 风险等级。

### 4.8 高新收入合规

| 指标 | 建议口径 | 待确认点 |
| --- | --- | --- |
| 本年高新收入总额 | 本年度高新标记销售订单金额 | 是否改用 Sales Invoice 收入 |
| 本年总营收总额 | 本年度销售金额 | 财务收入确认口径 |
| 高新收入占比 | 高新收入 / 总营收 | 分母为 0 的展示方式 |
| 研发项目数量 | 有效项目数或本年立项项目数 | 不能默认用未完成项目存量 |
| 本年研发费用 | 研发费用科目下的有效费用单据 | 科目范围、含税、来源单据 |
| 研发费用占比 | 研发费用 / 总营收 | 与合规标准确认 |

近 3 年趋势按年度聚合；研发项目 TOP10 按 `Sales Order.project` 关联项目汇总高新收入，并计算项目收入占高新收入总额的比例。Excel 中“研发项目A-研发项目J”是占位名称，不得创建为正式项目。

## 5. 目标和状态配置

### 5.1 KPI Metric Definition

每个指标建立一条定义，至少填写：指标编码、名称、分区、数据类型、来源单据、公式、统计范围、默认周期、评价方向、下钻报表、维护角色、口径版本和备注。该表单只描述“怎么算”，不录入当前金额、数量、达成率。

### 5.2 KPI Target

目标以“公司 + 指标编码 + 周期类型 + 周期值”唯一。目标表保存目标值、评价方向、预警阈值和危险阈值；看板运行时返回当前值、目标、达成率和状态。金额、数量和比例必须按指标数据类型填写，不能混用。

Excel 中出现以下待确认情况：

- 研发项目数量为 11、目标为 10、达成率 110%，但状态写成“未达标”；需确认目标方向。
- 安全库存预警数目标为 0，达成率显示 100%；需定义分母为 0 时的状态算法。
- 高新收入占比、研发费用占比的目标以 `0.6`、`0.05` 存储，界面显示为百分比，必须统一存储和展示单位。

## 6. 数据流与追溯

```text
公司/日期/业务员等筛选
        ↓
已提交销售、送货、发票、收款、采购、收货、工单、库存、项目单据
        ↓
指标计算层（按 KPI Metric Definition 的公式和版本）
        ↓
KPI Target / Aging Period Rule / Purchase Delay Risk Rule
        ↓
运营指标看板：卡片、图表、趋势、TOP10、状态
        ↓
原始订单/发票/收款/库存/工单/供应商/项目下钻
```

### 6.1 自动取数规则

1. 页面提交筛选条件后调用 `get_kpi_dashboard_data`，服务端重新查询业务表并计算，不读取 Excel 文件中的金额、数量或状态。
2. 事实数据只取符合指标定义的已提交单据，并应用公司、期间、状态、仓库、项目和权限过滤。
3. `KPI Target`、`Aging Period Rule` 和 `Purchase Delay Risk Rule` 只提供目标、阈值和分段规则，不替代订单、发票、收款、库存等事实数据。
4. 页面刷新或重新进入看板时重新取数；导出 Excel 应复用同一计算结果，避免页面与导出不一致。
5. 指标结果应支持下钻到原始单据。若业务单据尚未提交、被取消或当前用户无权查看，则不应被看板计入或暴露。

### 6.2 Excel 的用途

Excel 只用于以下场景：

- 确认指标名称、分区和展示形式；
- 作为真实系统数据计算结果的对照样本；
- 记录差异及其原因，例如期间不同、口径不同、单据缺失或样例计算错误；
- 本方案不导入、不保存 Excel 历史汇总值。

因此，用户不需要先把这份 Excel 上传到看板，才能生成看板数据；只要系统业务单据和指标配置完整，看板即可自动形成结果。

任何指标都应能反查到来源单据或明细。看板、导出 Excel 和下钻报表应共用同一计算口径，不能分别维护三套公式。

## 7. 实施顺序（仅针对 Excel 现有内容）

1. 按 Excel 现有 9 个分区确认字段名称、目标值和展示状态。
2. 为 Excel 中已有指标登记数据来源和计算公式。
3. 配置这些指标对应的目标值、账龄区间和采购延迟风险区间。
4. 以真实公司和已提交单据计算结果，与 Excel 样例逐项核对；差异记录原因，不直接改样例值。
5. 只实施 Excel 已有指标所需的代码调整和测试，不扩展其他看板内容。
6. 通过权限、日期、分母为 0、重复核销、多业务员分摊和异常状态验收后上线。

## 8. 验收清单

- 一个订单全部交货时只进入“整单已完成”；部分交货进入“交货中”；无交货进入“未交货”。
- 一张发票分多次收款时，已收、未收和结清状态不重复计算。
- 账龄 30/31/60/61/90/91/180/181 天边界分别落入正确区间。
- 未到期采购订单不进入采购及时率延迟分母。
- 多业务员单据按约定比例分摊，汇总不超过事实金额。
- 高新收入、总营收和研发费用的年度趋势可追溯到订单/发票/费用单据。
- 无目标、日期逆序、公司为空、分母为 0 时有明确状态，不伪造达成率。
- 无看板角色不能调用 API；无下钻权限时不暴露明细入口。

## 9. 风险控制

| 风险 | 控制措施 |
| --- | --- |
| 把 Excel 汇总值直接导入 | 当前值只读计算；Excel 仅作为验收样本 |
| 订单状态和交货事实不一致 | 由明细交货量判定，并单独输出异常 |
| 回款率超过 100% | 校验期间、核销和团队分摊，异常不参与目标判断 |
| 财务口径混用 | 在指标定义中记录来源单据、日期字段和公式版本 |
| 账龄区间重叠/断档 | 保存规则前校验连续性和唯一性 |
| 占位客户/供应商/项目被当成主数据 | 文档和验收数据明确标记样例，不创建正式记录 |
| 历史口径变化 | 递增 `definition_version`，确保当前指标公式和 Excel 对照口径可区分 |

## 10. 本次交付说明
