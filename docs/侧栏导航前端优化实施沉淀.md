# 侧栏导航前端优化实施沉淀

## 1. 实施范围与结论

本次只调整 Desk 前端侧栏的展示层级和排序，不修改后端业务逻辑、DocType、字段、权限、报表查询、数据库中的 Workspace Sidebar 记录或任何业务数据。

侧栏在 Desk 加载时读取现有 `frappe.boot.workspace_sidebar_item`，由前端脚本按模块规则重排内存中的导航数据，然后交给 Frappe 原生侧栏组件渲染。刷新页面后仍以原始工作区配置为数据源。

已落地的规则：

| 模块 | 根层展示 | 保留收纳夹 |
| --- | --- | --- |
| 采购 | 采购业务单据、物料、价格表、供应商评级标准、采购税费模板 | 其他表单、报表、设置 |
| 生产 | 物料清单、生产业务表单，以及原“设置/主数据”夹内的表单 | 物料计划、工具、其他表单、报表；原设置夹取消 |
| 销售 | 核心销售单据、物料与价格、销售配置表单 | 其他表单、报表 |
| 库存 | 物料、仓库、单位、库存业务单据，以及原工具/主数据表单 | 其他表单、报表、设置 |

根层链接统一按业务流程排序；同一条导航只保留原有入口，不新建业务入口。

## 2. 数据流

```text
Workspace Sidebar / Desk Boot
          |
          v
frappe.boot.workspace_sidebar_item
          |
          v
client_akivision/public/js/sidebar_icons.js
  - 识别当前模块
  - 展开指定收纳夹的子链接
  - 设置 child=0、indent=0
  - 按业务顺序排序根层链接
  - 保留约定的“其他表单/报表/设置”分组
          |
          v
frappe.ui.Sidebar.prepare()
          |
          v
Frappe 原生 Sidebar 渲染
          |
          v
用户点击 DocType / Report / Page
          |
          v
原有路由、权限和业务校验
```

前端变换仅在普通用户的侧栏初始化时执行；侧栏编辑模式不执行变换，避免把展示层临时排序反向保存到 Workspace Sidebar。

## 3. 依赖清单

### 3.1 运行时依赖

- Frappe Desk 原生 `frappe.boot.workspace_sidebar_item`。
- Frappe 原生 `frappe.ui.Sidebar`、`sidebar_setup` 事件和 Section Break 渲染机制。
- `client_akivision` 已有的 `app_include_js`：`/assets/client_akivision/js/sidebar_icons.js`。
- 现有 Workspace Sidebar、DocType、Report、Page 及用户权限配置。

### 3.2 不涉及的依赖

- 不依赖新增 API 或数据库字段。
- 不依赖修改 `after_migrate` 同步脚本。
- 不改变业务单据之间的创建、提交、库存扣减和数据校验流程。

## 4. 风险点清单

| 风险 | 影响 | 处理方式 |
| --- | --- | --- |
| Frappe 升级后侧栏数据结构变化 | 展开或排序规则可能失效 | 以 `type`、`label`、`child` 等稳定字段处理；升级后复测四个模块 |
| 中英文标签差异 | 规则无法识别分组 | 同时匹配中英文标签，并保留未识别分组 |
| 用户自定义侧栏 | 页面显示顺序与标准方案不同 | 编辑模式跳过前端重排，不覆盖用户自定义配置 |
| 重复入口 | 同一表单出现多次 | 仅重排现有链接，不创建新链接；复测时检查重复的 `link_type + link_to` |
| 权限导致链接缺失 | 不同角色看到的入口数量不同 | 以权限过滤后的结果为准，不强制显示无权限表单 |
| 缓存未更新 | 旧 JS 仍在浏览器中运行 | 发布后执行资源构建/缓存刷新，并用无缓存窗口复测 |
| 侧栏过长 | 小屏幕需要滚动 | 保持核心入口在顶部，低频内容留在收纳夹，验证桌面和窄屏布局 |

## 5. 需要复测的场景

### 5.1 导航结构

- 采购：主数据不再出现独立收纳夹；其他表单、报表、设置仍可展开。
- 生产：原设置/主数据中的表单与物料清单同级；物料计划、工具、其他表单、报表仍可访问。
- 销售：POS、物料与价格、主数据、设置等非例外分组中的链接均为根层；其他表单、报表仍保留。
- 库存：工具、主数据中的链接为根层；其他表单、报表、设置仍保留。
- 四个模块均无重复的同目标链接，根层链接无缩进。

### 5.2 路由与功能

- 点击每个根层 DocType，能打开对应列表页。
- 点击其他表单中的 DocType，能打开对应列表页。
- 点击报表链接，能打开报表页并保留原有筛选能力。
- 点击 Page、Dashboard、Workspace 类型链接，路由与原来一致。
- 切换模块后侧栏重新渲染，不串用上一个模块的链接。
- 浏览器刷新后布局保持一致，且没有重复追加链接。

### 5.3 数据字段与权限

- 打开采购申请、销售订单、生产工单、库存凭证等核心表单，字段、必填校验和操作按钮完整。
- 用普通业务角色验证无权限 DocType 不会因前端重排而泄露入口。
- 用系统管理员进入侧栏编辑模式，原始可编辑结构不被前端展示规则改写。

### 5.4 体验

- 默认展开侧栏和收起侧栏各验证一次。
- 1440px 以上桌面分辨率和窄屏分辨率各验证一次。
- 收纳夹默认状态、箭头、滚动位置和当前选中项正常。
- 控制台无新增 JavaScript 异常，网络请求无新增失败。
