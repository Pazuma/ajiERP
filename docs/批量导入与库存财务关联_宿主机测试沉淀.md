### 2.1 BOM 物料准确性结论

当前结论是“**计算链路静态验证通过，但尚未完成真实库存准确性验证**”。采购建议的 BOM 模式调用 ERPNext `BOM.get_exploded_items()` 展开子 BOM，取每个子件的 `stock_qty`（库存单位数量），再乘以筛选条件中的 `BOM Qty`；相同料号即使来自不同工序也会累加。

本次使用模拟的已展开两层 BOM 执行 `purchase_recommendation._get_basket_items`：`BOM-TEST-001` 中 `RAW-A-TEST` 的两条展开数量为 `2.5 + 1.5`、`RAW-B-TEST` 为 `4`；当 `BOM Qty = 3` 时，结果分别为 `12`、`12`。空 BOM 返回“没有物料”的明确错误。该测试未创建数据库记录、未验证实际 `Bin`、单位换算配置或 BOM 提交状态。

## 4. 数据流

```text
Excel/XLSX 文件
  -> Frappe FileUploader 生成 file_url
  -> create_inline_import 创建 Data Import 任务
  -> preview_inline_import 调用标准 Importer 做字段识别和预览
  -> start_inline_import 提交后台任务
  -> Data Import Importer 逐行创建/更新单据并写入 Data Import Log
  -> 可提交单据在 submit_after_import=1 时提交
  -> Purchase Receipt / Delivery Note / Stock Entry 更新 Bin、Stock Ledger Entry
  -> 销售或采购发票、付款单提交后更新 General Ledger Entry 和应收应付
  -> Safety Stock Status、Realtime Inventory、Purchase Recommendation、运营指标看板读取业务单据和库存汇总
```

关键关联：

- BOM 模式将已展开的 BOM 子件按 `stock_qty * BOM Qty` 汇总后交给采购建议。
- 安全库存报表读取 `Item Reorder`、`Bin.projected_qty`、`Item.safety_stock`，补货封装会以最大库存上限截断建议数量。
- 阶梯报价优先读取有效的 Pricing Rule；没有规则时读取已提交 Supplier Quotation 的多数量行；计算会比较需求数量和更高阶梯起订数量的总价。
- 看板安全库存预警数从 Item Reorder/Bin 聚合，库存金额从 Bin 与 Warehouse 聚合。

## 6. 问题与风险记录

| 编号 | 发现 | 影响 | 当前处理/建议 |
| --- | --- | --- | --- |
| T-01 | 表单内导入 Playwright 控制台出现一次临时资源 `404`，脚本仍通过 | 模拟页面存在非关键资源缺失；无法证明真实 Desk 资源完全正常 | 在 `aji_test.localhost` 打开浏览器 Network 面板复测，确认无业务脚本/样式 `404` |
| T-02 | 本轮未接入真实 Frappe 服务与 MariaDB | 无法验证真实 XLSX 解析、后台队列、库存流水、总账分录、权限和事务回滚 | 在 `aji_test.localhost` 用专用测试公司/仓库和 `E2E-IMPORT-YYYYMMDD-*` 前缀执行端到端用例 |
| T-03 | 当前前端在 Partial Success/Error/Timed Out 后显示最终状态并将主操作改为“关闭” | 虽然后端 `start_inline_import` 允许重启这些状态，但用户需去 Data Import 任务页重试，弹窗内没有直接重试按钮 | 不修改代码；真实复测时从 Data Import 表单点击标准重试并核对成功行未重复创建 |
| T-04 | 重复导入的结果依赖目标单据命名规则、唯一字段和导入模式 | “插入新记录”可能创建业务重复单据；标准 Importer 只保证同一个任务失败重试时跳过成功行 | 正式流程要求首导使用 Insert，修订使用 Update Existing Records + ID；真实用例必须验证两次上传同一文件的结果 |
| T-05 | 自动提交会触发不可逆业务副作用 | 采购入库、送货、库存调拨、发票、付款等可能更新库存或财务 | 自动提交保持默认关闭；只在隔离测试数据、审批人确认、先截图期初库存/账务后启用 |
| T-06 | BOM 齐套与补货取决于物料默认仓、单位换算、Item Reorder 和实际库存 | 设置不完整会导致少算、多算或没有采购建议 | 测试前创建有明确 UOM、仓库、reorder level、max stock limit 的专用物料 |
| T-07 | 阶梯报价规则需财务/采购确认币种、有效期和优先级 | 无效价格可能被排除，跨币种不会比较 | 为每个阶梯设置相同公司币种和有效期，验证 1/10/100 等边界数量 |
| T-08 | Purchase Recommendation 的 BOM 选择器仅限制 `is_active=1`，后端没有强制顶层 BOM `docstatus=1` | 草稿但启用的 BOM 也可能被用于采购比较；其子件或数量未定稿时，结果不能作为正式采购依据 | 不修改代码；真实复测只选择已提交的 `BOM-TEST-*`，并分别尝试草稿/已提交 BOM，记录是否允许及数量差异；正式操作前由工艺确认 BOM 版本 |

## 7. 需要在 aji_test.localhost 复测的场景

1. 使用真实 Excel 上传 Sales Order、Purchase Receipt、Delivery Note、Stock Entry、Payment Entry；在预览中检查所有必填字段、Link 字段和子表行。
2. 对同一 Data Import 制造一条合法行与一条非法 Link 行，开始导入后确认 Partial Success；修正失败行后重试，确认成功行没有重复创建。
3. 同一文件连续导入两次：Insert New Records 预期按目标单据唯一性拒绝或产生可识别重复；Update Existing Records 使用 ID 后预期只更新原单。
4. 对 Purchase Receipt、Delivery Note、Stock Entry 分别勾选“导入后自动提交”，导入前后比对 Bin、Stock Ledger Entry、实际数量、库存价值和对应单据状态。
5. 对 Sales Invoice、Purchase Invoice、Payment Entry 勾选自动提交，导入前后比对 General Ledger Entry、应收/应付余额和核销引用。
6. 创建并提交两层 `BOM-TEST-*`，分别令一个子件充足和不足；在 Purchase Recommendation 选择 `Compare By = BOM`、BOM、BOM Qty，核对展开后的子件与数量。基准为每个子件的 `BOM Explosion Item.stock_qty × BOM Qty`，相同料号跨工序必须累加。另以草稿但启用的 `BOM-TEST-*` 验证 T-08，并禁止将该结果用于正式采购。
7. 将 `Bin.projected_qty` 调低到安全库存线以下，运行自动补货；检查 Material Request 数量为缺口且不超过 `custom_max_stock_limit - projected_on_hand`。
8. 创建 1-9、10-99、100+ 三档有效采购价格；分别输入 9、10、99、100 的需求数量，核对 direct/recommended qty、rate、total 和 savings。
9. 提交上述库存与采购单据后，刷新 Safety Stock Status、Realtime Inventory、Purchase Recommendation 和运营指标看板，逐项同源单据、Bin、Stock Ledger Entry 和 GL Entry 对账。
10. 使用无导入权限、无提交权限、无报表权限账号分别执行，确认弹窗/API/下钻均被正确拒绝。
