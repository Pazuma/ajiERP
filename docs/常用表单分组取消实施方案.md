# 取消“常用表单”分组实施方案

## 1. 方案结论

当前“常用表单”分组增加了一次展开操作：用户需要先展开“常用表单”，再点击客户、订单、物料等入口。本方案取消该分组，只取消导航收纳方式，不取消高频表单入口。

实施后，各模块侧边栏采用以下结构：

```text
模块工作区
  -> 高频表单直接链接（模块顶部，不放入“常用表单”）
  -> 既有业务/专项分组
  -> 其他表单（低频表单统一收纳）
  -> 报表/看板/设置
```

高频表单仍属于原模块，用户可以在模块侧边栏直接点击，不需要先展开“常用表单”。低频辅助表单继续放在唯一的“其他表单”分组中。

本轮只编写实施方案，暂不修改代码、数据库或 Workspace 数据。

## 2. 现状与问题

现有实现位于：

- `client_akivision/config/other_forms_sidebar.json`
- `client_akivision/utils/other_forms_sidebar.py`

配置中的 `common_links` 会触发以下行为：

1. 创建或复用“常用表单” Section Break。
2. 将客户、订单、物料等高频链接集中到该分组。
3. 将分组放在模块前部。

这保证了高频入口集中，但用户仍需要执行“展开分组 -> 点击表单”两步操作。目标是保留入口集中和图标体验，同时把高频链接提升为模块侧边栏顶部的直接链接。

## 3. 目标与非目标

### 3.1 目标

- 删除各模块的“常用表单”分组标题和展开层级。
- 高频表单在所属模块侧边栏顶部直接显示并可点击。
- 保留现有高频表单的顺序、中文标签、Lucide 图标和原始 URL。
- 继续保留每个模块最多一个“其他表单”分组。
- 低频表单、报表、设置、子表和系统入口继续按现有规则处理。
- 迁移脚本可重复执行，不产生重复链接、重复分组或顺序漂移。

### 3.2 非目标

- 不删除任何 DocType、Workspace、Workspace Sidebar 或业务数据。
- 不修改 DocType 的 `module`、字段、权限、工作流、导入配置和路由。
- 不把所有表单都提升到顶部；只有配置明确声明的高频入口才提升。
- 不取消“其他表单”分组，不把低频表单重新平铺。
- 不修改 Frappe/ERPNext 官方核心代码。

## 4. 侧边栏交互设计

### 4.1 直接链接规则

高频入口以模块侧边栏的根层 Link Item 显示，位置建议为：

1. 模块入口、Workspace 或 Dashboard 链接之后。
2. 第一个业务 Section Break 之前。
3. 报表、设置和“其他表单”之前。

这些链接不再包在“常用表单” Section Break 中，因此用户进入模块后可以直接点击。

如果当前 Workspace 没有可用的业务分组，则直接放在模块侧边栏根层；不为了迁移而新建“常用表单”或“主流程”分组。

### 4.2 其他表单规则

“其他表单”继续作为低频表单的唯一收纳层，位置保持在业务入口之后、报表/设置之前。取消“常用表单”不得改变以下行为：

- 低频链接仍可通过“其他表单”展开后访问。
- 同一 `link_type + link_to` 只保留一个链接。
- 用户自定义且未声明的链接不删除、不整体重排。
- 图标仍由前端 `sidebar_icons.js` 注入，不写入数据库。

### 4.3 视觉与移动端

- 高频根层链接继续显示业务含义匹配的 Lucide 图标。
- 图标、文字和点击区域保持垂直对齐，不改变链接路由。
- 顶部高频入口过多时允许侧边栏自然滚动，不使用横向滚动或超长按钮。
- 390px 移动视口下，链接文字可换行或省略，但不能遮挡图标和相邻入口。

## 5. 高频入口清单

以下入口从“常用表单”分组提升为模块侧边栏直接链接。表单名称和目标 DocType 不改变。

| 模块 | 直接显示入口 |
| --- | --- |
| Selling | 客户、报价单、销售订单、送货单、销售发票、物料价格 |
| Buying | 供应商、采购申请、询价单、供应商报价、采购订单、采购收货、采购发票 |
| Stock | 物料、物料组、仓库、单位、库存凭证、采购入库、销售出库 |
| Accounts | 收付款、销售发票、采购发票、会计科目、公司、成本中心、收付款方式、银行账户 |
| Projects | 项目、任务、工时表、活动类型 |
| Manufacturing | 物料清单、生产工单、工序作业卡、库存凭证 |
| Assets | 固定资产、资产类别、位置 |

KPI Dashboard 当前只有低频规则入口（如 `Aging Period Rule`、`KPI Target`），继续放入“其他表单”，不新增“常用表单”。

## 6. 配置和代码实施方向

### 6.1 配置调整

保留 `common_links` 作为高频入口清单，但改变其语义：它表示“模块顶部直接链接”，不再表示一个分组。这样可以复用现有清单，避免重新维护一套表单名称。

后续可将字段名改为 `pinned_links`，但应先完成兼容读取：

1. 优先读取 `pinned_links`。
2. 未配置时兼容读取旧的 `common_links`。
3. 稳定运行后再考虑清理旧字段名。

### 6.2 同步器调整

`other_forms_sidebar.py` 计划调整为：

1. 查找并删除配置模块自己创建的“常用表单” Section Break。
2. 读取高频入口目标，按 `link_type + link_to` 复用现有链接或创建缺失的有效 DocType 链接。
3. 将高频链接移动到模块侧边栏根层的顶部位置。
4. 保留“其他表单”分组创建、去重、排序和不存在 DocType 的 warning 逻辑。
5. 只删除空的“常用表单”分组；如果其中存在未声明的用户自定义链接，先保留链接并记录 warning，不直接删除用户内容。
6. 迁移完成后仅清理 bootinfo 和 Desk 缓存。

排序操作必须使用稳定的 Item name 和 `idx`，重复执行结果应与第一次相同。

### 6.3 数据库处理边界

本方案需要调整 `Workspace Sidebar Item` 的分组归属和顺序，属于导航元数据迁移，不涉及业务表数据。迁移前应保存每个目标 Workspace 的：

- Section Break 名称、标签、`idx`、`child`、`collapsible`。
- 高频链接的 Item name、`link_type`、`link_to`、标签、图标和原 `idx`。
- 用户自定义链接清单。

不建议直接手工删除数据库记录；应使用可幂等的 patch 或现有同步器完成，并保留迁移日志。

## 7. 数据流

```text
bench migrate
  -> 读取 other_forms_sidebar.json
  -> 选择实际存在的 Workspace Sidebar
  -> 读取高频入口和低频入口声明
  -> 按 link_type + link_to 复用/创建链接
  -> 删除或迁移空的“常用表单” Section Break
  -> 高频链接移动到模块侧边栏根层顶部
  -> 低频链接继续放入唯一“其他表单”分组
  -> 按 idx 稳定重排并清理 bootinfo
  -> 用户退出 Desk 后重新登录看到直接入口
```

运行时点击高频链接仍通过原 Frappe 路由打开对应 DocType 列表；权限过滤、收藏、全局搜索和关联记录入口不改变。

## 8. 风险点与控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 删除“常用表单”时误删其中的用户自定义链接 | 用户个性化入口丢失 | 仅识别并处理配置声明的 Section Break；非声明链接先保留并记录 warning |
| 高频链接出现在两个位置 | 侧边栏重复、用户困惑 | 按 `link_type + link_to` 去重，迁移后逐模块检查重复项 |
| 入口被放入报表或设置区域 | 业务表单语义混乱 | 根层插入点固定在模块入口后、报表/设置前，并排除 Section Break |
| 旧版本 patch 再次创建“常用表单” | 分组重新出现 | 先清理同名空分组，迁移脚本必须幂等，重复执行结果不变 |
| 某些模块不存在或名称不同 | migrate 中断 | 沿用现有 sidebar 选择逻辑，跳过不存在工作区并记录 warning |
| 直接链接过多导致顶部拥挤 | 首屏信息密度过高 | 仅保留当前配置中的核心入口；不把“其他表单”内容提升到根层 |
| 用户权限不同导致链接数量不同 | 测试账号之间显示不一致 | 以真实权限过滤后的结果为准，分别用管理员和业务账号验收 |
| 缓存未清导致看不到变化 | 用户误判未生效 | migrate 后清理 bootinfo/Desk cache，退出 Desk 重新登录 |
| 移动端长标签遮挡 | 可用性下降 | 390px 视口检查图标、文字、点击区域和侧边栏滚动 |

## 9. 实施前快照与回滚

### 9.1 快照

实施前导出以下信息为 JSON 或表格：

- Selling、Buying、Stock、Accounts、Projects、Manufacturing、Assets、KPI Dashboard 的 Sidebar Items。
- 所有“常用表单”和“其他表单”分组及其子链接。
- 高频入口的 `name`、`link_type`、`link_to`、label、idx、icon。
- 用户自定义 Workspace 链接、收藏和快捷入口。

### 9.2 回滚

出现以下情况时暂停推广并回滚导航元数据：

- 高频入口打不开或跳转到错误 DocType。
- 其他表单链接丢失、重复或进入错误模块。
- 用户自定义链接被删除。
- 侧边栏出现白屏、JS 错误或移动端严重重叠。

回滚只恢复 Sidebar Item 的原分组和 `idx`，不回滚业务数据。回滚后执行 `bench --site <site> clear-cache` 并重新登录。

## 10. 验收顺序

1. 备份并记录各模块侧边栏快照。
2. 在测试站执行 `bench migrate`、`bench clear-cache`。
3. 使用 System Manager 检查每个模块：不存在“常用表单”分组，高频入口在顶部可直接点击。
4. 展开“其他表单”，确认低频表单仍完整，且每个模块最多一个分组。
5. 抽查客户、供应商、物料、仓库、销售订单、采购订单、库存凭证、项目、BOM、固定资产的 URL、权限和列表加载。
6. 使用业务账号复测 Selling、Buying、Stock、Accounts、Projects、Manufacturing、Assets 的菜单过滤。
7. 检查主流程入口、Excel 入口、报表、设置、子表没有被误移动。
8. 用 390px 移动视口检查顶部链接、图标、文字和滚动。
9. 连续执行两次 migrate，确认没有新增分组、重复链接或顺序漂移。

## 11. 验收标准

- 所有核心模块均不再显示“常用表单”分组。
- 高频表单在模块侧边栏顶部可直接点击，点击次数减少一次。
- 每个模块最多一个“其他表单”，低频入口仍在其中。
- 高频表单路由、权限、标签、图标和业务数据不变。
- Excel 主流程、主交易、报表、设置和子表未被误收纳。
- 管理员和业务账号均无白屏、JS 错误、错误跳转或越权入口。
- 桌面端和 390px 移动端布局清晰，无图标遮挡和文字溢出。
- 重复 migrate 具有幂等性，用户自定义链接未被删除。
