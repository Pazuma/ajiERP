# 业务单据正向关联项目与进度节点优化方案

> 文档日期：2026-09-13  
> 当前阶段：已按方案完成首版实现。  
> 方案原则：小增量、项目可选、节点可选、优先新增分支、不修改 ERPNext 标准接口、保留已有反向关联。

## 1. 背景与现状

当前项目进度已经实现：

- Project 中维护 `Project Progress Item` 进度节点子表。
- 节点上通过 `reference_doctype + reference_name` 反向选择一张具体业务单据。
- 业务单据提交时完成节点，取消时恢复节点。
- 节点已有 `actual_completed_on`、`completed_by` 和 `last_synced_on`。
- 项目已有预期进度、实际进度、偏差和健康状态汇总。

当前主要不足是操作方向与实际业务不一致：用户通常是在创建采购单、销售单、工单等单据时，已经知道它属于哪个项目及哪个流程节点。因此需要增加“业务单据 -> 项目 -> 项目节点”的正向关联。

## 2. 优化目标

业务单据新建或编辑时支持：

1. “关联项目”不必填，未选项目时不影响原有建单、保存和提交流程。
2. 选择项目后，才能选择该项目下的进度节点。
3. “关联步骤”也不必填，允许单据只归属项目、不驱动具体节点。
4. 更换或清空项目时，立即清空已选节点，服务端再做一次一致性校验。
5. 单据成功提交后记录该单据的实际完成时间，并汇总到节点。
6. 一个节点可以关联多张单据；全部有效关联单据完成后，节点才完成。
7. 保留已有“在 Project 节点上选择单据”的反向关联能力，旧数据无需立即迁移。

## 3. 交互与业务规则

### 3.1 业务单据字段

| 显示字段 | 是否必填 | 行为 |
| --- | --- | --- |
| 关联项目 | 否 | 优先复用单据已有的标准 `project` 字段；没有该字段的单据才新增 `custom_progress_project` |
| 关联步骤 | 否 | 仅显示已选项目的节点，保存项目内唯一的 `milestone_code` |
| 步骤名称 | 否 | 只读，由后端根据项目和节点编码回填，用于列表和导出展示 |
| 实际完成时间 | 否 | 只读；单据提交成功后记录，取消提交后清空 |

“关联步骤”不直接 Link 到 `Project Progress Item`。该 DocType 是 Project 子表，没有独立表单和权限语义，直接当 Link 目标会导致搜索、权限和跳转体验不稳定。首期使用 Autocomplete/Data 保存 `milestone_code`，服务端以 `parent + milestone_code` 唯一定位节点。

### 3.2 字段复用范围

当前支持的 10 类单据中，Sales Order、Purchase Order、BOM、Work Order、Delivery Note、Purchase Receipt、Sales Invoice、Purchase Invoice、Stock Entry 已有标准 `project` 字段，直接复用，不新增同义项目字段。

Material Request 当前没有头部 `project` 字段，仅对它新增 `custom_progress_project`。节点编码、名称和完成时间作为 `custom_*` 字段增量加到上述支持单据。

### 3.3 选择规则

- 项目为空：节点字段禁用或隐藏，节点编码、名称全部置空。
- 项目有值：调用新增查询接口，只返回当前项目节点。
- 切换项目：无条件清空原节点，防止跨项目错误关联。
- 保存时：后端校验项目存在、用户可读、节点属于该项目，并回填节点名称。
- 已提交单据：不允许直接改项目或节点；按 ERPNext 原有取消/修订流程处理。

### 3.4 完成时间与节点汇总口径

新增关联记录保存每张单据的状态和完成时间，不用一个节点时间覆盖多张单据的事实。

```text
单据为草稿：关联记录 = 未完成，单据实际完成时间 = 空
单据提交成功：关联记录 = 已完成，完成时间 = 当次成功提交时间
单据取消提交：关联记录 = 已取消，完成时间 = 空

节点有一张或多张有效关联单据：
  全部 docstatus = 1 -> 节点已完成
  任意一张未提交 -> 节点未完成
  节点 actual_completed_on = 最后一张有效单据的完成时间
```

关联数为零时，不自动完成节点。`Manual` 节点仍按现有手工确认逻辑执行，不允许业务单据选择手工节点，避免两种完成口径冲突。

## 4. 数据模型

### 4.1 新增 Project Progress Reference

新增独立 DocType `Project Progress Reference`，作为项目节点与业务单据的中间关联表：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `project` | Link / Project | 所属项目 |
| `progress_item` | Data | `Project Progress Item.name`，只用于稳定定位子表行 |
| `milestone_code` | Data | 项目内节点编码，便于查询和迁移 |
| `step_name` | Data | 节点名称快照 |
| `reference_doctype` | Link / DocType | 业务单据类型 |
| `reference_name` | Dynamic Link | 业务单据编号 |
| `status` | Select | Draft / Completed / Cancelled |
| `actual_completed_on` | Datetime | 该单据实际完成时间 |
| `completed_by` | Link / User | 完成操作人 |

唯一性规则：`reference_doctype + reference_name` 首期只能对应一个项目节点，与业务单据页面上的单一“关联步骤”字段保持一致。一个节点可以对应多张单据。

该 DocType 默认不放入桌面工作区，普通用户不手工新建；由单据保存、提交、取消和删除事件幂等维护。

### 4.2 保留 Project Progress Item 已有字段

不删除、不改名下列已有字段：

```text
reference_doctype
reference_name
status
actual_completed_on
completed_by
last_synced_on
```

新逻辑对节点计算时：

1. 如果存在 `Project Progress Reference` 记录，以新关联表汇总为准。
2. 如果不存在新关联记录，继续读取节点上的旧 `reference_doctype + reference_name`。
3. 旧数据可后续用独立补丁迁移，首期不强制迁移，不阻塞上线。

## 5. 新增接口与保留接口

### 5.1 新增接口

```python
get_project_progress_steps(project, txt=None)
validate_progress_selection(doc, method=None)
sync_progress_selection(doc, method=None)
remove_progress_selection(doc, method=None)
recalculate_progress_item(project, progress_item)
```

- `get_project_progress_steps` 只返回用户有权查看的项目节点，并排除 `Manual` 节点。
- `validate_progress_selection` 只校验和回填，不写关联表，避免单据验证失败时留下脏数据。
- `sync_progress_selection` 在业务单据保存成功后幂等新增或更新关联。
- `remove_progress_selection` 仅在草稿单据删除或关联被合法清空时删除对应关联。

### 5.2 保留老接口

下列方法名、参数和现有调用方不变：

```python
sync_progress_from_reference(doc, method=None)
get_reference_progress_links(reference_doctype, reference_name)
recalculate_project_progress(project)
calculate_project_progress(doc, as_of=None)
```

仅在方法内新增兼容分支：先查新关联表，再回退查询节点旧关联字段。现有 Project 页面、业务单据仪表盘提示和 `doc_events` 不需要改调用方式。

## 6. 调用链路

### 6.1 新建业务单据并选择节点

```text
打开业务单据
 -> project / custom_progress_project 选择项目（可空）
 -> project_progress_reference.js 清空原节点
 -> get_project_progress_steps(project)
 -> 用户选择 custom_progress_milestone_code（可空）
 -> validate 调用 validate_progress_selection
 -> 校验节点归属并回填 custom_progress_step_name
 -> 单据成功保存
 -> on_update 调用 sync_progress_selection
 -> 幂等写入 Project Progress Reference（Draft）
 -> 重算该节点及项目汇总
```

### 6.2 单据提交

```text
业务单据成功 Submit
 -> 现有 doc_events.on_submit
 -> sync_progress_from_reference(doc, method=None)       # 老接口不变
 -> 找到 Project Progress Reference
 -> status = Completed
 -> actual_completed_on = now_datetime()
 -> completed_by = frappe.session.user
 -> 回写单据 custom_progress_actual_completed_on
 -> recalculate_progress_item(project, progress_item)
 -> 全部关联单据完成后更新节点完成时间
 -> _persist_project_totals(project)
```

完成时间严格在 Submit 成功后记录，不在 `before_submit`、`validate` 或草稿保存时提前记录。

### 6.3 单据取消提交

```text
业务单据 Cancel
 -> 现有 doc_events.on_cancel
 -> sync_progress_from_reference(doc, method=None)
 -> 关联记录 status = Cancelled，清空完成人/完成时间
 -> 清空单据 custom_progress_actual_completed_on
 -> 重算节点：待开始/进行中/延期
 -> 重算项目实际进度和健康状态
```

### 6.4 项目页面查看关联单据

```text
打开 Project 流程进度
 -> 节点仍显示已有字段
 -> 节点有多张新关联单据时显示“关联单据 N 张”
 -> 点击打开关联列表，按 project + milestone_code 过滤
 -> 可跳转到具体业务单据
```

Project 节点子表上的旧“关联单据”字段继续保留。对已存在多单据关联的节点，不尝试将多个单号回写到这一个 Dynamic Link 字段，避免覆盖旧数据。

def recalculate_progress_item(project, progress_item):
	links = get_active_references(project, progress_item)
	if links:
		completed = all(link.status == "Completed" for link in links)
		completed_on = max(
			(link.actual_completed_on for link in links), default=None

## 8. 受影响模块

### 8.1 直接影响

- Project 流程进度、Project Progress Item、Project Progress Reference。
- Sales Order、Purchase Order、Material Request、BOM、Work Order、Delivery Note、Purchase Receipt、Sales Invoice、Purchase Invoice、Stock Entry 的表单页和生命周期事件。
- 项目预期进度、实际进度、进度偏差、节点完成时间。

### 8.2 间接影响与重点回归

- `hooks.py` 中各单据现有 `validate/on_update/on_submit/on_cancel/on_trash` 处理器顺序。
- 采购收货、库存移动、工单完工、发票过账等标准业务结果不得被关联逻辑改变。
- Project 成本核算、项目开发申请、标准 Task `percent_complete` 不得改变。
- 单据修订、复制、改名、删除草稿、取消后重新提交需要专项回归。
- 无项目的历史单据、无节点的历史项目、旧反向关联数据必须保持可打开、保存、提交和取消。
- 用户只能选择自己有权访问的 Project，不得通过手工调 API 越权关联。

## 10. 预期界面效果

业务单据的项目进度区域：

```text
项目进度

关联项目        PROJ-0007                 （可选）
关联步骤        PURCHASE / 采购完成     （可选，只显示 PROJ-0007 的节点）
实际完成时间    2026-09-13 14:26:08       （提交后只读显示）

[查看关联项目进度]
```

交互结果：

- 不选项目：表单与优化前一致，无额外必填和拦截。
- 只选项目：单据可正常保存和提交，不改变任何节点进度。
- 选项目和步骤：草稿建立关联，提交后记录单据完成时间并参与节点汇总。
- 多张单据关联同一节点：项目上可查看全部单据，最后一张提交后节点完成。
- 取消其中一张：节点恢复未完成，项目实际进度同步下降，不影响其他单据。

## 11. 验收标准

1. 上述 10 类单据的关联项目和关联步骤均为非必填。
2. 未选项目时无法选节点；选项目后只能看到当前项目的非手工节点。
3. 更换项目后旧节点自动清空，伪造请求也会被服务端拒绝。
4. 单据草稿保存不完成节点；成功提交才写实际完成时间。
5. 一个节点关联多张单据时，所有有效单据提交后节点才完成，节点完成时间取最后提交时间。
6. 任一关联单据取消后，该节点和项目汇总正确回退；重新提交后可再次完成。
7. 旧 Project Progress Item 上已有的 `reference_doctype/reference_name` 关联仍能提交、取消和重算。
8. `sync_progress_from_reference`、`get_reference_progress_links` 等现有接口签名不变，Project 现有按钮不需要改调用方式。
9. 无项目单据、无节点项目和历史单据的原有保存/提交/取消行为不变。
10. ERPNext 标准 Project、Task、采购、销售、生产、库存和财务接口无修改。

## 12. 风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 直接 Link 子表行导致搜索/权限不稳定 | 表单保存 `milestone_code`，关联表内同时保存子表行 `name` |
| 多张单据覆盖节点旧 Dynamic Link | 新增独立关联表，不将多个单号回写到旧单值字段 |
| 单据提交中途失败却提前记完成 | 只在 `on_submit` 成功链路记录时间，与当前事务一起回滚 |
| hooks 覆盖现有业务处理 | 使用列表追加处理器，不替换旧 handler |
| 循环更新触发自己 | 汇总字段用受控 `db_set/update_modified=False`，不再调用业务单据 `save/submit` |
| 项目或节点越权 | 查询接口、validate 和写关联表三层都校验 Project read 权限 |
| 节点删除后留孤儿关联 | Project validate 拦截删除已有效关联的节点，需先解除关联 |

## 13. 本次结论

推荐保留当前“项目节点反向关联一张单据”的实现，在其上新增“业务单据正向选择项目和节点”分支。用独立 `Project Progress Reference` 承载多单据关系和单据级完成时间，节点仅保留汇总状态和最终完成时间。

该方案不要求项目或节点必填，不改 ERPNext 标准 DocType 源码和标准接口，不一次性迁移旧数据，可按四个小阶段独立实施和回退。
