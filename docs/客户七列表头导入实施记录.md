# 客户七列表头导入

## 实现效果

客户列表现有导入弹窗的“客户清单”推荐模板提供七列：客户编号、客户名称、联系人、联系电话、地址、收货地址、负责业务。

上传包含客户编号、客户名称、收货地址的文件时进入新增客户专用分支；该分支校验全部七个表头。其他格式保留原有导入路径，不修改系统全局客户命名规则。

- 客户编号和客户名称必填，编号写入 Customer.name，同时保留 custom_customer_code。
- 负责业务按 Sales Person 编号或姓名匹配唯一、启用、非分组的业务人员，写入 custom_responsible_sales_person。不存在或重名时阻止导入，不自动创建业务人员。
- 自动创建并关联 Contact、账单 Address、收货 Address；设置客户默认联系人、主地址，收货地址标记为配送地址。
- 保留原始联系人、电话、账单地址、业务姓名文本。电话与编号按文本处理；Excel 中应使用文本格式，已经被 Excel 丢弃的前导零无法恢复。
- 完整地址原样保存到 address_line1。源文件没有城市、国家字段，城市显式设为“待补充”，国家使用系统默认国家或 China；需后续补全城市。
- 新增模式阻止已存在编号，更新模式按系统编号定位且空白值保留原值。旧客户外部编号与系统编号不一致时阻止导入并提示核对，不自动重命名历史客户。
- 预览不创建业务数据；执行时逐行事务，任一关联失败则该行整体回滚，其他行可成功，并记录成功/失败日志。
- 相同客户、地址文本与地址类型复用原地址；同名联系人复用，多个同名联系人阻止该行并提示核对。

## 文件与调用链

- `client_akivision/utils/customer_excel_import.py`：文件识别、预览校验、业务人员匹配、客户和关联资料写入、行级导入日志。
- `client_akivision/client_akivision/api/data_import.py`：新增模板下载接口，原预览和执行接口新增客户分支，接口参数保持不变。
- `client_akivision/public/js/inline_data_import.js`：推荐模板下载、七列预览和阻断提示。
- `client_akivision/utils/test_customer_excel_import.py`：真实 XLSX、模板、预览到执行、重复编号、业务人员校验及关联资料复用测试。

调用链：客户列表导入 → 下载七列模板 → 上传 → preview_inline_import → customer_excel_import.preview → 预检通过 → start_inline_import → 后台 run_inline_import → customer_excel_import.run → Customer / Contact / Address / Dynamic Link → 导入日志和状态。

影响模块：客户主档、联系人、地址、客户业务人员；后续销售订单继续通过现有客户业务人员读取逻辑获取人员，不改老接口。

## 部署和验证

同步以上代码到目标站点的同版本应用目录，核对服务器独立修改后合并。无需数据库迁移或数据库恢复。重启 Python Web/后台 worker，清理实际使用站点的缓存，浏览器强制刷新以加载新 JS。现有客户相关自定义字段须已安装。

本地验证：客户专项集成测试及 JavaScript 语法检查。服务器仍需同步代码后，用真实客户工作簿验收；没有直接操作远程服务器。
