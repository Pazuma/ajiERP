# 采购跟踪表与实际采购订单关联设计沉淀

## 1. 文档目的

本文用于沉淀截图所示采购跟踪表与 ERPNext 实际采购订单的结合方式。目标不是把 Excel 每一行原样复制成采购订单，而是让系统同时具备：

- 采购订单的真实业务数据；
- 采购明细、交期计划和分批收货跟踪；
- 发票、付款和对账结果；
- 与 Excel 类似的采购跟踪视图和导出结果。

本设计不改变采购订单系统编号生成规则。系统订单编号仍使用 `Purchase Order.name`，Excel 中原有“单号”如与系统编号不同，应保存为独立的外部订单号。

## 2. 总体原则

1. `Purchase Order` 是采购承诺的主数据来源。
2. `Purchase Order Item` 是物料、数量、价格、交期和仓库的明细来源。
3. 采购收货单是实际到货数量和到货日期的唯一事实来源。
4. 采购发票、付款单和付款分配是对账金额和付款状态的来源。
5. Excel 只补充外部单号、交货计划、历史跟踪信息和导出格式，不直接伪造库存或财务凭证。
6. 物料、供应商必须通过系统编码关联，不能依赖名称模糊匹配。

## 3. Excel 字段与系统字段映射

### 3.1 订单和物料字段

| 图片字段 | 系统落点 | 数据性质 | 说明 |
| --- | --- | --- | --- |
| 分类 | `Item.item_group` | 主数据 | 使用物料组；如“分类”与物料组含义不同，再增加独立分类字段。 |

| Excel/供应商单号 | `Purchase Order.order_confirmation_no` 或 `custom_external_order_no` | 外部标识 | 与系统订单编号分开保存。 |
| 日期 | `Purchase Order.transaction_date` | 订单事实 | 采购订单日期。 |
| 供应商编号 | `Purchase Order.supplier` | 主数据链接 | 使用 Supplier 文档名。 |
| 供应商名称 | `Purchase Order.supplier_name` | 取数结果 | 从供应商主数据带出。 |
| 物料编码 | `Purchase Order Item.item_code` | 主数据链接 | 作为物料关联主键。 |
| 物料名称 | `Purchase Order Item.item_name` | 取数结果 | 从物料主数据或采购明细带出。 |
| 单位 | `Purchase Order Item.uom` / `stock_uom` | 订单明细 | 保留采购单位与库存单位的换算关系。 |
| 数量 | `Purchase Order Item.qty` | 订单事实 | 当前订单的订购数量。 |
| 含税价 | 采购价格和税配置计算 | 计算结果 | 需根据价格是否含税判断，不能固定乘以税率。 |
| 含税金额 | 采购订单税额分摊结果 | 计算结果 | 明细含税金额合计应与订单含税总额一致。 |
| 税率 | `Purchase Taxes and Charges.rate` | 税配置 | 多税行时需明确采用合计税率或逐税行计算。 |
| 含税总额 | `Purchase Order.grand_total` / `rounded_total` | 订单事实 | 订单级金额，明细展示时按明细金额分摊。 |
| 最新交期 | `Purchase Order Item.schedule_date` | 订单明细计划 | 这是当前物料行的交期，不是整个采购订单的统一交期；订单含多个物料时每行可以不同。多批交货时以该物料的交货计划表为准。 |
| 机种 | `Item.custom_internal_model` | 物料主数据 | 当前项目已存在该物料自定义字段。 |

### 3.2 交货和对账字段

| 图片字段 | 系统落点 | 数据性质 | 说明 |
| --- | --- | --- | --- |
| 订单总数 | 按统计范围聚合 `Purchase Order Item.qty` | 计算结果 | 需在页面明确是同一物料的订单总量，不能与订单数量混用。 |
| 订单数量 | `Purchase Order Item.qty` | 订单事实 | 当前采购订单行数量。 |
| 订单1~订单6 | 交货计划明细的计划数量 | 计划数据 | 不建议建立固定的 1~6 字段，使用序号化子表。 |
| 交货1日期~交货6日期 | 交货计划明细的计划日期 | 计划数据 | 允许超过 6 批，报表按前 6 批横向展示，其余可展开查看。 |
| 已交 | 已提交 `Purchase Receipt Item.qty` 聚合 | 实际事实 | 不允许通过 Excel 手工回填。 |
| 未交 | 订单数量 - 已交数量 | 计算结果 | 小于 0 时需按异常处理，不能静默显示负数。 |
| 交货次数 | 关联采购收货单数量 | 计算结果 | 取消单据不计入实际交货次数。 |
| 实际交货日期 | `Purchase Receipt.posting_date` | 实际事实 | 分批收货时一行对应一次收货明细。 |
| 对账金额 | 采购发票、付款单和付款分配 | 财务事实 | 不直接取 Excel 手工金额。 |
| 是否已对账 | 应付金额与已核销/已付款金额比较 | 计算结果 | 需明确容差和预付款口径。 |

### 3.3 一个订单多个物料时的交期原则

一个 `Purchase Order` 可以包含多条 `Purchase Order Item`。每一条物料明细独立保存：

- 物料编码和名称；
- 订购数量；
- 当前物料行的 `schedule_date`；
- 该物料行的交货计划；
- 该物料行已收货、未收货和实际收货日期。

因此不能在采购订单头部只维护一个“订单交期”来代表所有物料。订单详情应以物料明细为单位展示交期，例如：

| 物料 | 订单数量 | 物料交期 | 已交 | 未交 |
| --- | ---: | --- | ---: | ---: |
| 物料 A | 100 | 2026-06-20 | 60 | 40 |
| 物料 B | 50 | 2026-07-10 | 0 | 50 |

如果列表或汇总页面必须显示订单级日期，只能明确标注为“最早交期”或“最晚交期”，由该订单全部物料行的交期计算得出，不能称为每个物料的实际交期。

## 4. 推荐数据结构

```text
Purchase Order
├── Purchase Order Item
│   ├── Item / Item Group / 机种
│   ├── 交货计划（新增子表，计划数量、计划日期、序号）
│   └── Purchase Receipt Item（实际收货）
├── Purchase Receipt
├── Purchase Invoice
└── Payment Entry / Payment Entry Reference
```

### 4.1 交货计划子表

建议增加“采购订单交货计划”子表，至少包含：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| 采购订单明细 | Link | 指向具体 `Purchase Order Item`。 |
| 批次序号 | Int | 1、2、3……，不限制为 6。 |
| 计划数量 | Float | 本批计划数量。 |
| 计划日期 | Date | 本批承诺日期。 |
| 备注 | Small Text | 供应商承诺、变更原因等。 |

实际收货不写回计划数量，而是通过 Purchase Receipt 关联后计算计划完成情况。交货计划必须关联到具体的 `Purchase Order Item`，不能只关联订单头，否则同一订单多个物料会无法区分各自交期。

## 5. 页面呈现方案

### 5.1 标准采购订单列表

采购订单列表只承担“找订单、看状态、进入详情”三个高频动作，控制为少量重要字段：

> 订单编号 - 供应商名称 - 状态 - 订单日期 - 含税总额

其中订单编号取 `Purchase Order.name`，点击进入采购订单详情。列表不展示物料明细、交货批次、收货数量和对账金额，避免横向列过多、首屏信息拥挤以及移动端难以操作。

列表保留标准的筛选、排序、分页、批量关闭/重开、生成采购收货/发票/预付款等操作；物料、交期、收货和对账信息下沉到订单详情或采购清单报表。

### 5.2 采购订单表单

点击订单编号进入详情后，展示完整业务信息，建议按以下区域组织：

- 基本信息：系统订单编号、外部订单号、日期、供应商、公司；
- 物料明细：分类、物料编码、物料名称、单位、数量、价格、税率、金额、该物料行交期、机种；
- 交货计划：按物料明细和批次维护计划数量、计划日期；
- 收货进度：只读显示已交、未交、交货次数、实际收货日期；
- 财务对账：只读显示含税总额、已开票金额、已付款金额、未付金额、对账状态。

列表中的字段与详情页的关系如下：

| 列表字段 | 详情页位置 | 交互 |
| --- | --- | --- |
| 订单编号 | 订单标题/基本信息 | 列表可点击，详情中只读。 |
| 供应商名称 | 基本信息 | 可进入供应商链接。 |
| 状态 | 基本信息/状态区 | 显示标准状态和权限动作。 |
| 订单日期 | 基本信息 | 只读或按单据状态控制编辑。 |
| 含税总额 | 金额汇总区 | 由订单税额计算，不在列表直接编辑。 |

其余截图字段全部在详情页的物料、交货计划、收货进度和财务对账区域查看。

### 5.3 采购清单报表

当前项目已有自定义 `Purchase List` 报表，代码位置为：

`client_akivision/client_akivision/client_akivision/report/purchase_list/`

该报表已经按采购订单、采购订单明细、采购收货明细和付款数据组织树形数据。后续应在该报表基础上增加 Excel 风格字段和筛选，不应另建一套脱离采购订单的数据表。

推荐报表列顺序：

> 系统订单编号 - 外部单号 - 分类 - 日期 - 供应商 - 物料编码 - 物料名称 - 单位 - 订单数量 - 含税价 - 含税金额 - 税率 - 含税总额 - 物料行交期 - 机种 - 计划交货 - 已交 - 未交 - 实际交货日期 - 对账状态

“订单1~订单6、交货日期1~交货日期6”可以作为导出视图的横向展开列；页面内部仍以交货计划子表保存，避免固定字段限制批次数量。

## 6. 数据流

1. 供应商、物料和物料分类先在主数据中维护。
2. 采购申请、询价或采购比价生成采购订单草稿。
3. 采购订单保存/提交后生成系统订单编号，并按物料明细保存外部单号、物料、数量、价格和各自交期。
4. 交货计划按物料明细记录供应商承诺的分批数量和日期。
5. 采购到货时创建采购收货单；系统根据 `purchase_order_item` 关联实际收货。
6. 采购发票和付款单通过采购订单、收货单或发票关联，形成对账金额。
7. 采购清单报表按订单明细聚合计划、收货和财务数据，提供 Excel 风格查询和导出。

## 7. 关联模块清单

| 模块 | 关联内容 |
| --- | --- |
| 供应商 | 供应商编号、名称、停用状态、付款条件。 |
| 物料/物料组 | 物料编码、名称、分类、单位、机种。 |
| 采购申请 | 需求数量、需求日期和来源追踪。 |
| 询价/供应商报价 | 供应商报价、比价结果和生成订单来源。 |
| 采购订单 | 订单主数据和采购承诺。 |
| 采购收货 | 实际到货、仓库、批次和库存影响。 |
| 采购发票 | 应付金额、税额和发票状态。 |
| 付款单 | 预付款、核销金额和付款状态。 |
| 库存 | 提交收货后产生库存流水，不能由 Excel 直接写入。 |
| 采购清单报表 | 汇总和下钻展示，不作为新的事实数据源。 |
| 采购看板/运营指标 | 使用订单、收货、发票和付款事实计算采购进度、延迟和金额指标。 |

## 8. Excel 导入与导出边界

### 可导入或维护

- 外部订单号；
- 采购跟踪备注；
- 能通过系统编码准确匹配的供应商和物料。

交货计划当前在采购订单详情的“交货计划”子表中维护。由于计划必须引用已保存的 `Purchase Order Item.name`，本次不把计划列加入新建采购订单的默认 Excel 导入字段，避免用物料名称或 Excel 行号造成错关联。后续如要开放导入，必须先增加“订单编号 + 物料编码/明细行号”的解析器和冲突校验。

### 不允许直接覆盖

- 系统订单编号；
- 采购订单数量和价格（除非走采购订单修订流程）；
- 实际已交数量；
- 实际收货日期；
- 库存数量；
- 发票金额、付款金额和对账结果。

导出时可以生成与截图相同的横向布局，但导出文件应标明“计划数据”和“实际数据”，避免用户误把计划交货量当成实际入库量。

## 9. 风险与控制

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| Excel 单号覆盖系统编号 | 破坏单据链接和历史关联 | 增加外部订单号，系统编号只读。 |
| 按物料名称匹配 | 同名物料错配 | 强制使用物料编码。 |
| 固定“交货1~6”字段 | 超过 6 批无法记录 | 使用序号化交货计划子表，报表再横向展开。 |
| 将计划当实际收货 | 虚增库存和交付率 | 实际数据只来自提交采购收货单。 |
| 手工维护对账金额 | 财务数据失真 | 从采购发票、付款单和分配记录计算。 |
| 订单总数/订单数量含义不清 | 汇总结果不一致 | 在字段说明和报表筛选中固定统计口径。 |
| 多税行或含税价处理错误 | 金额与订单总额不一致 | 以 ERPNext 税配置和 `grand_total` 为准，增加金额核对。 |
| 报表与订单表单数据不一致 | 用户不信任系统 | 报表统一通过订单明细和收货关联查询，不维护第二份事实数据。 |

## 10. 实施顺序建议

1. 确认 Excel 中“单号、订单总数、订单数量、交货”字段的业务定义。
2. 确认外部单号使用标准 `order_confirmation_no` 还是新增自定义字段。
3. 增加采购订单交货计划子表及权限。
4. 扩展采购清单报表，先完成订单、物料、收货和对账字段。
5. 增加交货计划录入和横向导出；完成订单明细键解析器后再开放计划导入。
6. 最后接入采购看板、延迟分析和供应商绩效等关联场景。

## 11. 验收与复测场景

- 新建采购订单后系统自动生成订单编号，外部单号可独立保存；
- 一个订单包含多个物料时，报表行与订单明细一一对应；
- 同一订单的不同物料使用不同交期时，详情和报表分别显示各物料行交期，不相互覆盖；
- 同一物料分多批交货时，计划数量、计划日期和实际收货按该物料明细分别核对；
- 一个物料分多次收货时，已交、未交、交货次数和实际日期正确；
- 计划交货日期与实际收货日期不同，页面能同时展示并标识延期；
- 订单全部收货、部分收货、未收货三种状态；
- 采购发票部分开票、全部开票、付款后对账状态正确；
- 取消的采购收货、取消的发票不计入实际汇总；
- 供应商、物料、日期、订单编号和外部单号筛选正常；
- 采购清单导出列与页面数据一致；
- 采购订单列表首列订单编号仍可点击进入详情；
- 无权限用户不能通过报表链接绕过采购订单权限；
- Excel 导入不会创建虚假的收货、库存或付款数据。

## 12. 当前结论

图片中的表格应在系统中体现为“采购订单主数据 + 采购订单明细 + 交货计划 + 实际收货 + 财务对账 + 采购清单报表”的组合，而不是单独维护一张 Excel 数据表。

其中，系统订单编号负责唯一定位采购订单；外部单号负责保留 Excel/供应商业务标识；计划字段负责跟踪承诺；收货和财务字段负责反映真实业务结果。

### 13.2 数据流

```text
采购订单明细
  -> custom_delivery_plans（承诺计划，按明细和批次）

  -> Purchase List（计划与实际并列展示）
```

计划数量用于跟踪供应商承诺，`planned_date` 用于计划日期；`received_qty`、实际收货日期和库存影响仍来自 `Purchase Receipt`。采购发票、付款和对账逻辑保持原有来源。

### 13.3 依赖清单

- ERPNext 标准 `Purchase Order`、`Purchase Order Item`、`Purchase Receipt Item`、`Item` 和 `Supplier`。
- Frappe 自定义字段、子表 DocType、`after_migrate` 钩子和采购订单文档事件。
- 采购清单 Script Report 的现有权限、筛选和树形数据结构。
- Excel 导入器对 Purchase Order 表格字段的动态读取能力。

### 13.4 风险点与控制

| 风险点 | 控制/解决方案 |
| --- | --- |
| 计划行选到其他订单的明细 | 保存时校验明细行 `parent` 属于当前采购订单；前端 Link 查询也限制当前订单。 |
| 计划数量超过订单数量 | 按采购订单明细汇总计划数量，超过时阻止保存。 |
| 计划被误认为实际入库 | 报表计划字段与已交字段分开，实际只查询 `docstatus = 1` 的采购收货。 |
| 固定交货 1~6 批次限制 | 使用 `sequence` 子表，批次数量不设上限；报表以摘要显示。 |
| 迁移时表字段尚未创建 | schema 同时挂在标准字段同步和 `after_migrate`，并使用幂等创建。 |

### 13.5 需要复测的场景

- 订单含两个物料、两个物料分别设置不同交期，详情和采购清单不串行。
- 同一物料设置 2 个以上计划批次，计划摘要按序号、数量、日期显示。
- 计划数量等于订单数量、低于订单数量和超过订单数量的保存结果。
- 计划关联其他采购订单明细、缺失日期、零数量时均被阻止。
- 部分收货、全部收货、未收货时，计划数量不改变已交/未交计算。
- 采购订单列表仍以订单编号为首列，点击可进入详情；移动端无横向溢出。
- Excel 导入字段可见，且不会直接创建收货、库存或付款事实。
- 采购订单 Excel 导入不默认创建交货计划；计划导入需在明细键解析器完成后单独验收。
