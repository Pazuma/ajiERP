# aki_erp 邮箱添加与收发使用手册

适用对象：管理员配置邮箱，业务人员使用已授权邮箱收发业务邮件。本章依据当前工作区的 Email Account、User Email、邮件收件箱及单据邮件功能编写；未连接客户邮箱进行真实收发验收。实际可用性须按第 7 节测试确认。

## 1. 先分清三种邮箱信息

| 填写位置 | 用途 | 是否代表可以收发 |
|---|---|---|
| 客户、供应商或联系人上的邮箱 | 记录对方地址，供业务邮件选择或填写收件人 | 否，仍需配置发送账户 |
| 用户登录邮箱 | 标识系统用户、接收适用的通知 | 否，不自动成为收发邮箱 |
| 电子邮件账户（Email Account） | 连接已经存在的邮箱服务，配置收信与发信 | 配置、授权及测试通过后才可使用 |

“添加邮箱”不是注册新的企业邮箱。先由公司向邮箱服务商开通真实账号，再由管理员连接到系统。给客户／供应商补地址时，打开对应联系人，按页面维护邮箱并保存；不会因此建立发送账户。

## 2. 使用前必须具备的条件

| 条件 | 谁确认 | 如何确认 |
|---|---|---|
| 公司授权使用的真实邮箱 | 邮箱负责人 | 可登录服务商网页邮箱，邮箱地址和使用人明确 |
| 开通发信 SMTP、收信 IMAP 或 POP | 邮箱管理员／服务商 | 取得服务器地址、端口和加密要求；仅发信可不启用收信 |
| 可用的认证方式 | 邮箱管理员 | 取得服务商要求的授权码／应用密码，或完成适用的 OAuth 授权；不默认使用网页登录密码 |
| 系统设置权限 | 系统管理员 | 标准 Email Account 创建和修改由 System Manager 管理，实际仍受站点权限影响 |
| 使用人的邮箱分配与业务权限 | 系统管理员 | 用户关联邮箱，并有相应收件箱及单据邮件操作权限 |
| 网络及后台任务正常 | 系统维护人员 | 服务器可连接邮件服务；邮件发送队列、收信定时任务及后台工作进程正常 |

邮箱服务商的安全策略、发信额度、附件限制或网络限制会影响收发。系统不能绕过这些限制；不要向客户承诺“配好地址立即自动收发”。

## 3. 管理员添加发送邮箱

1. 搜索“电子邮件账户／Email Account”，进入列表并“新建”。找不到入口或没有新建按钮，先检查权限。
2. 填写“邮箱地址（Email Address）”和易识别的“邮箱账户名称（Email Account Name）”，例如销售公共邮箱。名称用于识别，不会创建服务商账号。
3. 按实际服务选择“服务（Service）”或已有“邮箱域（Email Domain）”配置。服务商不在预置选项中时，按页面允许的手工服务器配置办理，不随意选相似名称。
4. 勾选“启用发送（Enable Outgoing）”，在发送设置填写 SMTP 服务器、端口，按服务商要求选择 TLS 或 SSL。端口及加密方式必须配套，不把其他公司的配置直接照抄。
5. 按“认证方式（Authentication Method）”填写所需凭据。Basic 方式填写服务商允许的密码或授权码；登录账号与邮箱地址不同时，按页面的不同登录 ID 选项填写。OAuth 方式需先由管理员完成相应连接应用设置，再按页面授权。
6. 普通认证邮箱不要勾选“不使用 SMTP 认证”。仅公司明确采用免认证中继且维护人员确认时，才按实际配置。
7. 是否设为“默认发送（Default Outgoing）”由管理员决定，它会影响系统选择发送账户。公共邮箱还需确认发件人地址／名称规则；签名按公司要求设置。
8. 点击“保存”，阅读连接或认证提示。报错先修正，不把保存成功当作已经向客户送达邮件。

**保密要求：** 授权码、密码和 OAuth 凭据只在授权配置处填写，不写入手册、聊天记录、客户邮件或截图。

## 4. 管理员启用收信并分配给用户

1. 打开已建立的 Email Account，勾选“启用接收（Enable Incoming）”。
2. 在收信设置填写服务器和端口，按服务商选择 IMAP 或 POP 及 SSL／STARTTLS。系统页面以“使用 IMAP（Use IMAP）”等字段控制协议；以服务商文档为准，不猜参数。
3. 核对同步选项、首次同步数量；使用 IMAP 时核对需同步的文件夹。初次接入前确认是否要同步历史邮件，避免导入不必要的历史信息。
4. “默认接收”“自动创建联系人”“自动关联”“自动回复”等属于按需选项，不是收发必须全部勾选。特别是“追加到（Append To）”可能使来信创建相应业务记录，未经确认不要设置。
5. 保存并处理连接提示。需要收信定时任务才能持续同步，不承诺即时推送。
6. 进入“用户（User）”，打开实际使用人，在“用户邮箱（User Emails）／Email Inbox”区域添加该 Email Account，保存。只在用户登录邮箱字段填地址不能替代这一步。
7. 按公司授权分配适用收件箱角色和业务单据权限，提醒用户重新登录或刷新。公共邮箱仅分配给获准查看内容的人员。

## 5. 业务人员发送采购订单等单据

1. 先保存并核对业务单据。对外正式采购订单须已完成公司规定的提交／审批，不能因能发邮件就跳过审核。
2. 在单据菜单中找“电子邮件／Email”。只有具备邮件权限且单据状态支持时才显示；没有入口时联系管理员。
3. 打开邮件窗口，核对实际发件人是否为获准使用的公司邮箱。不能确认时先取消，交管理员检查账户分配和默认设置。
4. 填写或核对供应商收件人、抄送、主题和正文。不要假设供应商档案有地址就一定自动带入正确收件人。
5. 需要附单据时，在窗口中按实际选项选择打印格式及附件，预览产品、规格、数量、税价、交期和条款；不把内部成本、其他客户资料或错误版本发出去。
6. 点击发送后，查看单据中的通信记录；有权限时查看邮件队列（Email Queue）状态。进入队列或出现通信记录不等于对方已经收到。
7. 首次使用或重要订单，请对方确认收件和订单内容。被退信时核对地址与退信原因，修正后再发，避免连续重复发送。

**业务边界：** 发送采购邮件不会自动得到供应商确认，不会替代订单审批，也不会创建收料、入库或付款记录。系统邮件状态不能保证对方已读或接受条款。

## 6. 查看来信与回复

1. 进入邮件收件箱（Inbox），选择已分配的邮箱。找不到菜单时请管理员确认入口，不把通知列表当作邮箱收件箱。
2. 打开来信，核对发件人、主题、正文和附件。查看不到新信时先确认网页邮箱已收到，再排查同步；不要立即重复建立账户。
3. 从邮件中的回复入口填写内容，核对发件账户、收件人及抄送，检查附件后发送。使用“全部回复”前再次确认接收范围。
4. 邮件是否关联业务单据取决于线程、引用及关联配置；没有关联时按当前页面允许方式核对或由业务人员登记，不假设邮件会自动更新采购进度。
5. 对方邮件承诺交期、修改价格或发货后，采购仍应按权限维护对应业务记录并通知有关岗位。

## 7. 首次启用验收

仅向公司授权的测试收件人发送测试邮件，不直接用真实客户批量试发。

| 测试 | 操作 | 合格标准 |
|---|---|---|
| 发送 | 从获准单据向测试邮箱发送一封带适用附件的邮件 | 对方实际收到，发件人、正文及附件正确；无退信 |
| 接收 | 从测试邮箱向系统配置邮箱发送一封测试来信 | 服务商网页邮箱和系统授权收件箱均能看到 |
| 回复 | 在系统回复测试来信 | 对方实际收到，收件人与线程内容正确 |
| 权限 | 使用实际业务人员账号进入邮箱和单据 | 可用获准邮箱操作，未授权人员不应看到该邮箱 |

若只配置发信，只验收发信，不宣传收信可用。记录测试日期、使用账号、结果和处理人；未通过的功能保持未启用或明确告知暂不可用。

## 8. 常见问题

| 现象 | 先检查什么 | 交给谁 |
|---|---|---|
| 能登录系统但不能发邮件 | 是否配置发送账户、是否分配及有邮件权限 | 系统管理员 |
| 认证失败 | 是否须授权码／OAuth，账号是否正确，服务商是否允许协议登录 | 邮箱管理员 |
| 连接超时或加密错误 | 服务器、端口、TLS／SSL及服务器网络 | 系统维护人员 |
| 已点发送但对方未收到 | 邮件队列、退信、对方垃圾箱、地址和服务商限制 | 系统及邮箱管理员 |
| 网页邮箱有信、系统无信 | 接收开关、同步文件夹、用户分配及收信后台任务 | 系统管理员 |
| 提示用户未关联邮箱 | User 的 User Emails／Email Inbox 是否已添加账户 | 系统管理员 |

问题反馈提供发生时间、单据号、邮件主题及原始错误提示；不发送密码或授权码。
