# 项目开发申请表与项目详情字段导出方案

状态：P1 字段、预算子表和首版 PDF 导出已形成实现基线；第 13、14 节为后续布局与 PDF 改版方案。本轮只更新文档，不实施第 13、14 节代码或站点元数据。

## 1. 背景与目标

P1 是《项目开发申请表》，P2 是当前 ERPNext `Project` 的项目详情页。本方案将 P1 的信息补全到 P2，并增加一条“按 P1 固定版式导出”的新分支。

本期导出以 **A4 纵向 PDF** 为主：表格、复选框、预算明细、签字区和分页样式按 P1 还原。现有 Excel 导出、项目成本明细、ERPNext 原生打印和项目标准成本计算保持不变。

本期明确不做：修改 ERPNext `Project` 标准控制器、重命名现有字段、把预算明细并入实际成本、改造旧导出接口、自动创建审批单或电子签名。

## 2. 当前基线与差距

当前业务代码位于 `development/frappe-bench/apps/client_akivision`。`Project` 使用 ERPNext 标准 DocType，应用已经有以下扩展：

- `custom_project_code`、`custom_technical_domain`、`custom_project_leader`；
- `project_cost_detail` 子表，用于实际发生的手工成本（物料消耗、测试费、其他费用）；
- `custom_project_cost_detail_total`，由实际成本明细汇总；
- `document_export_list.js` 已挂载到项目列表，但 `document_export.py` 当前没有 `Project` 导出配置，因此通用“导出已选数据”不应直接复用为 P1 表单导出。

P2 目前可以承载项目名称、优先级、项目编号、部门、负责人、预计起止日期和标准预计成本，但缺少 P1 的申请和研发说明字段。P1 的预算是“计划预算”，不能与现有“实际成本明细”混用。

## 3. P1 到 P2 的字段映射

### 3.1 复用现有字段

| P1 字段 | P2 字段 | 类型/处理 | 兼容说明 |
|---|---|---|---|
| 申请日期 | 新增 `custom_application_date` | Date | 不占用创建时间，允许补录真实申请日期 |
| 项目优先级 High/Medium/Low | `priority` | 标准 Select | 保留现有值；P1/PDF 固定显示顺序为 High、Medium、Low |
| 项目名称 | `project_name` | 标准 Data | 复用，不新增同义字段 |
| 项目编号 | `custom_project_code` | 既有自定义字段 | 复用现有导入和列表字段 |
| 部门 | `department` | 标准 Link: Department | 复用 |
| 项目负责人 | `custom_project_leader` | 既有 Link: User | PDF 显示用户全名；空值时签字区保留空线 |
| 项目启动日期 | `expected_start_date` | 标准 Date | P2 标签可显示为“项目启动日期”，字段名不变 |
| 项目完成日期 | `expected_end_date` | 标准 Date | P2 标签可显示为“项目完成日期”，字段名不变 |

`estimated_costing` 是 ERPNext 既有预计成本字段，历史导入和项目成本逻辑可能读取它。本期不改变其字段名和计算方式；P1 预算总额使用新增的 `custom_project_budget_total`。当新字段为空时，PDF 可按兼容规则回退显示 `estimated_costing`，避免历史项目导出为空。

### 3.3 新增预算明细子表

文件：`client_akivision/client_akivision/doctype/project_development_budget_detail/project_development_budget_detail.json`

| 字段名 | 标签 | 类型 | 规则 |
|---|---|---|---|
| `expense_category` | 费用分类 | Select | 人员人工费、直接投入费、固定资产折旧与摊销、无形资产摊销、委外研发费用、其他费用 |
| `amount` | 金额 | Currency | 非负数，人民币，允许 0 |
| `calculation_basis` | 计算依据 | Small Text | 对应 P1 的计算依据列 |
| `remarks` | 备注 | Small Text | 对应 P1 的备注列 |

P1 截图中第 3、4 个折旧/摊销行显示文字相同，但计算依据一行是“研发专用设备折旧”，另一行是“软件/专利摊销”。本方案暂按“固定资产折旧与摊销”和“无形资产摊销”拆分，实施前需由业务确认第二行正式名称；若确认必须完全重复显示，仍可通过选项标签兼容，不改变数据结构。

预算明细合计只写入 `custom_project_budget_total`，不回写 `estimated_costing`、`total_costing_amount`、毛利或实际成本字段。若需要把计划预算同步到 ERPNext 标准预计成本，另立迁移方案，避免改变旧报表口径。

## 4. 表单布局与交互

### 4.1 P2 详情页

在基础项目字段后增加“项目开发申请信息”区，按两列布局放置申请日期、优先级、产品属性和替代产品；参数区按 P1 顺序排列倍率、WD、分辨率、O/I距、TV畸变，业务影响度使用整行长文本。

预算明细区独立于现有“实际成本明细”区：

- 预算子表列顺序固定为“费用分类、金额、计算依据、备注”；
- 新增、删除或修改预算行时前端刷新预算合计；
- 服务端 `validate` 再计算一次合计并校验金额，前端结果不作为最终依据；
- 实际成本子表继续使用现有 `Project Cost Detail`，其成本类型、物料编码和日期规则不变。

### 4.2 P1 复选框与签字区

PDF 中产品属性固定呈现四个复选框，选中显示黑色方框/勾选，未选显示空框。项目负责人、部门经理和日期放在最后一页签字区；系统只带出已填写的姓名和日期，不伪造电子签名图片。

## 5. 导出功能设计

### 5.1 用户入口

- 项目列表“操作”菜单新增“导出项目开发申请表 PDF”；支持勾选一条或多条项目。
- 项目详情页“操作”菜单新增同名按钮，默认导出当前项目。
- 单条项目直接下载 PDF，多条项目按“一项目一 PDF”打包 ZIP；文件名使用 `项目开发申请表-{项目编号或名称}-{项目名}.pdf`，并对文件名做安全清洗。

不移除现有“导出已选数据/导出筛选结果”入口，不修改通用 `download_document_export` 的参数和返回格式。项目 P1 导出使用全新的方法名和前端分支，避免把固定版式需求塞入通用 Excel 配置。

### 5.2 PDF 版式

> 版式更新说明：本小节是首版设计基线。用户后续提供了更明确的纸质表单参考图，因此具体页面结构、字段顺序、合并单元格、默认文案和视觉风格以第 14 节为最终准则。本小节与第 14 节冲突的内容不再实施；A4 纵向、中文可读、长文本不丢失和稳定分页等通用要求继续有效。

模板文件：`client_akivision/templates/project_development_application.html`

样式文件：`client_akivision/public/css/project_development_application.css`

版式要求：

- A4 纵向、中文字体、标题“项目开发申请表”居中；
- 申请日期和优先级位于表格上方；
- 标签区使用参考图对应的浅灰绿色，预算列头使用浅灰色，表格采用黑色实线边框，长文本自动换行；
- “项目细节描述”采用单一主表，“产品属性”“项目描述”“业务影响度”“预算明细”“项目起始点要求”按第 14 节使用合并单元格；
- 预算表显示固定六类费用、金额、计算依据、备注和合计；
- 多页时重复表头，签字区只出现在最后一页；
- 空字段保留空白线或空单元格，不把 `None`、`0.0` 或英文字段名直接输出；
- 不依赖仓库根目录图片，首期不新增 Logo，保持 P1 原始表单风格。

### 5.3 服务端调用约定

新增模块：`client_akivision/utils/project_development_application.py`

建议新增白名单方法：

```text
download_project_development_application(document_names)
```

服务端流程：解析并去重名称 -> 数量上限校验 -> `frappe.get_doc("Project", name)` -> 读取权限校验 -> 排除不存在、无权限和已取消项目 -> 组装 P1 上下文 -> 渲染 Jinja 模板 -> 使用 `formal_pdf_export.render_pdf` 生成 PDF -> 单文件下载或 ZIP 下载。

前端只发送项目名称数组，不发送 HTML、字段名、SQL、模板路径或金额。导出全程只读，不更新 `modified`，不触发保存、提交、取消、成本重算、库存或财务写入。

## 8. 调用链路

### 8.1 保存链路

```text
Project 详情页填写 P1 字段/预算明细
  -> project_cost_detail.js 刷新显示合计
  -> 用户保存 Project
  -> ERPNext Project.validate()
  -> client_akivision Project validate 列表
       -> 既有 project_cost.validate_project_cost_details()
       -> 新增 project_development_application.validate_project_application()
  -> 校验预算金额、费用分类、产品属性数据
  -> 仅写入 Project 新字段和预算子表
```

标准 `update_costing()`、Timesheet/采购/库存实际成本聚合不变。

### 8.2 PDF 导出链路

```text
Project 列表勾选或详情页操作
  -> document_export_list.js / Project 详情按钮
  -> POST 新接口 download_project_development_application
  -> 解析名称、权限和取消状态校验
  -> project_development_application 读取 Project 与预算子表
  -> 计算/读取预算合计和 P1 显示值
  -> Jinja 模板 + CSS
  -> formal_pdf_export.render_pdf(A4 portrait)
  -> 单 PDF 下载；多项目 ZIP 下载
```

导出链路不进入保存、提交、审批、库存、财务凭证、实际成本更新或旧 Excel 下载链路。

## 10. 兼容与小增量策略

1. 只新增 `custom_` 字段、一个预算子表、一个 PDF 服务模块和前端分支，不修改 ERPNext 标准 DocType 源文件。
