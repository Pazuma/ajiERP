# 表单内弹窗导入实施沉淀

## 1. 交付结论

列表页点击“导入”后，用户留在当前表单列表中，通过弹窗完成文件上传、预览、警告确认和开始导入，不再跳转到独立的 Data Import 页面。

本次只替换交互入口，仍复用 Frappe 标准 Data Import 的解析、权限、后台任务、导入日志和失败重试能力。弹窗关闭后，当前列表自动刷新，已成功的数据可以立即看到。

## 2. 功能范围

- 支持 CSV、XLS、XLSX 文件。
- 弹窗内可选择标准模板或当前表单对应的业务模板，并勾选主表/子表字段。
- 模板字段支持全选、清空和必填字段默认勾选；下载会按选择生成 Excel 模板。
- 支持“插入新记录”和“更新已有记录”。
- 上传后显示标准导入预览表格和字段映射警告。
- 文件开始解析后锁定导入方式和提交选项；清除文件会释放未开始的临时任务。
- 可选择不发送通知邮件；可提交表单提供“导入后自动提交”。
- 导入过程中在弹窗显示成功、失败和总行数。
- 导入完成后不进入 Data Import 页面；用户可关闭弹窗继续使用当前列表。
- 失败或部分成功任务仍保留在 Data Import 中，便于管理员查看日志和重试。

## 3. 代码清单

| 文件 | 作用 |
| --- | --- |
| `client_akivision/public/js/inline_data_import.js` | 拦截 ListView 的标准“导入”菜单，打开弹窗、上传文件、渲染预览、启动任务和轮询进度 |
| `client_akivision/client_akivision/api/data_import.py` | 创建弹窗导入任务、保存文件并预览、保存列映射、读取模板字段、校验字段选择、启动任务和返回进度 |
| `client_akivision/public/css/data_import.css` | 弹窗宽度、预览表格、移动端高度和状态提示样式 |
| `client_akivision/hooks.py` | 在 Desk 全局加载弹窗导入脚本 |

## 4. 数据流

```text
列表页点击“导入”
  -> inline_data_import.js 替换 Frappe 默认路由动作
  -> 打开当前 DocType 的导入弹窗
  -> 加载匹配业务模板和主表/子表字段
  -> 用户选择模板、字段后可下载定制模板
  -> 用户选择 CSV/XLS/XLSX
  -> create_inline_import 创建标准 Data Import 任务
  -> 文件上传得到 file_url
  -> preview_inline_import 保存文件并调用标准 Importer 解析
  -> 返回前 10 行、列识别结果、字段映射和警告
  -> 用户确认后调用 start_inline_import
  -> Frappe 后台队列执行标准导入
  -> get_inline_import_status 轮询任务和 Data Import Log
  -> 成功/部分成功/失败后显示结果并刷新原列表
```

列映射操作仍写回标准 Data Import 的 `template_options`，不会修改 DocType 字段或用户列表配置。弹窗不是绕过权限的快捷入口，服务端会再次检查目标 DocType 的 `allow_import` 和当前用户的 `import` 权限。

## 5. 依赖清单

- Frappe ListView：提供标准“导入”菜单和当前列表刷新能力。
- Frappe Data Import：Importer、ImportPreview、Data Import Log、后台任务和失败行处理。
- Frappe FileUploader：处理文件上传和扩展名限制。
- ERPNext/自定义 DocType 元数据：目标表单必须开启 `allow_import`。
- Redis/RQ Scheduler：正式环境后台执行导入任务必须可用。
- 当前用户权限：目标 DocType 的导入权限、Link 目标记录读取权限，以及提交单据所需权限。

## 6. 风险点清单

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 用户上传非标准模板 | 预览出现未识别列或导入失败 | 先看预览和警告；必要时使用“Map Columns”；不允许带阻断警告直接启动 |
| 大文件在弹窗内解析时间较长 | 用户误以为页面卡死 | 显示“正在解析文件”，预览区域保留滚动高度；正式环境按批次控制文件大小 |
| Redis/RQ Scheduler 未运行 | 任务一直等待或无法启动 | 弹窗提示任务状态；部署前检查 worker、scheduler 和 Redis |
| 导入后自动提交 | 触发库存、会计、审批副作用 | 默认关闭；只有可提交表单显示选项，并按角色权限人工确认 |
| 用户关闭弹窗 | 任务仍可能在后台运行 | Data Import 任务和日志保留；可从 Data Import 查询状态和失败行 |
| 任务被重复点击 | 重复导入或重复后台任务 | 启动后禁用主按钮；服务端按任务状态拒绝重复启动 |
| 当前列表权限和导入权限不一致 | 用户能看到入口但服务端拒绝 | 弹窗创建、预览和启动接口逐次执行目标 DocType 权限检查 |
| 移动端预览列过多 | 表格横向阅读困难 | 弹窗正文允许横向滚动，移动视口限制弹窗高度，不改变数据内容 |

## 7. 需要复测的场景

### 7.1 基本流程

1. 以 System Manager 打开客户、物料或供应商列表，点击“导入”，确认不跳转到 `/app/data-import`。
2. 不上传文件直接点击“开始导入”，确认按钮不可用或提示先上传文件。
3. 上传标准 CSV/XLSX，确认弹窗显示预览行、字段标题和状态提示。
4. 点击“开始导入”，确认弹窗显示后台进度，完成后列表自动刷新。

### 7.2 字段、模板和警告

1. 上传缺少必填字段的文件，确认预览显示阻断警告且不能启动。
2. 上传包含未识别列的文件，使用“Map Columns”重新映射，确认预览刷新后可以继续。
3. 切换“插入新记录/更新已有记录”，确认预览重新解析，更新模式保留 ID 列要求。
4. 点击“下载模板”，确认仍使用 Frappe 标准模板下载，不打开 Data Import 页面。

### 7.3 权限和业务副作用

1. 无目标 DocType 导入权限的账号直接访问列表，确认菜单不显示或弹窗服务端拒绝。
2. 无 Data Import DocType 管理权限但有目标表单导入权限的业务账号，确认仍可通过弹窗完成导入。
3. 对 Sales Order、Purchase Order、Stock Entry 等可提交单据测试“导入后自动提交”，确认默认关闭，打开后按标准权限执行。
4. Link 字段填写不存在的客户、供应商或物料，确认错误行记录在标准导入日志中。

### 7.4 失败、重复和移动端

1. 导入中关闭弹窗，重新打开 Data Import 列表，确认任务仍可追踪。
2. 同一文件重复导入，确认唯一键或更新模式按标准逻辑处理，不产生无意重复数据。
3. 模拟 worker 停止，确认弹窗提示等待/失败，而不是白屏或跳转错误页面。
4. 使用 390px 视口打开弹窗，确认文件控件、主按钮、状态提示和预览表格不重叠，页面无横向溢出。
