# BOM 物料层级按需展开优化方案

## 1. 需求背景

当前 BOM「版本」页展示物料结构时，会沿组件行关联的子 BOM 递归展开其下级物料。对于只想先核对当前 BOM 直接组件的用户，首屏信息过多，不容易区分当前 BOM 的直接用料和子 BOM 内部用料。

本次希望在截图蓝框位置（版本选择控件右侧）增加「展开全部物料」操作：

- 初始状态只显示当前 BOM 的直接关联物料，不展示子 BOM 内部物料。
- 点击操作后，递归展示关联子 BOM 的全部有效物料。
- 再次点击后恢复为仅显示当前 BOM 的直接关联物料。
- 层级、用量和现有版本选择保持一致；此操作只切换只读视图，不修改 BOM 数据。

## 2. 目标界面

```text
查看版本
[V1 · 当前启用________________________________] [展开全部物料]
启用时间：2026-10-12 16:42:34

┌──────────┬──────┬────────────┬──────────┬──────┐
│ 型号     │ 层级 │ 物料名称   │ 图纸号   │ 用量 │
├──────────┼──────┼────────────┼──────────┼──────┤
│ 成品 A   │ 0    │            │ BOM-A    │ 1    │
│ 半成品 B │ 1    │ 半成品 B   │ BOM-B    │ 2    │
└──────────┴──────┴────────────┴──────────┴──────┘
```

点击「展开全部物料」后：

```text
查看版本
[V1 · 当前启用________________________________] [收起下级物料]

┌──────────┬──────┬────────────┬──────────┬──────┐
│ 型号     │ 层级 │ 物料名称   │ 图纸号   │ 用量 │
├──────────┼──────┼────────────┼──────────┼──────┤
│ 成品 A   │ 0    │            │ BOM-A    │ 1    │
│ 半成品 B │ 1    │ 半成品 B   │ BOM-B    │ 2    │
│ 原料 C   │ 2    │ 原料 C     │ ITEM-C   │ 6    │
│ 子件 D   │ 2    │ 子件 D     │ ITEM-D   │ 2    │
└──────────┴──────┴────────────┴──────────┴──────┘
```

按钮文案可采用状态表达：「展开全部物料」/「收起下级物料」。保持窄按钮尺寸，放在版本选择框右侧，窄屏时按钮换到选择框下一行，不挤压选择器。

## 3. 层级和数量口径

- 层级 `0`：当前所选 BOM 的顶层成品。
- 层级 `1`：当前所选 BOM 的直接组件，默认始终显示。
- 层级 `2` 及以上：直接组件关联的子 BOM 中的组件，只在点击展开后显示。
- 直接组件数量沿用当前 BOM 明细数量。
- 子 BOM 组件数量按父级组件用量和子 BOM 产出数量逐级折算；继续沿用现有累计用量口径。
- 当组件未关联子 BOM、设置为不展开、子 BOM 不可读、未提交/停用或产出数量无效时，不继续展示其下级，并在需要时沿用现有警告提示。
- 循环 BOM 必须停止递归，不能造成无限查询；沿用现有循环检测和警告行为。

## 4. 交互规则

1. 打开已保存 BOM 或切换版本时，默认请求直接物料模式；表格包括顶层行和当前 BOM 的直接组件，不含下级组件。
2. 点击「展开全部物料」后，以当前所选版本重新请求递归模式，并将按钮改为「收起下级物料」。
3. 点击「收起下级物料」后重新请求直接物料模式。
4. 切换版本后恢复默认直接物料模式，避免把上一版本的展开状态误带到另一个版本。
5. 请求过程中禁用切换按钮或显示加载状态；只接受与当前版本和当前请求序号匹配的响应，防止快速切换造成旧数据覆盖新数据。
6. 新建/未保存草稿仍使用当前草稿预览；默认只显示该草稿直接组件，点击展开时才查询其有效子 BOM。尚未保存的本级明细以表单内容为准。
7. 如果当前版本没有任何子 BOM，下级展开后表格保持不变，并可显示「没有可展开的下级物料」提示；不得重复插入行。
8. 按钮只控制展示，不触发保存、启用、版本创建或成本重算。

## 5. 当前实现和拟调整调用链

当前版本查看链路：

```text
BOM 表单打开/切换版本
  -> client_akivision/public/js/bom.js: render_versions()
  -> get_bom_version_view(bom, version_bom)
  -> _build_bom_version_view(target, summary)
  -> append() 递归展开 target.items 中关联的子 BOM
  -> 返回 items 给版本表格
```

当前草稿预览链路：

```text
BOM 草稿预览
  -> client_akivision/public/js/bom.js: render_bom_draft_editor()
  -> preview_bom_draft(doc)
  -> _build_bom_version_view(target, summary)
  -> append() 递归展开关联子 BOM
```

拟调整后调用链：

```text
版本选择 / 草稿预览
  -> 视图请求携带 expand_children=false（默认）
  -> 仅生成顶层 + 直接组件

点击「展开全部物料」
  -> 视图请求携带 expand_children=true
  -> 在同一权限、循环和有效性校验下递归生成下级组件
```

建议保留现有 API 方法名和现有响应结构，只给 `get_bom_version_view`、`preview_bom_draft` 增加可选参数 `expand_children`，默认 `0`。`_build_bom_version_view` 增加同名可选参数；仅在参数为真时递归。这样不新增接口，旧调用不传参数时自动使用较精简的直接物料视图，响应仍包含现有 `summary/items/warnings/costs` 字段。

## 6. 预计修改文件

| 文件 | 预计改动 |
|---|---|
| `client_akivision/client_akivision/api/bom.py` | 给版本查看和草稿预览增加可选展开参数；默认不递归，展开时沿用当前安全校验、用量折算和警告逻辑。 |
| `client_akivision/public/js/bom.js` | 在版本选择器右侧增加展开/收起控制；保存当前请求状态；切换版本后重置为收起；为草稿预览提供相同交互。 |
| `client_akivision/client_akivision/api/test_bom.py` 或 `client_akivision/utils/test_bom_version.py` | 覆盖默认直接层级、展开后递归层级、数量折算、无子 BOM、循环及无权限子 BOM 的行为。 |

不修改 ERPNext 原始 BOM/BOM Item DocType，不更改组件录入、BOM 提交、版本启用和生产工单取 BOM 逻辑。

## 7. 受影响模块

- BOM 版本只读查看：默认层级由递归结构改为直接组件结构，用户可按需展开。
- 新建/编辑 BOM 草稿预览：增加同样的按需展开控制；直接组件编辑行为不变。
- BOM 导入和模板校验：不受影响，仍只维护当前 BOM 的直接组件。
- 成本估算、BOM 启用和工单：不受影响，展开按钮不修改数据或计算口径。
- 权限边界：下级子 BOM 仍需通过现有 `has_permission("read")` 检查；无权子 BOM 不泄露明细。

## 8. 风险与兼容策略

- 递归仅在用户点击后执行，降低首次加载查询量；大量层级仍受循环检测和子 BOM 有效性检查约束。
- 版本查看及草稿预览默认参数为关闭，旧客户端和未改造调用继续可用。
- 保持响应字段结构不变，现有表格渲染、成本栏、警告和版本链接无需改接口契约。
- 不使用前端缓存作为权限边界；每次按需展开仍由服务端验证 BOM 和子 BOM 读取权限。
- 异步响应需关联版本名和请求序号，避免用户快速切版本时展示错版本明细。

## 9. 验收标准

1. 初次打开版本详情只显示顶层型号（层级 0）和当前 BOM 的直接组件（层级 1）。
2. 初始视图中不出现关联子 BOM 的内部组件（层级 2 及以上）。
3. 点击「展开全部物料」后能显示所有可读、有效子 BOM 的下级组件，并正确显示层级和累计用量。
4. 点击「收起下级物料」后只剩层级 0 和层级 1。
5. 切换版本后状态恢复默认收起，数据对应当前选中版本。
6. 新建草稿使用同一交互；展开读取已提交有效的子 BOM，当前草稿直接组件仍使用未保存表单数据。
7. 循环子 BOM 能停止并显示警告；无权读取的子 BOM 不返回其内部物料。
8. 无子 BOM、空表、快速连续点击和请求失败时页面无重复行、错版数据或前端异常。
9. 组件增删改、BOM 保存/启用、成本估算和生产工单引用不受该只读显示开关影响。

## 10. 实施范围

本文件是实施前方案沉淀，本次不修改代码、不变更站点数据。实施时按上述最小范围修改 API、BOM 前端脚本和定向测试，完成后再验证版本视图与草稿预览两条链路。
