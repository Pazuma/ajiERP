# 销售订单到销售出库简化流程实施沉淀

## 1. 实施结论

已根据《销售订单到销售出库简化流程沉淀》落地“傻瓜式”销售出库入口：

```text
已提交销售订单
    -> 创建 -> 一键创建销售送货单
    -> 系统生成草稿销售送货单
    -> 用户核对后提交
    -> 库存扣减，销售订单交付数量更新
```

拣货单不再作为普通单仓库一次出库的必经步骤。多仓库、批次、序列号、集中波次拣货等场景仍保留标准拣货单流程。

本次只生成草稿送货单，不自动提交，不绕过 ERPNext 原有库存、权限和超量交付校验。

## 2. 代码变更

| 文件 | 变更 |
|---|---|
| `client_akivision/utils/sales_order_delivery.py` | 新增简化出库后端映射；计算订单剩余量；扣除同一销售订单明细已有草稿送货数量；无剩余量时阻止重复生成 |
| `client_akivision/public/js/sales_order_delivery.js` | 在满足条件的销售订单“创建”菜单中增加“一键创建销售送货单”入口 |
| `client_akivision/hooks.py` | 注册 `Sales Order` 的 `doctype_js` |
| `docs/playwright_sales_order_delivery_simplification.mjs` | 真实站点 Playwright 验收脚本 |

## 3. 数据流

```text
Sales Order
  | docstatus=1，status 非 Closed/On Hold
  | 明细 qty > delivered_qty
  v
前端一键按钮
  | frappe.model.open_mapped_doc
  v
frappe.model.mapper.make_mapped_doc
  | client_akivision.utils.sales_order_delivery.make_simple_delivery_note
  v
读取 Sales Order Item
  | 剩余量 = qty - delivered_qty - 草稿 Delivery Note qty
  v
调用 ERPNext make_delivery_note
  | 保留标准客户、税费、价格、仓库、销售订单明细映射
  v
修正草稿明细数量并重新计算金额/税费/包装明细
  v
Delivery Note 草稿
  | 用户核对
  v
提交 Delivery Note
  | 库存扣减、Stock Ledger Entry、Bin、Sales Order delivered_qty 更新
```

重复保护只针对同一 `Sales Order Item`：

```text
订单数量 - 已交付数量 - 未提交草稿送货数量 = 本次可生成数量
```

已提交的送货单继续由 ERPNext 标准 `delivered_qty` 参与计算；草稿送货单通过 `Delivery Note Item.so_detail` 和 `against_sales_order` 汇总。

## 4. 入口显示条件

一键入口只在以下条件同时满足时显示：

- 销售订单已提交；
- 销售订单状态不是 `Closed` 或 `On Hold`；
- 不是委外订单；
- 未跳过销售送货单；
- `per_delivered < 100`；
- 当前用户有创建 `Delivery Note` 权限；
- 至少一行物料仍有未交付数量，且不是供应商直送行。

## 7. 验收中实时发现的问题

### 7.1 `custom_filters` 静态资源请求失败

现象：浏览器请求 `/custom_filters/public/js/naming_series_i18n.js` 失败。

影响：不影响本次销售订单映射和送货单草稿生成；可能影响自定义编号相关的前端增强功能。

解决方案：

1. 检查 `custom_filters` 应用是否正确安装、public 目录是否存在该文件。
2. 执行 `bench build --app custom_filters` 或重新安装/迁移该应用。
3. 清理缓存并重启站点后复测编号字段。

### 7.2 页面已有 `Cannot read properties of null (reading 'join')`

现象：销售订单页面加载期间出现已有前端异常，堆栈不在新增 `sales_order_delivery.js`。

影响：本次按钮点击、后端映射和送货单字段验收均通过；该异常可能影响页面其他非主流程区域，应单独排查。

解决方案：

1. 在浏览器控制台记录完整堆栈和触发模块。
2. 检查自定义字段、工作区导航或关联数据中是否存在 `null` 数组被直接调用 `.join()`。
3. 对相关字段统一使用空数组回退，例如 `values || []`，修复后重新执行销售订单全页回归。

## 8. 风险点清单与复测场景

| 风险点 | 处理方式 | 必须复测 |
|---|---|---|
| 同一订单已有草稿送货单 | 后端按 `so_detail` 汇总并扣除 | 先建草稿 5，再点击一键入口，剩余数量应减少 5；无剩余时应阻止生成 |
| 同一订单已部分提交送货 | 使用 ERPNext `delivered_qty` | 订单 20 已交付 3 时只能生成 17 |
| 已全部交付后重复出库 | 前端隐藏入口，后端再次校验 | `per_delivered=100`、Completed 订单不能生成 |
| 多明细订单 | 按明细行独立计算 | 一行已交付、一行未交付时只生成未交付行 |
| 多仓库 | 保留原生明细仓库 | 每行仓库与销售订单/库存规则一致 |
| 批次和序列号 | 不在自定义层绕过 ERPNext 校验 | 批次、序列号物料生成草稿后可正常复核并提交 |
| 委外订单/跳过送货 | 前端和后端阻止入口 | `is_subcontracted=1`、`skip_delivery_note=1` 不显示且接口拒绝 |
| 权限越权 | 后端检查 Delivery Note create 和 Sales Order read | 无创建权限用户不能通过接口生成草稿 |
| 并发点击 | 当前依赖草稿查询和提交时标准校验 | 两个浏览器同时点击，不能造成已提交超量；如需严格防重应增加数据库唯一业务锁 |
| 税费/金额/包装明细 | 裁剪数量后重新执行标准计算 | 含税、折扣、产品包订单核对金额和明细 |
| 移动端操作 | 已验证 390px 无横向溢出 | 手机宽度下创建菜单、入口和送货单明细可操作 |
| 站点静态资源 | 已记录 custom_filters 失败 | 修复依赖后重新检查命名系列和全页控制台错误 |

## 9. 发布与操作建议

1. 部署后执行 `bench build --app client_akivision`。
2. 执行 `bench --site <site> clear-cache`，必要时重启 web/worker。
3. 普通单仓库出库使用“销售订单 -> 创建 -> 一键创建销售送货单”。
4. 只核对草稿后提交送货单，不再从同一订单重复创建整单送货单。
5. 多仓库、批次、序列号或集中拣货场景继续使用标准拣货单。
6. 遇到“超出订单允许量”时先检查已提交和草稿送货单，不要直接放宽超量控制。

## 10. 当前效果

普通销售出库从“销售订单 -> 拣货单 -> 送货单”简化为“销售订单 -> 一键创建销售送货单 -> 提交”，同时保留标准库存过账和重复出库保护。测试结果证明主流程字段完整、剩余数量计算正确、已完成订单不会再次进入出库入口。
