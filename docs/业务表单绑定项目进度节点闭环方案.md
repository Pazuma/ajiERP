# 业务表单绑定项目进度节点闭环方案

> 文档日期：2026-09-15  
> 当前阶段：方案沉淀，暂不修改代码。  
> 核心目标：业务表单不是简单关联项目，而是绑定项目下的具体进度节点，作为该节点完成或推进的业务依据。

## 1. 核心理解

本功能的核心不是“表单挂到项目”，而是：

```text
业务表单 = 项目进度节点的完成依据
```

一个项目下有一组进度节点，例如：

```text
项目 222 / PROJ-0008

进度节点：
1. 需求确认
2. 采购准备
3. 生产加工
4. 质检
5. 交付
```

业务表单绑定到这些节点后，项目进度就可以通过业务表单的状态反推。

示例：

```text
销售订单 SO-0001
  -> 绑定节点：需求确认

采购订单 PO-0001
  -> 绑定节点：采购准备

采购送货单 PR-0001
  -> 绑定节点：采购准备

生产工单 WO-0001
  -> 绑定节点：生产加工

销售送货单 DN-0001
  -> 绑定节点：交付
```

这样项目负责人打开项目时，不只是看到“百分比”，而是能知道：

```text
项目进行到了哪一步
这个步骤为什么完成
是哪张业务表单推动的
什么时候完成
由谁完成
```

## 2. 业务定义

### 2.1 关联项目

表示这张业务表单属于哪个项目。

```text
关联项目 = 当前业务表单归属的项目
```

示例：

```text
生产工单 WO-0001
关联项目 = 222 / PROJ-0008
```

### 2.2 关联步骤 / 绑定进度节点

表示这张业务表单对应项目里的哪个进度节点。

```text
关联步骤 = 当前业务表单证明或推动的项目进度节点
```

示例：

```text
生产工单 WO-0001
关联项目 = PROJ-0008
关联步骤 = 生产加工
```

### 2.3 表单完成

不同表单的“完成”首版统一按提交状态判断。

```text
草稿 = 未完成
已提交 = 已完成
已取消 = 不再作为完成依据
```

后续如果某些表单有更细状态，例如生产工单 `Completed`、销售订单 `Closed`，可以再新增独立分支，不影响首版提交口径。

## 3. 目标闭环

完整闭环如下：

```text
项目开始
  -> 项目阶段 = 进行中
  -> 维护项目进度节点
  -> 创建业务表单
  -> 选择关联项目
  -> 选择该项目下的进度节点
  -> 保存业务表单
  -> 系统记录该表单与节点的绑定关系
  -> 提交业务表单
  -> 系统更新绑定记录为已完成
  -> 系统重新计算项目节点状态
  -> 项目进度页显示节点状态、完成时间、关联表单
```

## 4. 页面预期效果

### 4.1 业务表单页面

业务表单里应清楚显示：

```text
关联项目
[ 222 / PROJ-0008 ]

关联步骤
[ 生产加工 ]

步骤说明
当前表单完成后，将作为“生产加工”的完成依据。
```

如果用户先选择项目，关联步骤只能显示该项目下的节点。

```text
选择项目：PROJ-0008

关联步骤可选：
- 需求确认（进行中）
- 采购准备（待开始）
- 生产加工（待开始）
```

不应该出现其他项目的节点。

### 4.2 项目进度页

项目进度节点表应能体现节点与表单的关系。

预期展示：

```text
节点名称      状态       关联表单                       完成时间
需求确认      已完成     销售订单 SO-0001               2026-09-15 16:10
采购准备      进行中     采购订单 PO-0001（已完成）      -
                         采购送货单 PR-0001（草稿）
生产加工      待开始     生产工单 WO-0001（草稿）        -
交付          待开始     销售送货单 DN-0001（草稿）      -
```

当某个节点所有绑定表单都完成后：

```text
节点名称：采购准备
状态：已完成
关联表单：
- 采购订单 PO-0001：已完成
- 采购送货单 PR-0001：已完成
完成时间：最后一张完成表单的提交时间
```

## 5. 业务规则

### 5.1 项目与节点选择规则

```text
1. 一张业务表单必须先选择项目，才能选择关联步骤。
2. 关联步骤只能来自当前项目自己的进度节点。
3. 已完成节点默认不再提供给新表单绑定。
4. 如果切换项目，已选关联步骤必须清空。
5. 如果清空项目，关联步骤和步骤名称也必须清空。
```

### 5.2 表单与节点关系

首版保持简单清晰：

```text
一张业务表单 -> 一个项目 -> 一个进度节点
一个进度节点 -> 多张业务表单
```

暂不做：

```text
一张业务表单绑定多个节点
一个表单拆分推进多个步骤
```

原因：

```text
首版要保证逻辑可解释、可回滚、可验证。
如果一张表单能推动多个节点，取消提交、修改项目、修改节点时会显著增加复杂度。
```

### 5.3 多表单绑定同一个节点

一个进度节点可以绑定多张业务表单。

示例：

```text
采购准备节点绑定：
- 采购订单 PO-0001
- 采购送货单 PR-0001
```

完成规则：

```text
PO-0001 已提交，PR-0001 草稿
  -> 采购准备节点仍为进行中

PO-0001 已提交，PR-0001 已提交
  -> 采购准备节点变为已完成
  -> 完成时间 = PR-0001 的提交时间
```

### 5.4 表单取消或作废

如果业务表单取消提交：

```text
绑定记录状态 = 已取消
该表单不再作为节点完成依据
节点重新计算
```

示例：

```text
采购准备节点原本有：
- PO-0001 已完成
- PR-0001 已完成

节点状态 = 已完成

如果 PR-0001 被取消提交：
  -> PR-0001 状态 = 已取消
  -> 节点重新计算
  -> 采购准备节点回到进行中 / 延期
```

## 6. 数据关系

### 6.1 业务表单字段

每个支持的业务表单需要有以下信息：

```text
关联项目
关联步骤编码
步骤名称
实际完成时间
```

当前已有字段口径：

```text
project / custom_progress_project
custom_progress_milestone_code
custom_progress_step_name
custom_progress_actual_completed_on
```

### 6.2 项目节点

Project 上的进度节点来自：

```text
custom_project_progress_items
```

关键字段：

```text
milestone_code
subject
status
actual_completed_on
completed_by
```

### 6.3 中间绑定关系

业务表单与项目节点之间应通过中间表维护：

```text
Project Progress Reference
```

它表达的是：

```text
哪张业务表单
绑定到哪个项目
绑定到哪个项目节点
当前完成状态是什么
什么时候完成
谁完成的
```

## 7. 调用链路

### 7.1 创建业务表单

```text
打开业务表单
  -> 选择关联项目
  -> 系统查询该项目下可绑定节点
  -> 用户选择关联步骤
  -> 系统回填步骤名称
  -> 用户保存表单
  -> 后端校验节点属于当前项目
  -> 后端创建/更新 Project Progress Reference
```

### 7.2 提交业务表单

```text
业务表单 Submit
  -> 找到 Project Progress Reference
  -> 状态改为 Completed
  -> 写入 actual_completed_on
  -> 写入 completed_by
  -> 重算对应 Project Progress Item
  -> 如果该节点全部绑定表单完成
       节点状态 = 已完成
       节点完成时间 = 最后一张表单完成时间
  -> 重算 Project 总进度
```

### 7.3 项目进度展示

```text
打开 Project 流程进度
  -> 展示节点状态
  -> 展示节点完成时间
  -> 展示节点关联的业务表单
  -> 可跳转到对应业务表单
```

## 9. 小增量实现建议

### 阶段一：修正业务表单内绑定体验

目标：

```text
选择项目后，关联步骤必须清晰列出该项目下的节点。
选择步骤后，步骤名称自动回填。
保存后建立绑定关系。
```

范围：

```text
生产工单
采购订单
采购送货单
销售订单
销售送货单
```

### 阶段二：项目进度页展示关联表单

目标：

```text
项目进度节点上可以看到绑定了哪些业务表单。
每张表单显示草稿 / 已完成 / 已取消。
```

### 阶段三：从项目页创建表单前绑定节点

目标：

```text
项目详情页关联区点击 +
  -> 先选择绑定节点
  -> 再创建业务表单
  -> 自动带入项目和节点
```

### 阶段四：完善取消、修改、异常提示

目标：

```text
取消提交后重算节点
切换项目时清空节点
已完成节点不再默认可选
节点无可选项时明确提示
```

## 10. 预期最终效果

最终用户视角应该是：

```text
1. 打开业务表单
2. 选择项目
3. 选择该项目下的具体步骤
4. 保存表单
5. 提交表单
6. 回到项目进度
7. 能看到这个步骤被哪张表单完成、什么时候完成
```

项目负责人视角：

```text
打开项目
  -> 看节点状态
  -> 看关联表单
  -> 看完成时间
  -> 判断项目现在进行到了哪一步
```

这套闭环的核心价值是：项目进度不再只是人工填写的百分比，而是由销售、采购、生产、库存等实际业务表单共同驱动，进度变化有依据、可追溯、可解释。
