## 2. 现有导入能力与统一规则

现有配置文件为 `client_akivision/config/excel_import_tables.json`。其中客户、供应商、收款模式、研发项目、产品、销售订单、BOM、安全库存、采购订单、入库、送货、收付款、出库、固定资产、工时、借出样品、借回样品已配置导入目标；供应商回顾、实时库存、成品状态、汇总计算、各项指标汇总或看板数据被配置为只读或自动维护，不允许导入。

统一规则：

1. Link 字段必须使用系统名称/编码，不能把显示名称、公式结果或 Excel 行号当作 Link 值。
2. 业务事实进入单据主表或子表；金额、状态、累计数量、账龄、库存余额、及时率等由系统计算的字段只做校验，不直接导入。
3. 主数据优先但不要求一次性补齐全部辅助信息：客户、供应商、物料等 Excel 事实先导入；仓库、公司、币种、客户组、供应商组等可由站点默认配置补齐。
4. 一份 Excel 原始文件可以保留，但正式导入应使用“清洗后的导入副本”，删除公式、合并单元格、说明行和报表汇总区。
5. 公式列必须改为事实输入列或移出导入模板。涉及金额、年份、月份、未收/未交、订单完成等列，优先由 ERPNext 根据单据计算。

### 2.1 默认值与导入分级策略

导入器按以下三级处理缺失字段：

| 级别 | 处理方式 | 适用字段 | 是否允许先导入 |
|---|---|---|---|
| A：安全默认 | 使用站点/公司/物料主数据的默认值，记录“系统默认”来源 | Company、Currency、Customer Group、Supplier Group、Item Group、UOM、默认仓库、付款账户、收款账户、订单类型、启用标记 | 允许 |
| B：可空待补 | 先保存 Excel 已有事实，缺失字段留空或状态为“待补”，导入后人工完善 | 联系人、地址、负责人、项目负责人、备注、发票号、合同附件、预计归还日期、可选关联单据 | 允许，但不得提交依赖该字段的后续流程 |
| C：事实/关联阻断 | 不使用猜测值；缺失或无法唯一匹配时进入错误行/待处理清单 | Item 编码、Customer/Supplier Link、数量、日期、库存方向、银行金额、SN、采购/销售订单关联、核销单据 | 不允许直接落正式业务单据 |

默认值必须在导入日志中记录：字段、默认值、默认来源、原 Excel 是否为空、后续修正入口。人工修正不覆盖原始 Excel 文件，保留导入批次和修改记录。

该策略需要在正式导入器中实现为“导入前默认值注入 + Draft 保存 + 默认值日志”三步；仅在 Excel 模板中写死默认文字，不能保证站点中存在对应 Company、Warehouse、Account 或 UOM。标准 Data Import 不支持的默认值，应由本应用导入入口在校验后补入。

建议站点预先配置以下默认值：

- 默认 Company：当前站点业务公司；
- 默认 Currency：Company 默认币种；
- 默认 Customer Group/Supplier Group/Item Group：分别使用“默认客户组/默认供应商组/待分类物料”；
- 默认 UOM：Item 的 `stock_uom`，若物料没有库存单位则转 C 级待处理；
- 默认 Warehouse：按单据类型配置收货仓、成品仓、领料仓，不使用任意仓库；
- 默认 Payment Account：Company 的默认银行/现金账户；
- 默认 Sales Order `order_type`：`Sales`；默认 `is_active=1`、`is_default=0`；
- 默认安全库存申请类型：`Purchase`，但安全库存预警线和补货数量仍需区分；
- 默认缺失可选文本：留空，不填“未知”“N/A”等伪事实。

已落地的列表导入适配：客户/供应商/付款模式按编码更新已有记录；产品表按重复表头位置映射；`开发/已打样/已量产` 转为系统枚举；缺失物料组、UOM、项目负责人等非事实必填字段使用站点默认值并在预览中提示。适配代码只在 Data Import 任务中执行，未改变 ERPNext 核心业务校验。

不得默认的字段包括金额、数量、交易日期、库存源/目标方向、客户/供应商、物料编码、SN、采购/销售订单号和收付款核销对象。日期可使用 Excel 原值；Excel 无日期时应进入 B/C 级人工清单，而不是自动使用当前日期。

### 2.2 导入入口盘点与补齐

入口检查以两层能力为准：

1. **列表页入口**：目标 DocType 的列表页右上角“菜单 -> Import”。应用的 `inline_data_import.js` 会把标准 Import 菜单替换为带模板字段选择、预览和错误提示的 Excel 导入弹窗。
2. **Data Import 管理入口**：新建 `Data Import` 后，在“Excel 导入数据”选择器中按模块选择业务表；服务端只展示配置文件中 `importable=true` 且 DocType 开启 `allow_import`、当前用户拥有 Import 权限的表单。

本次检查结果：

| 表单 | 原状态 | 入口位置 | 调整 | 当前状态 |
|---|---|---|---|---|
| Customer、Supplier、Contact、Payment Terms Template、Project、Item、Sales Order、BOM、Purchase Order、Purchase Receipt、Delivery Note、Payment Entry、Stock Entry、Asset、Timesheet | 标准 DocType 已开启 `allow_import` | 各自列表页“菜单 -> Import”；Data Import 向导 | 无需新增入口，沿用统一弹窗导入 | 已有入口 |
| Finished Goods Status | 自动生成/自动更新的状态表 | 不提供 Import；只从收货、库存凭证和样品流程自动创建/更新 | 保持 `allow_import=0`，配置为只读；Excel 仅用于历史差异核对 | 按范围排除 |
| Sample Loan Out | 配置标记可导入，但 DocType 未开启 `allow_import` | 原来无列表 Import，也不出现在 Data Import 向导 | 在 DocType 元数据增加 `allow_import=1`；迁移补丁同步 | 已补入口 |
| Sample Loan In | 配置标记可导入，但 DocType 未开启 `allow_import` | 原来无列表 Import，也不出现在 Data Import 向导 | 在 DocType 元数据增加 `allow_import=1`；迁移补丁同步 | 已补入口 |
| 实时库存、供应商回顾、汇总计算、各项指标汇总或看板 | 只读报表 | 仅报表/看板查看入口 | 保持不可导入，避免把计算结果倒灌为业务事实 | 无导入入口（符合设计） |

补齐后的使用方式：从“借出清单/借回清单”列表进入 Import，选择对应模板字段并上传 Excel；也可以在 `Data Import` 表单的“Excel 导入数据”入口选择对应业务表。成品状态不提供导入入口，由收货、库存凭证和样品流程维护。导入仍遵循 A/B/C 分级：允许使用系统安全默认值，缺失的可选字段可先保存 Draft，SN、物料、数量、日期和关键单据关联等事实字段不能猜测。

上线要求：执行 `bench --site aji_test.localhost migrate` 使迁移补丁生效，然后清理缓存并刷新 Desk。若用户仍看不到入口，依次检查角色的 Create/Write/Import 权限、目标列表权限和浏览器缓存；服务端 `get_import_tables` 返回 `importable=true` 才表示向导可用。

## 4. 可导入表单的字段与模板调整

### 4.1 客户清单 -> Customer

表单位置为 Customer 基础信息区/联系人地址区。字段映射：

| Excel 字段 | 系统字段 | 位置 | 处理 |
|---|---|---|---|
| 客户编号 | `custom_customer_code` | 客户列表/基础信息 | 复用，自定义唯一编码 |
| 客户名称 | `customer_name` | 基础信息 | 复用，作为主名称 |
| 联系人 | `custom_excel_contact_name` | 详情，联系人关联旁 | 复用原始文本；后续可生成 Contact |
| 联系电话 | `custom_excel_contact_phone` | 详情 | 复用原始文本；正式手机号由 Contact 维护 |
| 地址 | `custom_excel_address` | 详情/地址关联旁 | 复用原始地址文本；正式 Address 另建 |
| 负责业务 | `custom_responsible_business_name` | 列表 | 复用原始业务员名称；有 Sales Person 主数据后再关联 `custom_responsible_sales_person` |

模板调整：补充客户类型、客户组、区域的默认值；去掉空白列和公式列；客户编号保持文本格式，避免 `AC001` 被转成数字。导入顺序为 Customer -> Contact -> Address -> 业务单据。

### 4.6 安全库存参数 -> Item 的 `reorder_levels`

目标为 Item 详情的“仓库补货参数”子表，而不是新建独立库存余额。

| Excel 字段 | 系统字段 | 位置 | 处理 |
|---|---|---|---|
| 物料编码 | `item_code` | Item 列表/关联键 | 复用，必须已存在 |
| 物料名称 | `item_name` | 基础信息 | 仅校验，不覆盖主数据 |
| 物料类型 | `item_group` | 基础信息 | 仅在新物料维护时使用 |
| 最低安全库存 | `warehouse_reorder_level` | `reorder_levels` 子表 | 复用 |
| 安全库存预警线 | `warehouse_reorder_qty` 或新增明确字段 | `reorder_levels` 子表 | 需业务确认“预警线”与“补货量”的含义，不能直接混填 |

### 4.20 导入后人工修正清单

每批导入结束后，系统应生成“默认值与待补字段”视图，至少包含：源文件、工作表、Excel 行号、单据名称、字段、导入值、默认来源、建议修正人、修正状态。优先人工修正以下内容：

1. 客户/供应商 Contact、Address、负责人和正式付款条件；
2. Item 分类、UOM、内部/外部型号、版本、适用机种和工程图纸；
3. 销售/采购订单的税费、仓库、交货计划和业务员；
4. 收付款的银行流水号、发票关联和核销对象；
5. 库存事务的源/目标仓、工单、BOM、批次/SN；
6. 样品/成品的 SN、客户、去向、归还日期和真实状态；
7. 固定资产类别、折旧方法、部门、保管人和原值凭证。

对 B 级字段，允许单据先保持 Draft；对 C 级字段，必须在人工补齐后才允许 Submit、影响库存或生成财务核销。

## 5. 不允许导入的报表文件

### 5.1 实时库存

`实时库存.xlsx` 的“初期、总入库、总出库、实时库存、总值”是库存流水/估值计算结果。目标是现有 Realtime Inventory 报表，不是 Item 或 Stock Entry。若要初始化库存，必须另做期初 Stock Reconciliation/Stock Entry，并经过仓库、批次、SN 和估值确认，不能把报表原样导入。

### 5.2 供应商回顾

“采购订单总数、按时到货订单数、到货及时率、延迟订单数、平均延迟天数、供应商评级”均由采购订单和收货日期计算。目标是供应商绩效报表；评级如需落库，应通过 Supplier Rating Record 流程生成，不能将 Excel 评级覆盖供应商主数据。

### 5.3 汇总计算和各项指标汇总/看板

这些文件包含跨销售、库存、样品、在制品的汇总和公式区。它们只能作为口径核对、历史快照或报表验收数据。导入事实单据后重新计算，不允许反向写入销售订单、库存或收款单。

## 6. 推荐导入顺序与依赖清单

### 6.1 推荐顺序

1. 先确认站点已有 Company、Currency、默认客户组/供应商组/物料组、默认账户和各类 Warehouse；缺少时先建立默认值，不要求把所有辅助字段补到 Excel；
2. 先导入 Customer、Supplier、Payment Terms Template、Project、Item；联系人、地址、负责人等 B 级字段随后人工补；
3. 导入 Item 的安全库存 `reorder_levels`，仓库缺失时使用已配置的默认仓库并生成待补清单；
4. 导入 Sales Order、Purchase Order，允许使用 Company、Currency、Order Type、仓库和付款条件默认值；
5. 导入 Purchase Receipt、Stock Entry、Delivery Note。涉及仓库方向、采购/销售订单行无法唯一关联的行不创建正式单据，转待处理清单；
6. 导入 Payment Entry 收款/付款。账户可以使用 Company 默认账户，但金额、日期和核销对象不得默认；
7. 导入 Sample Loan Out/In、Asset、Timesheet；Finished Goods Status 不导入，先由收货/库存/样品流程生成后再与 Excel 快照核对；允许 Draft 和 B 级待补状态，C 级事实缺失行暂停；
8. 人工修正默认值和待补字段后，再按业务需要 Submit；最后重算并核对实时库存、供应商回顾、汇总和看板。

### 6.2 依赖清单

- A 级默认值必须在站点中存在且名称唯一；不存在时不能硬编码，需进入默认值配置清单；
- Excel 中提供的 Customer、Supplier、Item、项目编号和外部单号必须唯一；无法唯一匹配的 Link 仍按 C 级阻断；
- 销售、采购和收付款可以先使用默认公司、币种和账户，但税费、交易金额、交易日期仍需使用 Excel 事实或人工补齐；
- 库存事务可以先使用按类型配置的默认仓库，但库存方向、数量、批次/SN 和库存类型必须明确；
- 收款/付款可以先保存 Draft，但正式核销必须有 Sales Invoice/Purchase Invoice，或业务明确允许核销到订单；
- 样品和成品状态可以先保存 Draft，但 Item、数量策略和状态来源必须可追溯；
- 固定资产可以先保存 Draft 并使用默认公司/数量，正式折旧前仍需 Asset Category、折旧方法、部门和保管人；
- 工时可以先保存 Draft，但 Employee、日期时间和 Project/Work Order 是计算人工成本前的必填事实；
- 导入用户需有相应 DocType 的 Create/Import 权限；Submit 权限只在人工修正后使用；
- 正式导入前必须在测试站点生成预览、默认值清单、待补清单、错误行和重复键检查。

## 7. 风险点清单与解决方案

| 风险点 | 影响 | 解决方案 |
|---|---|---|
| Excel 使用名称而非 Link 编码 | 关联失败或关联到错误对象 | 客户组/供应商组/仓库等可用默认值；客户、供应商、物料和单据关联仍要求唯一编码，失败转待处理 |
| 公式列导入 | 把过期计算结果写成事实 | 删除公式列，改由系统计算；公式值仅用于验收 |
| 总模板与独立文件表头不一致 | 字段错位 | 统一以 `excel_import_tables.json` 和字段字典为准，生成标准模板 |
| 销售订单/采购订单一行多明细未分组 | 创建重复主单 | 使用“主单外部编号 + 明细行号”分组 |
| 宽表交货1至交货7 | 无法直接映射标准子表 | 转换为交货计划子表，一批交货一行 |
| 发票和收款混在送货/回款表 | 财务状态不一致 | 发票单独导入 Sales Invoice/Purchase Invoice，Payment Entry 只做收付款 |
| 负数入库或正负说明混用 | 库存方向错误 | 按 Stock Entry 类型明确源/目标仓库和数量方向 |
| 空 SN 或型号无法唯一匹配 | 成品状态无法追踪 | 预览阶段阻断，要求补 SN/Item 编码 |
| 安全库存预警线与补货量含义不清 | 产生错误采购建议 | 增加独立预警线字段或业务确认字段语义 |
| 资产折旧金额直接导入 | 折旧计划和总账不一致 | 只导入原值、折旧方法、年限，系统生成计划 |
| 样品状态覆盖事实记录 | 借出/归还历史丢失 | 用借出单和归还单记录流转，状态只读计算 |
| 并发导入同一单据/物料 | 重复单据或库存重复 | 外部单号唯一约束，导入前后再次查重，失败整批回滚 |
| 默认值未被业务识别 | 后续人员误以为是 Excel 原始事实 | 导入日志记录默认来源，并提供“系统默认/待补”筛选和人工修正视图 |
| 历史日期、金额、编码格式混杂 | 日期解析、金额精度错误 | 统一日期格式、币种和数字格式，编码列设为文本 |

## 8. 导入前需要复测的场景

1. 每个可导入文件的空行、重复编码、重复外部单号和 Link 不存在场景；
2. 销售订单/采购订单多明细分组，以及同一订单多次交货；
3. 采购收货、送货、库存领料/退料/补料的库存方向和数量；
4. 收款/付款核销到发票、订单和未核销余额的状态；
5. 产品字段的总模板/独立文件表头差异，尤其产品首列 `No` 与 `Product name`；
6. 客户/供应商联系人、电话和地址是否生成正确关联记录；
7. 安全库存预警线、最高库存和建议补货量在报表中的计算；
8. 成品状态的 SN、空 SN 行、客户借出和销售状态流转；
9. 样品借出/借回/归还单对数量和逾期状态的影响；
10. 固定资产折旧计划、资产状态和会计凭证；
11. 工时起止时间、总工时、项目/工单关联及人工成本；
12. 默认公司、仓库、账户、UOM 不存在时是否正确转待处理；
13. B 级字段缺失时是否能保存 Draft、人工修正后再 Submit；
14. 无权限用户、重复导入、导入中刷新页面和失败回滚；
15. 桌面端及移动端导入预览表横向滚动、长表头、错误提示和禁用按钮状态。

## 10. 本轮结论

本轮已按方案修改导入配置、样品业务表单入口元数据和展示字段注册表：Sample Loan Out、Sample Loan In 开启标准 Excel Import；样品推荐模板明确包含公司、客户/供应商、日期、SN/物料、数量和仓库等关键字段；物料编码、来源仓库、状态和归还数量等系统计算字段保持只读提示；Finished Goods Status、实时库存、供应商回顾、汇总和看板继续禁止导入。没有上传目录中的真实 Excel，没有创建业务单据、库存变更或收付款。

Playwright 临时模拟页面验证通过导入入口、模板字段、上传预览、后台反馈和移动端布局。真实站点部署后必须执行 `bench --site aji_test.localhost migrate`、清理缓存并按第 8 节复测真实权限、默认值、Link 关联、Draft 保存和失败回滚；A 级字段才允许使用站点默认值，B 级字段可先保存 Draft，C 级事实字段缺失必须进入待处理清单。
