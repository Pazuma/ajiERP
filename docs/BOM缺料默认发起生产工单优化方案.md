# BOM 缺料默认发起生产工单优化方案

日期：2026-10-15  
状态：已于 2026-10-15 实施  
范围：分层组装生产工单的生产领料缺料弹窗

## 1. 背景与目标

当前“生产领料缺料处理”弹窗已经支持逐行选择：存在有效子 BOM 的物料可勾选“发起生产工单”，未勾选则为该物料本身创建采购申请；没有有效子 BOM 的物料固定走采购申请。

实际业务中，少数半成品缺料时应优先自制，大部分半成品及原材料应优先采购。每次由用户手工勾选，容易漏选或选错。

本方案在**子 BOM 本身**增加一个默认配置：`缺料时默认发起生产工单`。当该 BOM 作为上级 BOM 的组件子 BOM，且上级生产工单领料发现该物料短缺时，系统仅据此预勾选现有弹窗的“发起生产工单”复选框。用户仍可在弹窗内最终修改选择。

目标：

- 少数自制半成品在缺料弹窗中自动预勾选“发起生产工单”。
- 未配置或未勾选的半成品默认不勾选，确认后仍走现有采购申请流程。
- 原材料、无有效子 BOM 的物料继续默认采购，不能被错误地默认自制。
- 不改变现有缺口计算、库存记账、采购申请创建、子工单创建、已安排防重和权限校验。
- 不修改 ERPNext 核心代码，不改变旧接口契约，优先增加独立字段、读取接口与前端分支。

## 2. 设计结论

### 2.1 配置归属

配置应放在**半成品自身的 BOM 版本**，而不是放在 Item、成品 BOM 或生产工单上。

理由：

- 缺料时要不要自产，取决于该半成品的制造方案；同一成品下的不同半成品可以有不同默认策略。
- 当前缺料逻辑已经优先取成品 BOM 组件行指定的 `bom_no`，从而锁定具体子 BOM 版本。配置随该版本读取，避免新旧版本互相覆盖。
- BOM 更新版本时，`frappe.copy_doc` 会复制这个普通配置字段；历史 BOM、已提交工单和已生成补料单据仍保留原配置及原引用，不被回写。
- Item 层的 `custom_supply_mode` 继续用于“是否有采购/自制资格”的基础校验，不承担本次“弹窗默认值”的职责。

### 2.2 字段定义

在 `BOM` 增加自定义字段：

| 属性 | 方案 |
| --- | --- |
| 字段名 | `custom_default_create_work_order_on_shortage` |
| 中文标签 | 缺料时默认发起生产工单 |
| 类型 | `Check` |
| 默认值 | `0`（不勾选） |
| 所属单据 | BOM |
| 维护时机 | 新建 BOM 草稿或“更新版本”生成的 BOM 草稿 |
| 生效对象 | 已提交、已启用，且被缺料组件实际关联的子 BOM |
| 版本策略 | 字段随 BOM 版本复制；修改已启用版本时须走既有“更新版本”流程 |

字段放在 BOM 的“生产物料”表头区域，位于“数量 / 计量单位”之后，独占一行：

```text
┌────────────────────────────────────────────────────┐
│ 数量                         计量单位               │
│ [ 1                       ]  [ 个                ] │
│ ☑ 缺料时默认发起生产工单                            │
└────────────────────────────────────────────────────┘
```

字段只表达**默认值**，不代表强制自产，也不在勾选瞬间创建任何单据。

## 3. 弹窗预期效果

维持现有列、现有按钮和现有确认入口，仅调整“补料选择”列的初始选中状态。

```text
生产领料缺料处理
来源工单：MFG-WO-2026-00062。勾选创建子工单；未勾选采购该物料本身。

┌──────────┬──────┬──────┬──────┬──────┬──────────────────┬────────────────────┐
│ 物料     │ 本次需求 │ 可用库存 │ 缺口 │ 待安排 │ 补料选择         │ 子 BOM / 供应方式   │
├──────────┼──────┼──────┼──────┼──────┼──────────────────┼────────────────────┤
│ 半成品 B │ 10   │ 5    │ 5    │ 5    │ ☑ 发起生产工单   │ BOM-B；默认自制     │
│ 半成品 C │ 20   │ 0    │ 20   │ 20   │ ☐ 发起生产工单   │ BOM-C；默认采购     │
│ 原材料 D │ 50   │ 0    │ 50   │ 50   │ 采购申请          │ —；无子 BOM         │
└──────────┴──────┴──────┴──────┴──────┴──────────────────┴────────────────────┘

                                                   [确认并发起补料]
```

展示及默认规则：

| 缺料行情况 | 弹窗展示 | 初始状态 | 确认后的默认结果 |
| --- | --- | --- | --- |
| 存在有效子 BOM，字段为 `1` | “发起生产工单”复选框 | 勾选 | 创建子生产工单草稿 |
| 存在有效子 BOM，字段为 `0` | “发起生产工单”复选框 | 不勾选 | 创建采购申请草稿 |
| 没有有效子 BOM | “采购申请”文本 | 不可勾选 | 创建采购申请草稿 |
| 待安排数量为 0 | 复选框禁用 | 不产生新选择 | 不创建新单据，仅展示已有安排 |

用户可在确认前按行手动勾选或取消勾选：用户的最终勾选状态优先于 BOM 默认配置。

## 4. 实际业务流程

```text
维护半成品 BOM 草稿
    │
    ├─ 勾选“缺料时默认发起生产工单” → 该 BOM 版本默认自制
    └─ 不勾选                         → 该 BOM 版本默认采购
    │
保存并启用 BOM 版本
    │
成品生产工单开始 → 创建生产领料单 → 检查发料仓可用库存
    │
    ├─ 库存充足 → 按标准流程提交领料
    │
    └─ 库存不足 → 计算缺口、扣除已安排未完成补料
                      │
                      ├─ 找到组件行指定的有效子 BOM
                      │      │
                      │      ├─ BOM 配置为默认自制 → 弹窗预勾选
                      │      └─ BOM 未配置          → 弹窗默认不勾选
                      │
                      └─ 无有效子 BOM → 固定采购
    │
用户检查/修改每行复选框 → 点击“确认并发起补料”
    │
    ├─ 勾选 → 创建关联的子生产工单草稿
    │           → 子工单领料、生产、完工入库
    │           → 半成品库存进入主工单发料仓后重新领料
    │
    └─ 未勾选 → 创建该缺料物料的采购申请草稿
                → 采购订单、收货质检、正式入库
                → 到货入库后主工单重新领料
```

## 5. 调用链路

### 5.1 现有写入链路（保持不变）

```text
Stock Entry 生产领料提交前校验
  → stock_entry_shortage_dialog.js
  → window.akivision_layered_shortage(...)
  → layered_manufacturing.get_shortage_details(entry)
  → layered_shortage_dialog.js 渲染缺料列表
  → layered_manufacturing.allocate_direct_component_shortage(entry, decisions)
      → _shortages() 重算缺口与待安排数
      → 勾选：_allocate_shortage(... manufacture_qty=缺口)
      → 未勾选：_allocate_shortage(... purchase_qty=缺口)
      → 创建 Work Order 或 Material Request 草稿
      → 创建 Layered Supply Allocation 防重关联
```

### 5.2 本次新增的默认值读取分支

```text
layered_shortage_dialog.js 已得到 get_shortage_details() 的缺料行
  → 新增 get_direct_component_shortage_defaults(entry)
      → 复用 _entry() 和 _shortages()，服务端重新识别实际有效子 BOM
      → 读取 BOM.custom_default_create_work_order_on_shortage
      → 返回 { item_code + warehouse: default_create_work_order } 映射
  → 仅对“有有效子 BOM”的复选框设置 checked 初始值
  → 用户手动修改后，沿用原 decisions 提交
```

新增读取接口不接收前端传入的 BOM 编号、默认值或缺口数量；所有 BOM 识别仍以服务端 `_shortages()` 的结果为准。

## 7. 小增量与兼容策略

1. 不修改 ERPNext 标准 Doctype、标准库存接口或库存台账；库存变化继续只通过标准 Stock Entry、Purchase Receipt 等单据发生。
2. 不改变现有 `get_shortage_details(entry)` 结构，避免影响已有缺料弹窗、测试脚本或其他调用方。
3. 不改变现有 `allocate_direct_component_shortage(entry, decisions)`。它继续把复选框的最终布尔值作为采购/自产的唯一写入决策。
4. 新增接口只读、无写入，且服务端重新计算缺料和有效子 BOM；读取失败时前端安全回退为“不勾选”，即原有默认采购行为。
5. 新字段默认 `0`，已存在的 BOM、历史工单、历史库存单和已安排补料均不迁移、不回填、不改变默认结果。
6. 前端只在 `direct_component_supply` 分支启用该默认行为；普通工单及旧缺料采购弹窗维持原样。
7. 组件行有明确 `bom_no` 时优先读取该具体版本；没有明确子 BOM 时才沿现有逻辑读取物料当前有效默认 BOM，不引入新的 BOM 自动选择规则。

## 8. 权限、校验与异常边界

- 配置字段遵循 BOM 表单的现有写入权限；已启用 BOM 的变更通过现有“更新版本”流程完成。
- 默认值读取仅在工单、领料单、分层模式、公司和有效子 BOM 已通过现有校验后执行。
- 弹窗预勾选不绕过权限：用户最终勾选自产时，现有接口仍检查 Work Order 创建权限、BOM 读取权限、BOM 公司一致性；未勾选采购时仍检查 Material Request 创建权限和采购许可。
- 若子 BOM 已停用、取消、公司不一致或组件关联发生变化，服务端返回不可自产/默认不勾选；确认时按现有错误信息阻止错误创建。
- 若同一物料关联多个子 BOM，继续沿用现有“请先明确生产版本”校验，不自行选择其中一个默认值。
- 若已有未完成采购申请或子工单，继续沿用 `Layered Supply Allocation` 的防重逻辑；默认勾选不能切换已安排方式或额外创建全额补料。
- 用户取消弹窗、关闭弹窗或仅切换复选框均不写入 BOM、工单、采购申请或库存。

## 9. 受影响模块

| 模块 | 影响 | 处理方式 |
| --- | --- | --- |
| BOM / BOM 版本 | 新增一个版本化的默认策略字段 | 草稿维护，更新版本时复制；历史版本保持原值 |
| 成品生产工单 | 只在缺料弹窗初始状态上体现 | 不修改 `required_items`、工单状态或工单数量 |
| 子生产工单 | 勾选后沿用现有创建链路 | 保留父/根工单关联、BOM 版本、仓库与草稿状态 |
| 生产领料 / 库存 | 仍按现有缺口、可用库存、预留和待安排量计算 | 不直接增减库存，不自动提交原领料单 |
| 采购申请 / 采购订单 / 质检入库 | 未勾选时沿现有缺料采购申请创建 | 不改采购审批、质检、正式入库和付款流程 |
| 成本核算 | 无新增直接记账 | 子工单完工入库或采购正式入库后，沿现有库存价值进入主工单 |
| 普通工单、销售、其他库存单 | 不在本方案范围 | 不加载/不触发本新增默认分支 |

## 10. 验收用例与预期结果

1. 子 BOM-B 已启用且字段勾选，主工单缺少 B：弹窗中 B 的“发起生产工单”默认勾选；直接确认后只创建 B 的子生产工单草稿。
2. 子 BOM-C 已启用但字段未勾选，主工单缺少 C：弹窗默认不勾选；直接确认后只创建 C 的采购申请草稿。
3. 用户取消 B 的默认勾选：确认后创建 B 的采购申请，不创建子工单。
4. 用户勾选 C：确认后创建 C 的子工单，不创建采购申请；仍须满足现有 BOM、权限和公司校验。
5. 原材料 D 无有效子 BOM：显示“采购申请”而非复选框，确认后创建采购申请。
6. 当前组件行指定 BOM-B-V1，物料默认 BOM 已切换为 BOM-B-V2：缺料默认值必须读取 V1，确保已关联生产结构不被新版本改写。
7. BOM-B 更新出 V2 并勾选字段，后续新工单引用 V2：弹窗按 V2 预勾选；引用 V1 的旧工单保持 V1 的默认策略。
8. 缺口已有待完成采购/自产安排：再次打开弹窗不重复创建补料单据，不能用默认值绕过既有方式锁定。
9. 多用户同时确认相同缺口：沿用现有行锁和补料记录，仅允许一个有效补料安排。
10. 普通非分层工单、非生产领料库存单、采购收货、生产入库：页面和业务结果无变化。

## 11. 实施顺序与回退

实施顺序：

1. 新增 BOM 字段和表头布局，确认草稿可维护、版本复制正确、已提交版本不可直接篡改。
2. 实现并单测只读默认值接口，验证按组件实际引用 BOM 读取，而非信任前端数据。
3. 在缺料弹窗增加预勾选分支，执行 JavaScript 语法检查和现有分层缺料回归测试。
4. 用测试公司完成“主工单 → 缺料 → 自制/采购 → 入库 → 再领料”的全链路人工验收。
5. 仅在目标公司启用并观察新生成工单；已有补料单据和历史工单不做批量迁移。

回退方式：隐藏/停用前端默认值读取分支，或将 BOM 字段全部保持为 `0`。已经创建的 BOM 字段、子工单、采购申请、补料关联和库存流水均不删除；其后续处理仍按标准取消、停止、入库流程执行。

## 12. 非目标

- 不把采购/自制决策永久写回 Work Order `required_items`。
- 不在勾选 BOM 配置时自动创建工单、采购申请或预留库存。
- 不自动拆分缺口为部分自产、部分采购；现有直接组件模式保持“每一行确认时二选一”。
- 不改变物料的采购许可、自制许可或 `custom_supply_mode` 维护规则。
- 不自动将半成品产出直接视为主工单可用库存；子生产仍须按既有流程完成正式入库。
