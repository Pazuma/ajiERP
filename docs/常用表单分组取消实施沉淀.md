# 常用表单分组取消实施沉淀

## 1. 实施结论

已根据《常用表单分组取消实施方案》完成侧边栏同步逻辑调整：高频表单不再放在“常用表单”分组内，而是直接显示在所属模块侧边栏顶部；低频表单继续集中到唯一的“其他表单”分组。

本次调整只影响 Workspace Sidebar 导航元数据，不修改 DocType、业务数据、字段、权限、工作流、导入配置或表单路由。

## 2. 实际修改

| 文件 | 修改内容 |
| --- | --- |
| `client_akivision/utils/other_forms_sidebar.py` | 移除旧“常用表单”分组创建逻辑；将配置中的 `common_links` 作为顶部直接链接；保留“其他表单”创建、去重和排序；兼容清理旧分组；删除 Sidebar 子项时绕过无必要的动态链接队列 |
| `client_akivision/config/other_forms_sidebar.json` | 将 Selling 的“物料”补充为高频根层直链，避免旧分组因该入口而被保留 |
| `docs/playwright_other_forms_sidebar_ui.mjs` | 更新测试夹具和断言，验证顶部直链、无“常用表单”、低频收纳和移动端布局 |
| `docs/playwright_other_forms_sidebar_result.json` | 保存本轮 Chromium 验证结果 |
| `docs/playwright_other_forms_sidebar.png` | 保存桌面/移动模拟截图 |

配置文件 `client_akivision/config/other_forms_sidebar.json` 沿用现有 `common_links` 清单，避免重新维护入口名称和 DocType 映射。

## 3. 数据流

```text
bench migrate
  -> after_migrate 调用 sync_other_forms_sidebar_entries
  -> 读取 other_forms_sidebar.json
  -> 选择实际存在的 Workspace Sidebar
  -> 按 link_type + link_to 查找/创建高频入口和低频入口
  -> 去除目标链接重复项
  -> 清理没有未声明用户链接的旧“常用表单” Section Break
  -> 将 common_links 移到模块根层顶部
  -> 将低频 links 放到唯一“其他表单”分组
  -> 稳定重排 idx、清理 bootinfo 和 Desk 缓存
  -> 用户重新登录后直接点击高频表单
```

点击入口时仍由 Frappe 原生路由和权限系统处理。`sidebar_icons.js` 继续在前端渲染侧注入 Lucide 图标，不写入 Workspace Sidebar Item 的业务配置。

## 4. 依赖清单

- Frappe `Workspace Sidebar`、`Workspace Sidebar Item` DocType。
- `client_akivision/hooks.py` 中的 `after_migrate` 同步钩子。
- `client_akivision/config/other_forms_sidebar.json` 导航配置。
- 目标 DocType 元数据，用于判断 DocType 是否存在。
- 当前用户对 Workspace 和目标 DocType 的权限过滤。
- Frappe bootinfo/Desk 缓存清理机制。
- 前端 `sidebar_icons.js` 和 Frappe 内置 Lucide sprite。
- 真实站点迁移所需的 bench、数据库和缓存服务。

## 5. 安全与幂等处理

1. 高频、低频入口按 `link_type + link_to` 去重，不按显示名称去重。
2. 不存在的 DocType 只记录 warning，不阻断其他模块迁移。
3. 旧“常用表单”分组只有在其中不含未声明的 `child=1` 链接时才删除；位于标题后的根层链接不阻止标题清理。
4. 如果旧分组含有用户自定义或未声明链接，则保留该分组并记录 warning，避免误删用户入口。
5. 高频入口标签按配置同步，路由仍使用原始 `link_to`。
6. 重复执行 migrate 不创建第二个“其他表单”、第二份高频入口或顺序漂移。

## 6. 风险点清单

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 旧“常用表单”中有用户自定义链接 | 误删个性化入口 | 发现未声明链接时保留分组并记录 warning |
| 高频链接在旧分组和根层重复 | 用户看到重复菜单 | 同步器按 `link_type + link_to` 删除重复项 |
| 配置中的 DocType 在当前站点不存在 | 迁移异常或空链接 | 跳过不存在目标并输出 warning |
| 高频入口过多导致侧边栏首屏变长 | 顶部信息密度上升 | 只提升 `common_links` 声明的核心入口，低频入口仍收纳 |
| 缓存未刷新 | 用户看不到新结构 | migrate 后删除 bootinfo 并 clear cache，重新登录 |
| 权限过滤差异 | 不同账号看到的入口数量不同 | 以真实角色权限过滤结果为准分别验收 |
| 移动端中文标签过长 | 图标或文字重叠 | 使用 390px 视口检查侧边栏滚动和换行 |

## 7. 问题记录与解决方案

### 7.1 Playwright 首轮断言失败

- 现象：测试查找英文 `Sales Order`，实际配置标签为中文 `销售订单`；模拟数据也未包含 `Sales Order Analysis` 报表。
- 原因：测试夹具仍沿用“常用表单”旧实现中的英文标签和旧数据结构。
- 解决：将高频入口模拟为根层直链，使用配置中的中文标签，并补充报表模拟项。
- 结果：修正后 3 项 Playwright 检查全部通过。

### 7.2 用户自定义分组保护

- 风险：直接删除所有“常用表单”标题可能连带删除用户自行添加的链接。
- 解决：同步器检查分组下的链接目标；存在未声明链接时保留分组并输出 warning，仅清理完全由本方案声明的旧分组。

### 7.3 真实测试站迁移阻断

- 现象：`bench --site aji_test.localhost migrate` 在其他应用的 `deeplinkerp_branding` `after_migrate` 钩子处失败。
- 原因：该钩子删除旧 Workspace 时尝试排队动态链接清理，当前站点队列已有 600 个任务，触发 `QueueOverloaded`；不是本次侧边栏同步器报错。
- 解决：在测试站单独执行 `client_akivision.utils.other_forms_sidebar.sync_other_forms_sidebar_entries`，并将本同步器删除 Sidebar 子项的操作改为 `frappe.db.delete`，避免导航元数据迁移依赖后台队列。业务数据未删除。
- 后续：清理或完成积压队列后，仍需重新执行完整 `bench migrate`，确认其他应用的迁移钩子也成功。

### 7.4 真实站点复核结果

在 `aji_test.localhost` 执行同步函数和 `clear-cache` 后复核数据库：
