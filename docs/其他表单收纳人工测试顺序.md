# 模块“其他表单”收纳人工测试顺序

## 1. 测试目的

确认“其他表单”导航收纳实施后：

- 各业务模块最多只有一个“其他表单”分组。
- 各核心业务模块的客户日常使用的主数据和主交易入口直接显示在模块侧边栏顶部，不需要展开“常用表单”。
- 高频直链和其他表单中的业务入口显示与业务含义匹配的图标，图标与文字垂直对齐且不遮挡。
- 低频辅助表单出现在所属模块的“其他表单”中。
- Excel 主流程、主交易、报表、设置和子表没有被误收纳。
- 收纳后的表单仍可正常打开、保存、提交和查看关联记录。
- 原有权限、路由、导入配置、收藏和用户自定义菜单不受影响。
- 桌面端、移动端、中英文界面均无明显布局或使用问题。

本文件用于真实 Frappe 站点人工验收。Playwright 模拟导航只用于快速验证结构，不能替代真实站点迁移和权限测试。

## 2. 测试准备

### 2.1 环境准备

1. 使用测试站点，不要直接在生产环境执行回滚或删除操作。
2. 记录站点名称、公司、执行人、执行时间、代码版本和数据库备份点。
3. 部署代码后执行：

```bash
bench --site <site> migrate
bench --site <site> clear-cache
```

4. 退出 Desk 后重新登录，避免旧的 bootinfo/sidebar 缓存影响判断。
5. 准备 Chrome 或 Edge 桌面窗口，以及 390px 移动模拟视口。

### 2.2 测试账号

| 账号 | 用途 |
| --- | --- |
| System Manager | 查看全部工作区和收纳入口 |
| Sales User/Manager | Selling 权限和销售表单验证 |
| Purchase User/Manager | Buying 权限和采购表单验证 |
| Stock User/Manager | Stock 权限和库存表单验证 |
| Accounts User/Manager | Accounts/KPI 规则入口验证 |
| Manufacturing User/Manager | Manufacturing 工程图纸和工艺入口验证 |
| Projects User | Projects 入口验证 |
| 无对应模块权限账号 | 菜单过滤和直接访问拒绝验证 |

### 2.3 迁移前快照

迁移前保存以下信息，用于回归和回滚对比：

- 各 Workspace Sidebar 的分组名称、链接名称、`link_type`、`link_to`、`idx`。
- 用户自定义的 Sidebar 链接、收藏和快捷入口。
- Excel 导入表清单及 `module`、`doctype`、`importable`、默认字段。
- 需要抽查的 DocType 模块属性、角色权限和路由。

### 2.4 本次重点检查

本次除了检查低频表单是否收纳，还要检查高频入口是否被拎出并集中显示：

| 模块 | 高频直链重点入口 |
| --- | --- |
| Selling | 客户、报价单、销售订单、送货单、销售发票、物料、物料价格 |
| Buying | 供应商、采购申请、询价单、供应商报价、采购订单、采购收货、采购发票 |
| Stock | 物料、物料组、仓库、单位、库存凭证、采购入库、销售出库 |
| Projects | 项目、任务、工时表、活动类型 |
| Manufacturing | 物料清单、生产工单、工序作业卡、库存凭证 |
| Assets | 固定资产、资产类别、位置 |

## 3. 执行顺序

### 第 1 步：迁移和入口检查

操作：

1. 执行 `migrate` 和 `clear-cache`。
2. 使用 System Manager 登录 Desk。
3. 依次打开 Selling、Buying、Stock、Accounts/KPI Dashboard、Projects、Manufacturing、Assets。

预期：

- 迁移完成，无 `ERROR`；不存在的可选 DocType 只产生 warning。
- 各工作区可以正常打开，无白屏和 JS 错误。
- 其他表单分组出现于业务入口之后、报表或设置入口之前。
- 每个模块最多出现一个“其他表单”。

### 第 2 步：收纳分组唯一性和重复链接检查

操作：

1. 在每个模块展开“其他表单”。
2. 记录分组内所有链接。
3. 在同一模块的其他分组中搜索相同 DocType。
4. 重新执行一次 `migrate`，清缓存并再次检查。

预期：

- 每个模块最多一个“其他表单”。
- 收纳链接在原分组不再重复出现。
- 重复执行迁移不会增加第二个分组或重复链接。
- 未声明的用户自定义链接不被删除或整体重排。

同时检查高频直链：

- 每个核心模块不应再显示“常用表单”分组。
- 表格中的高频入口直接出现在模块侧边栏顶部，且同一模块内不重复出现。
- 高频直链位于模块入口之后、业务分组之前；“其他表单”位于业务分组之后、报表/设置之前。
- 抽查物料、物料组、仓库、单位、库存凭证，确认分别显示物料、层级、仓库、标尺、清单类图标；低频表单至少显示通用表单图标。

重点抽查：`Blanket Order`、`Purchase Comparison`、`Product Bundle`、`Engineering Drawing`、`Asset Maintenance`、`KPI Target`、`Aging Period Rule`。

### 第 3 步：主流程入口保留检查

操作：

在各模块确认以下入口仍在原主流程或专项分组：

| 模块 | 必须保留的入口 |
| --- | --- |
| Selling | Customer、Quotation、Sales Order、Delivery Note、Sales Invoice |
| Buying | Supplier、Material Request、Purchase Order、Purchase Receipt、Purchase Invoice |
| Stock | Item、Warehouse、Material Request、Stock Entry、Stock Reconciliation、Purchase Receipt、Delivery Note |
| Accounts | Payment Entry、Sales Invoice、Purchase Invoice、Account、Company、Mode of Payment |
| Projects | Project、Task、Timesheet、Activity Type |
| Manufacturing | BOM、Work Order、Job Card、Stock Entry |
| Assets | Asset、Asset Category、Location |

预期：

- 主流程入口仍然容易找到，没有被隐藏到“其他表单”。
- Excel 对应表单没有被移动到“其他表单”。
- 报表、看板、趋势图和只读统计入口仍位于 Reports/Financial Reports/KPI Dashboard。
- Settings、系统单例、权限入口和子表没有被当作普通表单收纳。
- 高频入口虽然提升到侧边栏根层，仍属于原模块，不得被移动到其他模块或改变 URL。
- 图标仅来自 Frappe 内置 Lucide 图标，不应加载外部图片或改变入口路由。

### 第 4 步：收纳表单打开和基础操作

按模块抽查以下表单：

| 模块 | 抽查表单 |
| --- | --- |
| Selling | Blanket Order、Sales Partner、Sales Person、Campaign、Pricing Rule |
| Buying | Purchase Comparison、Supplier Quote Import、Purchase Delay Risk Rule、Misc Purchase Invoice Request |
| Stock | Product Bundle、Item Alternative、Quality Inspection、Serial No、Batch |
| Accounts/KPI | Payment Request、Budget、Bank、KPI Target、Aging Period Rule |
| Projects | Project Template、Project Type、Project Update、Activity Cost |
| Manufacturing | Workstation、Operation、Routing、Engineering Drawing、Engineering Drawing Settings |
| Assets | Asset Movement、Asset Maintenance、Asset Value Adjustment、Asset Repair |

对每个表单执行：

1. 点击菜单进入列表页。
2. 点击“新建”。
3. 填写最小合法字段并保存草稿。
4. 重新打开记录，检查字段值。
5. 对可提交单据执行提交；对有审批的单据验证审批动作。
6. 从关联记录或详情页返回原业务单据。

预期：

- 菜单链接路由正确，没有跳转到错误 DocType。
- 表单原有字段、校验、保存、提交、审批和关联逻辑不变。
- 收纳只改变入口位置，不改变业务对象行为。

### 第 5 步：权限和直接访问检查

操作：

1. 使用有权限账号打开收纳表单，验证查看、新建、编辑和提交权限。
2. 使用无权限账号重新登录，检查对应链接是否隐藏。
3. 使用无权限账号直接访问该 DocType URL。
4. 对 Accounts、KPI、采购规则等敏感配置重复测试。

预期：

- 有权限用户可以正常使用收纳表单。
- 无权限用户看不到链接，或只能看到 Frappe 按权限过滤后的结果。
- 直接访问不能绕过 Frappe 权限校验。
- 本次导航同步没有新增角色权限或导入权限。

### 第 6 步：Excel 导入回归

操作：

1. 打开 Excel 导入向导。
2. 核对工作表总数、模块、DocType 和导入开关。
3. 分别检查客户、供应商、销售订单、采购订单、物料、收付款、项目、工时、BOM、固定资产等入口。
4. 检查只读统计入口仍不可导入。
5. 使用一份测试模板执行一次预览，不提交正式业务数据。

预期：

- Excel 工作表数量和默认字段未变化。
- 主流程表单仍在原模块，不因导航收纳变成不可导入。
- 实时库存、汇总计算、供应商回顾等只读结果仍不可导入。
- 导入预览和字段校验正常。

### 第 7 步：多语言、缓存和重复迁移

操作：

1. 切换中文界面，确认分组显示为“其他表单”。
2. 切换英文界面，确认分组显示为“Other Forms”。
3. 清理缓存、重新登录，再次检查分组。
4. 连续执行两次 `migrate`，比较前后 Sidebar。

预期：

- 中英文界面各只有一个逻辑分组，不因标签翻译产生两个分组。
- 缓存刷新后菜单结构稳定。
- 重复迁移不增加分组、不增加链接、不改变未声明入口顺序。

### 第 8 步：移动端和视觉体验

操作：

1. 使用 1440px、1024px、768px 和 390px 视口检查。
2. 展开和收起“其他表单”。
3. 点击长名称入口，例如 `Misc Purchase Invoice Request`、`Engineering Drawing Settings`。
4. 检查触控区域、文字截断、滚动和返回行为。

预期：

- 页面无横向溢出。
- 分组标题、链接文字和箭头不重叠。
- 长名称不会遮挡相邻内容。
- 移动端可以展开、点击和返回，不出现无法操作的窄区域。

### 第 9 步：回滚演练

仅在测试站点执行。

操作：

1. 保存当前 Sidebar 快照。
2. 删除本方案新增的“其他表单”分组及其声明链接，或恢复迁移前快照。
3. 清理缓存并重新登录。
4. 检查业务表单、数据、权限和用户自定义链接。

预期：

- 只恢复菜单结构，不删除任何 DocType 或业务数据。
- 角色权限、路由、导入配置和列表视图不受影响。
- 回滚后可以再次执行迁移并恢复“其他表单”。

| 用例编号 | OFS-SELL-001 |
| 站点/代码版本 | 站点名、commit 或发布日期 |

发现问题时必须记录：

1. 问题现象和复现步骤。
2. 实际结果与预期结果。
3. 账号、角色、模块、浏览器和视口。
4. Console、服务器日志和迁移日志时间。
5. 根因判断、临时规避方案和代码/配置解决方案。
6. 修复后的复测结果。

## 5. 通过标准

- 迁移和缓存无错误，warning 均可解释。
- 各模块“其他表单”唯一，收纳链接唯一。
- 主流程、Excel 表单、报表、设置和子表位置符合方案。
- 至少一项收纳表单完成打开、保存、提交或审批回归。
- 有权限和无权限账号结果符合原授权。
- Excel 导入配置无变化。
- 中英文和 390px 移动端无明显布局问题。
- 所有失败项完成修复和复测后，才能标记人工验收通过。
