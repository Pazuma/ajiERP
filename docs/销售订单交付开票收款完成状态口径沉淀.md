# 销售订单交付、开票、收款与最终完成状态口径沉淀

## 1. 文档目的

本文记录销售订单从出库到收款结清的最终业务口径，解决“销售送货单完成后，客户还没有付款，但销售订单已经显示完成”的理解和展示问题。

本次只确认业务规则和后续实现边界，不修改前端、后端、数据库、权限或历史单据数据。

## 2. 已确认的业务结论

销售送货单提交只代表货物已经出库，不代表客户已经付款。

销售发票提交只代表已经形成应收，不代表客户已经付款。

销售订单只有同时满足以下条件，才算“最终完成”：

```text
销售订单全部交付
  + 订单应开票内容已经全部开票
  + 关联销售发票全部已付款
  = 销售订单最终完成
```

其中“全部已付款”以销售发票的标准付款状态为准，原则上要求：

```text
Sales Invoice.docstatus = 1
Sales Invoice.outstanding_amount <= 0
Sales Invoice.status = Paid
```

## 3. 三层业务状态

销售订单需要区分履约状态、开票状态和收款状态，不能把“已交货”直接显示为业务最终完成。

| 状态层 | 建议状态 | 主要判断依据 | 业务含义 |
|---|---|---|---|
| 交付状态 | 未交付、交付中、已交付 | `Sales Order Item.delivered_qty`、`per_delivered` | 货物是否已实际出库 |
| 开票状态 | 未开票、部分开票、已开票 | `per_billed`、关联 Sales Invoice | 是否已经形成完整应收 |
| 收款状态 | 未收款、部分收款、已付款 | Sales Invoice `status`、`outstanding_amount` | 发票是否已经收款结清 |
| 最终状态 | 未完成、已完成 | 三层状态综合判断 | 订单业务闭环是否完成 |

最终状态的推荐判断如下：

```text
final_completed =
    all_delivered
    AND all_invoiced
    AND all_invoices_paid
```

## 4. 状态流转

| 业务场景 | 交付状态 | 开票状态 | 收款状态 | 销售订单最终状态 |
|---|---|---|---|---|
| 尚未出库 | 未交付 | 未开票 | 无 | 未完成 |
| 已提交送货单，未开票 | 已交付 | 未开票 | 无 | 待开票 |
| 已开票但未收款 | 已交付 | 已开票 | 未付款 | 待收款 |
| 已收到部分款项 | 已交付 | 已开票 | 部分收款 | 部分收款 |
| 全部发票已付款 | 已交付 | 已开票 | 已付款 | 已完成 |
| 仅收销售订单订金，未核销发票 | 已交付或未交付 | 未开票或部分开票 | 预收未核销 | 未完成 |
| 多张发票中仍有一张未付款 | 已交付 | 已开票 | 部分收款 | 未完成 |

没有销售发票时，即使销售订单已经送货完成，也不能显示“最终完成”。

## 5. 单据关联和数据来源

判断订单是否已完成时，必须沿着单据关联链路获取数据，不能通过客户名称、金额或日期进行模糊匹配。

```text
Sales Order
  -> Sales Order Item
  -> Delivery Note Item.against_sales_order / so_detail
  -> Sales Invoice Item.sales_order 或 dn_detail
  -> Payment Entry Reference.reference_name = Sales Invoice
```

### 5.1 交付完成

- 只统计已提交的 Delivery Note（`docstatus = 1`）。
- 每一条有效销售订单明细的 `delivered_qty >= qty`，才算全部交付。
- 订单级可以辅助检查 `per_delivered >= 100`。
- 送货单草稿不扣减已交付数量，也不能作为交付完成事实。

### 5.2 开票完成

- 只统计已提交的 Sales Invoice（`docstatus = 1`）。
- 优先使用 Sales Invoice Item 的 `sales_order` 关联销售订单。
- 从 Delivery Note 创建发票时，还要支持通过 `dn_detail` 追溯到 Delivery Note Item，再追溯到 `against_sales_order` 和 `so_detail`。
- 订单存在未开票数量或未覆盖的应开票内容时，不能进入最终完成。
- 通常可以辅助检查 `per_billed >= 100`，但多次开票、退货和贷项凭证场景仍需按实际关联明细核对。

### 5.3 收款完成

- 以 Sales Invoice 的 `outstanding_amount <= 0` 和标准状态 `Paid` 为主要事实。
- Payment Entry 必须是已提交的 Receive 类型。
- 收款必须在 Payment Entry References 中实际分配到对应 Sales Invoice。
- 只看 Payment Entry 总金额，不能证明对应发票已经核销。
- 收到销售订单订金但尚未核销发票时，属于预收款，不算该发票已付款。

## 6. 销售发票列表中的状态解释

销售发票列表中的“未付”和“已付款”是发票层面的财务状态：

| 销售发票状态 | 对应订单的收款判断 |
|---|---|
| 未付（Unpaid） | 不能完成 |
| 部分付款（Partly Paid） | 不能完成 |
| 已付款（Paid） | 满足该发票的收款条件 |

一个销售订单如果关联多张销售发票，必须所有发票都为“已付款”，订单才能满足最终完成的收款条件。

## 7. 当前系统展示口径问题

当前销售订单/交付报表将所有销售订单明细交付完成时显示为“已交货”，这属于履约状态，不等同于财务结清。

当前看板中的“完成订单”也使用“已交货”作为筛选条件，容易让用户把“已出库”误解为“已收款”。

后续展示应将以下内容分开：

```text
出库状态：已交付
开票状态：已开票
收款状态：未付款 / 部分收款 / 已付款
订单最终状态：未完成 / 已完成
```

建议保留 ERPNext 原生 `Sales Order.status` 的标准含义，不直接把“客户已付款”写入原生状态计算。后续如需在销售订单页面、销售订单清单或看板显示最终状态，应增加独立的业务完成状态或报表计算字段。

## 8. 特殊场景口径

### 8.1 分批交付

第一次只交付部分数量时，订单为“交付中”；只有所有明细交付数量达到订单数量后，才满足交付条件。

### 8.2 分批收款

发票分多次收款时，发票为“部分付款”期间，订单不能显示最终完成；最后一笔收款核销后发票变为“已付款”，才满足该发票条件。

### 8.3 多张发票

同一销售订单存在多张发票时，不能只判断其中一张。所有关联发票都必须提交且已付款。

### 8.4 贷项凭证、折让和核销

`outstanding_amount = 0` 可能来自客户付款，也可能来自贷项凭证、折让或核销。默认“财务结清”可以使用余额为 0；如果业务要求必须是客户实际到账，则还需要单独统计 Receive 类型 Payment Entry 的发票核销金额，并明确是否允许折让、贷项或核销计入完成。

### 8.5 退货或取消

Delivery Note 退货、Sales Invoice 取消、Payment Entry 取消后，应重新计算订单状态。只要交付、开票或收款条件有一项不再满足，订单就不能继续显示最终完成。

## 9. 验收场景

1. 订单全部送货，未创建发票：显示“待开票”，不能完成。
2. 订单全部送货，发票未付款：显示“待收款”，不能完成。
3. 发票部分付款：显示“部分收款”，不能完成。
4. 发票全部付款且 `outstanding_amount = 0`：订单显示“已完成”。
5. 一个订单两张发票，一张已付款、一张未付款：订单不能完成。
6. 收款直接关联销售订单但未核销销售发票：订单不能完成。
7. 销售发票因贷项凭证余额为 0：按确认的财务口径判断，不能默认等同于实际收款。
8. 付款或发票取消后：订单状态恢复为相应的未完成状态。
9. 分批交付、分批开票、分批收款：只有三项全部完成后才显示“已完成”。

## 10. 后续实施边界

后续实现前需要先确定展示位置和字段方案：

1. 是修改销售订单清单/看板中的“完成订单”口径，还是增加销售订单表单上的最终状态字段。
2. 是否保留“已交货”指标，并新增“已收款完成订单”指标。
3. 是否将贷项、折让和核销导致的发票余额为 0 视为已付款。
4. 是否需要处理历史销售订单的状态回算。

在上述口径确认前，不直接修改 ERPNext 原生销售订单状态，也不自动提交发票或收款单。
